# Restricted local account tools

Use this reference only when the trusted host explicitly supplies the `dev-test-accounts-v1` profile and the `dev_test_accounts_call` tool. The host fixes the local socket and maps the operating-system caller UID to current authorization. Model requests cannot select a principal, credential, private file, origin or signer. Do not inspect host policy, unlock input or another user's storage.

The only methods are `accounts`, `open`, `close`, `describe`, `task`, `capabilities`, `context`, `move` and `lookup`. Account creation, transfer, construction, scheduling, raw native commands and administrative operations are unavailable through this profile. Missing access is a stop condition; do not switch to a broader tool.

1. Call `{"method":"accounts"}` and choose an authorized grant from the returned directory. Before opening it, obtain the current Unix time and that grant's public session-expiry upper bound from the trusted host's non-secret run input or approved public clock/authorization information. The current `accounts` response lists identities and bindings; it does **not** provide this expiry bound. If the host has not supplied it, stop and report missing public session-expiry information; do not inspect policy or guess an expiry.

   `open` requires `expires_at_unix`: an unsigned 64-bit JSON integer containing **absolute Unix seconds**, not milliseconds, a duration, a string or an expression. The selected value must satisfy `now_unix < expires_at_unix <= session_expiry_upper_bound_unix`. The host's public upper bound must not exceed the earliest grant expiry, caller-credential expiry and this run's deadline. Choose a short finite session within the remaining run: for example, calculate `min(now_unix + desired_session_seconds, session_expiry_upper_bound_unix)`, respecting any host-supplied minimum session duration. If no positive permitted interval remains, stop. Use a fresh approved clock reading when elapsed time makes the supplied reading stale.

   Request template (replace both placeholders before sending; `<selected-absolute-Unix-seconds>` must become an integer without quotes):

   ```text
   {"method":"open","grant_ref":"<returned-grant>","expires_at_unix":<selected-absolute-Unix-seconds>}
   ```

   Retain the returned `session_ref`, binding and `expires_at_unix`. A session reference is not authentication and cannot change its account, world, Agent or resource. `session_expiry_required` means this required field was missing: correct the request using the public time/bound above. `session_expiry_exceeds_parent` means the requested expiry exceeds the caller's authorization; do not extend that authorization yourself. `session_scope_denied` can include a past expiry, exceeding the grant's expiry or another scope mismatch: recheck the public interval and binding, and stop for host clarification if they do not explain it. An expired or unavailable authorization is a stop condition, not permission to guess successively larger or smaller timestamps.
2. Use `describe`, `task` and `capabilities` with `session_ref` to read the complete current task and limits. Switching A to B requires B's separate grant and session; switching back uses A's own session. Never reuse B's context for A.
3. Obtain context using `{"method":"context","session_ref":"<session>","operation":{"request_id":"context-A-1","arguments":{"kind":"context"}}}`. Preserve the full response and its binding. Read the verified full goal text and soft constraints in the context. Require `active_goal.content.goal_text`, complete `soft_constraints`, and `active_goal.source` with the matching task fence, active goal reference, owner and read/activation commits. If content, constraints or source binding is missing, stop; the destination allowlist is not a substitute for the task goal. An unavailable or unknown context cannot authorize a move.
   Context preparation can complete asynchronously. A first response with `status: unknown`, or an observation whose original operation is pending/unknown, is not permission to move and does not require a replacement Context. Retain the original Context request ID and exact body. Within the remaining authorized time/call budget, query it using `{"method":"lookup","session_ref":"<current-session>","operation":{"request_id":"lookup-context-A-1","arguments":{"kind":"lookup","original_request_id":"context-A-1"}}}`. Target the original Context ID, not a previous Lookup ID. Repeated queries still count toward the budget; stop at its limit rather than polling indefinitely.

   Read the returned `result.observation`: for a usable Context it includes `operation`, `context`, `usable_context`, `native_authority` and `active_goal`. Require the original operation's `outcome.status` to be `committed`, `usable_context: true`, and the complete verified goal/source and same-account/task authority before choosing a Move. The Move's `context_request_id` remains the original Context request ID even when that Context was recovered through Lookup. A Committed prefix alone does not establish write eligibility: `usable_context: false` / `context_state: unavailable`, an expired lease, missing proof or a host-declared lookup-only recovery permits no new Move. Preserve that terminal/unknown result and report the boundary; this profile provides no administrative context renewal or rebind.
4. Choose only an allowed destination justified by the full task and current context. Send `{"method":"move","session_ref":"<session>","operation":{"request_id":"move-A-1","arguments":{"kind":"move","context_request_id":"context-A-1","to":[1,0,0]}}}` only if that destination is actually allowed. The example destination is not universal authorization.
5. If the response is lost or unknown, retain the original move ID and exact body. Reconcile using `{"method":"lookup","session_ref":"<session>","operation":{"request_id":"lookup-A-1","arguments":{"kind":"lookup","original_request_id":"move-A-1"}}}`. Do not create a replacement move ID or context to conceal an unresolved original. Same-ID replay preserves the original operation but every admitted request still consumes the tool-call budget.
   Ordinary backend restart invalidates in-memory sessions without deleting durable original operations or resetting usage. On `session_unavailable`, retain each original request ID/body and account binding. If current authorization and the public expiry interval still permit it, use `open` as above for the same grant to obtain a new session, then `lookup` the original Context or Move ID with that new session. Do not resend a new Context/Move merely because the old session disappeared. If the grant/credential is expired, revoked or unavailable, stop and ask the host for current authorization; a new session cannot extend it. A newly supplied authorization does not itself prove that an old Context is writable. Reconcile the original and recheck its current eligibility. Unknown transport results do not prove rejection or absence of effects.
6. Read the canonical operation observation and world outcome. JSON-RPC success and root `status: ok` only establish transport/admission success; they do not prove that a move committed. Preserve `unknown`, conflict and rejection states. Stop when authorization, session lifetime or budget expires. `close` prevents later session admission; it does not undo an accepted world action.

The host starts the dedicated `oasis7_dev_test_local_tools stdio APPROVED_SOCKET` process under a distinct restricted model UID. Only the trusted daemon receives private policy and credentials. The stdio bridge forwards one request once and returns the backend business response without inventing success or new operation IDs. It does not launch a model or establish model-provider spending authority.

Local protocol and synthetic transport tests do not certify an external model's gameplay. Actual model acceptance remains pending separately authorized execution and canonical world evidence.
