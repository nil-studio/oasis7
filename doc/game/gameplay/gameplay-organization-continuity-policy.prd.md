## 1. 场景、范围与取舍

一个组织的负责人长时间没有回来，成员希望维持已经承诺的供货，但仓库里既有组织自己的原料，也有客户寄存物和成员个人资产。维护者需要知道自己能继续什么、谁可以接替、什么时候必须等候，以及原负责人回来后如何恢复。政策必须让连续经营和退出都可执行，同时把损失、停顿和不得处分的部分说明白。

v1 适用于正式登记了组织身份、charter 授权来源、资产权属与连续性政策的组织。既有联盟可以保留原身份后接入；没有上述事实的旧联盟不能因为缺字段就被推定为无人所有资产。Agent 的个人 claim/upkeep/reclaim、区域 charter 退化、战争处置、普通治理资格与保供授权各按原 authority 运行。

玩家可选择保持正常经营、预先指定接替人、为有限维护存入资金、申请恢复、提出异议、重组或解散。保护会暂时减少扩张和交易机会；接替需要公开承担有限义务且不能得到免费资产；重组可能保住业务但延迟剩余分配；清算可能失去产能且不保证足额偿债。若当前没有合格接替人或安全处置路径，允许停在保护和可读等待，不能以“必须结束”为由降价甩卖或扩权。

## 2. 活动与时间政策

<a id="oc-policy-time"></a>
### 2.1 有效活动、通知和保护窗口

Trace refs: O7-REQ-6e6d890d-c94d-4b43-9947-bfccf2f066e3；声明：[REQ-WR-OC-002](../../product/world-rules-core-gameplay/organization-continuity-dissolution-and-dormancy-protection.prd.md#req-wr-oc-002)。

有效活动必须是有权主体或其仍有效的 Agent 委托在该组织经营范围内，实际完成并形成世界 receipt 的履约交付、外部服务结算、非循环生产交付，或实施已获授权且改变真实业务责任的经营决定。持续自主业务的真实交付可以保持组织活跃，不要求人类一直在线。只开订单未履约、内部往返转账、登录、心跳、重连、聊天、投票重放、改名、拒绝动作、自动扣 upkeep 和保护维护自身不算有效活动；同一来源效果只计一次。无组织归属证据或事实来源不可核验时保持未知，不推定为不活跃。

政策周期 `P` 固定为 **1,440 个有效连续性 tick**，不等于现实一天。所有观察、通知、保护、授权和申诉截止使用同一个世界连续性时钟 `C(t) = 自启用以来已提交的权威逻辑 tick 数 − 其中已在权威日志记录的服务暂停区间并集长度`。runtime 不读取客户端时间、不依据进程运行时长补算。世界停机、尚不能接受权威写入、或正式通知/异议入口被权威标为不可用期间不消耗窗口，恢复不能补扣离线时长。玩家个人离线而世界与正式入口持续可用时，窗口继续，但离线、未读和不回复本身都不表示放弃权利。

`C` 是单调累计值。每个尚未计入的逻辑 tick 区间只按提交时可验证的可用/暂停事实确定一次增量；证据缺失或过期则不推进。暂停区间不得在计时已经确认后倒填并回减 `C`，也不能复活已过期授权。迟发现服务故障时通过新的关联恢复/纠错结果保护受影响权利，原时间、原授权终止和历史 receipt 保留。

| 参数 | v1 默认值 | 规则含义 |
| --- | --- | --- |
| 不活跃观察窗 | `30P` | 从启用或最后一个有效活动的较晚者起，满窗且仍无有效活动才可通知；旧 `last_active` 不直接导入 |
| 通知窗 | `7P` | 完整通知已持久发布到组织公告和已知权利人的正式收件面后开始；外部邮件/推送为补充，未读不推导同意 |
| 保护窗 | `30P` | 通知窗结束且事实仍成立后开始；到期只允许评估受限持续，不自动解散或转移所有权 |
| 接替候选收集窗 | `7P` | 保护期最后一个候选窗收集自愿申请；资格按该轮固定事实比较，任命前再次重验 |
| 单次有限授权期限 | `7P` | 到期失效；续任是显式新决定，重验范围、资格、资金与未决义务，不自动续期 |
| 成员接替最低资格历史 | 通知前已连续加入 `7P`，且此前 `120P` 内有 `2` 份不同来源的相关履约/维护能力 receipt | 能力事实可来自同类独立业务；不能要求在不活跃观察窗内必须有组织活动而形成互相矛盾的资格 |
| 资产清单/拟处分公示窗 | `7P` | 首次处分或扩大处分范围前，向受影响权利人公布具体清单和债权处理；新增范围单独计时 |
| 申诉提交窗 | 被申诉结果可读通知后 `14P` | 限本次程序性申诉；仍未最终处分的权利可申请 reclaim；新发现权属/欺诈事实另起关联程序 |
| 补证窗 / 裁决复查点 | 各 `7P` | 缺证请求补证到期可终止该请求；已受理争议到复查点仍未裁决则继续阻塞争议范围，绝不自动通过或驳回 |

通知列明触发事实、最后有效活动、政策版本、范围、剩余窗口、允许动作、受限动作与主张入口。对象、资产范围或影响后果扩大时，新增部分重新完整通知并给予保护；不能用旧通知覆盖新权利人。重复通知、换 case ID 和换政策不得缩短已在保护中的剩余窗口。

在通知阶段，确认真实活动恢复或事实错误后关闭该通知；在保护或受限持续阶段，活动只是恢复证据，须经 reclaim/恢复确认后更正阶段，不能靠打一条心跳解除冻结或已成立义务。相同原因被纠正后不得立刻重复开案；重新达到观察窗或出现独立风险事实才可新开案。

## 3. 接替与恢复政策

<a id="oc-policy-succession"></a>
### 3.1 资格、排序、撤销与部分交接

Trace refs: O7-REQ-b59a4fa5-9b5f-4119-abf6-7c0f2b4f4268；声明：[REQ-WR-OC-003](../../product/world-rules-core-gameplay/organization-continuity-dissolution-and-dormancy-protection.prd.md#req-wr-oc-003)。

候选必须主动接受公开的工作范围和期限，具备该类动作的现行世界资格，有可核验能力和足额的专用维护预算，没有与拟处置范围冲突的撤权/裁决，并披露自己或关联主体是否为买方、优先受偿人或争议受益人。候选不能裁决自己的资格、申诉或与自身关联的资产交易；相关冲突必须切出给预先有权、无利益冲突的裁决主体。外部代币持有量、出资额、登录先后和首个请求抵达均不单独产生资格。

| 顺位 | 合格候选范围 | 同顺位比较 |
| --- | --- | --- |
| 1 | 通知前已由有效 charter 指定的接替人，且其资格与接受意愿仍成立 | 预先登记的接替顺序；同一顺序冲突则阻塞，不猜测 |
| 2 | 满足 §2.1 历史条件的既有成员 | 连续成员资格更早者优先；仍相同按本轮有效申请的权威提交序、主体稳定 ID 排序 |
| 3 | 通知前已进入 charter 认可名册、具有同类能力证明的中立维护人 | 该名册预先公布的顺序；同序按本轮有效申请的权威提交序、主体稳定 ID 排序 |

排序决定推荐候选，不能替代任命权限。有效 charter 的任命者或其已声明的治理程序，必须按上述排序确认任命；跳过更高顺位仅能基于拒绝、到期未接受或可验证的资格失败并给出理由。charter 缺任命/争议处理 authority，或所有候选均不合格时，维持保护和最小安全停止，不让普通多数、节点运营者、出资人或 API 管理员接管。既有合法治理程序决定“谁能批准”，本政策不另定治理权重。

有限授权仅用于所列资产/业务的安全停止、既有义务履行、预算内维护和明确批准的有限重启；不附带所有权、再委托、出售、借贷、抵押、新长期订单、制造追加产能或保供新授权。专用预算没有资金时为零，不允许垫付后自动取得优先债权。愿意补资者按明确赠与或原合同提供资金，不因此提升接替优先级。

撤销、到期、资格丧失、预算不足或维护目的消失后，受影响范围停止接纳新动作并回到保护；已经确认的履约责任、在制品和外部在途结算继续依原合同处置。原有权主体回来后可申请 reclaim：先确认其当前权利，再原子收回重叠临时授权并恢复合法控制；未决债务、已消费成本和已合法交付不得清零。

部分交接只按可独立经营和结算的权利单元进行：可拆的物料批次须先有权威拆分结果；独立设施可分别交接；同一个 Agent 控制权、单设施独占操作权、不可拆合同/托管包和共享在制工序不得按百分比拆成两份。冻结、争议或占用中的范围先解除相应阻塞；不重叠且无共享义务的部分可以先交接。旧授权未确认请求永不自动迁移；新主体显式重提也不能获得旧队列位置、重复退款或重复维护效果。

<a id="oc-policy-remedies"></a>
### 3.2 reclaim、申诉与结案

Trace refs: O7-REQ-6e6d890d-c94d-4b43-9947-bfccf2f066e3；声明：[REQ-WR-OC-002](../../product/world-rules-core-gameplay/organization-continuity-dissolution-and-dormancy-protection.prd.md#req-wr-oc-002)。

组织当前合法代表可就组织控制申请 reclaim；成员和第三方可就有来源证明的独立所有权、托管物、合同债权或受影响的程序权利提出申诉。历史头衔或以前控制过 Agent 不足以证明现在有组织处置权。

请求登记不授予控制、不取消义务。具有有效身份、具体争议范围和可核验证据引用的请求被受理后，只暂停该范围内不可逆转让、剩余分配及扩权交接；查询、最小安全停止和不触及争议资产的已成立义务继续。形式不完整的补证请求不产生停留效果；同一主体、同一范围和同一事实的一项请求可补证，不能靠换 ID 延长窗口或叠加全局冻结。

正式救济入口因服务或案件/主体容量不足而不能保障合法提出请求时，该 case 暂停新的不可逆处分、首次外部派发及扩权交接，手动操作同样受限。关门时尚未到期且受影响的程序性救济窗口保留剩余量，恢复入口后按已记录关门区间顺延未来截止；不回拨 `C`、不延长或复活操作授权，也不复活关门前已经到期的窗口。拒收请求本身不创建新的全局停留效果；原请求补证/裁决、查询、安全停止和已经合法开始的固定履约继续按原规则处理，其他组织不受该 case 的容量阻塞影响。

裁决者由该组织事前有效 charter 或已有适用治理程序确定，且不得是请求人、被质疑维护者或关联交易受益人。证据齐全的客观事实错误可按已预授权规则更正；需主观裁量却无独立有权裁决者时保持待决。受理、驳回、撤回、补证过期、支持和部分支持分别可读；驳回/撤回只解除该请求造成的限制，不能解除案件原有保护或其他有效争议。

全部或部分支持只能恢复仍可恢复的范围；对已合法完成的第三方转移，不从新权利人处直接夺回，而依适用责任作新补偿/纠错裁决。已解决的 case 保留权利、责任和 receipt；新事实开启关联 case，不能改写旧结果。

## 4. 资产、义务与处置

<a id="oc-policy-estate"></a>
### 4.1 estate 白名单与清偿顺序

Trace refs: O7-REQ-366c9e94-4bd6-41f8-93dd-8d87f163f21a；声明：[REQ-WR-OC-001](../../product/world-rules-core-gameplay/organization-continuity-dissolution-and-dormancy-protection.prd.md#req-wr-oc-001)。

estate 是按权威清单隔离权利与义务的处置容器，不是新所有人。清单只可包括有正式组织权属 receipt 的可转让库存/余额、设施产权、既有业务收益请求权，以及原专业规则明确允许转交的经营或 Agent 控制权。后两类始终只是其已有权利，不能扩张成永久所有权。

成员个人资产、第三方寄存/escrow、租赁物、受限补贴、不可转让资格、治理权限、Agent 身份/记忆/历史、外部代币/服务额度以及所有权有争议的物品，不属于自由处分资产。托管物单列返还账，租赁物依合同归还，受限余额按其发放规则处理；未知权属进入隔离清单，不能视为无人认领剩余。

| 阶段 | 必须完成的处置决定 | 资金/资产不足或存在争议时 |
| --- | --- | --- |
| 1. 风险冻结与清单 | 固定清单、权利人、冻结版本、适用合同与潜在责任；限制新负债、抵押和范围内不可逆处分 | 未核实对象隔离；其他可独立范围继续查明和保全 |
| 2. 既有合同 | 已成立制造、物流、保供、服务与工资等合同在原预算/授权内完成，或按原合同合法终止；列明在制品、预留、赔付与在途效果 | 不能自动转给新成员或追加产能；确认损失/债权并保留占用，待结算或有权裁决 |
| 3. 可识别托管返还 | 第三方所有物原物返还；可分余额按原账本返还；不得先拿去清偿组织债务 | 同一可分托管池因已证实损失不足时，按各人的已确认份额同比分配实际可返还量，差额保留责任请求；不跨池摊损 |
| 4. 债权、成本与责任 | 已有有效担保从其抵押物/所得优先处理；保全实际成本仅限事先批准专用预算；剩余合法普通债权同级按比例清偿 | 不足不向独立成员自动追缴；未清偿责任继续保留，不以 case 结案视为免除；争议额须预留或隔离 |
| 5. Agent/设施/持续业务 | 在前序权利、负担和偿付计划已确认/预留后，优先选择有明确接收人和义务同意的重组或持续经营转让；无安全交易则保管、停机或依原规则退休 | 首版不自动无底价拍卖，不为强制结案销毁身份或低价出售；处分所得回到前序清偿账，不能直接发给成员 |
| 6. 剩余 | 前序义务已履行、足额预留或经适用程序明确终结后，按冻结前有效 charter 的剩余权益份额分配 | 无合法份额规则时，按冻结时具有剩余权益的成员等份；成员名单/资格存在争议则隔离对应份额，不给维护者或运营者 |

阶段 4 的“处理”包含确定债权、优先级及预留/偿付计划，不要求先凭空付清所有债务才能出售设施。阶段 5 变现必须绑定已经公开的清偿计划，所得先回流阶段 4，只有真正无负担的净剩余才可进入阶段 6。对未知数量且无法形成可靠上限的责任，相关资产不得标为已足额预留。

同级可分资产不足时，每个权利人的实得基础份额为 `floor(可分配量 × 该权利人已确认请求量 / 同级已确认请求总量)`；剩余最小单位按小数余数从大到小分配，同余数按权利人稳定 ID 排序。金额和数量使用原资产最小单位；不同币种/物料分别计算，不建立隐含汇率、任意估值或负余额。不可分资产不能按比例复制；可按已授权且公开对价的交易变现，或经所有受影响权利人同意作有价实物分配；条件不成立继续保全。

charter 剩余份额只在固定快照中决定末级权益，不能使成员利益优先于第三方所有权、既有担保或债权。正常章程修改在新 case 生效；通知后临时改份额、短暂转让或换组织不能改变本次优先级。新发现负债或资产追加到同一来源账，所有已占用、已支付和已处分量在跨请求、跨授权、跨关联 case 中累计去重。

## 5. 专业验收与证据边界

| 验收 | 给定 / 当 | 可判定结果 | 上游及系统方法 |

## 6. Non-Goals

- 不改个人 Agent claim、区域 charter、普通治理权重、保供准入、配方成本或外部资产结算规则。
- 不启动 SC32 制度试点，不要求将联盟迁入 WASM，不由本政策直接赋予任何主体治理、处分或恢复权限。
- 不定义 runtime wire schema、数据库、签名、跨节点协议、UI 布局或部署操作；具体技术义务由既有[系统设计](../../world-runtime/runtime/organization-continuity-and-disposition.design.md)承接。
- 不承诺自动全额偿付、自动卖出、无限维护或永久存储所有敏感材料；保留可追溯责任与权利身份，数据生命周期消费存储 authority。
