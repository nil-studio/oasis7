## 测试范围

普通 CI 是默认验证方式。成功规划后轻量 baseline 始终执行；选择器使用完整 Git name-status diff、base/head 两侧 Cargo 关系及必要目录映射选择 Rust、Web、场景、平台、打包和运维合同测试。

Rust 变化覆盖自身及需要验证的反向消费者，删除和重命名覆盖两端；保留有效 features、WASM、生成输入和平台组合。workspace、features、锁文件、共享生成器及共享或尚未分类的 CI 控制输入变化采用保守普通 required，图解析失败仍扩大覆盖；未登记路径按下述门禁阻断。

已审读并按精确路径登记的独立 GitHub 元数据和 CodeQL workflow，由 baseline 和现有 workflow_governance 合同测试承接。该分类仅取消无关的共享控制全量触发，真实源码、嵌入输入和测试消费者仍取并集；未知 workflow、共享 Actions、构建与缓存控制继续保守全量。Rust 嵌入输入应识别源文件中的真实宏调用，注释、普通字符串、raw string 内的测试源码文本不单独扩大范围；真实动态输入无法解析时仍保守扩大。

`./scripts/ci-tests.sh required` 是普通必要测试的本地入口；`full` 保留广覆盖回归。Rust workflow 已配置每四小时 schedule，由完整组集合、平台矩阵和扩展回归共同形成完整结果。真实产品测试、WASM 确定性、共识、持久化、安全、升级恢复和跨平台打包均继续保留，调整的是执行时点与适用范围。

### 未登记路径门禁

Trace ID: O7-REQ-4e7f2e0d-9147-43d9-a593-00a8db9b21df

选择范围中的路径必须匹配 Cargo 包归属、显式目录规则或共享构建/CI 控制规则。未登记路径属于范围规则缺口，必须使规划失败并列出所有未登记路径，不得用全量回退或额外组请求掩盖；新增、删除及重命名两端均适用。

规划失败不启动测试组，最终 `required-gate` 仍执行并失败，不能 Pending 或伪装成功。

依赖图/Git 输入无法解析时仍保留保守全量，不能将解析失败误报为确定的路径缺口。

规则使用事件基线的可信版本；引入独立目录前先将归属及真实验证入口登记进基线。

候选分支自行新增忽略规则不能为自身放行。该要求属于 CI 专业治理，不新增玩家或游戏行为要求。

## 调度和结果

select 先产生明确的非空矩阵，按资源组并行执行。最终唯一 `required-gate` 使用可靠的 always 汇总，并显式依赖 select 和所有组。选中组必须 success；未选中组可以 skipped 或 success；失败、取消、缺失、未知及意外 skipped 都必须阻断。矩阵不吞退出码，采用 fail-fast=false。

记录 source HEAD、base 和实际测试对象及运行链接。普通 PR 权限只读，从事件 base 提取可信选择器及执行清单；候选控制变化不能缩小基线覆盖。CI 控制、安全或兼容边界变化接受对应能力的独立评审。

## 专项条件

缺测试先补普通 CI。只有普通 runner 难以提供的真实长期状态、专用硬件或受控环境才使用专项验证，说明具体不足、环境、版本、通过标准和实际结果。阻塞专项纳入同一 PR 最终汇总；调试 dispatch 不能替代 PR 检查。

CI 结果对应实际 source HEAD。main 前进或分支显示 `BEHIND` 本身不使该结果失效；只有合并冲突或 main 的相关变化带来明确集成风险时，才按需更新分支并验证实际组合。source HEAD 变化后重新运行必要普通 CI，复审实际变化与受影响部分；具体合入规则遵循开发流程规范。产品层的签名、checkpoint 和状态一致性证明仍按专业合同验证。

CodeQL 技术扫描见 [CodeQL 设计](codeql-integration.design.md)，实际 required/advisory 按 GitHub CI 与生效保护执行。

## PR 快速反馈与四小时完整回归

Trace ID: O7-REQ-a34ef03b-c8ee-4988-af23-67ad20e65e29

本要求面向开发者、CI 维护者和发布负责人：普通 PR 尽快验证本次变更及必要消费者，main 周期回归验证更广的组合与长时间行为。部分集成问题允许在合入后发现，完整回归的失败处置与发布版本校验承担相应保障。当前接口与失败边界由[分层实施设计](ci-tiered-execution.design.md#ci-fast-pr-periodic-full-design)承接；本地合同验证不能代替 hosted 覆盖、时延和容量验收。

### 反馈目标与统计口径

普通文档或配置变更目标为 1～3 分钟，普通代码 PR 目标为 5～10 分钟；普通 PR 的成功反馈 P95 不超过 10 分钟。反馈时间从 workflow 创建到当前 source HEAD 的最终 `required-gate` 终态，包含排队、选测、安装、缓存恢复、编译、测试和汇总；排队与各执行阶段另列。

普通范围由运行前的可信计划确定。大范围依赖/工具链变更、具体关键风险或无法可靠限定影响范围时，允许必要加测超过十分钟，并在计划中给出原因和检查集合；不能在运行超时后把普通样本改成例外。冷缓存仍计入所属范围，不从统计中删除。

报告固定观察窗口、样本数、成功与失败/超时/取消分布、冷暖缓存及例外原因。所有普通成功样本均计入成功反馈 P95，失败到结论的耗时另列，避免早失败拉低性能数字；不能只选暖缓存或较快运行。样本不足时仅报告观察值。十分钟是工程验收目标，未完成检查不得因超时、取消或忽略退出码而通过。

<a id="ci-pr-fast-selection"></a>
### 快速检查的准入与迁出规则

先判断本次变更需要在合入前证明哪些行为，再优化这些检查的执行成本。PR 必要集合由三部分取并集：始终进入的轻量基线、影响命中的快速行为检查、风险命中的必要定向加测。基线入口始终执行，内部文档、格式等检查按真实输入适用；纯说明文档不因此运行无关业务测试。定向加测可以包含重型用例，仍由同一 PR 门禁汇总。

选择单位是可独立执行的检查、Cargo target 或完整 case，不能直接按旧 job 名称、单元/集成测试名称或 required/full 标签判定快慢。具体准入规则如下：

1. **有明确的变更关联。** 除普适基线外，检查必须对应修改的行为、真实输入或必要消费者；路径、依赖、生成输入和删除/重命名共同决定影响范围。测试短不是所有 PR 都运行它的理由。
2. **能检出应在合入前发现的缺陷。** 受影响行为的快速集合覆盖适用的正常路径、拒绝/错误路径、边界、不变量和已有缺陷回归。用例选择依据这些合同，不按固定数量抽样；只有编译、启动成功或 happy-path smoke 不足以证明行为正确。
3. **可重复、隔离且有界。** 测试使用固定或可回放输入、独立临时资源和明确终止/清理条件，不依赖人工操作、生产状态或不受控外部服务。普通 runner 内的真实子进程、浏览器、临时数据库和回环网络可以进入快速层；需要真实进程、平台或身份链路证明的合同不能由 mock 替代。
4. **完整成本符合快速目标。** 连同准备、编译和执行前置评估整条 PR 关键路径，按上述成功反馈 P95 验收。case 很短但必须构建整套重型产物时，先拆构建目标或复用兼容产物；现有 required 标签和单次暖缓存结果都不是准入证明。无耗时历史的新增测试先保留必要执行，再量测优化。
5. **重型职责有明确承接。** 广 feature/平台组合、长历史、压力、恢复矩阵及完整打包可以默认放周期层，同时说明对应基础行为在快速层如何验证、哪些变化触发合入前完整场景。若完整场景是检出本次权限、数据完整性、恢复或协议等关键风险的唯一有效检查，必须在本 PR 加测；快速检查不需要冒充长场景的全部证明。
6. **迁出后仍实际执行。** 迁出旧 PR 检查前，核对周期真实入口、原断言、操作长度、平台/features 和失败传播，并验证相关风险仍能触发定向执行。新增及修改行为的回归用例先进入其受影响 PR 的必要集合；仅承担扩展覆盖的用例才可按上述规则安排周期执行，标签语义由 [case 分级要求](ci-testcase-tiering.prd.md#case-tier-assignment)细化。

必要集合超出预算时，优先减少无关编译、合理并行及复用产物；普通范围仍超预算就报告未达标，不能仅因耗时长改为例外或迁出。已有不稳定测试先定位修复，不能仅因 flaky 下放周期层。不得通过随机漏选、截短完整场景、删断言、吞失败或重试覆盖首次失败满足目标；允许例外的范围仍须在运行前按关键风险或大范围变化判定。

### 各模块的分配方向

| 检查职责 | PR 与 main push 的快速集合 | 每四小时完整集合 |
| --- | --- | --- |
| 基础与文档治理 | 本次变更、必要索引和受影响引用关系；无相关输入时及时结束对应子检查 | 全库一致性及历史内容报告；保留原阻断/报告语义 |
| Rust | 受影响 crate/target、必要反向消费者的编译、Clippy，以及符合准入规则的正常/拒绝/边界/回归用例和适用 features | 全仓适用检查、扩展 feature/target 组合与完整集成回归 |
| Formal process | 受影响的状态转换与关键不变量，命中风险时追加保持原长度的真实进程场景 | 全部既有逻辑 suite、长历史、故障恢复与五个物理分片 |
| Viewer、Launcher、Command Center | 前端/接口/Core/生成类型合同及适用编译；身份、会话或平台行为变化追加相应真实验证 | 完整浏览器、WASM、跨模块和 App 打包验证 |
| 平台、打包、运维 | 修改对应行为时的必要定向验证 | 全部适用平台与打包/运维回归，保留有界压力和稳定性场景 |

分配到周期层的检查必须有真实执行入口，`full` 包含快速集合及所有迁出的适用检查。单一 Linux job 不能代替原生 Windows/macOS 行为。付费模型、生产环境和专用硬件验证仍按既有授权与环境合同执行，不因周期调度自动扩大范围；未执行的范围明确列出。

ordinary Rust 的快速范围由可信组件合同决定，不再只对白名单中的少量文件生效。Runtime、World State、Simulator、World Service、World Projection、oasis7、Viewer Codec、Observability 和 Launcher Config 的已登记源码，在证明改动可达所选 Cargo target/features 后，执行所属组件完整非 ignored library 测试及必要的独立 integration；已登记的增量候选准备/查询仍执行 Runtime 全部原生 unit 和真实物理重开 integration。最低 case 清单保护正常、拒绝、边界与取消行为，不是用例数量上限。修改 integration、fixture、生成输入、未映射源码、不可达 feature gate 及共享控制时，继续执行能覆盖真实输入的原必要范围，不能仅因位于组件目录就忽略。

反向消费者图继续用于识别影响、直接平台需求与明确风险，但不再把每次有界内部改动都升级为全部上层长回归。明确 Formal 风险规则优先于组件快速合同；持久化、恢复、历史裁剪、共识、身份、host 和共享协议的必要定向加测保留。Launcher 完整 release 构建可以由真实直接输入触发，并由周期 full 覆盖其余组合；适用的 WASM 编译仍保留，只有证明改动在 WASM source 路由上不可达时才移除无关检查。

快速执行应在同一 runner 完成目标构建与测试，避免为了传递本轮刚编译的产物串行分配两台 runner。strict Clippy 使用相同可信 target/features 清单，在已有 Rust baseline 任务中并行执行；必须明确唯一执行组，不能因迁移而漏跑或放宽失败门禁。Rust baseline 保留格式、架构、依赖与必要治理；NewAPI accounting、独立工具锁文件等专项按真实影响触发，完整 profile 继续执行原全集。新执行能力须由可信 BASE 启用，旧 BASE、关键风险及周期完整计划保留兼容入口。十分钟/P95 仍以包含排队与准备的真实 hosted 数据验收；候选策略的只读性能预览不得替代本 PR 的可信 required 检查或发布证明。

架构检查保留全部声明与登记配置的依赖图。只有全部直接输入已由可信普通快速目标承接时，额外的 feature、平台及上层消费者编译矩阵才安排到周期 full；当轮仍实际编译、检查和测试快速目标。延期项明确记录，混合安全或未覆盖输入保留原矩阵；完整层负责发现仅在这些额外组合中暴露的兼容编译错误。

### 关键改动的定向加测

| 输入或风险 | 合入前必要验证 |
| --- | --- |
| 身份、签名、权限或托管密钥 | 授权/拒绝路径、身份绑定与相关端到端合同 |
| 编码、快照、持久化及恢复 | 往返完整性、关键不变量、受影响恢复场景 |
| 共识、最终性及确定性 | 对应状态转换、协议合同、实际确定性消费者 |
| Cargo 依赖、features、工具链、生成输入 | 受影响消费者和构建组合；影响无法可靠限定时扩大必要集合 |
| CI 选择、执行或汇总控制 | 可信基线覆盖、选择与失败传播、零匹配/取消/意外跳过的负例 |

定向加测属于普通 CI 的必要集合，不因风险标签重复运行另一套相同测试；只有具体环境不足时才适用上文的环境专项。删除、重命名、嵌入输入、依赖关系与未知路径规则保持。现有用例可按真实职责迁移，不能减少断言、操作长度或恢复条件来满足时延。

### 周期、主线健康与发布

main 的完整回归每四小时启动一次，保留手动候选验证入口。每轮固定 source SHA，并汇总所有适用平台、features 和检查；周期是启动间隔，发现延迟另含调度等待与运行时长。调度延迟、缺失运行和超时必须可见，不声称准点或四小时内必有结论。

main push 保留快速组合验证，不因每次合入重复启动完整重回归。PR 新提交可取消旧 PR 运行；周期完整回归使用独立并发控制，避免频繁 push 使其一直无法完成。完整回归应在下个周期前结束并保留容量余量，重任务不能占尽 PR 执行容量。

完整回归失败时记录最后成功 SHA、失败 SHA、提交区间、失败检查和运行链接，区分产品回归、测试不稳定与基础设施故障，优先修复或回退。真实失败不得由自动重试覆盖；没有可靠绿色版本时明确标为未知。普通 PR 不等待下一轮 full；已确认严重主线回归限制受影响范围继续扩大，允许修复及无关工作推进。

新发布或推广的候选必须具有同一 source SHA、适用平台/features 和完整检查集合的成功结果，且原发布验证仍需完成。需要发布尚未覆盖的候选时立即执行该候选完整验证；更早 main 的绿色结果不能代签。已有明确授权的保留版本回滚继续遵守恢复合同，不能据新普通发布规则阻断既有紧急恢复，也不能将回滚改称新版本验证成功。

完整结果由可信 main 验证入口产生并绑定检查定义及实际 run/attempt；首次候选 bootstrap 只验证接线，不能取得发布资格。Testnet 继续支持可信 main 入口的固定候选来源，仍须取得该准确候选的完整结果；其余发布来源限制保留。查询窗口、产物保留和失败重跑的处理见配对设计，过期、缺项或身份无法核实均阻止相应发布动作。

### 切换与验收

当前实现同时接入快速计划、构建范围、完整库存、调度/汇总及发布结果消费，保留 `required-gate` 的稳定入口和只读 PR 权限。迁移位置与适用条件由同源执行入口核对，实际 hosted 覆盖与耗时仍须验收。CI 自身变更由可信基线验证并接受独立评审，不能自行缩小本轮门禁；旧 BASE 回退期间仍执行旧必要范围。

<a id="ci-install-cache-evidence"></a>
### 缓存复用与真实证据

**目标**：缓存是可以丢弃的加速层。未命中、被回收或首次使用时，冷安装仍应正确、安全且可观察。可信 writer 与普通 PR/候选消费者的权限边界遵循[包来源与缓存安全规则](../../engineering/workflow/package-source-security.md)，不为提高命中率扩大写权限。

**验收**：

- 区分未命中、命中后校验成功、缓存损坏和恢复错误；只有验证合格的工具可进入构建。损坏缓存不得作为成功的冷/热样本，也不得回退到未经验证的 binary。
- 描述实际生产者与消费者的 workflow、事件、ref/scope、平台、架构、工具版本和安装策略。若跨 tag 复用需要默认分支 seed，必须确认有效 main writer、实际保存结果及后续消费者可达性；不能仅凭 key 不含 tag 或名称相同宣称可跨 tag 复用。
- 读取同类构建依赖的消费者使用可信 producer 的缓存身份，不因工作流或 gate 名称重复保存相同依赖。普通 Rust CI 与 Release / Mainnet 的 core、support、sync、soak 共享一个原生依赖快照，由可信 main 完整回归任务统一生产；并行消费者保持只读。producer 显式编译各消费者需要的 feature 组合，完整成功后才保存，不能把功能超集、下载的测试 binary 或首先结束的 shard 当作完整 target。生产覆盖变化须更新共享缓存版本。不同 target/profile 的产物可以共存，Cargo 仍按实际输入判断复用；WASM 发布包、ECS 与 Formal workspace 保留其生产频率和恢复合同适用的专用缓存。
- 共享须对齐工具链、环境指纹、路径与 cache version。临时 GitHub-hosted runner 的无关预装 Rust 工具链不参与共享身份，固定的实际构建工具链仍校验并参与 hash。registry、target 的库存节省与每个消费者恢复大包的传输成本分别量测；没有 hosted 数据时不承诺耗时收益。缺少缓存或缺少对应产物时，消费者继续原构建和测试。
- 跨 tag 命中须有真实 writer 和 reader 的运行记录；尚未 seed、没有可达缓存或未执行 reader 时如实记为未验证，允许通过正确的冷路径完成必要工作。
- 冷/热对比包含恢复、准备/验证和保存成本，不能只统计省去的安装时间。

### apt 安装预算与故障处置

**目标**：先从实际 job 日志核实 apt 耗时、锁等待、网络失败和重试频率，再决定是否改造。若进入实现，安装必须有覆盖命令执行、等待、退避、重试及清理的有限总预算；具体参数由观测数据和运行环境决定，不建立仓库统一的固定全局 SLO。

**实施后的验收**：

## 真实覆盖与执行结果合同

本节是测试专业要求，不新增玩家产品承诺或另一条合入审批链。实施状态仍由实际候选与运行记录证明。

**required/full 包含关系**：对同一 source、平台、features、target 和适用范围，`full` 的实际检查集合必须包含对应的 `required` 集合。不能仅因函数名为 full 或总测试数更多就视为满足；Clippy、独立 Viewer browser smoke 等 required 检查不能被另一项编译/测试成功替代。平台不适用项有明确原因及受支持平台入口，缺依赖、缺 target、命令未执行不是“不适用”。每个适用检查失败都传播到 suite 和已有最终汇总。

**native/WASM**：稳定工具链 smoke、需要确定性工具链的真实 builtin 构建/hash 和容器接线测试分别取证。维护实际消费者到构建入口、产物和验证命令的映射；缺少必要 WASM target 或全局设置 `BUILD_STD=0` 不能把 required 验证变成空执行。fake Docker 只证明调用/参数合同，不证明真实容器编译、产物或 hash；已明确退役且没有消费者的旧 lane 不重新变成必跑现场。

**构建 wrapper**：wrapper 保留被包装命令的退出结果、参数边界和有效 target 选择。子命令正常删除 target 并返回 0 后，退出记账不能为更新 `last_used` 等元数据重建 target 或制造失败；lease 释放和 GC 占用保护仍成立。多个互相冲突的 target-dir 必须归一为唯一有效值或明确拒绝，不能靠不同层解析出不同路径。原生 Windows 的跨进程等待/取消与 I/O 故障必须在原生 Windows 分别验证，WSL 或短于系统重试窗口的样本不能代签。

**扫描与证据**：CodeQL 每种声称支持的语言及 default/extended 组合分别记录执行、分析上传和 finding 处置。结果集合不完整、API 后页失败、run/attempt/source/category/App 不匹配时保留未知，不以当前零条结果认定零 finding。

具体扫描和启用仍归 [CodeQL 设计](codeql-integration.design.md)；本节不启用 observe、不增加 required check、不改变查询集合或超时。

验收至少包含：故意从 full 漏掉一项 required 被识别；各选中命令返回非零使 suite 失败；真实消费者路径未执行时不能报通过；wrapper 删除 target/非零退出/带空格参数/`--` 应用参数/环境覆盖/原生 Windows 长等待与取消分别保持合同。已合入依赖升级只复核剩余兼容边界，不无条件重复历史版本或完整 fleet 验收。

## 真实进程验收与共享产物

普通 required 与真实节点、长历史、健康副本集、存储恢复、生命周期 CLI 验收分开反馈；正式分片的最小构建与普通测试构建独立调度，正式分片就绪后立即启动，不等待 Viewer、普通集成测试或 default-feature snapshot 等额外变体。

<a id="ci-formal-cache-budget"></a>
### 正式缓存容量与保留

本节细化上述共享产物要求的有界加速义务，沿用同一 Trace ID。普通构建、正式进程构建和固定 ECS `ecs` profile 的独立 workspace 缓存族统一适用该容量要求：单份 staging、该族远端总量、兼容代数和仓库当前实际存储上限分别约束；新增保存前须取得完整库存及有效仓库额度，并按保守新增量检查仓库总占用。

优先读取实时额度；额度端点明确拒绝读取时，可使用可信 workflow 中已核验、记录来源的保守仓库预算，报告须区分配置预算与未知的实时额度，不得把 GitHub 默认值猜作当前设置。实时额度可用时与配置预算取较小值；限流、无效响应、库存失败及没有已核验预算均不能借此放行。

待缓存 workspace 编译产物的原始字节超过单份准备上限时跳过保存，继续正常产物和测试流程；完整 target、所选文件原始字节与硬链接去重体积分别记录。

远端容量使用 GitHub 实际存储的压缩字节按缓存族和 ref 汇总，不能把 raw 上限、下载流量或恢复次数当成库存。若使用预压缩 payload 估计新增量，必须另计实际上传包装的保守上界，不得将硬链接去重体积直接当成压缩体积。

共享原生、ECS、Release Web、Linux/Windows/macOS 原生及同族 Testnet Linux packaging 依赖缓存 writer 同样受完整仓库预算约束。自动 post 保存须在原清理与压缩完成后、任何远端预留或上传前，按最终待上传归档的真实字节重新清点；不得用 job 启动前的库存、历史包大小或原始 target 大小代替本次上传量。

上游调用形式变化、归档缺失/变化或准入查询失败时跳过缓存上传，继续保留原构建与测试结果。保持现有 key、restore 范围、cache version 和成功后保存语义，候选不新增写入权限。

Release 同样只允许 source plan、实际 checkout、事件与 workflow SHA 一致的可信 main 成功构建写入，其他 ref、历史 tag 和失败构建不得通过这些 cache action 保存。Release 保留既有缓存 token scope，此处保存限制由 action 条件和上传准入执行；Testnet 候选仍由独立 job 使用只读 token。

该边界治理明确接线的依赖 writer；工具缓存及其他 writer 与并发运行仍可能在清点后改变库存，不宣称全仓原子预留。

正式缓存保留包含 source SHA 的不可变 key，分别记录单份原始准备上限、单份压缩上传上界、两代常驻目标和临时第三代写入上限；每次保存仍须满足包含依赖缓存和其他 ref 的完整仓库预算，族上限不是预留额度。

已存在多份旧兼容条目时，允许明确记录、只用于尚无库存的新兼容前缀的有界迁移写入峰值；仍须先通过全仓准入。缓存族包含其历次兼容指纹和 source SHA，不能通过 lockfile 或构建配置变化重新获得无关预算。

成功可信 main producer 的当前精确 key 经 API 确认唯一且完整后，可按该 key 退役该族其他未受保护的兼容组；没有新 current 时，只有下述经源码祖先关系核验的补偿规则可以跨组退休。保存步骤成功本身不证明保存已完成。

两代是空间充足时的保留目标，允许有界的临时第三代；容量紧张时可通过下面的补偿维护减少额外历史代，始终保留相应完整替代锚点及活动保护集。

可信 main 的启动维护和成功 producer 后的维护均允许补偿回收，不以本轮新保存成功为前提；保存被拒绝或先前维护未完成时，后续运行仍有恢复机会。

无 confirmed current key 的 workspace 族按已识别格式的完整兼容前缀与 cache version 分组，默认保留最新两代；常规容量回收先处理同组更旧的额外副本，保留唯一最新的非零完整恢复锚点；仍有压力时才适用下述源码祖先退休规则。

该入口也保留明确退役 workspace 格式及共享原生、ECS、Release 依赖冗余回收规则，依赖分组只去掉已有 restore 前缀后的依赖 hash，仍完整隔离平台、宿主架构、目标命名空间、环境和 archive version。

不能凭创建时间跨兼容组认定整个环境 hash 或 archive version 过时，不能以本轮尚不存在的 key 冒充恢复锚点；同 key 多 version、创建时间歧义、无完整条目或两次清点间锚点变化均保留相应组。缺失依赖仍由 Cargo 正常补编，不承诺不同快照是内容超集。旧的窄范围 bootstrap 模式保持原白名单，新 workflow 使用明确的补偿维护模式。

空间压力下，当前固定 Linux X64 writer 合同内的 ordinary v1、Formal v3、ECS v2 允许以已有完整条目作为跨兼容组替代锚点：必须同族、同格式和同 cache version，旧 source 是替代 source 的严格 Git 祖先，替代 source 是本次已验证 main run source 的祖先或自身。

以不可变 SHA 查询核验关系，不以创建时间、可变 branch 或相同 archive version 推断平台兼容；同 source 的不同配置、无关分支和未知格式保留。

替代锚点自身不得进入任何删除集合，明确 current 优先；候选和替代在两次库存中的不可变身份及替代关系必须一致。

历史对象不可得、无祖先关系或局部比较预算用尽时不做未获证明的跨组删除，常规可证明的同组回收仍按原合同执行；权限、限流、无效响应或全局预算失败仍保守关闭。该退休不扩大消费者恢复范围，不声称不同兼容组的 payload 可互换。

保留已确认的当前精确条目、每个未被上述可信关系替代的兼容组恢复锚点，以及清点中可见的当前或相关活跃 workflow 最早开始后新建或被访问的缓存；零字节条目因上传完整性未确认而保留，不可作为恢复锚点。

空间充足时保留第二个兼容恢复副本；为明确的依赖轮换空间目标，可以回收该副本，但不能删除未被可信后继替代的唯一锚点、当前精确条目、歧义组或活动保护集。保护集超过预算时报告缺口，不为达标扩大删除范围。

补偿维护使用共享的 2.5 GiB 依赖轮换空间目标，按有效仓库额度减去该目标计算常驻容量，优先正常多余代回收，再仅按全仓空间或各族常驻预算的缺口缩减额外 workspace 代数；全仓有空间不能掩盖单族超额造成的轮换阻塞。该数值是容量策略，不是假定后续依赖归档必然不超过它。

可信 main schedule/manual-full 中 ordinary/Formal 的保存必须在本次上传上界之外仍留下这部分空间，避免先占用共享依赖 writer 稍后需要的容量；普通 push 保持原 workspace 上传准入。

依赖 writer 最终仍依据本次实际归档和最新完整库存准入，可以使用这部分空间。

空间目标、计划与实际回收、活动保护导致的缺口分别报告；并发 writer 与未来归档增长可能使保存继续被拒绝，不宣称原子预留或必然进展。

同一维护入口可回收明确枚举的旧原生、Release gate、Web 与 ECS 命名空间，但必须先确认各自替代族存在完整的 main 缓存；缺少替代、仍活跃、零字节或身份变化时保留。此规则只退役已迁移的命名空间，不按“最新创建”推断任意环境 hash 已失效，不扩大 restore 范围，也不授予消费者删除权限。

回收只处理明确归属的缓存族与 main ref；PR 保持只读，不取得删除权限。执行前的第二次完整清点只能缩小首次删除计划，不能新增删除对象。

活跃运行清单因计数漂移或分页提前结束而不完整时，可在原请求和总时长预算内最多执行三次完整重读，每次丢弃失败尝试的全部部分结果；无效字段、身份冲突、权限或限流失败不借重试放宽校验。

最终仍不完整则零删除。其他完整分页、身份或字段校验失败，或条目归属未知时保留原数据；API 超时及清理失败只影响容量治理结论，不覆盖必要构建与测试结果。

报告须区分完整库存、部分结果、计划删除、已确认删除及仍超预算，不能把未执行或未确认的删除写成已释放空间。

验收覆盖多页库存、后页失败、同 key 不同 version/ref、未知条目、保存未确认、旧版本迟于新版本完成、近期访问、零字节上传、两次清点间身份变化、受保护条目超额及重复回收；同时核对候选无删除权限、可信 Rust/Release 启动维护及 Rust/ECS/Release 结束接线和必要 CI 的原有失败传播。

回放实际容量样本，分别验证退役格式迁移、首次写入、兼容恢复和第三代轮换；归档回归覆盖硬链接去重、实际 GNU tar/gzip 与 zstd 上传包装的保守界限、未知工具/环境及文件变化拒绝、展开界限和旧格式兼容；单包上限不因错误的通用压缩估算而放宽。

组合回放须包含 Release 增长、连续 Cargo.lock 换代、无 compatible workspace key 和 Formal 接近单包门槛的状态。hosted 写入、实际释放空间与冷热运行收益分别由真实记录证明，文档和本地 fixture 不代签。
