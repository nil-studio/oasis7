## 测试范围

普通 CI 是默认验证方式。成功规划后轻量 baseline 始终执行；选择器使用完整 Git name-status diff、base/head 两侧 Cargo 关系及必要目录映射选择 Rust、Web、场景、平台、打包和运维合同测试。

Rust 变化覆盖自身及需要验证的反向消费者，删除和重命名覆盖两端；保留有效 features、WASM、生成输入和平台组合。workspace、features、锁文件、共享生成器及 CI 控制输入变化采用保守普通 required，图解析失败仍扩大覆盖；未登记路径按下述门禁阻断。

`./scripts/ci-tests.sh required` 是普通必要测试的本地入口；`full` 保留广覆盖回归，nightly 执行适用 full。真实产品测试、WASM 确定性、共识、持久化、安全、升级恢复和跨平台打包均继续保留，不因流程精简删除。

### 未登记路径门禁

Trace ID: O7-REQ-4e7f2e0d-9147-43d9-a593-00a8db9b21df

选择范围中的路径必须匹配 Cargo 包归属、显式目录规则或共享构建/CI 控制规则。未登记路径属于范围规则缺口，必须使规划失败并列出所有未登记路径，不得用全量回退或额外组请求掩盖；新增、删除及重命名两端均适用。规划失败不启动测试组，最终 `required-gate` 仍执行并失败，不能 Pending 或伪装成功。依赖图/Git 输入无法解析时仍保留保守全量，不能将解析失败误报为确定的路径缺口。

规则使用事件基线的可信版本；引入独立目录前先将归属及真实验证入口登记进基线。候选分支自行新增忽略规则不能为自身放行。该要求属于 CI 专业治理，不新增玩家或游戏行为要求。

## 调度和结果

select 先产生明确的非空矩阵，按资源组并行执行。最终唯一 `required-gate` 使用可靠的 always 汇总，并显式依赖 select 和所有组。选中组必须 success；未选中组可以 skipped 或 success；失败、取消、缺失、未知及意外 skipped 都必须阻断。矩阵不吞退出码，采用 fail-fast=false。

记录 source HEAD、base 和实际测试对象及运行链接。普通 PR 权限只读，从事件 base 提取可信选择器及执行清单；候选控制变化不能缩小基线覆盖。CI 控制、安全或兼容边界变化接受对应能力的独立评审。

## 专项条件

缺测试先补普通 CI。只有普通 runner 难以提供的真实长期状态、专用硬件或受控环境才使用专项验证，说明具体不足、环境、版本、通过标准和实际结果。阻塞专项纳入同一 PR 最终汇总；调试 dispatch 不能替代 PR 检查。

CI 结果对应实际 source HEAD。main 前进或分支显示 `BEHIND` 本身不使该结果失效；只有合并冲突或 main 的相关变化带来明确集成风险时，才按需更新分支并验证实际组合。source HEAD 变化后重新运行必要普通 CI，复审实际变化与受影响部分；具体合入规则遵循开发流程规范。产品层的签名、checkpoint 和状态一致性证明仍按专业合同验证。

CodeQL 技术扫描见 [CodeQL 设计](codeql-integration.design.md)，实际 required/advisory 按 GitHub CI 与生效保护执行。

<a id="ci-install-trunk"></a>
### Release 复用经过验证的 Trunk

**目标**：在现有安装器支持的 Linux x86_64 环境，Release Web 构建复用经过固定摘要和版本验证的预编译 Trunk，不因冷缓存而重复源码编译同一工具。工具版本与支持平台由安装器及配对设计维护，升级时同步审读来源、摘要、兼容性和调用方。

**本次实现合同**：Release 只读恢复预编译 archive，再调用[共享验证安装器](../../../scripts/install-ci-trunk.sh)准备工具；冷未命中按同一安装器下载与校验，不增加 Release 缓存 writer。此处说明候选接线范围，main 合入、hosted 运行及实际耗时仍以各自记录为准。

**验收**：

- 冷路径取得正确工具后能继续执行原有 Web 构建与验证；热路径使用同一验证合同，不以缓存命中跳过摘要或版本检查。
- 不支持的平台、版本不符、摘要不符、下载或提取失败必须有明确的失败结果，不得继续执行未验证工具或静默降级到另一种来源。
- 工具准备成功、Web 构建成功和 Release 完成分别记录，不互相代替；真实 Release 验证由实际运行结果证明。

<a id="ci-install-cache-evidence"></a>
### 缓存复用与真实证据

**目标**：缓存是可以丢弃的加速层。未命中、被回收或首次使用时，冷安装仍应正确、安全且可观察。可信 writer 与普通 PR/候选消费者的权限边界遵循[包来源与缓存安全规则](../../engineering/workflow/package-source-security.md)，不为提高命中率扩大写权限。

**验收**：

- 区分未命中、命中后校验成功、缓存损坏和恢复错误；只有验证合格的工具可进入构建。损坏缓存不得作为成功的冷/热样本，也不得回退到未经验证的 binary。
- 描述实际生产者与消费者的 workflow、事件、ref/scope、平台、架构、工具版本和安装策略。若跨 tag 复用需要默认分支 seed，必须确认有效 main writer、实际保存结果及后续消费者可达性；不能仅凭 key 不含 tag 或名称相同宣称可跨 tag 复用。
- 读取同类构建依赖的消费者使用可信 producer 的缓存身份，不因工作流或 gate 名称重复保存相同依赖。普通 Rust CI 与 Release / Mainnet 的 core、support、sync、soak 共享一个原生依赖快照，由可信 main 完整回归任务统一生产；并行消费者保持只读。producer 显式编译各消费者需要的 feature 组合，完整成功后才保存，不能把功能超集、下载的测试 binary 或首先结束的 shard 当作完整 target。生产覆盖变化须更新共享缓存版本。不同 target/profile 的产物可以共存，Cargo 仍按实际输入判断复用；WASM 发布包、ECS 与 Formal workspace 保留其生产频率和恢复合同适用的专用缓存。
- 共享须对齐工具链、环境指纹、路径与 cache version。临时 GitHub-hosted runner 的无关预装 Rust 工具链不参与共享身份，固定的实际构建工具链仍校验并参与 hash。registry、target 的库存节省与每个消费者恢复大包的传输成本分别量测；没有 hosted 数据时不承诺耗时收益。缺少缓存或缺少对应产物时，消费者继续原构建和测试。
- 跨 tag 命中须有真实 writer 和 reader 的运行记录；尚未 seed、没有可达缓存或未执行 reader 时如实记为未验证，允许通过正确的冷路径完成必要工作。
- 冷/热对比包含恢复、准备/验证和保存成本，不能只统计省去的安装时间。

<a id="ci-install-apt-budget"></a>
### apt 安装预算与故障处置

**目标**：先从实际 job 日志核实 apt 耗时、锁等待、网络失败和重试频率，再决定是否改造。若进入实现，安装必须有覆盖命令执行、等待、退避、重试及清理的有限总预算；具体参数由观测数据和运行环境决定，不建立仓库统一的固定全局 SLO。

**实施后的验收**：

- 仅对已识别的可重试临时错误进行有限重试，次数和退避计入总预算；永久错误、权限/配置错误和未知失败保留诊断并失败，不无条件重跑。
- 超时或取消应终止安装启动的受控进程组，必要的终止宽限也受预算约束；返回时不得遗留继续持锁、下载或安装的受控进程。不得为此终止其他任务或宿主的无关进程。
- 分别验证正常完成、短暂失败后恢复、重试耗尽、永久失败、子进程超时及取消；父 shell 退出不能单独证明子进程已结束。
- 必要依赖未就绪时不运行依赖它的测试，不将失败改写成跳过或成功；结果沿现有 job 与 required 汇总传播。

<a id="ci-install-measurement"></a>
### 量测与交付判定

**目标**：以实际数据判断优化是否减少关键路径耗时，同时保持原有构建、测试、权限与失败语义。记录固定源提交、workflow/job 与运行链接、平台和工具版本、缓存状态、样本窗口与样本数；安装、缓存恢复、校验、构建和保存分别计时，失败与取消样本单独保留。

**验收**：可比较的冷/热样本需具有一致的工具与平台范围，并说明 runner、网络和其他并发差异。没有足够样本时只报告观察值及限制，不设默认性能门槛或宣称稳定收益；Cargo cold/no-op 编译指标不能替代依赖准备和跨 tag 缓存量测。

本次交付包含需求与系统设计的整理、Release archive 恢复与共享安装器接线；候选实现、本地合同验证、main 合入、hosted 构建、缓存 writer/reader 运行和冷/热收益分别以实际记录证明，不互相代替。apt 本次仅承接观察与条件实施要求，不宣称已改造或完成故障验收。结构检查、本地 fixture、旧绿色 CI 和文档状态不能证明未执行的 hosted 或量测结果。本节不新增通用检查名称、审批链或强制性能门禁。

<a id="ci-real-coverage"></a>
## 真实覆盖与执行结果合同

本节是测试专业要求，不新增玩家产品承诺或另一条合入审批链。实施状态仍由实际候选与运行记录证明。

**required/full 包含关系**：对同一 source、平台、features、target 和适用范围，`full` 的实际检查集合必须包含对应的 `required` 集合。不能仅因函数名为 full 或总测试数更多就视为满足；Clippy、独立 Viewer browser smoke 等 required 检查不能被另一项编译/测试成功替代。平台不适用项有明确原因及受支持平台入口，缺依赖、缺 target、命令未执行不是“不适用”。每个适用检查失败都传播到 suite 和已有最终汇总。

**native/WASM**：稳定工具链 smoke、需要确定性工具链的真实 builtin 构建/hash 和容器接线测试分别取证。维护实际消费者到构建入口、产物和验证命令的映射；缺少必要 WASM target 或全局设置 `BUILD_STD=0` 不能把 required 验证变成空执行。fake Docker 只证明调用/参数合同，不证明真实容器编译、产物或 hash；已明确退役且没有消费者的旧 lane 不重新变成必跑现场。

**构建 wrapper**：wrapper 保留被包装命令的退出结果、参数边界和有效 target 选择。子命令正常删除 target 并返回 0 后，退出记账不能为更新 `last_used` 等元数据重建 target 或制造失败；lease 释放和 GC 占用保护仍成立。多个互相冲突的 target-dir 必须归一为唯一有效值或明确拒绝，不能靠不同层解析出不同路径。原生 Windows 的跨进程等待/取消与 I/O 故障必须在原生 Windows 分别验证，WSL 或短于系统重试窗口的样本不能代签。

**扫描与证据**：CodeQL 每种声称支持的语言及 default/extended 组合分别记录执行、分析上传和 finding 处置。结果集合不完整、API 后页失败、run/attempt/source/category/App 不匹配时保留未知，不以当前零条结果认定零 finding。具体扫描和启用仍归 [CodeQL 设计](codeql-integration.design.md)；本节不启用 observe、不增加 required check、不改变查询集合或超时。

验收至少包含：故意从 full 漏掉一项 required 被识别；各选中命令返回非零使 suite 失败；真实消费者路径未执行时不能报通过；wrapper 删除 target/非零退出/带空格参数/`--` 应用参数/环境覆盖/原生 Windows 长等待与取消分别保持合同。已合入依赖升级只复核剩余兼容边界，不无条件重复历史版本或完整 fleet 验收。

## RustSec 例外基线与到期处置

当前 RustSec 例外集合为空。`deny.toml` 的 `advisories.ignore` 必须保持空数组，`serde_cbor`、`paste`、`ttf-parser` 三个已移除的包在 `bans.deny` 中按包名禁止重新进入依赖图，包括通过 Cargo 依赖别名或传递依赖进入的情况。既有到期直接依赖基线随例外移除，不保留无实际例外的续期义务。

[基线检查器](../../../scripts/check-rustsec-ignore-baseline.sh) 用标准 TOML 解析器检查完整的 ignore 集合与禁止包配置。非空 ignore、无效类型/语法、缺失的禁止项以及为禁止项设置版本或豁免范围均被拒绝；单引号、引号表名、同行元素和注释按 TOML 语义处理。任何未来例外或重新引入这些包都必须作为明确的策略变更独立评审，不能靠过期基线或依赖别名绕过。

Rust 基线检查执行 `cargo deny --locked --all-features check advisories bans`，由 cargo-deny 检查真实 Cargo 依赖图中的 advisory 及禁止包；基线检查器另扫描全部仓库 Cargo.lock 的 package.name，防止独立模块和兼容 fixture 残留旧包。配置 fixture 只验证配置策略，不能代替真实依赖图检查；验收须同时覆盖空例外正例、隐藏/重复的 advisory、坏配置、禁止项移除或缩小、依赖别名与传递依赖的实际包身份。

<a id="ci-formal-process"></a>
## 真实进程验收与共享产物

Trace ID: O7-REQ-d9292810-5229-417f-9fc8-262ee04759c7

普通 required 与真实节点、长历史、健康副本集、存储恢复、生命周期 CLI 验收分开反馈；正式分片的最小构建与普通测试构建独立调度，正式分片就绪后立即启动，不等待 Viewer、普通集成测试或 default-feature snapshot 等额外变体。相关核心 Rust 代码、反向消费者及不确定控制输入仍必须通过全部真实进程分片，独立前端和纯文档按既有选择器决定范围。不得删除验收、降低断言或用警告代替失败。

同一 workflow run、同一 tested commit 的正式最小构建供五个分片复用，普通组使用自己的必要构建闭包；分片不得自行编译。各消费者只下载执行闭包需要的产物，采用低等级压缩并记录原始/压缩字节数及二进制体积分布。保留 source/tested SHA、生产 run/attempt、编译器、平台、profile、features、二进制摘要及测试清单核验。同 run 的失败重跑可消费较早 attempt 的成功产物，禁止跨提交替换或消费者缺产物时回退编译。

每个显式 ignored 验收只归属一个逻辑 suite 和一个物理分片，辅助子进程不独立调度；可按完整用例的实测耗时调整物理分片，逻辑归属与全部覆盖保持。长历史的 70 次连续操作及健康集合的 40 次操作不能拆断或减少。下载后核对实际测试清单，精确调度须真实执行一个测试；失败、取消、超时、缺失及被选中却跳过均阻断固定汇总。分片间不因前一分片失败取消其他分片。普通空 harness 可不执行，不代表任何验收通过。

workspace crate 缓存仅作有界加速：普通构建与正式进程构建使用各自的缓存族，候选运行保持只读，由可信 main producer 写入；普通构建只复用完整的非测试 library 和构建脚本单位，不减少原测试产物、feature 组合或测试覆盖。本地准备容量与远端保留容量分别受约束。缓存未命中时执行同一完整构建，不以命中率替代实际编译、产物校验或测试结果。阶段计时分别覆盖构建、打包、传输、重开、请求、查询与停止；没有可比较的实际样本时不得宣称端到端收益。

验收须包含全新 Linux runner 下载后的真实执行，不能以 YAML、fixture 或静态审阅代签。进程心跳仅证明存活；操作绝对期限与生产协议保持原语义。清理仅处理当前测试拥有的进程，清理无法确认时停止该分片，保留首次失败与清理结果。诊断上传只允许无凭据的运行摘要，不上传世界临时目录或私钥。

<a id="ci-formal-cache-budget"></a>
### 正式缓存容量与保留

本节细化上述共享产物要求的有界加速义务，沿用同一 Trace ID。普通构建、正式进程构建和固定 ECS `ecs` profile 的独立 workspace 缓存族统一适用该容量要求：单份 staging、该族远端总量、兼容代数和仓库当前实际存储上限分别约束；新增保存前须取得完整库存及有效仓库额度，并按保守新增量检查仓库总占用。优先读取实时额度；额度端点明确拒绝读取时，可使用可信 workflow 中已核验、记录来源的保守仓库预算，报告须区分配置预算与未知的实时额度，不得把 GitHub 默认值猜作当前设置。实时额度可用时与配置预算取较小值；限流、无效响应、库存失败及没有已核验预算均不能借此放行。额度未知或容量不足时跳过缓存保存，继续完整构建；不得为该加速入口自动提高存储额度或删除其他缓存族。该检查反映清点时的容量，不是跨 workflow 的原子预留。待缓存 workspace 编译产物的原始字节超过单份准备上限时跳过保存，继续正常产物和测试流程；完整 target、所选文件原始字节与硬链接去重体积分别记录。远端容量使用 GitHub 实际存储的压缩字节按缓存族和 ref 汇总，不能把 raw 上限、下载流量或恢复次数当成库存。若使用预压缩 payload 估计新增量，必须另计实际上传包装的保守上界，不得将硬链接去重体积直接当成压缩体积。

共享原生、ECS、Release Web、Linux/Windows/macOS 原生及同族 Testnet Linux packaging 依赖缓存 writer 同样受完整仓库预算约束。自动 post 保存须在原清理与压缩完成后、任何远端预留或上传前，按最终待上传归档的真实字节重新清点；不得用 job 启动前的库存、历史包大小或原始 target 大小代替本次上传量。上游调用形式变化、归档缺失/变化或准入查询失败时跳过缓存上传，继续保留原构建与测试结果。保持现有 key、restore 范围、cache version 和成功后保存语义，候选不新增写入权限。Release 同样只允许 source plan、实际 checkout、事件与 workflow SHA 一致的可信 main 成功构建写入，其他 ref、历史 tag 和失败构建不得通过这些 cache action 保存。Release 保留既有缓存 token scope，此处保存限制由 action 条件和上传准入执行；Testnet 候选仍由独立 job 使用只读 token。该边界治理明确接线的依赖 writer；工具缓存及其他 writer 与并发运行仍可能在清点后改变库存，不宣称全仓原子预留。

正式缓存保留包含 source SHA 的不可变 key，分别记录单份原始准备上限、单份压缩上传上界、两代常驻目标和临时第三代写入上限；每次保存仍须满足包含依赖缓存和其他 ref 的完整仓库预算，族上限不是预留额度。已存在多份旧兼容条目时，允许明确记录、只用于尚无库存的新兼容前缀的有界迁移写入峰值；仍须先通过全仓准入。缓存族包含其历次兼容指纹和 source SHA，不能通过 lockfile 或构建配置变化重新获得无关预算。成功可信 main producer 的当前精确 key 经 API 确认唯一且完整后，可按该 key 退役该族其他未受保护的兼容组；没有新 current 时，只有下述经源码祖先关系核验的补偿规则可以跨组退休。保存步骤成功本身不证明保存已完成。两代是空间充足时的保留目标，允许有界的临时第三代；容量紧张时可通过下面的补偿维护减少额外历史代，始终保留相应完整替代锚点及活动保护集。

可信 main 的启动维护和成功 producer 后的维护均允许补偿回收，不以本轮新保存成功为前提；保存被拒绝或先前维护未完成时，后续运行仍有恢复机会。无 confirmed current key 的 workspace 族按已识别格式的完整兼容前缀与 cache version 分组，默认保留最新两代；常规容量回收先处理同组更旧的额外副本，保留唯一最新的非零完整恢复锚点；仍有压力时才适用下述源码祖先退休规则。该入口也保留明确退役 workspace 格式及共享原生、ECS、Release 依赖冗余回收规则，依赖分组只去掉已有 restore 前缀后的依赖 hash，仍完整隔离平台、宿主架构、目标命名空间、环境和 archive version。不能凭创建时间跨兼容组认定整个环境 hash 或 archive version 过时，不能以本轮尚不存在的 key 冒充恢复锚点；同 key 多 version、创建时间歧义、无完整条目或两次清点间锚点变化均保留相应组。缺失依赖仍由 Cargo 正常补编，不承诺不同快照是内容超集。旧的窄范围 bootstrap 模式保持原白名单，新 workflow 使用明确的补偿维护模式。

空间压力下，当前固定 Linux X64 writer 合同内的 ordinary v1、Formal v3、ECS v2 允许以已有完整条目作为跨兼容组替代锚点：必须同族、同格式和同 cache version，旧 source 是替代 source 的严格 Git 祖先，替代 source 是本次已验证 main run source 的祖先或自身。以不可变 SHA 查询核验关系，不以创建时间、可变 branch 或相同 archive version 推断平台兼容；同 source 的不同配置、无关分支和未知格式保留。替代锚点自身不得进入任何删除集合，明确 current 优先；候选和替代在两次库存中的不可变身份及替代关系必须一致。历史对象不可得、无祖先关系或局部比较预算用尽时不做未获证明的跨组删除，常规可证明的同组回收仍按原合同执行；权限、限流、无效响应或全局预算失败仍保守关闭。该退休不扩大消费者恢复范围，不声称不同兼容组的 payload 可互换。

保留已确认的当前精确条目、每个未被上述可信关系替代的兼容组恢复锚点，以及清点中可见的当前或相关活跃 workflow 最早开始后新建或被访问的缓存；零字节条目因上传完整性未确认而保留，不可作为恢复锚点。空间充足时保留第二个兼容恢复副本；为明确的依赖轮换空间目标，可以回收该副本，但不能删除未被可信后继替代的唯一锚点、当前精确条目、歧义组或活动保护集。保护集超过预算时报告缺口，不为达标扩大删除范围。

补偿维护使用共享的 2.5 GiB 依赖轮换空间目标，按有效仓库额度减去该目标计算常驻容量，优先正常多余代回收，再仅按全仓空间或各族常驻预算的缺口缩减额外 workspace 代数；全仓有空间不能掩盖单族超额造成的轮换阻塞。该数值是容量策略，不是假定后续依赖归档必然不超过它。可信 main schedule/manual-full 中 ordinary/Formal 的保存必须在本次上传上界之外仍留下这部分空间，避免先占用共享依赖 writer 稍后需要的容量；普通 push 保持原 workspace 上传准入。依赖 writer 最终仍依据本次实际归档和最新完整库存准入，可以使用这部分空间。空间目标、计划与实际回收、活动保护导致的缺口分别报告；并发 writer 与未来归档增长可能使保存继续被拒绝，不宣称原子预留或必然进展。

同一维护入口可回收明确枚举的旧原生、Release gate、Web 与 ECS 命名空间，但必须先确认各自替代族存在完整的 main 缓存；缺少替代、仍活跃、零字节或身份变化时保留。此规则只退役已迁移的命名空间，不按“最新创建”推断任意环境 hash 已失效，不扩大 restore 范围，也不授予消费者删除权限。

回收只处理明确归属的缓存族与 main ref；PR 保持只读，不取得删除权限。执行前的第二次完整清点只能缩小首次删除计划，不能新增删除对象。活跃运行清单因计数漂移或分页提前结束而不完整时，可在原请求和总时长预算内最多执行三次完整重读，每次丢弃失败尝试的全部部分结果；无效字段、身份冲突、权限或限流失败不借重试放宽校验。最终仍不完整则零删除。其他完整分页、身份或字段校验失败，或条目归属未知时保留原数据；API 超时及清理失败只影响容量治理结论，不覆盖必要构建与测试结果。报告须区分完整库存、部分结果、计划删除、已确认删除及仍超预算，不能把未执行或未确认的删除写成已释放空间。

验收覆盖多页库存、后页失败、同 key 不同 version/ref、未知条目、保存未确认、旧版本迟于新版本完成、近期访问、零字节上传、两次清点间身份变化、受保护条目超额及重复回收；同时核对候选无删除权限、可信 Rust/Release 启动维护及 Rust/ECS/Release 结束接线和必要 CI 的原有失败传播。回放实际容量样本，分别验证退役格式迁移、首次写入、兼容恢复和第三代轮换；归档回归覆盖硬链接去重、实际 GNU tar/gzip 与 zstd 上传包装的保守界限、未知工具/环境及文件变化拒绝、展开界限和旧格式兼容；单包上限不因错误的通用压缩估算而放宽。组合回放须包含 Release 增长、连续 Cargo.lock 换代、无 compatible workspace key 和 Formal 接近单包门槛的状态。hosted 写入、实际释放空间与冷热运行收益分别由真实记录证明，文档和本地 fixture 不代签。
