# Launcher 引导配置与状态交接验收方法

## 目的与执行边界

本方法验收[引导配置设计](../../world-simulator/launcher/game-client-launcher-guided-configuration-and-usability.design.md)中的实际阅读顺序、配置四层、当前请求/旧结果、真实恢复、双语、尺寸和键盘目标。它细化原[Launcher 人工清单](../launcher/launcher-manual-test-checklist-2026-03-10.prd.md)的 Flow-LMTC-002/004、AC-2/4 及[主测试手册 S6](../../../testing-manual.md)，不增加 requirement、测试 tier 或发行裁决。

下文全部是可执行方法，**不是本候选已运行结果**。文档/SVG 检查只证明交付源可读；受控 handler 或 transport 只证明所注入的阶段；真实 native/Web 分别验证实际交互；非作者理解另行记录。模型、游戏、真实转账、公开服务或外部收费操作仅在已有授权和前置具备时执行，本方法不自动启动它们。

## 固定输入与独立预期

- 记录 source/base/tested tree、Launcher 构建/配置、实际 native 或 Web、OS/浏览器、语言、viewport/缩放、入口声明与 authority 来源。每份结果保留实际环境，不将两平台的不同输入拼成同一次成功。
- 选择同一受支持路径的三个配置 A/B/C，仅改可明确辨认且允许修改的非 secret 字段，例如测试用 Web 端口。A/B/C 是方法中的变量，不要求产品提供命名 profile。固定 normalize 后的完整值及与实例的关联；示例端口必须在实际环境核实可用。
- 从控制面原响应与实际实例独立建立预期：提交的配置、`ok`/error、被接受配置、当前实例/状态、请求代次和 storage 前后值。界面标签、日志颜色和截图不充当唯一 oracle。
- 准备无画像、可用旧画像、存储读取/写入失败；旧 poll、当前响应、迟到拒绝/成功；配置缺项、真实拒绝、传输未知和正常恢复。使用既有测试 seam 或获准控制面，不为本方法发明 HTTP 状态/字段。
- 所有配置、日志、截图和导出使用脱敏值；secret 用专用无价值 canary 检查泄漏，不能导出真实 token/key。配置对照不显示 secret 明文。
- 当前源码接点与未实现差异见[设计 §3](../../world-simulator/launcher/game-client-launcher-guided-configuration-and-usability.design.md#launcher-uiux-source-baseline)。缺失的状态/关联或平台能力应记未实施/blocked，不用直接赋最终 UI 状态代替真实 handler。

<a id="launcher-uiux-01"></a>
## LG-01：源、静态稿与正常旅程

1. 从配对 PRD 当前合同核对两张 SVG 的每个按钮：应落到实际已有动作或明确目标文案。检查模式来自入口契约，未用链角色/provider/alias 推导玩家可玩性；没有新 pure_api、热应用或自动修复入口。
2. 解析 SVG 为 XML，确认可编辑文字和矢量、`DESIGN TARGET` 标识、无外链脚本/位图/字体/凭据。按原 viewBox 渲染为 PNG，逐帧检查文字完整、重叠、边界、主 CTA 和状态，不以 XML 成功代替视觉检查。编辑一段测试文字再撤回，确认源可维护。
3. 对拟实现候选，先在 native、再在 Web 独立完成：首次打开→阅读当前入口→修复实际缺项→关闭引导→明确 Start→读取当前请求→核对实例→打开游戏页。每步记录真实 handler 与结果，而非只捕获最终绿色状态。
4. 正常预期为：检查通过尚未启动；接受属于当前提交；Running 属于被接受配置对应实例；打开页面只证明页面动作/到达。世界动作是否成功不由这些步骤推断。跳过/继续引导与专家模式不绕过任何前置。
5. 反例包含“后台已有 A，但新入口请求失败”和“页面打开失败”。不得从 A Running 或 `open_browser` 调用推定本次成功。

原源码可用于定位输入和控件，不能作为设计已实现的 oracle。SVG 的代表性组合不穷尽下面的动态用例。

<a id="launcher-uiux-02"></a>
## LG-02：草稿、接受、运行与最近成功

| 固定前置与真实操作 | 独立预期与要读回的结果 |
| --- | --- |
| 原 C1：保存可证实的 A；重新打开为 idle 且控制面配置 B；点击 Restore A，再消费 B 的旧 poll | 编辑区仍 A 且 dirty/差异可见；控制面接受配置仍 B、无运行实例；没有自动 Start、画像改写或假成功 |
| 原 C2：A Running，连续多帧编辑无效 B；执行画像保存触发点 | 当前运行仍 A；B 未应用；最后成功画像仍 A。对实际文件/Web storage 读回，不只检查内存文本 |
| 原 C2 后半：沿合法 Stop/Start 路径提交 C，先收到接受但未确认运行，再确认 C 对应实例成功运行并保存 | 仅接受时仍保留 A 画像；C 的接受与实际运行关联证实后才保存 C。文件/Web storage 必须读回 C；不能用旧 A 的 Running 为 C 补证 |
| 提交 B 后继续编辑 C，再接收 B 被接受的回应 | 接受/运行区只更新 B 可证明阶段；C 的 dirty 与输入保留；不显示 C 已运行 |
| 恢复画像缺失、读取失败、写入失败 | 无画像与存储失败各有真实结果；不伪造成功/恢复值；修复后可显式再次操作；平台原有合法缺省回退仍按原合同 |
| 原 L5：只有 launcher GUI 文件存在，game binary 不存在；点击 Autofill 后尝试启动 | 缺 game blocker 仍存在；未用 GUI 自身代替 game，也未成功启动；随后提供真实有效 game 输入再测正常路径 |
| native-only 字段与 Web | Web 不渲染或要求不适用字段；native 保持其原检查。secret 改动只出现安全摘要，canary 不落入截图/日志/公开 snapshot |

通过必须同时满足可见解释和真实状态/存储对账。修改目标标签但保存了 B、或后端正确却仍显示 B 已生效，均为失败。用例沿原 C1/C2/L5，不把本方法记为新世界功能。

<a id="launcher-uiux-03"></a>
## LG-03：当前请求与旧结果、乱序和拒绝

1. 保留 A 活动实例，编辑 B，经真实 Start 路径得到重复启动拒绝，同时响应携带 A Running 的快照。核对界面同时保留“B 本次未接受”和“A 仍在运行”；旧句柄及原配置不被替换。若 UI 在运行中禁用 Start，则从既有控制面入口构造该合法拒绝 seam，另核 UI 禁用原因，不能把不可点击当作用例已执行。
2. 发起当前控制请求前保留旧 Ready poll；在请求进行时和结束后分别送达旧响应。只允许当前代次的事实更新当前状态；旧成功、旧失败都不覆盖当前结果。检查当前目标关联与底层请求计数。控制请求结束但链仍 Starting 时，原合法 Stop/状态探测仍可用；仅控制请求在途时防止同域重复控制，不能把 Starting 本身变成新增禁停条件。
3. 分别在请求发出前失败、发出后丢回应、收到明确拒绝三处注入故障。前两者按实际可证明阶段解释；无法排除服务器已处理时显示未确认并先查询，不能自动 Start/Stop。明确拒绝保留其真实原因，不改为传输未知。
4. 让当前请求完成后再有新编辑、语言切换或专家模式切换。旧结果不清新草稿，不改提交对象，poll/错误更新不抢焦点。
5. Stop 报错或回应丢失时，先保留未确认/失败，再沿当前探测核对。没有实例证据不得显示已停止；重连也不能自动补发 Stop/Start。

每次保留原输入/回应顺序、请求代次、实际发送次数、最后可确认实例与 UI 对照。状态构造单测、请求计数为零的占位样例以及只测 loader 不测最终 handler 均不足以通过。

<a id="launcher-uiux-04"></a>
## LG-04：失败分类与可恢复下一步

| 输入/故障 | 入口上必须读到 | 执行下一步后的独立判据 |
| --- | --- | --- |
| Game 或 Chain 缺字段 | 正确目标、具体缺项和“打开配置”动作 | 进入对应已有字段；修改后重新检查；关闭不自动启动 |
| Provider 未就绪或无 LLM | 本路径 blocked、实际原因 | 只进入原支持的配置/检查；不改 Script 后宣称原入口成功 |
| 链功能 disabled | 关闭与网络故障分开，相关工具受原前置限制 | 显式启用只改配置；主游戏动作是否受影响按其真实依赖决定 |
| `chain_node_role=observer`，但无玩家 observer authority | 保留链角色含义，不凭此显示“玩家仅观察”或可玩 | 不新增模式选择或 observer 启动；实际受限入口另固定其合法来源验证文案 |
| 后端/状态探测不可达 | 本次状态未确认、原因及真实探测/诊断入口 | 探测可以恢复新当前证据，但不隐式重发行动、不恢复旧授权 |
| 当前身份/会话失效 | 当前入口需重新验证，仅可披露原因 | 已支持的目标入口认证/返回路径可达；不存在该动作时只解释与返回，不造按钮 |
| stale execution world | 当前尝试的错误与已有建议，不拼接旧尝试日志 | 仅当真实建议存在才提供原恢复动作；操作后重验当前实例/authority，旧数据未被删除 |
| 浏览器打开被系统拒绝 | 未打开页面、保留安全地址与再次打开入口 | 后续实际到达单独核对，不能用 Launcher 绿灯补证 |
| 设置/反馈/转账摘要出现 | 原专业结果阶段及当前 action 身份 | 按对应方法核对；storage/受理/旧 receipt 不成为世界完成或完整历史 |

每个有效恢复至少有一个合法正例；全部保持 blocked 不能证明可恢复。对应负例继续失败时仍保留准确原因和可达返回，不无限转圈或用空白清除问题。为本次注入恢复前置而修改的测试配置要在记录中注明；不把人工补证解释为产品自动恢复。

## LG-05：双语、空间与键盘

使用同候选同状态，在 native 和 Web 各自验证 zh/en。至少覆盖 1280×800、1024×768、390×844、360×800、844×390、640×360；采用实际平台可用尺寸，不将桌面截图等比缩小冒充窄屏。分别增加 200% 文本、长 CJK/英文原因、长安全路径、多项错误和软键盘样本；不支持的环境明确记录。

1. 在正常、配置 blocked、请求在途、状态未确认、旧 A/新 B 四层对照上逐一检查：首屏是否可辨当前目标、主要原因及下一步；完整结果、配置与退出当前编辑路径是否可达；横向溢出和固定最低高是否遮挡关键控件。
2. 仅用键盘打开引导/高级配置、定位错误字段、编辑、到达关闭/下一操作并返回。记录实际焦点顺序与可见焦点；检查非模态窗口不形成焦点陷阱，返回已消失的入口有可见回退位置。
3. 输入中文 IME、Enter、Escape，确认输入期间不启动/停止/关闭；焦点落在明确按钮后才按平台标准激活。Escape 关闭最上层允许关闭的窗口，不能退出 Launcher 或停止服务。
4. 在焦点位于字段时注入 poll、错误、语言切换和请求完成；原输入与焦点不被更新抢走。旋转、缩放及软键盘收放不提交、不清草稿或改请求对象。
5. 以实际字体/颜色检查普通文字 4.5:1 和重要边界/焦点 3:1 目标；同时核对文字原因，不仅看色块。图标/disabled 原因、当前语言、窗口标题和字段名有适用框架支持的可访问表达。屏幕阅读器与 native/Web 辅助技术各自记录实测，不由 DOM/egui 存在推定。
6. 将若干长原因和翻译缺失注入展示路径。缺译使用可读 fallback 并留下诊断，不显示空白/技术键；完整否定词、对象与动作后果不能被截断。

截图须有完整 viewport 及必要局部，操作序列另留日志/录屏或可核实的键盘记录；静态帧不能证明 IME、焦点、软键盘或读屏行为。可见实现修改沿 S6 取得真实浏览器证据，本次目标稿渲染单独标为静态设计检查。

<a id="launcher-uiux-06"></a>
## LG-06：独立阅读与交付判定

请未参与实现/撰写的检查者，在实际可用候选中完成一个正常修复和一个故障恢复；保留任务提示及实际操作，不先教其“正确答案”。让其说明：当前运行使用哪个配置；刚才的请求是否被接受、还不知道什么；下一步会查询、修改输入还是启动；页面/服务成功是否已经证明世界行动成功。

答案与控制面原件核对。混淆草稿和运行、旧成功和本次结果、探测和提交、observer 与可玩时，记录具体文案/位置问题并修复复测。没有实际独立操作者时保持未执行；作者自评或模型摘要不能代签真人理解。此方法不估算留存、正式可玩性或发行 readiness。

## 结果记录与恢复

沿现有 PR/QA 记录保存每项执行/未执行、期望/实际、源/稿/构建身份、平台/语言/尺寸、原响应与状态对照、截图/操作记录及缺项；不另建全项目状态表。使用原清单的 `pass/conditional/fail/blocked`，说明它对应哪一方法、哪一输入和环境。

设计层可在文本/源/稿一致且独立评审通过后交付；真实实现、native/Web、可访问性和独立理解分别保留自己的结论。补齐同候选缺项后复测原用例；若换候选/配置/平台，作为新范围记录，不回填旧失败为成功。全文不允许用静态稿、另一平台成功或旧历史 green 代签未执行的适用义务。
