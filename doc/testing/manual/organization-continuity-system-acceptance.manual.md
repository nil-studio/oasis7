# 组织连续性与处置系统验收手册

Owner：`qa_engineer`；生命周期：`active`；Last reviewed：2026-10-19。

本手册是[组织连续性与处置设计](../../world-runtime/runtime/organization-continuity-and-disposition.design.md)的目标验收计划，当前未执行，不构成运行或发布证据。固定消费本 PR 的 [organization-continuity-policy-v1](../../game/gameplay/gameplay-organization-continuity-policy.prd.md)、`OrganizationContinuityV1` schema、命令与容量上限；缺少组织测试驱动、原业务 adapter 或权威读面时记录未验证，不用 Agent claim、普通 grant、源码存在或文档检查代签。

运行须固定 source/tested tree、政策/快照、环境、输入顺序与注入点；每场景留存前后资产、义务占用/履行、授权范围、请求和 receipt，失败差分及未覆盖范围。局部 fixture 不证明真实网络，表面截图不证明状态原子性。

本次文档 PR 只核对合同与验收可判定性，不触发未来实现的真实游戏验收。实现时 `test_tier_required` 选择下列状态/权限/守恒和读面用例，`test_tier_full` 覆盖真实持久化、跨节点 authority 与正式 Viewer/Agent/API；分别给出结果，不能以某一层通过代签其他层。

<a id="oc-verify-001"></a>
### OC-VERIFY-001：处置顺序和独立权利

固定 runtime fixture，包含独立成员资产、未完成合同、托管余额、债权责任、Agent/设施和剩余。分别尝试跳阶段、未知义务、重复返还及提交失败；核对拒绝零资源变动，只有全部前序条件成立才进入下一步，资产总变化与每步唯一 receipt 对账，Agent 身份/历史不删除。覆盖 OC-1/2；不证明真实拍卖价格或外部结算。

| 子场景 | 刺激 | 必须观察的结果 |
| --- | --- | --- |
| 白名单与冻结 | 混入 builder/成员个人物料、客户 escrow、租赁物、受限资金与未知权属；冻结前后分别提交转移 | 仅有组织权属的合法范围进入 estate；其他分入返还/原规则/隔离；冻结前合法已提交结果保留，冻结后请求重验，不部分改余额或权限 |
| 清偿与变现 | 余额不足但有可变现设施；未决债权中一项金额未知 | 先确认负担/偿付计划，已预留的明确部分可按合法规则推进；未知责任阻塞相关资产；出售所得回到清偿层，不直接分给成员，也不要求凭空先付清债才可变现 |
| 同级不足与最小单位 | 仅测试数据：可分量 5，同级 A/B 请求量为 4/3 | 基础份额为 2/2，余下 1 按最大余数给 A，实得 3/2；每种资产单独守恒，不使用隐含汇率、不复制不可分设施 |
| 分批处置不双扣 | 仅测试数据：原来源/底层可支出量均为 100，第一批确认支出 40，checkpoint 后余额/剩余来源均为 60，再请求支出 60 | 第二批允许准确 60，累计实付 100、余额 0；不能把已反映到余额的历史 40 再减一次而只允许 20；重复第二批/换 ID 额外请求均不再支出 |
| 原业务占用 | 制造认领预留、WIP、未交付产品、保供承诺/补偿预算仍活跃；尝试以交接/新 case 释放 | 原 origin/owner 仍持有占用；只有原业务结算/取消或同根 typed adapter 能释放一次；不新增需求、复制退款或继承不可转让授权 |

给每一步保存清单版本、policy hash、原来源量/当前 owner 可用量、预留与结算差分和 receipt；未核实的托管/责任不能被“已解决”标签抹除。

<a id="oc-verify-002"></a>
### OC-VERIFY-002：基础阶段与请求层

固定权威时间/政策，覆盖通知事实纠正、未读/不可达、保护前后边界、无效资格、reclaim/申诉登记/拒绝/过期/撤回/确认以及撤销回到保护。逐项检查可做/不可做与基础阶段不被 pending 请求覆盖；已解决新事实创建新程序。覆盖 OC-3/4/6；时长数值从实际政策取，不在测试中另立规则。

1. 用同组织真实自主交付与登录/心跳/聊天/循环转账/保护维护作对照。只前者更新有效活动，Agent claim idle/grace 和成员个人 `last_active` 不直接推动组织阶段。
2. 从政策 fixture 读取各窗口，在截止 `C-1 / C / C+1` 分别提交；到期本身不授予处分权，授权在截止等值时不可执行。固定同一 tick 的不同权威输入顺序，不能使用客户端发送时间抢优先级。
3. 完整/部分通知收件面、未读、服务暂停、世界停机和可用性证据缺失/过期分别覆盖；通知不完整不启动窗口，已暂停区间不计时，重启不补扣离线时长。玩家个人离线不抹除权利。
4. 仅测试数据：已确认 `C=100`、grant 在 `C=90` 到期，后来补报过去 30 tick 不可用。必须拒绝把 C 改成 70 或复活旧 grant；必要救济走新决定/新窗口，保留旧时间与 receipt。缺证区间从未累计时，下一次提交只累计经核验的非负增量。
5. 覆盖旧通知扩大资产范围、新权利人出现、政策更新与关闭错误通知后立即重开。新增范围享有完整窗口；旧 case 不被新政策缩短或凭重复通知任意重置。
6. 对相同权利/事实提交 reclaim 与 appeal：缺证补正、无资格拒绝、有权受理、无独立裁决者、部分支持、驳回、撤回和裁决超过复查点分别核对。请求不自动获权；受理只影响其 stay scope，待决超时不默认裁决；终止一项请求不移除别的 stay、原保护或已成立债务。结案后新事实使用关联的新 case。

<a id="oc-verify-003"></a>
### OC-VERIFY-003：交接与重复效果竞态

构造同范围两次替代、部分重叠、互不重叠、旧授权执行/撤销、reclaim/申诉并发，枚举合法权威提交顺序。注入收缩旧范围、激活新范围、写 receipt 前后的崩溃及响应丢失；核对每次成功交接只有一个 receipt、重叠范围最多一个授权、失败全部不变、不重叠范围保留。旧待决请求不自动迁移；换 ID 新请求须核验同来源已履行/占用，无重复处分。覆盖 OC-7 与 OC-4。

- 对预指定接替人、合格成员和事前中立名册，构造自愿接受、预算不足、资格过期、关联买方和被撤权场景，复算排序及跳过理由；推荐结果不能自动发授权，裁决者不能审自己利益。
- 同一 Agent/设施即使 `action_kind` 不同，maintenance/operation 与 disposition 仍按冲突表互斥；检查不同 case/组织请求同一资产 lineage 的唯一性。
- 可分 lot 先由原 owner 形成权威切片，再交接相交子范围；不可分控制权、合同包、共享 WIP 或外部在途占用拒绝拆分。可独立的非重叠单元可以完成，不冻结无关范围。
- 新旧授权范围切换、case version、scope root、revocation generation、预算、来源账与 receipt 任一 CAS 条件失败时，都不能留下新授权与旧授权双活、丢失余量或部分扣费。
- 交接后重发旧请求保持原 grant 绑定；新申请引用 `supersedes` 也不继承原优先级/效果。同 scope/主体/事实的重复 remedy 只修改原 revision，不重置窗口。

<a id="oc-verify-004"></a>
### OC-VERIFY-004：恢复、真实读面与隔离

同候选 checkpoint + journal 重启和真实多节点回读，比对阶段、授权范围、占用/履行量和 receipt；缺依赖/未知版本必须阻断，不能再次执行已提交的业务效果。按实际容量阈值注入超限与超时，核对无关组织不被冻结。正式外部浏览器窄屏/桌面及 Agent/API 对照同一权威结果，检查基础阶段与待决请求并存、原因/义务/下一步可读，陈旧投影不表示已恢复。覆盖 OC-5；本次未提供专用测试、浏览器或跨节点运行证据。

| 恢复/兼容切点 | 判定 |
| --- | --- |
| 冻结/交接/扣款提交前失败、generation 替换未知、提交后响应丢失 | 分别保持无业务变动、停止旧 writer 并核对、或返回原 receipt；不能统一当成回滚成功 |
| outbox 预留提交、dispatch 前后、外部成功但 ack 丢失、ack 写入前后 | 原 effect key/目标/量稳定；未知保留占用；query/retry/重复 ack 不复制付款/返还；外部不支持持久幂等/查询/明确终态时该 adapter 不可启用 |
| outbox 已登记，首次派发许可前撤销/期满；对照许可已提交但 ack 丢失 | 前者不得首次外发、不得换 grant 继承旧项；后者只能沿原 key 履行固定原合同。检查 `dispatch_ready→inflight` 许可 CAS、C 等值拒绝、重复 worker 和撤销/交接顺序 |
| checkpoint + suffix replay | 同一 C/policy hash、manifest、grant/唯一索引、remedy/stay、admission gate/计数/窗口顺延、来源量与 outbox/receipt；恢复时网络调用计数为零，启动后仅查询/派发已提交且具合法许可的 outbox |
| 丢 policy、asset lineage、ack、未决请求或去重 tombstone | 候选不得发布可写状态；不将缺失解释为未发生或可重新处分 |
| 旧联盟→显式 v1、旧客户端、新 schema→旧 writer | 不从旧 Agent 活动回填不活跃；旧客户端收窄/拒绝写；旧 writer 不得丢弃新字段；历史 AllianceDissolved replay 不生成新 case/退款 |
| 命令/证据/scope/manifest/请求/分页上限及 limit+1 | 明确拒绝、不截断、不部分提交；分页绑定同 root；无资格、格式错误或被拒的超限请求不生成新 stay，既有请求查询/补证按原规则保留 |
| case/受影响主体请求配额分别满额，合法新救济无法接纳；随后手动处分、首次 dispatch、扩权交接，再重启重试 | 最后名额接纳已同根关闭有界 case gate；所有上述入口和重启后仍拒绝，不依赖被拒请求创建记录。释放容量并恢复入口后条件重开，尚未到期的受影响救济窗口只计一次关门区间；C 不回拨、旧 grant 不续期，关门前已到期窗口不复活，其他组织及已合法开始的固定在途义务不被该 gate 冻结 |
| 正式读面 | 原因、窗口/暂停、清单与隔离项、前序义务、候选与新旧授权、独立请求/stay、receipt/下一步一致；敏感证据按权限分离，未知不变成完成 |

跨节点 run 使用真实 authority profile 和同一 source/build，不以 fixture 复制状态代签；通过各节点权威查询核验相同来源和结果，再记录正式 surface 的可读性。实际执行结果只写入实现 PR 和运行证据，不把本计划标为 PASS。
