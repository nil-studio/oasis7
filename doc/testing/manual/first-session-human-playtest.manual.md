# 受控首局真人试玩操作手册

- 主责：`qa_engineer` 组织候选核对、主持和原始记录；`producer_system_designer` 确定本轮目标玩家与结论范围；玩法、Agent、Runtime 和 Viewer owner 接收对应问题。
- 适用范围：实际支持的 `starter-industrial-smelter-to-assembler-v1` / `production_only`，观察首笔铁锭、Assembler 候选理解、真实阻塞与两次会话接续。每轮固定一个 formal 玩家入口；`viewer` 与 `pure_api` 分别取证。
- 本文交付可复用方法、邀请与主持文案、记录格式和虚构填写示例。没有本轮实际记录时，真人执行保持未执行；文档合入不表示已经招募、通过试玩或获准开放候选。

## 1. 本轮要回答的问题与原合同

首轮沿[可玩性证据 PRD §4](../../product/world-rules-core-gameplay/playability-evidence-and-claim-boundaries.prd.md#4-产品结论边界)，以 **5–8 名目标测试者、两次会话**定位问题。逐人保留独立完成、提示后完成、他人代操作、未完成或未覆盖；报告实际人数和情境，不从这个样本推出总体通过率、D1/D7 留存或市场结论。缺席、退出和不能执行的任务均保留原事实，不补成完成。

本方法先观察五件事：玩家是否理解当前目标与投入；是否区分提交、实际成果与下一候选；是否理解真实阻塞和安全下一步；能否解释自己的目标或约束怎样影响 Agent；是否自行继续，以及回来后能否接续。它组织[首局分项验证](../../product/world-rules-core-gameplay/first-session-and-continuation.design.md#val-first-decision-sample)与[假设观察方法](../../product/world-rules-core-gameplay/first-session-and-continuation.design.md#playtest-hypothesis-review)，不重新设计首屏、布局、生产规则或经营分支。

## 2. 参与者选择与未发送的招募材料

### 2.1 选择办法

producer 与 QA 先说明本轮针对什么玩家：例如对资源生产、持续经营或通过 Agent 安排行动有兴趣，首次使用本候选正式入口的人。该描述是本轮选择理由，不是新建全游戏用户画像。通过已有获准渠道征集自愿回应，按下列问题选择 5–8 名适用参与者；不按熟练度筛成全部专家，也不把不了解游戏概念预判为不能参加。

| 筛选问题，可直接询问 | 用于本轮选择与记录 | 不应据此推导 |
| --- | --- | --- |
| “你最近是否玩过需要安排资源、生产或自动执行的游戏？可以简单说说；没有也可以。” | 记录相关经验的实际差异，说明样本选择为何符合本轮问题。 | 不设置新手/熟手固定配额，不把一个游戏名等同于能力。 |
| “你是否玩过 oasis7、看过本次界面或任务材料，或者参与过开发、测试？” | 分开首次接触、已有经验和内部参与者；预读过具体样例的人不计入该样例的首次识读。 | 不隐去熟悉程度，也不把作者试走计入外部首见结果。 |
| “你会使用什么设备、语言和输入方式参加？平时主要怎样完成这类操作？” | 核对本轮实际支持的入口、键盘/鼠标/触控或 API 使用方式；记录操作熟悉度。 | 不从能用浏览器推定能用 pure API，也不以一个环境覆盖另一环境。 |
| “文字大小、输入方式、动效或其他使用条件，有没有需要我们事先了解的安排？只说操作需要即可。” | 按实际支持核对放大、键盘、减弱动效等需求；无法支持的组合明确记录，不勉强开始。 | 不索取诊断、病史或其他无关个人资料；不能把未覆盖需求写成无障碍通过。 |
| “本轮安排两次会话。你是否愿意按约定时间参加？过程中可以暂停、跳过问题或结束。” | 记录是否能安排两场、实际缺席/退出；联系沿原获准渠道，不复制进公开研究记录。 | 不把接受第二次预约当成想继续玩，也不把退出当成游戏失败。 |

选择完成后，在本轮原记录中写实际招募来源、入选理由、经验与操作/无障碍需求覆盖、参与者熟悉程度，以及未覆盖群体和原因。样本偏向开发者、单一语言或某类设备时如实限定结论；未覆盖不能靠增加 persona 补齐。内部试走与外部研究分开列人数，不用内部样本填满外部研究名额。

## 3. 固定候选、任务事实与记录条件

### 3.1 主持人与事实核对者的分工

QA 在执行记录中指定主持与事实核对责任；可以由同一人承担，但须分开记录“参与者看见什么”和“后台核对到什么”。主持人只提供下文任务和已记录的提示，不把内部 oracle、源码或答案传给参与者。世界结果由原专业入口核对，参与者说“成功了”不能代签实际结算。

按[首局候选准备](../../world-simulator/viewer/first-session-content-delivery.manual.md#fs-content-candidate)和[实际入口场景](../../world-simulator/viewer/first-session-content-delivery.manual.md#fs-content-runtime)准备可用路径，保留以下输入。复用已有运行记录及证据，不为每人复制全部工程报告。

| 执行前固定的输入 | 本轮应填写的具体内容 |
| --- | --- |
| 比较单位 | 体验目标；`viewer` 或 `pure_api`；实际 source/tested tree、bundle/内容版本或明确变更范围；会话与观察窗。影响体验解释的语言、平台、设备、viewport、输入/辅助设置纳入范围。 |
| 世界与权限 | 同一参与者两场所用 world/branch、主体/Agent 关联、当前目标与有效授权；公开记录使用脱敏定位，凭据不进入材料。记录两场之间实际版本、授权与世界变化。 |
| 首产物边界 | 固定 profile、实际工厂/配方、合法材料/电力/输出条件及 authority 来源；已有合法 Smelter 不要求重造，缺前置不免费补料或 debug 注入。 |
| 当前候选能力 | 哪些操作、Agent 代办、帮助、原请求回查和安全停止真实可用；Assembler 是候选、可提交建设还是仍缺条件，分别核清。没有能力不能给参与者安排假任务。 |
| 成果 oracle | 匹配 production receipt、owner-bound 正量铁锭结算、持久首产物里程碑及后继候选的核对入口；不能从截图、余额增加或 accepted 单独推断本次生产成功。 |
| 时间与结束 | 本轮可用会话窗口、参与者约定的结束方式、技术/主持资源限制；实际耗时另记，不制定新的首产物时限或每人必须玩满的分钟数。 |
| 资料范围 | 实际采用的笔记、截图、日志或其他记录方式、用途和访问边界；所选原始证据位置与负责 owner。只在已获准范围采集，未确认的录音录像或敏感材料不新增。 |

记录整场开始至结束的总墙钟耗时，另分接入/安装/登录/加载、进入可控制世界后的游玩及其中等待；说明包含关系，避免相加重复计时。未完成和退出者同样保留耗时，不只统计成功者；world tick 另记实际来源，不换算为未经核实的现实耗时。`0–30 分钟`沿[首局具体样本](../../product/world-rules-core-gameplay/first-session-and-continuation.prd.md#first-session-concrete-sample)仅为观察窗口，不是强制成长、事故或完成脚本。记录哪些步骤由准备者完成；预先登录、配置好的 Agent 或已建工厂不能代签参与者完成了这些步骤。

本篇任务文本不含按钮名称。Viewer 保留实际可见操作与结果；pure API 使用该候选交付的玩家 Skill/公开帮助和实际请求/回应记录，不由主持人发送内部解法，不以 API 结果代签 Viewer 操作。若本轮只覆盖其中一个入口，另一入口明确未覆盖。

### 3.2 预先准备事实答案，不给玩家背答案

QA 根据本轮状态写明以下答案及证据位置：当前目标和完成边界；实际投入、消费账本与产出；当前接受/执行/结算或未知状态；成果属于谁、能否精确关联本次决定；Assembler 的用途、已满足和未满足条件；主要 blocker、保留/占用/消费/损失价值与安全下一步。运行中状态变化后，用相应 revision 的事实核对当时回答，不能事后拿新状态判旧答案错误。

这些答案不是固定配方常量或示例图数字。事实未知就预先标未知；参与者合理回答“不知道、还没确认”不能判作概念失败。没有实际候选时可以用明确标注的桌面案例演练主持，但不填真人执行结果。

## 4. 开场、提示与观察规则

### 4.1 每场开场文本

> 今天我们想了解你怎样判断目标、结果和接下来做什么。这不是对你的操作能力的考试；觉得不清楚或暂时不想继续都可以直接说。你可以按自己的方式使用入口和公开帮助，也可以暂停、跳过问题或结束。
>
> 我们按事先说明的范围记录操作和回答，不需要你的密码、密钥或私人内容。一般会先观察你怎样做，再询问理由；如果你希望得到帮助，可以提出。得到帮助后的操作会如实记为有提示，不会算作你最初就知道。结束参与不会自动取消已经提交的世界操作；遇到结果未知，我们会说明当前可核对的范围和原请求下一步。

主持人不要夸奖某条路线、暗示应该尽快做完、反复催问继续意愿，或要求持续说话而改变参与者节奏。提问本身也可能影响注意力；按实际时点记录，先保留未经追问的行为，再进行访谈。

### 4.2 提示记录方式

下列 H0–H4 仅是本手册的观察标签，不是游戏功能、评分或新测试层级。每次介入保留任务、时点、触发原因、原话/动作、此前表现和之后表现。

| 标签 | 可使用的内容 | 如何判定与记录 |
| --- | --- | --- |
| H0：原任务与产品自身信息 | 宣读本节开场及任务；参与者自行使用当前可用引导和公开帮助。 | 保留实际所见帮助与使用情况；无额外主持帮助的完成可记独立完成，不把产品正常引导隐藏掉。 |
| H1：中性追问或重述 | “你现在在判断什么？”“你希望下一步发生什么？”或原任务原样重述。 | 不提供答案，但仍记录它发生在决定前还是后。若提醒影响了当前被测判断，后续该项记提示后完成；追问之后的继续不能记未经催促的继续。已在提问前发生的独立行为保持原记录。 |
| H2：指向已存在的公开信息 | 参与者请求帮助后：“你可以查看这个入口提供的公开帮助，再决定是否继续。”必要时指向真实可用的信息入口。 | 记录具体指向，不能假设帮助已存在；受影响任务的后续完成为提示后完成。 |
| H3：解释状态或给出操作路径 | 为继续诊断而说明真实状态、按钮名称或实际步骤；安全干预也记录具体内容。 | 先封存介入前的回答/操作；之后只证明相应帮助条件下的结果，不能回填独立理解。 |
| H4：他人代操作 | 在参与者愿意且现有授权允许时，由获准操作者完成某步。 | 写清谁做了哪一步、原因与结果，归为他人代操作；不索取凭据、不越权接管。参与者后续理解另测，不能把这一步改计为本人独立完成。 |

开始前选定本轮允许的帮助范围，参与者请求帮助、无法继续或需要保护现有权利/未知结果时按实际情况介入，不设统一“卡住若干秒就提示”门槛。不为了保持无提示记录而放任越权或未知请求重复提交。完成后的访谈不能追改访谈前表现；若访谈已经解释答案，后续关联任务必须保留这次学习暴露。

## 5. 第一场：首产物、自由继续与解释

### 5.1 顺序与任务文本

先按本轮实际入口完成必要接入，记录协助和耗时。若本场另执行 PW-READABILITY，须在可操作首屏就绪后、**宣读 T1 铁锭任务之前**完成原方法的独立五秒首读和回答；不提前告诉要从页面发现的目标、blocker 或下一步。已听过任务、看过答案或接受提示的样例记录其暴露，不能补算为独立首读；原答案记录后再进入 T1，且保留首读提问对后续观察的影响。

下面 T1–T4 是观察任务编号，不要求每位参与者走完，也不新增强制游戏教程。自然出现阻塞、离场或未知结果时沿对应条款处理，不能为了顺序完整制造结果。

| 任务与开始条件 | 主持人可直接使用的文本/动作 | 观察与记录 | 停止或转入条件 |
| --- | --- | --- | --- |
| T1：参与者进入本轮可用的首局状态 | “请尝试得到第一笔铁锭，用来判断下一步是否建设装配设施。请按你认为合适的方式进行；也可以暂缓或结束。”不补按钮、数字或完成答案。 | 首先查看什么、采用或拒绝目标的理由、是否识别当前方案/成本、提交与反馈、是否使用帮助。事实核对者另记实际 authority、操作与成果。 | 无合法路径就观察当前 blocker 和真实恢复决定，不向世界补资源。参与者停止或窗口结束就记录到达位置。 |
| T2：出现首产成果，或参与者自己表明阶段结束 | **先不宣读下一任务、不问“还想玩吗”**，观察参与者在既定会话窗口内自行继续、查看下一候选、暂缓或结束。开场已允许自由选择，不要求保持固定沉默时长。 | 首个未经追问的后继行为与原话；是否真的选择了受支持用途，还是等待/误以为还必须完成；自然停点。若主持已催促或示意，记录介入后的行为。 | 参与者要结束时不强留；若其还愿意回答，再进入 T3。没有可观察的自由窗口记未观察，不填不愿继续。 |
| T3：自由行为已记录，参与者愿意说明刚才的判断 | 依实际经历问：“你刚才想完成什么？”“这次投入换来了什么？”“哪些结果已经确认，哪些还没有？”“下一项现在能做什么，还缺什么？”再问“你刚才选择继续或停下，主要考虑了什么？” | 原话逐题分开；与当时事实核对。追问不说正确答案，理解错误先记下；如必须解释，标 H3。 | 未实际生产则不要求解释不存在的成果；可以询问当前状态与下一步。参与者不愿回答记未覆盖该问题。 |
| T4：已有匹配完成基线，且随后实际形成单一可比约束变化 | 按 §7 核对后再说：“现在请根据这里的情况，决定是否以及怎样继续下一次生产。”先观察选择，再问“你根据什么作出这个判断？哪些东西还保留着？” | 变化前后事实、唯一变化与未变化条件、玩家解释/选择、提示前后表现；正常帮助保持可用。 | 前一链未完成、变化不成立、不能隔离其他影响、参与者已结束时均记未覆盖，不补造迁移通过。 |

在 T1 自然产生受支持的目标/约束委托时，记录玩家表达、Agent 实际收到/采用范围与后续行为，保留其自然发生的来源。若本轮需要定向观察委托，在 T2 的自由行为已记录、且参与者自愿继续后才执行下面的 TA。TA 及其后续操作均标为研究任务诱发，不能回填为 T2 的自然继续；参与者已经离场就记未覆盖，不为补足任务把其留下。

#### TA：条件性的目标委托、保留或纠正

本任务沿 FS-12 和[原分项验证](../../product/world-rules-core-gameplay/first-session-and-continuation.design.md#val-first-decision-sample)，使用 §3 预检已确认的真实代办目标/约束与有效授权。准备者先区分目标、软偏好和实际执行约束；“何时需要请示”只有当前入口确实支持时才列为可选约束，不承诺玩家说出的所有限制都会成为强制规则。

1. **让玩家提出实际目标。** 主持人读：“如果你愿意继续，请选一件你现在希望 Agent 处理、并且当前入口支持的事，用你自己的话说明目标。有你希望它遵守、且当前支持的限制，也可以一并说明；你也可以决定这次不委托。”观察玩家选择、表达、使用公开信息及提交过程，不代写指令。玩家提出不受支持的目标时，如实记录入口怎样解释和玩家怎样调整；不能替换成隐藏解法后仍算独立完成。
2. **观察实际采用与后果。** 保留原目标/约束、接受或拒绝、实际采用范围，以及之后的真实行动与结果。确认收到、Prompt 更新或生产成功本身都不能证明该约束影响了执行；事实核对者按当前原始证据关联玩家决定、Agent 采用和后果。只有计划而未观察到采用/后果时保持未验证，不由主持人解释补成因果。
3. **先记表现，再问理解。** 在已观察的阶段后问：“你希望它完成什么、遵守什么？”“从哪些结果看出它按你的意思做了，或者没有？”原话与实际采用范围分开。提问或解释的时点按 H1–H3 记录，不把后来学会的说法改成最初独立理解。
4. **条件成立时观察保留或纠正决定。** 仅当当前存在真实可修改目标/约束或暂停未来行为的能力，才问：“看过刚才的结果，你打算保留现有安排，还是有哪件事希望调整？保留也可以。”玩家选择保留就记录理由，纠正分支记未观察，不强迫改目标。玩家确有调整意愿且所选调整受支持时，再说：“请用当前支持的方式作出你想要的调整。你预期哪些后续行为会改变，从哪一步开始？”随后观察实际提交、采用与结果；不预告一定能立即停止或撤销已开始工作。
5. **核对生效边界和旧结果归属。** 分别记录调整前后目标/约束、原请求、已结算结果、仍待决义务、当前证据支持的最早生效点及之后真实改变的行为。旧结果仍归原请求，调整不追溯取消结算，暂停未来代办不等于撤销未知提交。回读后再问：“哪些结果已经发生，哪些还没有确认？这次调整影响了哪一部分？”缺精确关联、生效点或后续观察就保留相应证据缺口；结果未知时转 §8，不能换 ID 重做。

委托、保留决定、实际纠正和玩家主体感分别判定；只有新的实际选择才使用新的 `decision_id`。没有可用代办时 TA 未覆盖；只有委托而无可用调整能力时仅记录已观察部分，纠正未覆盖。研究任务后的继续、额外主持提示和当场退出均保持原来源，不转写为自发动机。

### 5.2 第一次离场的主持文本

参与者决定离场后停止新增研究任务；若其愿意简短交接，再请其说明已完成和仍待处理的事项。必要的世界状态由获准 owner 核对，不以交接或回答问题为结束参与的条件。结束说明不能用新目标诱导留下：

> 这场可以到这里。我们记录的是你在这次条件下的操作与判断。当前已确认的成果是〈实际结果；没有则说明没有〉，仍待核对的请求或义务是〈实际范围〉。关闭会话不等于取消这些请求。现在可用的安全下一步是〈按原授权核实的原请求回查、暂停未来代办或其他现有动作〉。
>
> 第二场是我们事先安排的接续观察，时间为〈双方已有约定〉；参加这次预约不会被写成自发回访。你也可以不继续参加。

没有待决请求时不虚构一项风险；有未知请求时按 §8 交接，不要求参与者继续操作直到研究者满意。保存已得成果、当前目标、已知待决定位与有效委托状态；不要求当场建成 Assembler、完成持续能力或产生交易。

## 6. 第二场：先自行接续，再询问理由

开始前，QA 核对是否仍是同一世界/主体与可比较候选，记录间隔、版本、权限、目标、世界和服务变化。世界自然推进可以成为这次接续的事实；版本或入口范围变化须明确，不能把两个不同候选拼成同版本通过。准备者不重置玩家成果、不恢复失效授权，也不提前给参与者复述上次答案。

| 任务与开始条件 | 主持文本与顺序 | 观察与判定边界 |
| --- | --- | --- |
| T5：预约回来，当前入口可用 | “这是我们约好的第二场。请回到上次的世界，按你自己的判断处理接下来最值得做的一件事。”先观察第一动作；缺乏安全操作条件时先按 §8 处理并记录介入。 | 找到旧目标/成果、区分旧成果和新变化、检查待决请求与现权限、形成当前下一步。找不到上下文、需要提醒和代操作分别记录。登录恢复、世界恢复与玩家理解分开，不以重连成功代签接续。 |
| T6：已完成首次自行判断，且参与者愿意继续 | “你现在想优先做什么？为什么？”仅在实际存在可比较用途时继续问“选择这件事，会让哪件事推迟？”“下一次回来，你会先看什么？” | 记录第一动作是在提问之前还是之后。实际资源替代用途、后续决定和约束由事实核对者检查；只有一条路线、仅多两个按钮或可无成本兼得时，不宣称形成实质经营分支。 |

| T8：参与者自然停止后，进行自愿访谈 | “哪一段最清楚？哪一段让你犹豫？”“有哪一次结果和你的预期不同？”“哪些事是你决定的，哪些是 Agent 自己安排的？”“如果没有这次预约，你是否还会想回来？会为了什么，或为什么不会？” | 区分真实行为、预约接续、事后意愿自述与研究者推断。最后一问是被询问的意愿，不是自然回访证据；拒答和不想继续如实记录，不追问到得到积极回答。 |

## 7. 单约束迁移与真实经营选择的适用检查

执行 T4/T7 前，使用[原单约束配对样例](../../game/gameplay/gameplay-industrial-representative-execution-walkthrough.prd.md#single-constraint-decision-transfer)及[首局迁移要求](../../product/world-rules-core-gameplay/first-session-and-continuation.prd.md#first-decision-transfer)核对：

1. 先确认前一链路已在 `production_only` 的真实完成边界取得匹配 receipt；接受、入列、库存变化或主持人解释不作为完成基线。
2. 选择该链下一次实际受支持行动的一个已知变化，例如本次所需某项输入不足；不把原 walkthrough 中其他 profile 的物流、多输入或终端条件强加给当前 canonical 配方。
3. 列出变化前后 authority 与唯一变化，并核对工厂、配方、权限、其余输入、电力、输出、实际依赖等条件仍可比较。上次正常消费导致多个约束同时变化时，不能只挑其中一项称为单约束。
4. 不在真人正常会话中扣走材料、伪造事故或添加 debug 资源。无法通过真实已支持条件形成样例时，记录未覆盖；另做的 fixture 或桌面推演只保留其结构证明，不能顶替实际入口理解。
5. 先观察玩家如何决定，再询问 blocker、保留/占用/已耗/损失价值、下一安全动作及生效条件。可接受同义解释和合理延期，不要求复述术语或一定继续生产。上一轮成果保留不表示所有旧材料仍可自由支配。
6. 分开写链路完成、迁移理解、继续意愿与提示。已在前一场学过答案、接受过解释或看过该样例时保留暴露情况；辅助后的正确选择不能回写为独立迁移。

经营选择沿[首局具体样本](../../product/world-rules-core-gameplay/first-session-and-continuation.prd.md#first-session-concrete-sample)和[首次分支承诺](../../product/world-rules-core-gameplay/first-session-and-continuation.prd.md#31-首次分支承诺)判断。深化生产、为 Assembler 准备材料或暂缓只在当前有真实用途、成本/时机与后续差异时可比较。没有成立的替代用途就记录“操作选择/证据不足”，不从玩家解释流畅推导策略深度，不为了研究补买家、奖励或未来功能。

## 8. 暂停、退出与未知请求

| 触发情形 | 当场处理与可直接使用的说明 | 原记录中的结果 |
| --- | --- | --- |

## 9. 原始记录与填写示例

### 9.1 在本轮原证据中填写

记录使用当前 PR/Task 所引用的原研究/运行证据位置，不在长期手册追加个人结果或建立平行人员台账。每场有一段候选上下文和一张观察表；必要原始材料沿原位置引用。公开稿只保留去标识化 participant/session 标识和所需事实，联系信息不混入观察 JSON。

**会话上下文：** 研究目标与比较单位；招募渠道/选择理由及未覆盖群体；参与者代号、相关经验、候选熟悉程度、入口操作与无障碍需求覆盖；内外部样本性质；会话编号、实际时间窗、接入与游玩分别耗时；source/tested tree、内容/环境、world/主体/Agent 的获准定位；初始事实与证据；主持/事实核对责任；本轮允许提示；上一场和变更关联。未知字段明确写未知，不能填写虚构 source 或默认版本。

| 时间/顺序、任务、participant_id/session_id、decision_id（适用时） | 行为与可见事实 | 参与者原话 | 干预：标签、原话/动作、触发与前后 | 权威事实与原始证据定位 | 研究者推断、判定与未覆盖 |
| --- | --- | --- | --- | --- | --- |
| 按实际观察填写；没有实际决定不分配 decision_id | 只写看到的动作、状态和先后，不写“感到好玩”等猜测 | 尽量保留原句；摘要必须标为摘要，拒答不补写 | 无额外介入写 H0；发生则完整记录，不能只写“稍作帮助” | 对应当时 revision/请求/receipt/页面等；未取得明确写缺失 | 推断单独写依据与替代解释；完成情况和理解/意愿分别填 |

`decision_id` 标识该参与者一次具体选择，跨快照、跨会话重看同一选择仍沿用原 ID；新的实际决定使用新 ID。打开同一页、重复显示成果或复述上次选择不能增加有效决策数。若不能确认两条记录是否同一次选择，先保留不确定性，不靠改 ID 凑数量。

### 9.2 明确虚构的完整填写例子

**以下全部是填写演示，不存在真实参与者、候选、receipt、文件或运行结果；不得作为真人记录导入、验收或对外引用。** 示例上下文为虚构 `EX-candidate-A`、`viewer`、桌面中文入口、`EX-world-A`；`EX-P01` 首次见此示例；第一场 `EX-S1` 与预约第二场 `EX-S2` 使用同一虚构世界。所有时间是演示相对顺序。假设 QA 已核清示例中写出的事实，但这些事实没有现实证据。

| 顺序、任务与身份 | 行为与可见事实（虚构） | 原话（虚构） | 干预（虚构） | 权威事实/证据定位（虚构，均不存在） | 推断、判定与未覆盖（仅演示） |
| --- | --- | --- | --- | --- | --- |
| S1 +07:10，T1，EX-P01/EX-S1/EX-D01 | 查看方案后提交；页面先显示已接受，随后出现首产物 | “刚才只是接下了，现在这笔铁锭才出来。” | H0；无额外主持提示 | 假设匹配 receipt、owner output、持久里程碑一致；定位 `EX-result-1` 只是示例标签 | 可以记录此例首产物独立完成及所表达的状态区分；不能据此写持续能力或交付完成。 |
| S1 +09:20，T2，同一 EX-D01 的结果观察 | 看完 Assembler 候选后主动说今天到这里；未提交建设 | “我想先停下，装配还缺什么下次再看。” | H0；此前未询问是否继续 | 假设 Assembler 仍有真实缺口；`EX-state-2` 为示例标签 | 已观察到自然结束和一句未来意愿；不能推断已完成建设、讨厌游戏或会实际回来。T4 本场未覆盖。 |
| S2 +02:00，T5，EX-P01/EX-S2/EX-D01 | 预约回来后读到原首产物，未再次生产 | “这是上次的成果，今天还没做新的。” | H0；主持只给 T5 原任务 | 假设仍为同一历史 receipt；`EX-return-1` 为示例标签 | 旧成果识别可记录；EX-D01 仍只是一项决定。预约接续不能算自发回访。 |
| S2 +05:00，T7，EX-P01/EX-S2/EX-D02 | 假设下一合法 cycle 仅一项输入不足；先找不到下一步，查看帮助后决定暂缓 | 介入前：“不知道现在还能做什么。”介入后：“先不排下一次，已经得到的铁锭还在；补齐前要再核对条件。” | H2，参与者请求帮助后主持说：“你可以查看这个入口提供的公开帮助，再决定是否继续。” | 假设其余条件可比、旧成果保留，当前没有新提交；`EX-before/after` 为示例标签 | 只能记提示后解释与选择，不能记独立迁移；未实际补料或恢复生产，不写恢复成功。继续动机仍需另记。 |

### 9.3 可选复用现有真人观察汇总

[现有 summary writer](../../../crates/oasis7_viewer/scripts/write-gameplay-attraction-automation-summary.mjs)从 `humanObservations` 数组读取对象：`participant_id`、`session_id` 必须为非空字符串，且 `observation`、`outcome`、`choice` 至少一个为非空字符串。计入其决策去重还需非空字符串 `decision_id`、`choice`、`consequence`；键是 `participant_id + decision_id`，不包括 session。同一键的决策汇总保留最后一条，原观察 records 仍保留。因此不要只看汇总项而丢失前次错误、提示和修正过程。

下面仅演示兼容字段，**同样是虚构数据，不能导入正式人类证据**：

```json
[
  {
    "participant_id": "EX-P01",
    "session_id": "EX-S1",
    "decision_id": "EX-D01",
    "choice": "虚构示例：选择当前合法方案生产首笔铁锭",
    "consequence": "虚构示例：对应首产物完成，Assembler 仍只是候选",
    "observation": "仅为字段演示，没有真实玩家或运行证据"
  },
  {
    "participant_id": "EX-P01",
    "session_id": "EX-S2",
    "decision_id": "EX-D01",
    "choice": "虚构示例：选择当前合法方案生产首笔铁锭",
    "consequence": "虚构示例：对应首产物完成，Assembler 仍只是候选",
    "observation": "仅为跨会话去重演示：回看原决定和旧成果，没有新增生产，不是自发回访证据"
  }
]
```

实际采用沿[gameplay 原入口说明](../../game/gameplay/README.md)及[原包装脚本](../../../scripts/verify-gameplay-attraction-automation.sh)的 `--human-observations-json` 传入真实、去标识化对象数组，`--candidate` 仍只是调用者注记，不验证世界或候选身份。包装脚本会进入其原验证流程；不要为了文档审读或手工填表运行它。

writer 的 `human_observation.status=observed` 只说明收到了可消费记录；不能认证参与者、提示程度、正确理解、有效经营选择或 L5 完成。其 `meaningful_decision_count` 只是符合上述非空字段条件后按参与者/决定去重的计数，不自动证明选择有价值；`retention_status` 保持 `unverified`。不完整记录会被排除计数，不能把排除后人数当实际招募/完成分母。观察对象的额外字段也会原样保留在 input/report，导入前逐项脱敏，不放联系信息、凭据或未获准的原始私密材料。机器不会辨认本文虚构样例，真实性仍需原始记录和 QA 核对。

## 10. 分项判据、探索问题与结论

### 10.1 有既定语义的验收观察

判据在本轮开始前依据 §3 的事实答案明确，分别保存执行状态、完成情况与理解判断。未观察/未覆盖不算通过；已有充分证据的失败不能用另一任务成功抵消。判定只覆盖本轮实际子项，不自动宣布整个上位 AC 完成。

| 观察项 | 本轮可据以判断的结果 | 缺失或反例如何处理 |
| --- | --- | --- |
| 目标、投入与首产物边界 | 玩家能用自己的话说明当前目标、这次付出与实际所得；理解接受/执行不等于已结算，首产物不等于稳定、交付或已建 Assembler。实际结算由 oracle 独立验证。 | 状态/数量与事实不符交技术 owner；事实正确但难发现交呈现/帮助 owner；经解释才理解保留辅助条件。 |
| blocker 与安全下一步 | 玩家依据当前事实说明主要限制、保留与已耗/占用价值，作出当前合法的恢复、延期或重新定目标决定，并知道何时需重查。 | 主持给出答案不算独立理解；没有安全路径就如实停止并保留缺口，不强迫继续生产。 |
| 单约束迁移 | §7 前置确实成立；玩家在变化后解释 blocker、保留价值和下一安全动作/条件，提示前后分别有记录。 | 基线未完成、多个约束混杂或没遇到该变化均未覆盖；会背原例却不能判断新条件交教学/内容 owner。 |
| 回访事实与上下文 | 同世界读回旧成果和原目标/义务，按当前权限与资源形成真实第一动作；未知提交仍按原请求核对，不误认为可重复生产。 | 找不到原上下文、需要提醒、当前入口不可用和世界恢复问题分别报告；不得以预约出席或登录成功判通过。 |
| 局部五秒识读（选择执行时） | 严格沿 [PW-READABILITY](pixel-world-visualization-validation.manual.md#pw-readability)和[首局内容识读](../../world-simulator/viewer/first-session-content-delivery.manual.md#fs-content-player)固定未预读的场景、正确答案、五秒观察与原始回答；保留原至少 5 位、各核心题至少 4/5 正确及信任负例不得误归因的局部标准。 | 单列真正未预读该样例的人数；第二场重复看同例不能补成首次识读。该局部门槛不应用于两场完成、经营价值、Agent 主体感或好玩性，未执行则明确未执行。 |

### 10.2 探索性问题，不设全局“好玩通过”

| 问题与待观察假设 | 寻找的行为/自述及反证 | 结论如何使用 |
| --- | --- | --- |
| 理解首产物是否打开值得继续的选择？假设是用途清楚后，玩家能形成自己的下一目标。 | 自由窗口内的真实后继选择、停止原因和事后解释；反证包括理解正确却没有值得做的事，或只因主持要求才继续。 | 区分缺理解与缺有价值的用途；继续点击、长时间停留或内容量不能替代动机。 |
| 阻塞是可理解的取舍，还是令人放弃的摩擦？ | 玩家如何查原因、是否比较等待/补足/暂缓，何时请求帮助；“不知道”“不值得”等原话分别保留。 | 等待或离场本身不是失败；结合真实可用动作、代价与玩家理由定位问题，不给挫败统一阈值。 |
| 玩家是否感到目标/约束能影响 Agent？ | 明确玩家决定、Agent 实际采用和后续结果的关联；玩家能指出改变了什么。反证包括只看到 Agent 很忙、解释很长或生产成功，却说不出自己的影响。 | 因果关联与主体感自述分别记录；随机行为差异不能直接当玩家控制效果，缺可核对关联保持未验证。 |
| 首产物后的经营选择是否有实质后果？ | 同约束下真实替代用途、机会成本和后续两次决定；偏好及其改变/不变的理由。 | 多数人选同一路线不是自动失败；若其他路线在所有适用目标中始终无价值，交 gameplay 核查支配性方案，不补奖励掩盖问题。 |
| 玩家是否想再次进入？ | 无催促继续、自然结束、被询问的意愿、预约接续、获准观察到的自发回访分别保留。 | 意愿自述不能代替行为，预约不能代替自发；小样本只用于定位与解释，不推出 D1/D7 或长期留存。 |

QA 在原记录汇总每个任务实际尝试人数及五种完成情况、提示性质、关键原话、技术事实与不确定性；不要只呈现通过比例或隐去退出者。分别给出“技术可用”“体验可理解”“继续/回访信号”三类结论及未覆盖范围。producer 再按 PE 原合同作 `go/watch/hold/block` 建议，说明适用入口、候选与观察窗；内部正向结果不覆盖外部反证，不升级公开 claim。

## 11. 复测与手册自身的核对

### 11.1 发现与变更后的复测

| 触发 | 下一步与受影响复测 | 保留边界 |
| --- | --- | --- |
| 实际结果、权限、请求身份或重复效果不符 | 交对应技术 owner 复现、修复和普通回归；新候选沿原首局 QA 方法验真，再复测相应玩家任务。 | 技术回归通过不代签理解，旧失败不因后来一轮成功被删除。 |
| 文案、布局、帮助、译文、字体或输入方式影响理解 | 对照原首局内容与可访问性方法修相应内容；复测受影响目标/状态及必要环境，识读按原范围选择新鲜样例/参与者。 | 已知样例的练熟结果不能当冷启动；无需为无关改动重做整套研究。 |
| 规则、配方、成本、授权、可用动作、Agent 代办或分支用途变化 | 先重建该任务事实答案和样例适用性，再测成本理解、迁移、控制感或选择的受影响部分。 | 变化不明时不能合并原比较单位，不用旧候选正向行为抵消新缺口。 |
| 第一场与第二场之间候选、世界或支持环境改变 | 写清变更和影响；能解释的原世界接续继续观察，不能比较的项另记新尝试或未覆盖。 | 不伪造同版本双会话，不通过重置成果制造接续成功。 |
| 发现主持提示泄题、样本只覆盖熟手或记录混写事实/推断 | 保留污染来源，修主持/选择/记录方法，针对该问题重新取适用观察。 | 已发生的辅助表现仍有诊断价值，但不能追改为独立结果或代表未覆盖群体。 |

复测绑定原 finding、修复内容/候选、受影响任务和新证据；对规则、内容、交互与支持环境的变更说明为何选择该范围。尚未修复或不具备真实场景时保留缺口，不无限增加样本直到得到积极结果。

### 11.2 文档交付和主持演练的有界检查

本手册内容审读按[真人方案规范](../../engineering/doc-governance/product-documentation-standard.design.md#player-playtest-plan)检查目标玩家、任务初态、允许提示、原始记录、判据/假设和复测触发。仓库治理检查由当前 PR 负责人组织；静态检查与下面桌面演练都不是实际真人执行。

| 明确虚构的演练输入 | 合格的主持/记录处理 |
| --- | --- |
| 参与者说已完成，只有 accepted，没有适用 receipt | 保留原话，事实结论仍未确认；不填首产物技术通过，不诱导重新提交。 |
| 主持给按钮路径后成功，又在总结中写独立完成 | 应检出并改为提示后完成，保留前后；不能删除提示记录。 |
| 首场结束，第二场按预约出现 | 分开自然结束与预约接续，留存未验证；不把未催促访谈前的行为与访谈后行为混写。 |
| 没有匹配完成基线，或同时缺料和缺电 | 单约束迁移未覆盖；不得缩成只看缺料后宣布通过。 |
| 参与者中途撤回参与，同时存在未知世界请求 | 研究立即停止；原请求在已有权限内回查或交接未知，不强留、不自动撤销、不保证全副本删除。 |
| 两条快照跨会话描述同一 participant/decision | 原记录都保留，决策只计一次；writer observed 不变成人类理解或回访通过。 |
| 只有作者试走、静态稿或本文 EX 样例 | 分别标内部/桌面方法材料，外部真人研究未执行；不填实际外部人数或运行通过。 |

审读结果只报告已核对的路径、来源、方法与反例；实际招募、会话、世界运行、素材加载和真人结论保持各自的执行状态。问题沿原 PR/Task 与专业 owner 继续处理，本文不保存每轮状态或替代现有发行判断。
