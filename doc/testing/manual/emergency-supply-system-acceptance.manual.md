### ES-VERIFY-001：授权、政策与危机证据

| 场景 | 输入 / 刺激 | 必须观察到的结果 |
| --- | --- | --- |
| 常态与系统性危机 | 普通涨价、单处故障、短暂不足，与持续跨地点/主体短缺对照；分别取进入比例、主体数、地点数、成熟期、新鲜度、授权起止的边界值及边界外值。 | 仅满足首版全部合取条件者进入授权；普通 Crisis 状态不签发保供；其余资源/余额/资格不变，常态市场继续。 |
| 证据完整性 | 逐项删除/篡改需求、控制主体、地点归属、资源/provenance、world/root/政策、授权来源、预算、复核主体与入口。 | 缺项、未知版本、错 world、陈旧/不完整样本、分母为零与越界均有稳定拒绝，不从汇总百分比猜原始数据。 |
| 反虚构需求 | 客户端放大消耗、临时增负载、危机中注册公共服务、账户改名/拆号、同原义务生成重叠消耗区间、换代理/组织接替。 | 来源不合格或额度不增加；`need_key` 仍绑定原义务/资源/非重叠区间，不从 caller request 派生新需求。 |
| 覆盖分离 | 常态供给不足，但先投入足额保供承诺；另构造真实常态供给连续恢复。 | 第一组 `effective_coverage` 足额但 `normal_coverage` 未恢复，不触发提前市场恢复；第二组才按退出阈值关闭。转库、到期或组织交接不能洗掉保供 provenance。 |
| 规范区域与重复授权 | 两个授权分别圈选同 canonical region 的一半地点、并发占相同区域/品类/窗口槽；另用子区域新 ID、换资金账户或区域拆分申请预算。 | 相同规范槽至多一项授权生效，获准授权仍覆盖完整区域分母与批次；不能按拆分范围避开阈值或重置区间预算。缺 region/预算 lineage 拒绝。 |

每个授权正例必须同时有可读包、真实权限/finality 与预算占用证据；只看到 `accepted` 或未出现错误不判通过。

<a id="es-verify-002"></a>
### ES-VERIFY-002：冻结、公平、资源竞争与原子性

1. 固定同一区域窗口的五类快照、完整请求集合、主体聚合、路线/存储供给计划与预算。覆盖不同消耗区间、公共关键服务/其他最低运行优先级、资源足够与不足；对手算可对账的小样例核对比例向下取整、余数排序与稳定身份决胜。枚举请求投递、Map 遍历、恢复重放顺序；同控制主体拆成多个账户/请求与不拆的分配总额相同。首版提供 seed 或随机配置应被拒绝为不支持，不能改变结果。
2. 将请求分别置于关闭 tick 前、恰好关闭、关闭后，验证边界关闭不可变；显式替换在冻结前只能留一份，冻结后不能改成员。改变政策、资源池或授权后，旧批次不重排；重评估形成新 revision 并保留显式确认和旧处置，不吸收后来请求。
3. 两个地点争同一真实资源池时，区域分量在一个 batch 中按政策同比例提交；两项相同槽授权不能分开抢资源。与其他规范区域保供、普通制造/市场、组织资产交接争底层库存/运力/目的地/余额时，逐对象 revision/CAS 只允许合法集合成功；无关 world 状态前进不造成拒绝。
4. 对资格、需求累计、区域归属、资源、资金和政策逐项制造快照漂移；注入 prepare 失败、日志/共识发布前失败、提交后响应丢失、重复 effect 和同 key 异 payload。失败全批零经济变化，成功只有一份 receipt；换 request ID 也不能重新消费同一 batch 或数量区间。
5. 验证授权预算占用与实际承诺转换不重复计费；并发授权的未承诺额度加累计承诺不超区间上限。取消/退款/续期/换账户后，同一预算区间累计承诺不下降，旧 escrow 与新预算不重叠。资源不足或资金耗尽只降低新承诺量，不能挪用旧已承诺资金。

对账输出至少包含每主体/地点分配向量、底层资源/运力/接收容量占用、共享需求版本、区域槽、预算区间累计、escrow 和 effect IDs；仅 root 相同不足以证明玩家份额与资金正确。

### ES-VERIFY-003：退出、部分履行、跨授权与恢复

| 对象 / 竞态 | 覆盖方法 | 判定 |
| --- | --- | --- |
| 有效期与停止 | 开始前/开始时/到期前/到期时；撤销、证据过期、持续恢复，清理任务延迟。 | 谓词失效即无新资格或出发，待审/登记不延长效力；保供覆盖不冒充常态恢复。 |
| 释放与出发 | 同一承诺在两个合法权威顺序分别运行释放→出发、出发→退出。 | 前者释放且不能出发；后者仅能按原数量/地点/价格/截止履约或退回；不能无限继续或新授权展期。 |
| 部分接收/退回/损失 | 不重叠数量区间分别接收、拒收、延误、真实损失、可退回和无路线保管。 | 只接收部分增加履行并付款，未处置区间保留一次占用；超时不伪造退款/损失。退回必须物理完成，缺路线 `custody_blocked`。 |
| 最终结算与解除 | 将最终接收/结算、取消、退回终结及损失 receipt 置于不同顺序，并重复各步。 | 相同区间仅一处置，结算原子把 committed 转 fulfilled；释放与结算不能同时腾出同一需求。 |
| 续期与新请求 | 保留旧在途，创建新的合法授权/请求；隐藏旧关联、换 request/账户、组织接替、重复需求和新的真实消耗区间分别对照。 | 可申请量扣旧已履行与所有活跃承诺；新控制人不继承旧临时资格；真正新窗口也扣实际库存与可用承诺。 |
| 申诉 | 期限内/外、自利复核者、未授权复核、无裁决超时、部分争议与无争议部分并行。 | 申诉登记不恢复资格或自动退款；有权裁决只处置指定未结区间，新补偿有新预算；无争议部分继续，历史不改写。 |
| 恢复 | 在登记、冻结、分配、出发、部分接收、结算前后分别 checkpoint + 非空日志恢复，对照不中断执行；删除任一必要 artifact/ledger/receipt/资源引用。 | 完整输入恢复同一需求/资金/数量区间和 receipt；缺依赖阻断，不能默认为空、新建身份或再次派发。已提交响应丢失返回原结果。 |

归档后重放旧请求、旧授权和旧结算，验证最小累计/终态/防重放事实仍阻止第二次价值；没有 archive 原件时显示不可核验，不重新执行。未结保供 escrow/物资在组织退出的剩余资产分配中必须仍被排除。

<a id="es-verify-004"></a>
### ES-VERIFY-004：结算价值、物理边界、读面与兼容

- **补偿与采购。** 对同一 commitment 同时请求采购付款、补偿付款和现金配给；付款仅为该义务真实接收量和已完成运输费用，不能付三份。覆盖无普通参考价、参考价样本不足、关联方交易、超价、restricted starter 资金、预算不足、退回费用超上限与溢出，证明无凭空 OC 或无偿征用。无参考价时真实捐入库存仍可按政策配给。
- **物理与用途。** 路线不可达、目的地存储不足、实际到达但未接收、未完成结算、电力 adapter 缺失时均不能显示完成。尝试转让、兑换、转为自由库存、重复用于制造或代他人消耗，核对资源原子拒绝与原需求不变；常态交易独立继续。
- **正式读面。** 在同一候选/来源 commit 下，Viewer/API/Agent 显示同一授权、自己的 `allocated/partial/denied/expired` 与独立履行阶段、各数量/锁款/原因、历史 receipt 和真实下一步；已分配后释放保留原分配事实。覆盖未分配类别为空、部分完成后到期、重连、陈旧节点、缺 receipt、无安全动作、历史归档与权限变化；不泄露其他人的私有证明。
- **容量。** 对设计 §9 各上限与 +1、证据不可取、评估超预算做确定性对照。窗口超容量整体 `overflowed`，不让前 N 个请求成为隐式赢家；同候选支持节点处置相同，无部分分配或无关交易冻结。
- **兼容。** 启用前旧快照只读为空保供；启用后缺 schema、未知 version、缺政策 artifact 拒绝恢复。新授权不改旧承诺政策；关闭新入口仍能有限结清旧在途。含新义务状态不能交给旧二进制忽略读取，Crisis/brake/普通运输不自动迁移成保供。

full-tier 依照[测试规范](../prd.md)选取真实网络、持久化和浏览器环境。最终记录每一阶段分别取得的生产写点、receipt、对账与正式读面证据；任何阶段缺证据都保留其未验证结论。
