# 网页自带模型连接验收手册

- 生命周期：`active`
- Owner role：`qa_engineer`
- 适用设计：[模型连接系统设计](../../world-simulator/llm/self-supplied-model-connection.design.md#verification-mapping)。
- 产品要求：[网页自带模型连接](../../product/agents-world-simulation/self-supplied-model-connection.prd.md)。

本文是目标功能的验收方法，不声明功能已实现、当前部署支持或以下场景已经通过。实现 PR 固定实际 source/build、协议/模型/路由、部署与浏览器、场景窗口及测试命令；不为尚不存在的测试编造命令。普通 CI 使用假凭证与受控协议 fixture，不使用真实 Key 或发起付费请求。

适用范围变更：下列 BYOK-01～08 的执行端、内存凭证与租约步骤用于现有 Launcher 托管路径。浏览器直连/localStorage 目标须按[浏览器专项映射](../../world-simulator/llm/self-supplied-model-connection.design.md#verification-mapping)修订和执行对应步骤，不能把本文旧路径的通过记录代签新路径；本次设计 PR 不执行或声明浏览器验收完成。

真实模型与游戏自主行为依[独立试玩手册](agent-runtime-self-playtest.manual.md)组织，另需有效测试凭证、有限总预算与隔离世界。不得在聊天、日志、截图、HAR 或结果原件中暴露 Key、私有目标和完整供应商错误体。确定性模拟、浏览器 UI 验证、真实供应商调用及世界结果分别报告，缺前置如实保留未验证。

## 准备与证据

- 固定候选、实际执行端身份、认证/会话方式、provider/model/protocol/preset revision 与允许路由。
- 确认默认关闭；测试开启使用受控部署，未建信任或认证不完整时先测试拒收凭证。
- 使用独立账号、独立浏览器会话及可识别但无真实价值的 canary secret 做负例；仅在明确授权的 BYOK-08 使用真实推理凭证。
- 每项记录刺激、实际非零执行数量、结果、脱敏证据和未覆盖范围。测试成功不自动改变发行支持清单或功能开关。

<a id="byok-01"></a>

## BYOK-01：网页主流程与部署负例

分别选择 DeepSeek/OpenRouter，从当前账号和 Agent 的模型连接入口完成配置、显式 probe、查看结果和单独确认开始。无需 LetAI、CLI、手填地址或重复创建 Agent。检查前后不应自动开始游戏或持续消费。对静态入口、缺执行端、无认证和不可信执行端验证 Key 输入/提交不可用且原因可读。检查键盘、桌面与窄屏的凭证接收方、费用与主动作。

判定：模型可用、执行方状态、游戏权限和世界结果分别呈现；真实开始仍须满足 BYOK-04。UI fixture 只证明其实际显示范围。

浏览器入场只读诊断：对 `/participant/owner-view` 分别注入上游超时、传输失败、非 200、响应读取失败/超限、JSON 解码、类型结构、往返结构、签名及上下文校验失败。

页面保留 `participant_read_*` 固定白名单码、当前失败阶段与网关实际 HTTP 状态；未知或拼接任意文字的码不展示。固定分类仅说明本次读取在哪一层失败，不证明原世界操作失败、未生效或正在执行。`operation_pending` 仍用于原有结果未知路径，不因新增诊断重发提交或创建替代原件。

每类错误体/异常注入 canary，断言签名、目标、请求和原始异常不进入公开诊断，并核对 submit/lookup 的未知恢复语义保持不变。

<a id="byok-02"></a>

## BYOK-02：凭证与租户隔离

两个账号/会话交叉读取、probe、activate、lease、stop 和 delete 同一连接，注入无 CSRF、错误 Origin、旧版本、伪造 owner、任意 URL/headers、跨 origin 重定向及私网/metadata 地址。检查请求级 secret 注入、响应、应用/异常日志、配置/快照、分享、浏览器存储与缓存；供应商响应和错误中也注入 canary。

判定：每次访问重新认证，跨主体不泄露对象存在；出站仅限受准预设且无 secret 转发；无全局 Key 回退、跨账号复用、持久化 secret 或明文回显。验证断开/到期/退出/重启的内存释放路径；不以此宣称抵御宿主管理员或浏览器恶意插件。

<a id="byok-03"></a>

## BYOK-03：并发预算与未知用量

有限调用/token/并发/时间预算下并发 probe 与运行调用，重复相同 probe ID，注入发送前后丢响应、429/Retry-After、5xx、认证/余额错误及缺失或畸形 usage。每次物理发送前核对原子预留，重试也计费；验证达到限制后无新上游请求。

判定：重复 probe 不多发请求；未知已发请求的预留不按零返还；认证/余额/不兼容不自动循环、充值或换公共 Key。只有价格/锁定路由/收费项均可核算时才核对本应用费用上界，否则显示费用未知或估算及可强制的调用/token 限制，不宣称整个供应商账户硬封顶。

<a id="byok-04"></a>

## BYOK-04：授权工具与世界结果

分别构造有效和无效/过期目标、grant 与 executor fence。仅用普通受限 Game Client 完成授权观察、工具/报价、合法行动及原结果回读；对模型建议越权、直接写世界、伪造成功与缺必要输入的情况验证明确阻塞。

判定：连接和 probe 不授予游戏权限；实际效果从 Runtime 原件核对。首个支持场景、旧入口保留范围和完整能力迁移分别说明，不把文本响应或受理当作世界成果。自主行为取证依独立试玩方法，固定脚本不代签。

<a id="byok-05"></a>

## BYOK-05：租约与重启

使用受控时钟/真实服务分别覆盖有效续期、浏览器后台节流、关闭网页未送达 unload、滑动期限/绝对期限到期、登录撤销、执行端重启与实例失联。核对到期后的物理模型请求计数，并从页面回访检查模型状态和既有世界作业。

判定：到期不复活、不从环境/其他实例恢复 Key；重新连接和开始需确认，不自动扩大游戏授权；已受理世界作业继续依 Runtime 规则。页面心跳不代签 worker 正在执行。

<a id="byok-06"></a>

## BYOK-06：切换、Stop 与原操作

模型调用/世界提交在途时，从两个标签页交错 activate、stop、换模型/Key、delete 与迟到回复；检查 CAS 冲突和旧运行代结果。分别丢弃世界原提交响应并重启/重连，沿原 operation 查询。

判定：Stop 永久撤销当前运行代但可保留有效连接；再次确认创建新代，旧输出不能复活。断开忘记另销毁凭证/禁续期。已有 action/outcome 优先原件，未知不生成替代行动；停用不改写已提交世界效果，不保证上游取消或退费。

<a id="byok-07"></a>

## BYOK-07：协议与工具往返

用固定 Chat Completions/Responses 响应覆盖多工具 call ID、参数增量、结果顺序、必要推理历史、流式终态缺失/中断、字段损坏、截断与未知 usage。OpenRouter 检查锁定 provider.only、禁集合外回退/跨模型回退、require_parameters；Responses 检查完整无状态历史、store:false 和空 previous_response_id。验证不支持字段或工具时明确拒绝而非静默删约束、切协议或把文本 JSON 当行动。

增加无付费的多轮 Harness + Provider 组合回归，分别覆盖默认调用者快照与 Provider 结构化会话：同一 Context 至少三轮只读/报价工具往返，检查每个结果在 supplier ID 通道出现一次，user prompt 不重复嵌入累计 transcript；多工具批次保留调用与结果顺序；新 Context 首轮包含完整新切点、目标与 fence。用可识别的非敏感标记验证必要 assistant 推理历史仍在，不能仅以最终响应成功判定。

以完整编码后的候选请求构造低于、等于、超过 byte/token 配置边界的输入，包含“新增片段很小但累计必要历史超限”和首次完整 Context 就超限。断言预检无会话修改、host 持久物理调用预留或网络请求，返回 typed `input_limit`，不新增 unknown usage、不 retry/新 slot/清历史/重置预算。另注入预检之后的 Stop/fence 变化，确认不能凭预检通过发送；已预留后的竞态或结果不明维持保守预算，不误退款。

容量阻塞后检查原 Context、已验证结果与 action/operation 身份仍保留，原未知操作先查；Stop 能独立完成且旧运行代迟到输出失效。重启/重连不得复活旧代、重放未知动作或清零持久预算。记录实际请求编码大小与限额、物理发送和预留增量，不记录完整 prompt/Key；这些离线负例不能代签 BYOK-08 的获授权真实模型持续试玩。

判定：模型适配保持工具因果和协议终态；上游调用标识不被当作免费重试保证。固定 fixture 不能证明真实供应商/模型兼容。

<a id="byok-08"></a>

## BYOK-08：两家真实供应商组合

在另行授权的真实 Key 和有限预算下，独立试玩者分别按固定供应商/模型/协议/路由/构建/部署完成 BYOK-01 与 BYOK-04，核对世界原件，并做 Stop、重启/回访及可行故障负例。记录真实请求与供应商用量；不在未经授权情况下调用真实模型。

判定：两家分别取证，未覆盖组合保持不可用或明确实验状态；一个供应商成功不能代签另一个，连接测试不能代签完整可玩、长期托管或公开发行。用户延期此项时保留未验证，不将普通 CI 改标为真实试玩通过。


失败分类负例：对同一受信预设分别注入 `finish_reason=length`（即使含完整工具JSON）、模型身份不符、意外SSE、未知终态、未登记工具及空/重复/超长tool ID；断言回复整份拒绝、没有游戏动作、无自动重试，并在Harness报告和执行状态得到不同的本地固定分类。注入任意含canary的Provider错误code/message/trace，公开状态只能为 `other` 且不含原文；旧报告缺诊断字段仍可解码。Stop与迟到错误竞态保留Stop结果，不泄露被丢弃回复。真实复测只采集固定分类、预算和权威世界结果，不能为诊断保留回复或推理原文。

恢复负例：在同任务／完整 fence 下完成 Context 与动作，越过 hot window 后退出执行器 OS 进程并重开原 SDK，核对原 prefix／动作仍能签名回读、预算未重置且不重复效果。已过期 Context 不得因此取得写权；任务或 fence 退休释放派生 pin。对已压缩引用但仍有记录头的历史查询，应得到 `HistoryUnavailable` 并阻塞新效果；部分缺失、损坏、冲突材料保持失败关闭。

Context 租期恢复回归：Stop／OS 重启前保留一个已提交 prefix 且无 action/outcome，等待原 tick lease 过期；恢复先扫完全部原件，再以原身份提交一次 `context_expired`，Committed 后才新建后续 Context。验证不读过期私有正文、不加业务 turn、不重置预算；原件 Unknown、清理 Pending／Rejected、其他 aborted 或撤权均不得进入新决策。
