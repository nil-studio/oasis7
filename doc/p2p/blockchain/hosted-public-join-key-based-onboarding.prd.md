## 1. Executive Summary

### 1.1 Problem Statement｜问题

历史问题基线中的公开玩家入口只接受邮箱登录，用户必须填写地址、离开游戏收取验证码，再返回完成验证；邮箱与邮件投递还成为账户服务的前置依赖。对希望立即体验游戏的用户，这是不必要的注册负担。

本次不是把“输入邮箱”换成“手动管理私钥”，而是新增可在客户端完成的公钥凭证注册，并把登录方式从玩家账号本身分离出来。

### 1.2 当前基线与问题证据

下表保留 2026-10-13 固定快照的问题依据，不描述当前 v2 的全部实现状态。P0 采用范围见文首及 §6.4，静态实现与待验证条件见配套设计 §11.2、§18.4；不把设计目标或源码交付当成已上线能力。

| 已核对事实 | 对本次产品设计的影响 | 依据 |
| --- | --- | --- |
| 身份 broker 拒绝非邮箱通道；非测试初始化调用 SMTP 配置加载 | 必须增加免邮箱路径，并让邮件配置缺失只影响邮箱通道 | [R1] |
| 账户记录直接包含 `login_channel`、`normalized_login_hint` 等字段 | 不能只扩充一个通道枚举；需要支持同一账号关联多个凭证 | [R2] |
| 已有设计分别定义 `hosted_account_id`、`player_id`、`device_session_id`、`signer_ref` | 保留稳定账号与玩家身份；不将公钥直接替换成玩家主键 | [R3] |
| Viewer 持久化会话恢复材料，并在读取时重写白名单字段，不恢复旧 `privateKey` | 不恢复浏览器明文长期私钥路径；会话材料仍有敏感性，不宣称消除了会话窃取风险 | [R4] |
| 既有 PRD 的 SC-1、AC-2 等条款要求邮箱默认入口 | 该历史默认已由本专题 P0 及 custody PRD 的 SC-1 / AC-2 承接为推荐 Passkey、邮箱可选；保留旧快照作为问题来源 | [R5] |
| 既有设计仍把 managed custody、外部钱包绑定与迁出列为未完成目标 | 免邮箱注册不得被宣传成资产自托管或生产级钱包已完成 | [R3][R5] |

### 1.3 Proposed Solution｜产品方案

**网页以通行密钥（Passkey）作为推荐注册方式，邮箱保留为可选登录与恢复方式；受保护的本地公私钥作为客户端扩展方式。三者接入同一账号与玩家身份，不另建平行账户体系。**

通行密钥使用公钥认证，私钥由认证器或凭证管理器管理，网站登记公钥凭证；WebAuthn 允许在凭证注册时创建账号，不要求事先完成邮箱注册。[W1]

首版固定以下产品决策：

| 决策 | 产品要求 |
| --- | --- |
| 默认入口 | 支持的网页环境优先显示“免邮箱创建账号”，操作时明确将创建通行密钥 |
| 邮箱地位 | 不作为免邮箱注册或普通游玩的必填项；旧邮箱账号继续可用 |
| 账号模型 | 一个稳定账号可以有多个登录凭证；增加、撤销和更换凭证不创建新的玩家身份 |
| 注册与准入 | 注册成功只证明账号已建立；进入世界仍需通过资格、容量、会话和 runtime 绑定检查 |
| 密钥用途 | 登录凭证、短期游戏会话密钥、资产签名密钥分开；本次不自动授予资产权限 |
| 恢复承诺 | 提供备用凭证与可选邮箱恢复；没有任何可用凭据时，不承诺人工无条件找回 |
| 阶段边界 | 首版完成网页闭环；本地密钥生成、加密备份与导入为下一阶段，不阻塞网页首版 |

### 1.4 Success Criteria｜成功指标

以下数字为本方案提出的验收目标，**不是现有测量结果**。正式测试须记录构建版本、设备、浏览器、网络与部署配置。

| 指标 | 定义及目标 | 验证方式 |
| --- | --- | --- |
| SC-1：摆脱邮箱前置 | 未配置 SMTP 时，支持的环境可完成免邮箱注册、退出、重新登录和玩家身份恢复；规定用例全部通过 | 无 SMTP 部署 E2E |
| SC-2：降低首次操作负担 | 至少 20 名首次使用者，在已具备可用认证器的环境中，至少 80% 无人工协助、60 秒内到达“账号已创建”；站点表单必填身份字段为 0（不含系统 PIN 等本地验证） | 可用性观察；系统验证时间计入，世界排队时间不计入 |
| SC-3：身份连续性 | 增加凭证、跨设备登录、可用凭据恢复、网络重试及邮箱升级测试中，账号与玩家映射一致率 100%；重复角色和错误合并为 0 | 迁移、集成和 E2E 断言 |
| SC-4：失败可解释 | 本文错误矩阵的全部场景显示准确阶段、可执行下一步与诊断编号；不得将注册成功展示为已进入世界 | UI 与 API 契约测试 |
| SC-5：安全不回退 | 已定义的重放、越权绑定、凭证撤销、跨环境误用、最后凭证删除、准入绕过及密钥泄露检查全部通过 | 安全回归；任何绕过均阻止放量 |

不以“公钥账号数量上涨”单独衡量成功，也不通过删除用户取消、认证器不可用等样本来美化转化率。

### 2.3 页面与交互规则

#### A. 注册 / 登录入口

在支持环境中，推荐入口为“免邮箱创建账号”，说明文字为“使用通行密钥，通过设备的指纹、面容或 PIN 等方式确认，无需填写邮箱”。并列提供“已有账号？登录”和“使用邮箱”；保留部署已允许的“先看看”。不得自动弹出系统认证窗口。

用户点击免邮箱创建后，主按钮进入进行中状态，避免重复提交。系统确认取消后回到原页；不自动改走邮箱，不自动创建另一个账号，也不将取消显示为系统故障。

昵称不是身份验证因子。注册不要求用户填写昵称：系统生成可修改的显示名称，用户进入后可编辑。名称不得直接使用邮箱地址、公钥或完整账号 ID；凭证选择器中的显示名称与当前游戏昵称可不同，不得据此判断账号归属。

不支持通行密钥或运行在受限内嵌浏览器时，说明限制，并提供系统浏览器入口、可用的其他认证器选项或邮箱通道。若当前设备与部署没有任何可用认证方式，应明确建议更换设备或返回已开放的访客浏览，不假装认证入口可用。不得静默降级为浏览器明文保存长期私钥。

#### B. 注册结果页

结果分别显示账号、世界和准入状态。例如：

> 账号已创建。当前测试世界名额已满，你的账号已保留，可稍后重试进入。

只有收到 runtime 的有效玩家绑定结果，才能显示“已进入世界”并开放玩法输入。注册成功、会话已签发、玩家已绑定不能共用一个“完成”状态。

当账号建立但会话或准入失败时，主操作为“重试进入”，不得要求重新注册或重新生成密钥。

#### C. 账号安全中心

分为“登录方式”“已登录会话”“恢复方式”三个区域，不把凭证列表当作设备清单。

通行密钥可能同步到多台设备，也可能绑定特定设备，因此“一条凭证”不等于“一台设备”。撤销同步凭证会影响所有使用该凭证的设备，必须在确认框中说明。[W2]

登录方式显示类型、用户命名、创建时间、最近认证时间、可用状态和必要的恢复提示。设备会话显示可识别的会话标签、最近活跃时间、当前会话标记及退出操作；无法可靠识别硬件型号时显示“未知设备”，不猜测。

默认排序：当前认证凭证 / 当前会话置顶，其余按最近使用时间降序；从未使用的记录按创建时间降序。撤销记录收进历史区，不与可用项混排。

### 2.4 Critical User Flows｜关键流程

#### Flow-KEYAUTH-001：新用户通过通行密钥创建账号

`打开公开入口 → 点击免邮箱创建账号 → 阅读简短保存提示 → 完成系统通行密钥创建 → 服务端校验标准注册响应 → 登记账号与凭证 → 获取或恢复稳定玩家映射 → 检查准入 → 发放会话 → runtime 绑定 → 进入游戏`

产品约束：

- 不要求邮箱、密码、手机号、钱包安装或手工复制公私钥。用户须主动确认创建；对外不承诺“一次点击绝对完成”，系统确认步骤由真实环境决定。
- 通行密钥按 WebAuthn 注册仪式处理，不把它描述为自定义字符串签名；本地原生密钥使用单独的签名挑战流程。
- 注册事务未成功前不能展示“账号已创建”。注册已成功但响应丢失时，后续登录应恢复既有账号，不再建立第二份身份。
- 凭证可在系统中创建成功而服务端登记失败；这时须说明“通行密钥已在设备创建，但账号登记未完成”。同一注册响应可在有效期内按幂等规则重试；超时且仍未登记时明确重新创建，不承诺未登记凭证可以直接登录。
- 登记成功后提示“建议添加另一种登录或恢复方式”，允许跳过并开始普通试玩，不强制把邮箱补回。

#### Flow-KEYAUTH-002：老用户免邮箱登录

`点击登录 → 选择通行密钥 → 完成系统验证 → 恢复账号登录态与玩家映射 → 用户选择进入世界 → 检查准入 → 必要时明确确认控制接管 → 签发世界会话 → runtime 绑定`

账号登录会话与世界控制会话分开。第二台设备仅登录账号时不替换第一台设备的世界控制；同一玩家在同一世界保留一个控制会话，接管须明确确认。

登录不要求用户记住账号 ID 或邮箱。不能发现凭证、用户取消或服务端没有对应登记时，显示可区分的帮助入口，但不得向未认证查询者披露具体账号是否存在。

已有凭证登录失败时不得自动注册新账号；“创建新账号”始终是单独且明确的用户操作。

#### Flow-KEYAUTH-003：旧邮箱账号升级

`邮箱登录旧账号 → 打开账号安全中心 → 添加通行密钥 → 完成必要的重新认证 → 创建并验证新凭证 → 绑定成功 → 原账号继续使用`

从未登记过公钥凭证的旧邮箱账号，可用新近完成的邮箱验证码认证添加第一个通行密钥。账号曾登记过公钥凭证但当前不可用，不得被当作“旧邮箱账号首次升级”绕过恢复规则。

升级后保留原 `hosted_account_id`、既有 `player_id`、准入资格和历史归属。不要求用户通过注册首页创建一个新账号再合并。

#### Flow-KEYAUTH-004：添加备用凭证与撤销旧凭证

`已有账号 → 验证现有凭证 → 创建并验证备用凭证 → 明确显示绑定成功 → 需要时验证保留凭证 → 撤销旧凭证`

仅持有浏览器会话、账号 ID 或一个新公钥不足以添加凭证。对于已有公钥凭证的账号，常规添加与撤销须使用已有有效公钥凭证重新认证；本方案的新近认证有效窗口为 5 分钟。

同一登录凭证不能同时绑定到两个账号。遇到冲突保留双方账号，不转移凭证，不自动合并，不暴露另一账号的信息。

撤销当前凭证前必须证明另一个保留凭证可用；禁止常规界面删除最后一个有效登录凭证。因泄露发起的紧急冻结可以关闭全部凭证，但必须单独确认可能无法恢复的后果，并由恢复流程处理。

#### Flow-KEYAUTH-005：添加可选邮箱登录与恢复

`用现有公钥凭证重新认证 → 点击添加邮箱登录与恢复 → 查看恢复信任说明 → 输入邮箱并验证验证码 → 邮箱绑定同一账号`

界面必须说明：“启用后，邮箱可用于登录游戏和申请恢复登录凭证；请保护邮箱账号。此操作不会授予邮箱重置资产密钥的权限。”

未绑定邮箱不影响账号有效性、普通游戏权限或已获得资格。邮箱已绑定其他账号时拒绝重复绑定，不根据同名、同设备或邮箱相同自动合并账号。

绑定后邮箱可用于普通登录；涉及替换已有公钥凭证时仍执行 Flow-KEYAUTH-006，不能仅凭一次邮箱登录直接重置全部登录方式。

#### Flow-KEYAUTH-006：设备或凭证丢失后恢复

按已具备的证明选择路径，不要求先绑定邮箱：

| 已有条件 | 处理方式 | 不做的承诺 |
| --- | --- | --- |
| 同步通行密钥仍可用 | 在可用设备完成正常认证，恢复原账号 | 不保证所有浏览器、系统和凭证管理器自动互通 |
| 另一个已登记的通行密钥可用 | 使用备用凭证登录，再添加新凭证、撤销丢失凭证 | 不要求复制原私钥 |
| 原生本地密钥的加密备份可用 | P1 客户端本地解密并导入，再进行签名认证 | 不把 Passkey 当作本系统可导出的裸私钥文件 |
| 已提前绑定并验证恢复邮箱 | 可先邮箱登录普通游戏；替换丢失的公钥凭证进入下述受限恢复流程 | 不承诺邮箱能恢复自托管资产私钥 |
| 所有凭证不可用，且没有可用恢复方式 | 明确告知当前无法证明账号控制权；允许返回访客入口或明确创建新账号 | 客服不能仅凭昵称、截图、IP 或知道公钥接管旧账号 |

**邮箱替换登录凭证的受限恢复规则（P0）：**

1. 恢复邮箱必须在恢复申请前已绑定至少 24 小时；申请时重新验证邮箱并预登记具体候选公钥凭证。候选在完成恢复前不能登录；恢复申请、通知、批准均绑定该候选，不允许等待期间偷换目标。同一账号最多有一个进行中的恢复申请。
2. 申请进入 24 小时等待期，账号安全中心、既有活动会话和已绑定邮箱显示或收到通知；无邮箱以外的有效通知渠道时，不宣称通知能识别真正的账号主人。
3. 已有公钥凭证持有人可通过新鲜认证取消或批准申请；批准后可提前结束等待。重新提交不能绕过等待，也不能改变已通知的目标内容。
4. 等待结束仍未取消时，申请人必须再次验证同一邮箱，并用预登记的候选凭证完成新鲜持有证明；最终事务才激活该凭证。到期不等于自动获得账号控制权。
5. 恢复完成须作为一个安全变更提交：新凭证生效，旧公钥登录凭证与既有会话撤销，原账号和玩家映射不变。恢复申请创建 7 天后仍未完成则过期。
6. 邮箱刚被替换、账号已冻结或处于安全争议状态时，不得自动完成恢复；显示具体阻断原因并进入已授权处置渠道。邮件服务故障不降低验证标准。
7. 恢复事件必须进入后续授权上下文和审计；不修改资产 `signer_ref`，不生成资产迁移授权，也不绕过既有高风险动作策略。

这是用户主动选择信任邮箱后的恢复方式，24 小时等待仅降低部分风险，**不使邮箱恢复等价于原公钥持有证明**。用户可不启用邮箱恢复，选择多凭证保障。

#### Flow-KEYAUTH-008：网页会话内导入已绑定密钥

Trace ID: O7-REQ-45c9a6e2-d624-4a57-bced-b96b6aa78f69

登录首屏使用自然中文说明账号操作与状态，不直接显示协议字段或英文技术术语。通行密钥保持主要入口；会话内密钥导入默认收起，用户展开“使用已绑定密钥登录”后才显示输入和完整安全告知。

允许用户显式输入 Ed25519 公钥及 32 字节私钥种子（各 64 位十六进制），仅在本次浏览器内存中签署账号登录挑战；不生成、自动备份或持久化长期私钥。导入表单提交后立即清空私钥，退出或关闭页面释放签名引用。用户自行保管原始密钥；页面说明该入口不具备 Passkey 的来源绑定和硬件用户验证保证，勿输入钱包或节点私钥。

已有账号先以有效凭证登录并重新认证，再签名绑定导入公钥；公钥全局唯一归属一个账号。登录只接受已绑定且有效的公钥，未绑定、已撤销、错误配对、过期及重放证明拒绝，不能静默建号或合并账号。导入凭证参与备用凭证数量、撤销、最后公钥保护及会话失效；敏感操作仍须新鲜持有证明。该入口是本次新增的有限导入能力，独立于下述尚未发布的受保护客户端生成及加密备份功能。

#### Flow-KEYAUTH-007：客户端直接创建本地公私钥（P1）

`选择本地身份 → 客户端在受保护环境生成登录密钥 → 本地保存成功 → 对服务器的一次性注册挑战签名 → 验证后登记账号 → 获取游戏会话`

提供“导出加密身份备份”和“导入身份备份”。本阶段只承诺项目规定格式的登录身份备份，不接受任意钱包助记词、节点私钥或链上资产私钥充当登录凭证。

备份在本地加密，导入在本地解密；服务器不接收私钥或备份口令。忘记备份口令、文件损坏且无其他凭据时，不能承诺解密恢复。未通过保护能力验收的平台不开放本地密钥入口，仍可使用通行密钥或邮箱。

| 邮箱凭证 | 规范化邮箱、验证时间、绑定时间、恢复启用状态 | 添加、验证、替换、解绑 | 每账号首版至多一个邮箱登录因子；一个邮箱因子只绑定一个账号；不影响玩家主键 | 现有账号证明 + 新邮箱验证；恢复场景另行处理 |

| 恢复申请 | `recovery_request_id`、目标账号、方式、创建时间、最早完成时间、过期时间、状态 | `pending → approved / waiting → completed / cancelled / expired / blocked` | 服务端时间为准；仅未取消、未过期且再次验证通过可完成 | 预先登记的恢复方式，或已有有效公钥凭证 |
| 资格与名额 | 邀请或资格引用、准入结果、容量结果、绑定结果 | 注册后重试进入世界 | 不把公钥数当真人数；一次注册不自动赠送免费模型额度或永久占用 slot | 既有准入服务与运营规则 |

### 2.6 生命周期与权限

**三个相互独立的状态维度：**

| 维度 | 状态与含义 |
| --- | --- |
| 账号状态 | `active` 可正常认证；`frozen` 按安全策略阻断；不因暂时无法进入世界而变成注册失败 |
| 认证状态 | `guest` 未认证；`authenticated` 已证明某种登录因子；`reauthenticated` 在指定操作窗口内再次认证；恢复申请另有状态，不假装更强认证 |
| 世界接入状态 | `not_requested → checking → waiting / denied / session_issued → runtime_bound`；只有最终绑定且授权有效时才能执行对应玩法输入 |

邮箱账号直接升级、公钥账号常规管理和公钥账号丢失后恢复，是三种不同权限路径：

| 操作 | 允许条件 | 必须拒绝的情况 |
| --- | --- | --- |
| 普通登录和已授权玩法 | 任一已登记且有效的登录凭证 + 当前准入与会话授权 | 仅提交公钥字符串、客户端自报账号或已撤销凭证 |
| 旧邮箱账号添加首个公钥凭证 | 从未登记公钥凭证的旧账号 + 5 分钟内完成的邮箱验证 + 有效新凭证登记 | 曾经有公钥凭证的账号冒用该路径恢复 |
| 公钥账号增加凭证、添加邮箱、修改恢复设置 | 5 分钟内完成已有公钥凭证认证 + 新因子的有效验证 | 仅有旧浏览器会话或一次普通邮箱登录 |
| 撤销公钥凭证 | 验证另一个将保留的有效公钥凭证；恢复流程完成时可按安全变更统一撤销旧凭证 | 通过普通删除操作删掉最后一个有效公钥凭证，或仅用待删除凭证证明剩余凭证可用 |
| 邮箱替换丢失公钥凭证 | 完整受限恢复流程 | 新提交一个未预先绑定的邮箱就接管账号 |
| 退出当前会话 | 当前会话本人 | 未认证请求指定其他人的会话 |
| 退出其他会话 | 当前账号的新鲜公钥认证；从未登记公钥的旧邮箱账号可用新鲜邮箱认证 | 使用任意旧会话批量踢出其他会话 |
| 资产转移、资产签名或治理 | 独立专题定义的授权与签名规则 | 因新增 Passkey、邮箱恢复或公钥注册而自动放行 |

公钥账号通过普通界面解绑邮箱后仍保留可用公钥凭证；旧邮箱账号若没有其他有效登录凭证，不得直接解绑唯一邮箱。更换邮箱须验证现有权限及新邮箱，完成后旧邮箱不能继续用于登录或新建恢复申请，新邮箱的恢复等待资格重新计时。

### 2.7 准入、资源与邀请测试

注册前允许进行不创建账号的资格预检查，并展示当前世界是否开放；资格预检查不是邮箱要求。邀请码或一次性邀请资格须在真正授予资格时原子消费，重复请求不得重复扣减。

账号创建后，资格暂不可用、世界满员或 runtime 暂停均不撤销账号。界面应保留用户原目标世界，允许稍后重试，不要求重新生成密钥。注册行为本身不得永久占用玩家名额。

注册通道必须具备服务端注册挑战、失败认证、账号和网络来源等维度的限流，以及独立的准入和资源配额检查。不能通过更换公钥轻易绕过对同一邀请资格或已知会话的约束，也不能宣称完全识别所有多账号行为。

邀请测试部署必须为未认证挑战配置单实例 / 共享服务总量保护，为免费模型资源配置独立预算。所有上限在放量前有明确配置和压测证据，不能以“以后再加风控”开启公开无限注册。IP 地址不是唯一真人标识，不能仅因多人共享网络就永久封禁账号。

### 2.9 Non-Goals｜不在本次范围

不建立“公钥即账号 ID”的新链上身份体系，不要求更换 runtime / 链上签名算法，不引入通用钱包登录、助记词钱包、资产私钥托管或导出，不复用 node / validator / governance 密钥，不实现自动账号合并、社交恢复或任意客服接管，不让 AI Agent 在没有用户确认的情况下登记或替换长期凭证。

不承诺 Passkey 解决全部账号风险，不承诺任意节点域名都能直接使用同一 Passkey，也不宣称免邮箱意味着完全去中心化、无身份服务依赖或一人一号。

## 3. AI System Requirements｜AI 系统要求

本功能不使用大模型进行身份判定、密钥生成、签名验证或恢复审批，因此没有模型能力、推理质量或 token 消耗要求。

AI 助手可以解释操作、展示脱敏状态和指向安全中心，但不得索取用户私钥、备份口令、完整恢复证明或邮箱验证码。登录和恢复必须由确定性服务端校验与用户控制的认证器完成；自然语言“用户同意”不能替代有效的认证证据。

## 4. Technical Specifications

### 4.1 Architecture Overview｜产品层架构边界

统一登录后的接入关系为：

```text
通行密钥 / 邮箱 / 本地登录密钥
                  ↓
          验证对应类型的登录证明
                  ↓
           稳定 hosted_account_id
                  ↓
      目标世界的既有 player_id 映射
                  ↓
       资格、容量、会话签发与恢复
                  ↓
            runtime 玩家绑定
                  ↓
           已获授权的普通玩法
```

资产签名体系为另一条授权链，不因上述流程成功而自动放行。本次不得把 managed custody 的实现作为免邮箱普通试玩的前置依赖。

| 系统边界 | 本专题要求 | 留给对应系统设计的内容 |
| --- | --- | --- |
| 身份服务 | 多凭证映射、正确注册和认证、凭证撤销与恢复；邮箱故障局部降级 | API、challenge 存储、会话与事务绑定、密码学库和错误协议 |
| 账户存储 | 账号与凭证独立建模；类型专属材料不混装；唯一性、幂等和可回退迁移 | 表结构、索引、条件写、事务补偿与数据版本 |
| 玩家会话与 runtime | 保持既有账号 / 玩家绑定；验证资格、会话和授权；接收撤销与恢复结果 | 授权上下文、撤销传播、并发与 epoch 处理 |
| Viewer / 客户端 | 正确入口、系统认证、分阶段反馈、安全中心；本地密钥能力单独开关 | WebAuthn 接入、原生安全存储、备份格式、客户端兼容策略 |
| 运营与部署 | 能分开控制新注册、既有登录、邮箱通道和恢复；不绕过验证降级 | 配置名称、告警阈值、回滚方式和故障处理手册 |

现有存储有 `file` 与 `tablestore` 分支。[R2] 两者只要仍属于宣称支持的部署方式，就必须能保存新凭证并通过相应一致性测试；不能只更新某一后端，另一后端默默创建孤立账号。

### 4.2 身份与凭证约束

`hosted_account_id` 保持服务端稳定标识；WebAuthn `userHandle` 使用不含邮箱等可识别信息的稳定、不透明值。`player_id` 延续现有身份作用域，不借此次改造引入新的跨世界合并语义。

登录凭证分为通行密钥、邮箱、原生本地公钥。Passkey 的公开验证材料不预设为 Ed25519，也不要求和现有短期设备签名密钥使用同一种算法。不能直接复用游戏消息验签函数作为完整 WebAuthn 验证器。

公钥凭证唯一性由其类型和适用身份域共同确定；指纹与显示标签仅用于识别，不能替代实际凭证验证。注册前预分配的临时标识不是已建立账号，不得永久占用玩家资源。

所有敏感账号变更必须绑定目标账号、操作类型、有效期和发起上下文。重放防护同时覆盖并发请求和服务重启；多个实例不能各自接受同一份已消费证明。

### 4.3 登录来源、域名与多节点

WebAuthn 凭证有 RP 作用域，服务器必须验证相应 origin / RP 信息；不是任意网址都可使用同一凭证。[W1]

产品要求：正式公开玩家入口有稳定、明确的身份服务域；更换世界节点不要求用户重新注册。世界承载节点数量或地址变化，不改变账号归属。需要跨站点衔接时，由系统设计承接受控的身份交接，不把长期私钥或完整会话令牌放进跳转 URL。

开发、staging 和公开部署必须隔离凭证与认证挑战的信任范围。RP 或域名变更须被视为账号可访问性的迁移，不得在用户注册后直接换域导致所有账号无法登录。

原生本地密钥的证明须绑定身份服务、环境、用途及有效期，不提供“签一次就能在所有节点无限登录”的通用签名。

### 4.4 Edge Cases & Error Handling｜异常矩阵

所有失败返回面向用户的说明和脱敏诊断编号。下表为产品错误语义，不固定协议错误码。

| 情况 | 用户看到的状态 | 恢复动作与不变量 |
| --- | --- | --- |
| 浏览器不支持或环境受限 | 当前环境不能创建通行密钥 | 打开系统浏览器 / 选择可用其他入口；不保存裸私钥作为降级 |
| 用户取消系统确认 | 尚未完成创建或登录 | 返回原页可重试；不自动创建账号 |
| challenge 过期 | 本次确认已过期 | 重新获取挑战；旧响应不得重新生效 |
| 签名、来源或用户验证不满足要求 | 无法完成身份验证 | 重新认证或切换已登记方式；不签发会话、不自动换号 |
| 凭证已创建但登记未成功 | 账号登记未完成 | 有效期内幂等重试；过期后明确重新创建；未登记凭证不被误认作已注册 |
| 注册成功但响应丢失 | 正在确认注册结果 | 在原尝试上下文恢复结果，或通过新鲜登录恢复已注册身份；不重放旧响应发放新会话 |
| 账号已创建、准入失败 | 已有账号，尚不能进入该世界 | 保留账号，展示资格或容量原因；稍后重试进入 |
| 会话已签发、runtime 绑定失败 | 已登录，尚未进入世界 | 以既有账号重试 / 恢复，不重新建号；原临时名额按既有租约规则释放 |
| 多标签页注册或重复点击 | 创建进行中 / 已处理 | 相同尝试幂等；不同且均经用户确认的新凭证不能仅凭同设备自动合并 |
| 同一凭证被两个账号并发绑定 | 绑定冲突 | 最多一个绑定成功；另一请求明确失败，不产生部分覆盖 |
| 邮箱已属于其他账号 | 无法绑定该邮箱 | 不透露另一账号详情；引导选择其他方式，不自动合并 |
| 凭证或会话被撤销 | 登录方式 / 会话已失效 | 使用其他有效凭证；阻止刷新旧会话重新取得权限 |
| 服务或身份记录异常 | 账号服务暂不可用 | 安全失败并给诊断编号；不得创建“临时新身份”掩盖数据损坏 |
| 所有凭证丢失 | 无可验证的登录方式 | 展示已登记恢复渠道；无渠道则明确无法证明旧账号控制权 |
| 恢复等待期间凭证持有人取消 | 恢复申请已取消 | 后续旧申请证明全部失效，不能到期后继续完成 |
| 恢复完成响应丢失 | 正在确认恢复结果 | 校验恢复记录并用新凭证登录；不得恢复已撤销旧凭证 |
| 客户端备份损坏或口令错误（P1） | 无法导入该身份备份 | 不上传文件、口令或私钥；不自动生成另一个身份 |

幂等不等于重复认证：同一操作重试可以返回非敏感结果或复用同一受控结果，但不能用已消费的签名跨会话获取新授权。超过恢复上下文有效期须重新认证。

### 4.5 Non-Functional Requirements｜非功能目标

以下是邀请测试阶段的产品验收基线，不是容量或性能实测值。超出该规模的承诺需追加验证，不能直接外推。

| NFR | 目标 | 验收说明 |
| --- | --- | --- |
| NFR-01：服务响应 | 10,000 个账号、30,000 个公钥凭证、20 个并发客户端，以每秒 5 次有效认证请求持续 10 分钟，服务端认证与登记请求 P95 ≤ 1 秒，非预期服务错误率 < 1% | 不计用户系统确认、邮件送达和世界排队；记录硬件与存储后端，每个对外支持后端分别验证 |
| NFR-02：交互反馈 | 用户点击后 300 毫秒内出现可感知反馈；每个等待状态有说明和取消 / 返回能力 | 客户端性能采样；不得在网络超时期间维持无提示空白页 |
| NFR-03：撤销一致性 | 凭证撤销、会话撤销和恢复完成后，服务端授权生效上限 60 秒 | 覆盖已有连接、刷新、节点切换；无法确认撤销状态时不得无限续期旧权限 |
| NFR-04：挑战安全 | 新公钥认证挑战默认有效期 120 秒，至少 32 字节密码学安全随机量；成功后原子消费；每份挑战最多接受 5 次失败验证 | 参数为本方案基线；过期、并发及重启后重放测试；邮箱验证码沿用独立策略 |
| NFR-05：防滥用保护 | 邀请测试初始默认：每网络来源每分钟至多 60 个注册挑战、整个部署每分钟至多 300 个；每来源每小时至多 10 个新账号、环境每天至多 100 个新账号 | 可由运营审计调高；保留共享网络的受控例外。额度拒绝返回可重试说明，不等价于封禁现有账号 |
| NFR-06：并发正确性 | 同一凭证只能绑定一个账号；同一成功注册尝试只建立一份账号关系；一次邀请资格只消费一次 | 至少 20 个并发冲突请求验证；故障注入验证部分写入不会形成可利用身份 |
| NFR-07：浏览器兼容 | 发布支持矩阵至少覆盖 macOS Safari / Chrome、Windows Edge / Chrome、iOS Safari、Android Chrome 的发布时稳定版本；至少验证一个硬件安全密钥方案 | 这些组合是要求验证的目标，不是现有兼容性结论；每个对外声明支持的组合有真实设备注册、登录、取消、恢复及撤销证据 |
| NFR-08：兼容降级 | 所有不支持或受限环境都有明确替代入口；不要求生物识别为唯一手段；支持键盘操作和读屏可理解的状态提示 | 包含内嵌浏览器、缺少平台认证器、系统验证失败和访问性检查 |
| NFR-09：敏感信息 | 业务 API、日志、埋点、错误报告中，裸私钥、备份口令、生物信息、完整 OTP 与可重放认证材料的泄露数量为 0 | 浏览器网络检查、日志扫描与主动异常注入；原生备份检查在 P1 执行 |
| NFR-10：可恢复性 | 客户端刷新、身份服务重启、存储短时异常后，已提交账号与玩家映射不丢失；不能恢复的未完成挑战允许安全重启 | 不要求把过期挑战恢复为有效；要求可重新认证而不建重复身份 |
| NFR-11：登录独立性 | SMTP 配置缺失或投递失败不影响已开放公钥方式的注册和登录；新注册开关不改变已有凭证可用性 | 分别关闭邮件、注册、恢复通道进行测试；身份存储故障不伪装为成功 |
| NFR-12：扩展与迁移 | 增加认证方式不更改已有账号 / 玩家 ID；未来签名算法按凭证类型扩展 | 旧邮箱记录、不同公钥类型和旧会话兼容回归；不得通过全量重建账号完成迁移 |

限流不是身份真实性证明。多实例部署的计数与一次性资格必须具有部署范围的约束，不能增加一个实例就成倍增加同一主体可绕过的限额。用于恢复和已有账号登录的保护额度应与新注册分开，避免攻击者耗尽注册额度后顺带阻断老用户。

### 4.6 Security & Privacy｜安全与隐私

**认证器边界。** 通行密钥注册与认证要求用户主动参与，首版需要本地用户验证能力；不能因为设备缺少指纹就断言不可用，应允许系统支持的 PIN 等方式。生物识别处理不发送给 oasis7 服务端。[W2] 不强制采集认证器唯一硬件标识，不把认证器型号当实名身份。

**标准验证边界。** 使用成熟的 WebAuthn 实现并完成标准注册 / 认证响应验证，不能只检验一段签名就宣称支持 Passkey。首版使用可发现凭证以实现不输入邮箱的登录；不得把签名计数器当作唯一重放防线或因同步场景的计数行为直接永久封号。[W1][W3]

**浏览器与本地密钥。** 不在 `localStorage`、普通明文配置、URL、剪贴板自动填充或分析平台保存长期登录私钥。原生私钥只交给经过验收的本地保护机制；不能保护时拒绝启用该模式。浏览器中的短期会话恢复材料继续按敏感凭据处理，不声称使用 Passkey 后不再需要 XSS 与会话防护。

**会话劫持防护。** 登录成功应签发新的会话上下文，敏感变更不得只信任长期未重新认证的登录态。绑定凭证、替换邮箱与恢复提交均有反跨站请求及重放约束；系统设计必须证明第三方不能借用户已登录状态给账号增加攻击者凭证。

**恢复强度。** 邮箱恢复是单独的信任选择，不冒充旧私钥证明。恢复完成、凭证撤销及邮箱替换均保留认证方式与恢复来源；后续高风险授权不能只看“已登录”一个布尔值。没有独立资产授权能力时继续拒绝相关动作。

**数据最小化。** 无邮箱账号不创建伪造邮箱，也不为了下游系统填 `account_id@...` 当作已验证邮箱。邮箱字段为空是合法账号状态。下游通知、模型额度或其他消费者必须处理缺少邮箱的情况，不能把注册成功后补邮箱变成隐形门槛。

邮箱验证码可以经加密连接在专门的认证请求中提交给身份服务，但不能回显给其他客户端、进入日志或转发给分析系统；“零泄露”不等于禁止必要的认证提交。

**审计与保留。** 安全审计至少记录账号内部标识、操作、凭证内部引用、结果、认证类型、恢复事件、服务端时间与诊断编号，不记录完整挑战响应、会话令牌、OTP、私钥或备份文件。初始保留策略：安全审计 90 天、运行诊断 30 天、用于反滥用的完整 IP 最多 7 天；后续仅保留限流所需的最小派生标识及聚合结果。调整保留策略须有明确用途和访问权限。

### 4.7 可观测性与漏斗

建议记录以下脱敏事件，并保持注册、登录和世界接入的不同分母：

`onboarding_started → credential_registration_submitted → account_registered → login_succeeded → admission_checked → player_session_issued → runtime_bound`

另记录 `user_cancelled`、`unsupported_environment`、`credential_bind_conflict`、`credential_revoked`、`session_revoked`、`recovery_started`、`recovery_cancelled`、`recovery_completed`。不能可靠观察系统本地是否完成创建时，不伪造 `credential_created` 事件。

产品看板分别报告注册完成率、认证成功率、准入通过率、runtime 绑定成功率与恢复完成率；取消、兼容问题和服务错误分别列示。世界满员不计为认证失败，认证成功也不计为已经开始游戏。安全埋点只用于产品诊断与反滥用，不公开跨站追踪标识。

## 5. Risks & Roadmap

### 5.1 Phased Rollout｜能力分期

| 阶段 | 对用户交付的能力 | 必须完成的边界 | 不随本阶段承诺 |
| --- | --- | --- | --- |
| MVP / P0 | 网页免邮箱创建与登录；旧邮箱兼容；多凭证管理；会话退出；备用凭证及可选邮箱恢复；分阶段准入反馈 | P0 验收通过；真实平台验证；迁移和回退保留账号可访问性；邮件不再是公钥入口的前置 | 原生私钥备份、通用钱包登录、资产自托管 |
| v1.1 / P1 | 受保护客户端直接生成本地公私钥；加密身份备份与导入；同一账号关联本地凭证 | 每个开放平台完成本地保护、备份损坏、错误口令、密钥轮换及撤销测试 | 在任意平台或普通网页中保存原生长期私钥 |
| 后续独立专题 | 根据实际需求扩展外部钱包、资产自托管或其他恢复能力 | 另有独立产品和系统设计，明确资产授权与迁移关系 | 本文不自动批准或预先宣告这些能力已具备 |

阶段描述的是交付能力，不规定 PR 数量、人员分配和日程。首版不能仅发布“创建通行密钥”按钮，而将身份连续性、可用恢复路径和撤销留给后续补丁。

### 5.2 发布、降级与回退要求

新注册应从受控测试群体逐步开放。发布前验证账户迁移、支持矩阵、恢复流程、限流和错误提示，不把本地 QA 免邮箱测试接口暴露为公开注册替代。

关闭新用户注册时，已有通行密钥账号和邮箱账号仍能登录；关闭邮箱通道时，保留公钥登录；关闭邮箱恢复时展示真实原因，已有备用凭证仍可使用。

**新增公钥账号一旦真实产生，旧版“只能邮箱登录”的程序就不是安全的回滚目标。** 回退必须保留支持该凭证的认证服务或兼容读取能力；不能要求所有免邮箱用户临时补邮箱才能恢复访问。界面回退不得删除凭证数据或撤销原玩家映射。

若某类凭证存在已确认安全问题，可以有意暂停该类认证并撤销相关会话，但必须清楚告知影响和可用恢复方式。这是安全阻断，不得伪装成无损降级，也不得跳过验证来维持表面可用。

### 5.3 主要风险与控制

| 风险 | 影响 | 产品控制 |
| --- | --- | --- |
| 认证器不可用或用户不理解 Passkey | 首次注册流失 | 解释用设备确认的行为，不灌输密码学；显示兼容入口与真实限制 |
| 清缓存被误认为删除账号 / 密钥 | 用户误建第二账号 | 将清除会话、撤销凭证与注销账号区分；登录失败不自动注册 |
| 用户只有单个不可恢复凭证 | 设备丢失后无法访问 | 可跳过但持续可见的恢复提示；至少支持第二凭证；不夸大同步可靠性 |
| 邮箱成为公钥账号的薄弱恢复因子 | 邮箱失陷导致登录身份被替换 | 显式启用、等待与通知、有效凭证取消、重新验证、保留恢复来源；承认残余风险 |
| 公钥可批量创建 | 账号、slot 和模型额度被刷取 | 注册保护与资格 / 额度分离；幂等消费邀请；不声称公钥代表独立真人 |
| 身份服务域名或部署信任域改变 | 已有 Passkey 不能使用 | 稳定身份入口；域名变更单独迁移；多节点承载与登录信任域解耦 |
| 账号与凭证迁移不一致 | 旧玩家换号、重复身份或被错误合并 | 保留稳定 ID、唯一性约束、并发 / 故障回归、可兼容回退 |
| 身份权限与资产权限混淆 | 恢复账号等价于资产接管 | 登录与资产签名职责分离；保留 step-up 和资产授权；不改写 custody 状态 |
| 原生密钥备份泄露（P1） | 登录凭证被复制 | 本地加密、主动导出、泄露后轮换与撤销；不把备份复制等同于新增独立凭证 |

### 6.2 首版完成定义

首版放量须同时满足：P0 对应 AC 全部通过；支持矩阵有真实证据；20 名首次使用者完成可用性观察；无 SMTP 部署、老邮箱迁移和兼容回退演练通过；没有已知的越权绑定、跨账号恢复、重放放行或私钥泄露缺陷。

产品可用性指标若未达标，应调整入口和提示并重新验证，不以删除恢复提示、强迫绑定邮箱或静默生成临时账号换取更高转化。P1 尚未完成不阻断 P0，但客户端原生密钥入口必须保持未发布状态。

### 6.3 Decision Log｜产品决策记录

| 已选方案 | 未选方案 | 原因与边界 |
| --- | --- | --- |
| 网页推荐 Passkey | 普通网页生成并明文保存长期私钥 | 用户无需手工维护裸私钥；延续已有浏览器安全边界。原生密钥属于受保护客户端扩展 |
| 多凭证关联稳定账号 | 邮箱、公钥或公钥哈希直接充当玩家 ID | 换凭证、恢复和跨设备不应改变玩家身份；保留现有分层 [R3] |
| 邮箱可选、原账号兼容 | 删除邮箱或强制所有人迁移到 Passkey | 支持旧用户与兼容环境；免邮箱是新增选择，不是新的使用门槛 |
| 首次注册不强制备份或绑定邮箱 | 必须抄写助记词 / 下载私钥 / 收邮箱验证码才能开始 | 普通试玩优先减少负担；用可跳过提示明确无法恢复的风险 |
| 常规凭证管理要求已有公钥重新认证 | 仅凭浏览器登录态或任意一次邮箱登录新增 / 替换密钥 | 保护长期登录身份；邮箱恢复采用明确的独立信任流程 |
| 预先登记邮箱可进行受限恢复 | 客服根据昵称、截图或设备信息直接重置密钥 | 没有有效证明不能声称确认账号控制权；恢复不等于资产解密 |
| 注册、认证、世界准入分别反馈 | 验证公钥成功即认为已进入世界 | 防止误导、绕过容量与免费资源限制，也便于诊断 |
| 身份入口独立于世界节点 | 每个节点独立注册一套用户身份 | 节点变化不应迫使玩家换号；Passkey 的作用域不能忽略 [W1] |
| 登录凭证与资产签名分开 | 把登录私钥顺便用作链上资产控制密钥 | 不让降低注册负担扩散成资产托管改造；保留现有独立专题 [R3][R5] |
| 关闭注册仍保留已有凭证登录 | 发生问题直接回滚成邮箱唯一入口 | 已有免邮箱账号不能因回退永久失去访问能力 |
