## 1. 问题、目标与非目标

### Ed25519 key management extension

The current extension adds root-only semantic inventory, lifecycle state, encrypted import/export, encrypted custody snapshots and generic file signing. It does not deploy a release or enable installed-host signing. `control/key-catalog.json` is canonical root-owned control with installation binding, immutable signer IDs/public keys, mutable descriptions/tags, lifecycle state and ordered public events. Existing uncatalogued keys retain rollback-only nonexportable behavior. Generic signing requires a catalog entry. Every worker authorization path, including retries and result inspection, checks current key state.

<a id="des-local-signer-key-lifecycle"></a>
Creation and import publish an inactive catalog entry under the custody lock before materializing private files. Creation activates only after validating the complete pair; imports remain inactive. Rotation first disables the old key and does not rewrite grants. Deletion first records a public tombstone and then removes the seed. Interrupted operations therefore fail closed, and administrative recovery must bind the exact existing maintenance target. IDs and retained public fingerprints are never recycled.

<a id="des-local-signer-envelopes"></a>
Encrypted envelopes have closed authenticated headers, fixed Argon2id v19 parameters (64 MiB, three iterations, one lane), random salt/nonce and XChaCha20-Poly1305 encryption. Decrypted secret buffers and derived keys use zeroizing storage. The administrator can export only explicitly exportable keys; encrypted whole-store disaster recovery includes nonexportable seeds only through explicit opt-in. This is software authorization, not hardware-backed extraction resistance.

<a id="des-local-signer-backup"></a>
Snapshots include keys, canonical control and signing reservations/results. Backup requires disabled policy and a locked coherent snapshot. Restore validates before effects, binds a reviewed plan to the current installation configuration and encrypted input, and creates files only in an empty target or the exact matching interrupted restore. Durable maintenance blocks worker use until completion. Restored policy is disabled and all historical grants are revoked; consumed records remain. Host accounts, executable bindings and sudo policy are outside the snapshot.

<a id="des-local-signer-file-signature"></a>
`file_ed25519_v1` signs the `oasis7:file-signature:v1` domain separator and canonical context/file-digest/length envelope. Exact payload approval and existing restricted grants remain required. Rollback signing retains its existing wire contract. Verification must reconstruct this envelope; no generic signature constitutes blockchain authority.

<a id="des-local-signer-key-failures"></a>
Acceptance covers key lifecycle denial, default export denial, wrong-password/tamper rejection, imported inactive state, committed-record snapshot integrity, interrupted restore durability and existing rollback negative regressions. Independent security review and applicable CI are required before delivery; fixture checks do not establish host deployment.

Merged M0 provides the three Rust executables and root-only post-install management. This source delivery implements a versioned release package and real macOS installation backend with explicit plan/apply, protected custody, external caller jobs and no initial signing authority. Source tests do not establish a host installation or permission acceptance.

This professional contract does not change product promises, blockchain authority admission, signing payloads, policy/grant semantics, key creation, backups/restore, identity bridge M1 or workflow policy. Original Downloads attachments are design inputs: V2 design SHA256 `68d73f88474d9ba0ea89020266d7063c729eaa3f050d913f495b01a971d8bdcd`; V2 runbook SHA256 `512908ebab4fc4ceedf6aa7e847a664c627fed16de3aa0bbf532e181c2cd3708`. ## 4. 边界与结构

`oasis7_signer_protocol` owns bounded IPC framing, wire types, domain-separated request identities and pure payload validation. It has no key store, host privilege, installation or process-management dependency. `oasis7_local_signer` retains custody, authorization decisions, filesystem checks and worker/admin execution, and reexports existing protocol paths for source compatibility. Extraction does not change schemas, signed bytes or grant semantics.


### des-local-signer-install

Trace refs: O7-REQ-103d7ad7-33f2-41b8-a741-a9c4b383b4c3. The local negative obligation from [REQ-DCS-003](../../product/world-infrastructure/distributed-consensus-and-state-availability.prd.md#req-dcs-003) is that installation, caller/task labels, grants and file signatures confer no blockchain/governance authority. Fresh success remains INSTALLED_UNREADY without key/policy/grant. This is not proof of validator admission, governance rotation, network role isolation or a compromised-service/full-topology scenario.

<a id="des-local-signer-release"></a>
`package-release.py` produces the closed candidate release; `install-release.py` contains the fixed CLI and independently approvable bootstrap literal; `installer.py` validates the admitted release and `macos_host.py` provides real platform effects. Every root plan/apply starts at a separately approved native Rust runtime gate staged in a protected root-owned location outside the candidate release. The gate is a separate trust artifact and is not a member of the candidate release manifest; candidate package provenance cannot authorize execution of the gate. The operator checks the gate's exact bytes against an independently supplied gate digest before invocation. The fixed `/usr/bin/env -i` prefix clears inherited variables before the gate is loaded; the gate path and its expected Python identity do not come from the candidate manifest, plan, or environment. The gate pins the direct Command Line Tools Python 3.9 executable and Python3.framework, Apple code requirement, executable/framework CDHashes, and exact allowed dependency install-name closure in its separately approved binary. A changed CLT identity requires a rebuilt gate and fresh independent approval.

Before Python starts, the gate opens the fixed runtime, framework and path ancestors through retained nofollow descriptors and checks type, owner, mode, link count, native ACL evidence, filesystem provenance, and path-name identity. It verifies the executable and framework resources with the explicit Apple requirement, checks the exact dependency allowlist, then rechecks descriptor and pathname identities immediately before `execve`. After admission, the gate uses `execve` on the fixed direct Python path with `-I -S -B -c` and the bounded bootstrap bytes read from a separately protected external source after matching their independent digest. No installer or candidate code runs before that boundary. It never follows `/usr/bin/python3`, `xcrun`, `DEVELOPER_DIR`, or inherited Python settings.

The gate passes a bounded canonical runtime-attestation record on a pipe inherited at fixed FD 3. The bootstrap must validate this record before opening or capturing candidate-stage descriptors, and then compare it with compiled expected runtime facts, `sys.executable`, Python version, `-I -S -B` flags, and the absolute standard-library-only import path under the sealed framework. It adds the observed runtime identity and bootstrap digest to plan observations. Plan, apply, and complete-repeat must compare the current attestation to the approved plan before effects or installed-state readback. The gate artifact hash is an independent approval input and is deliberately absent from its own attestation. Candidate release capture remains anchored through retained nofollow descriptors with same-descriptor `fgetattrlist` ACL checks: only the exact absent-ACL omission with its zero reference or bounded `kauth_filesec` carrying `KAUTH_FILESEC_NOACL` is accepted; zero-entry, populated, malformed, unsupported and failed ACL observations reject. The closed manifest, launcher, modules and binaries are captured once and passed as an immutable capsule. The candidate stage is not reopened after admission. Native ACL, metadata, runtime identity or attestation uncertainty fails closed. Runtime Rust owns fixed binding load and caller job resolution. Fixture backends remain importer-only injected objects, unavailable through production CLI/environment. Worker remains a fixed Rust executable, never a Python interpreter run as signer.

Approved release installer may execute as root only through a separately authorized host action. Caller cannot modify installed binding/code/control or access seeds; signer cannot alter control. External caller job content is ordinary untrusted input whose bytes are validated by the existing protocol and approved digest. Caller-owned ancestors of Documents remain caller-owned and provide no custody authority.

## 5. 关键运行流程

1. Package already-built release binaries plus installer modules; emit manifest digest for independent approval. Never execute build products as root during packaging.
2. Plan first verifies the protected native gate's bytes against its independently supplied digest, then invokes that gate through the fixed `env -i` prefix with the independently approved bootstrap source/digest and `plan` arguments. The gate admits only its compiled CLT Python identity before starting Python. The bootstrap validates the inherited FD 3 attestation before candidate capture, verifies the exact captured manifest/member bytes against independent release digests, and records the runtime identity in canonical plan observations alongside platform, host facts, paths, account allocation, effective ACL/sudo and conflicts. Plan produces canonical JSON without mutations. Import, release validation and file publication consume the same immutable candidate capture; none reopen candidate-stage files by path.
3. Apply requires root, the same independently approved gate/bootstrap/release digests, and the expected plan digest. The gate repeats pre-Python runtime checks; the bootstrap validates its current FD 3 attestation against the planned runtime identity before candidate capture or installer effects. For a fresh installation, recompute live plan observations and refuse drift before effects. For a complete repeat, verify the supplied original plan digest and receipt, compare current runtime identity to the plan before installed-state validation, then perform full installed readback. A complete receipt alone is insufficient. Partial journals return RECOVERY_REQUIRED. All subprocesses use fixed absolute executable paths, argument arrays, bounded output, timeout and clean environment; no shell or caller-selected executable.
4. Acquire protected installer lock; durably journal intent; allocate dedicated account/group; create protected directories; stage verified release bytes; publish root binding with observed store/jobs identities; verify keyless/grantless/policyless layout; publish narrow sudo include last; verify complete installation and publish report.
5. Success reports installed-but-unready. Exact repeat verifies every owned artifact and returns VERIFIED_UNCHANGED. Drift/conflict refuses repair. Interrupted apply leaves a durable RECOVERY_REQUIRED record; no automatic deletion, overwrite, rollback, key generation or activation.

No arbitrary command or shell field. Identity IDs are supplied explicitly to plan, stable across retries; `signing_enabled` is always false. ### 6.1 Pre-Python runtime gate and attestation

Before each plan or apply, the operator verifies the exact separately staged gate bytes against `EXPECTED_RUNTIME_GATE_SHA256`, supplied independently of the gate, bootstrap and candidate package. After that guard, the only supported executable prefix is `/usr/bin/env -i PATH=/usr/bin:/bin:/usr/sbin:/sbin LANG=C LC_ALL=C "$APPROVED_RUNTIME_GATE"`; inherited `DYLD_*`, `DEVELOPER_DIR`, `PYTHON*`, and other variables are absent before the native gate is loaded. The gate accepts a protected bootstrap source path and independent digest before `--`; its command shape is:

```text
/usr/bin/env -i PATH=/usr/bin:/bin:/usr/sbin:/sbin LANG=C LC_ALL=C \
  "$APPROVED_RUNTIME_GATE" \
  --bootstrap-source "$APPROVED_BOOTSTRAP_SOURCE" \
  --expected-bootstrap-sha256 "$EXPECTED_BOOTSTRAP_SHA256" -- plan|apply <approved CLI arguments>
```

The separately approved gate is root-owned, nonwritable, ACL-free and protected through every ancestor; it is outside the candidate stage and is installed create-only. The first delivery compiles the direct `/Library/Developer/CommandLineTools/Library/Frameworks/Python3.framework/Versions/3.9/bin/python3.9` path, Python3.framework identity, exact executable/framework CDHashes, Apple anchor plus `com.apple.python3` requirement, and fixed dependency allowlist into that gate. A CLT update or changed identity requires a new gate artifact and fresh independent digest approval. The candidate plan cannot select or relax this expected identity.

The gate retains nofollow descriptors for the fixed runtime, framework and ancestors; validates regular-file/directory types, owner/group/mode/link-count, same-descriptor native ACL, filesystem provenance, and path identity; and performs strict Apple executable plus deep framework/resource signature verification with the fixed system verifier. Because Apple signature validation is path-based, it rechecks retained-descriptor metadata and each resolved name immediately after verification and immediately before `execve`. It then directly starts the fixed Python executable with `-I -S -B -c <captured bootstrap bytes>` and an allowlisted clean environment. This limits nonroot path substitution under immutable root/system ancestry; it is not atomic against a concurrent trusted-root mutation or operating-system update.

The native dependency policy checks the exact `LC_LOAD_DYLIB` closure of the direct runtime, Python3.framework and the 15 bootstrap-imported native modules `_blake2`, `_bz2`, `_ctypes`, `_fcntl` (`fcntl`), `_hashlib`, `_heapq`, `_json`, `_lzma`, `_posixsubprocess`, `_sha3`, `_struct`, `grp`, `math`, `select` and `zlib`. The `fcntl` extension was inspected in the Python 3.9 test framework and loads only `/usr/lib/libSystem.B.dylib`, already in the OS allowlist; Runtime must confirm that exact module identity/closure under the pinned CLT path. The only non-framework install names observed are `@executable_path/../Python3` (resolved under the pinned framework), `/usr/lib/libSystem.B.dylib`, `/usr/lib/libbz2.1.0.dylib`, `/usr/lib/libffi.dylib`, `/usr/lib/libssl.46.dylib`, `/usr/lib/libcrypto.44.dylib`, `/usr/lib/liblzma.5.dylib`, `/usr/lib/libz.1.dylib`, `/System/Library/PrivateFrameworks/TrustEvaluationAgent.framework/Versions/A/TrustEvaluationAgent`, `/System/Library/Frameworks/CoreFoundation.framework/Versions/A/CoreFoundation`, and the runtime's `LC_LOAD_DYLINKER /usr/lib/dyld`. Unknown or additional names block; the policy is an exact list, not a path-prefix allowlist. The gate's fixed `dependency_policy_id` selects this compiled closure and it verifies the sorted actual load-name set before startup. On the observed host, the `/usr/lib` names are supplied by the dyld shared cache rather than ordinary per-library files. The gate does not claim per-library descriptor or signature attestation for those entries; it explicitly relies on the currently booted trusted Apple OS, system volume and dyld shared cache. If that platform trust assumption is not accepted, installation is blocked rather than broadening the allowlist.

For Python transport, the gate emits one canonical, closed-schema JSON attestation of at most 4096 bytes through a pipe inherited at fixed FD 3; FD 3 is a compile-time constant, not an argument or environment selector. The record has exactly 23 lexically sorted keys and all values are strings: `apple_anchor`, `bootstrap_sha256`, `dependency_policy_id`, `framework_cdhash`, `framework_dev`, `framework_ino`, `framework_mode`, `framework_path`, `framework_resource_seal`, `framework_uid`, `os_build`, `policy_id`, `requirement_id`, `runtime_arch`, `runtime_cdhash`, `runtime_dev`, `runtime_ino`, `runtime_mode`, `runtime_path`, `runtime_uid`, `runtime_version`, `schema_version`, `system_volume_trust`. The fixed values are `apple_anchor=apple`, `dependency_policy_id=clt-python39-apple-dyld-v1`, `framework_path=/Library/Developer/CommandLineTools/Library/Frameworks/Python3.framework/Versions/3.9`, `framework_resource_seal=valid`, `policy_id=clt-python3.9-v1`, `requirement_id=com.apple.python3`, `runtime_path=/Library/Developer/CommandLineTools/Library/Frameworks/Python3.framework/Versions/3.9/bin/python3.9`, `runtime_version=3.9`, `schema_version=oasis7.local-signer.runtime-attestation.v1`, and `system_volume_trust=current-booted-apple-os`. The compiled runtime CDHash is `77e5dcc021cbfa7e2c3940b5ea150e3da037f3cf`; the framework CDHash is `a43551195b8d2eefd9356d81c1098ffc9e0a8b47`; both must match exactly. Runtime and framework UID are decimal string `0`; device and inode values are positive canonical decimal strings; mode fields are canonical decimal strings encoding full `st_mode`; `runtime_mode` must describe a regular executable with owner-execute and `framework_mode` the expected directory/code object; both must be UID 0, ACL-free, and have no group/other write bits, with set-id and sticky bits rejected. Exact observed modes are plan-bound and must match on apply/repeat. Architecture is `arm64` or `x86_64`; the bootstrap digest is 64 lowercase hex; CDHashes are 40 lowercase hex; and `os_build` matches `[A-Za-z0-9._-]{1,128}`. Serialization is compact UTF-8 JSON with ASCII-safe values, lexical key order, and exactly one final LF; Python rejects duplicate, extra or wrongly typed fields, canonicalizes again, and requires byte equality. The gate emits no self-reported gate hash. The record is transport, not cryptographic proof: trust comes from independent gate/bootstrap approval and the protected invocation path, and there is no protection claim against a root attacker.

The gate creates the pipe, writes the canonical record, closes its writer, maps the read end to FD 3, clears close-on-exec for that descriptor, and closes other unexpected descriptors before `execve`. At bootstrap entry, before opening candidate-stage paths, Python requires FD 3 to be a FIFO with effective-UID ownership and read-only `F_GETFL` access, reads through EOF with a 4097-byte cap, rejects records over 4096 bytes, and closes the descriptor. Python rejects duplicate, extra, non-string, noncanonical or mismatched fields; it checks fixed values against gate-policy literals and dynamic values against the running process and descriptor facts. It verifies `sys.executable`, Python 3.9, `isolated=1`, `no_site=1`, `dont_write_bytecode=1`, and only absolute stdlib paths under the pinned framework. Missing, malformed, oversized, mismatched or unreadable evidence blocks before package capture and before `_bootstrap_execute`. Plan observations record this identity and bootstrap digest. Apply compares the fresh attestation with its approved plan before effects; complete-repeat does the same before installed-state readback and `VERIFIED_UNCHANGED`.

Installation `oasis7.local_signer_installation.v3` preserves M0 top-level binding fields; callers become exact `{uid,work_dir,work_device_id,work_inode}`. Device/inode values come from retained descriptors after creation. v2 is rejected; no fallback to store/work. ## 7. 状态、事务与持久化

The protected journal progresses intent → identity → layout → release → binding → validated → sudo → complete, fsyncing data and parent directories at each boundary. Account/directory creation cannot be atomically rolled back as one transaction; failure explicitly exposes partial effects. Lock prevents concurrent applies. The complete journal/receipt binds the original manifest, bootstrap and plan digests, attested runtime identity, installation/deployment identity and resulting protected filesystem/account identities. Complete-repeat requires the same original approved plan and release plus fresh runtime-attestation equality and full readback of code/config/store/jobs/account/ACL/sudo metadata and initial unready state; installed observations are expected to differ from pre-install absence, so this branch does not regenerate a fresh pre-install plan. Receipt alone is insufficient. Partial journal, missing receipt, foreign state or any readback drift returns RECOVERY_REQUIRED/BLOCKED without repair. Existing enabled policy, keys, grants or unknown installation block first-install apply.

Source files use nofollow regular-file descriptors with nlink=1; hash and copy the same bounded bytes. Destination operations use trusted retained parent descriptors, create-only writes and atomic publication. Recheck identity/ownership/ACL at use; replacing a parent or approved binary fails closed. Package output is create-only; release identities cannot overwrite prior versions. Jobs leaf is caller-owned 0700 and bound by device/inode; Runtime retains its descriptor while accessing jobs.

## 12. 决策、长期风险与未决问题

The following retained path-scoped contract conflicts with the broad mount-inventory wording in §8. This documentation normalization preserves both and records the unresolved decision; it does not authorize a new admission policy, platform exception or host action.

Host filesystem admission is path scoped. Retain nofollow descriptors for the root and every existing component of config, code, store, journal, sudo and caller jobs paths. Darwin `fstatfs64` on those descriptors must report local APFS/HFS with ownership enforcement; remote, autofs, unknown and `noowners` target filesystems are rejected. An unrelated system `auto_home` mount is not an installation dependency. Recheck pathname/descriptor metadata and filesystem identity before returning observation; an absent component must remain absent. These filesystem facts are included in the approved plan identities and are reobserved before apply. Concurrent trusted-root mutation remains excluded.

The approved external caller jobs layout is `/private/var/db/oasis7-local-signer-jobs` (root:wheel 0711), an exact caller-owned 0700 child, then the installer-created caller-owned 0700 job leaf. The operator must qualify the exact caller UID/GID and approve parent provisioning separately before host plan/apply. Do not remove the home ACL or change HOME/Documents permissions to enable traversal. Source approval alone does not create these host paths.

The separate native gate, external bootstrap, and candidate release require independent digest inputs; none authenticates a publisher, and the candidate manifest does not authorize the gate or expected CLT identity. The native gate is not included in the candidate release manifest. Approved package staging under `/private/var/db/oasis7-local-signer-approved/<release-id>` is a separately authorized administrator operation preceding installer startup; it is distinct from the protected gate/bootstrap trust path and final executable release directory. Apple static code verification is path-based; descriptor and pathname rechecks under protected root-owned ancestry prevent unprivileged substitution but do not provide atomic signature-validation-to-exec against a concurrent trusted-root mutation or OS update. The exact allowed `/usr/lib` dependencies are dyld shared-cache install names on the observed host, not ordinary per-file objects that this gate independently opens and signs. Their acceptance explicitly trusts the currently booted Apple OS, system volume and dyld shared cache; no per-library descriptor/signature proof is claimed. If this platform trust assumption or root-mutation boundary is not acceptable, installation blocks pending a stronger platform primitive. Actual macOS ACL semantics, shell approval custody, account and sudo behavior still require separate operator/host acceptance. Broader caller privilege or unsupported Python/OS tools blocks installation rather than expands permissions. External communication/runbook review includes LiveOps under the repository role contract. Source delivery completion does not authorize a host apply.
