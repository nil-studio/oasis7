# Viewer 音频制作与验收手册

本手册服务[音频内容与交付设计](viewer-audio-content-delivery.design.md)，分别核查设计、实际声音、消费者和真实平台。步骤和用例不是执行结果；没有音频素材或播放器时，只能记录设计审阅，不能把下面的方法标为运行通过。新文案和听感仍需独立审校。

普通文档变更沿[测试选择树](../../../testing-manual.md#testing-default-selection-tree)执行适用文档检查，不因此启动游戏、付费模型、音频录制或真人招募。实际采用时沿原任务授权选择既有测试和 [S6 浏览器闭环](../../testing/manual/web-ui-agent-browser-closure-manual.manual.md)；本手册不改变原入口、账号、环境或发布限制。

<a id="audio-validation-cases"></a>
## 1. 验证层级与输入

| 层级 / 方法 | 输入与执行目的 | 可以得出的结论 |
| --- | --- | --- |
| AU-STATIC / AU-EVENT | 固定产品/专业设计、所审源码、事件与反例 | 设计是否有来源、语义与边界缺陷；不能证明播放 |
| AU-ASSET | 实际生成器、配方版本、三份参考文件与试听设备 | 声波是否符合规格、试听发现了什么；不能证明游戏实际消费这些内容 |
| AU-STATE | 实际门控/适配代码、可控时钟与成功/失败/迟到的音频替身 | 本地状态、抑制、释放和零世界副作用；不证明浏览器权限或耳听体验 |
| AU-RUNTIME | 同候选实际 Web 或 native 世界窗口、输入身份、声音内容和输出设备 | 该组合的真实播放、暂停/关闭、失败与长时表现；其他平台分别验证 |
| AU-EQUIVALENCE | 同一实际候选的默认静音/开启/零音量/不可用，双语与目标 viewport | 关键事实和操作是否等价、控件是否可读可操作；机器检查不代签真人理解 |
| AU-CANDIDATE | 原构建身份、实际消费者、内容与平台 | 本次到底采用了哪份内容、验证了什么；不自动升级为发行就绪 |

记录本次 source/实际 tested tree、设计与内容版本、生成器和 bundle/安装包身份、原请求/世界输入及所用环境。真实请求标识按原证据权限保留，公开摘要不附带 Key、Prompt、私聊、完整 scope 或其他玩家数据。没有所需环境、设备或真实适配时，注明受影响用例和原因；未执行不填通过。

<a id="audio-static-review"></a>
## 2. AU-STATIC：来源、适用表面与交付范围

先读[产品声音要求](../../product/agents-world-simulation/player-readable-surface-continuity.prd.md#req-agent-surface-006)、[当前源码基线](viewer-audio-content-delivery.design.md#audio-current-baseline)和[事件合同](viewer-audio-content-delivery.design.md#audio-event-contract)，逐项核对：

1. Web、native 世界窗口、离线回放、Launcher、官网、工程控制台与 `pure_api` 各有准确边界；native 候选沿原 WebView authority，不用已有 Launcher 配置窗口冒充世界窗口。
2. 短功能提示、音乐、环境循环、空间声和语音分别有采用决定与理由；不以“暂无音频文件”推导整个领域不适用。
3. 每个 E01～E03 都有实际或明确待实现的消费者、必要事实、当前原操作关联、声音键及完整文字；没有从原始世界事件和错误关键词直接驱动声音的旁路。
4. S00～S02 的 v1 配方、三个参考产物、设置正文和实际生成器分开标识；未制作的文件没有虚构路径、hash 或“已可用”状态。
5. 来源审查只覆盖实际读过的路径和基线，不由关键字零命中宣称全部部署无声音。代码或设计改动后重新追消费者，不只更新日期。
6. 需求承接与验证映射逐条匹配；当前设计上游的文件和锚点、原控制面 authority、手册内用例锚点可解析。

可在候选仓库读取下列真实来源，命中仅帮助定位，不能代替审读；关键词未匹配时 `rg` 返回 1，不表示已经完成全游戏审计。

```bash
git rev-parse HEAD
rg -n 'AudioContext|OscillatorNode|AudioBuffer|speechSynthesis|speechRecognition|bevy_audio|\.ogg|\.wav|\.mp3' \
  crates/oasis7_viewer/software_safe_src \
  crates/pixel_world_bridge/src \
  crates/pixel_world_bridge/Cargo.toml \
  crates/oasis7_viewer/package.json \
  crates/oasis7_client_launcher/src \
  site/assets/app.js
rg --files crates/oasis7_viewer crates/pixel_world_bridge crates/oasis7_client_launcher site \
  | rg '\.(wav|ogg|mp3|flac|aac|opus|m4a|webm)$'
```

独立审阅至少追两条完整路径：当前原操作的可信结果到声音/文字，以及身份已变后旧结果到无声音/无错误归因。手算配方和静态推演的事实写在实际 PR，不建立第二份长期执行记录。

<a id="audio-event-cases"></a>
## 3. AU-EVENT：事件语义与负例

先在设计层对下表推演，再在真实接入的原反馈适配边界验证。输入用当前专业 authority 的真实字段和已有受控测试能力，不能仅把测试名或字符串 `success` 送进声音函数。播放器替身只能观测候选和调用；身份、请求匹配与原结果语义仍须由原消费者检验。

| 用例 | 刺激与关键前提 | 必须观察的声音和原界面结果 |
| --- | --- | --- |
| AE01 显式试听 | 默认进入后不操作；再明确开启并试听 | 初始零声音、零音频上下文；成功开启只播一次 S00，说明为本地试听；零世界提交、查询和模型调用 |
| AE02 已受理与预检 | 当前请求签名/发送、ACK/received/accepted/pending；另给只读预检通过 | 无 E02/E03；原文字保持各自阶段，不把排队或检查表示为执行 |
| AE03 可信处置 | 当前同身份/世界/原请求的实时权威处置已被原消费者接纳并展示 | 仅一次 E02/S01；文字保留处置与实际效果差别。首次认领的 committed 若仍待世界同步，不显示已拥有 Agent |
| AE04 可信拒绝 | 当前原请求的明确拒绝、阻塞和到期分别输入 | 仅一次 E03/S02；不同时产生 E02；原因与修正/等待/停止仍可读 |
| AE05 结果未知 | 超时、断网、缺回执、查询 Unknown/HistoryUnavailable 和查询权限失败分别输入 | 无声；保持未知/受阻与原查询路径，不把查询错误写成原操作拒绝，不重发世界请求 |
| AE06 模式不支持 | 当前模式不支持，另叠加连接中断 | 不借连接恢复产生声音成功感或行动能力；若原当前请求已被权威明确拒绝，仍按 E03，只能说明原拒绝 |
| AE07 重读与恢复 | 初始化快照、重新开启、重连、恢复胶囊、历史查询、Seek 或离线播放包含既有 committed/rejected | 无 E02/E03；可读结果保留真实语义，不补播声音 |
| AE08 重复与迟到 | 同结果重复投递/渲染；旧 ACK 在可信终态之后到达；后续请求已替换当前反馈 | 同等待实例至多一次提示机会；旧结果无声，不改变新操作的声音资格/等待状态 |
| AE09 多玩家隔离 | A 当前等待时 B 或匿名连接失败；再切换 B，A 旧结果到达 | 无跨身份提示和私有文字；A 的回调不能给 B 的提示消耗/恢复资格 |
| AE10 世界与绑定 | 相同请求标识出现在其他世界、原绑定失效、分支/fence 变化或世界切换 | 旧资格失效，旧声源停止；没有用请求字符串相同推当前归属 |
| AE11 无稳定关联 | legacy 输入缺原请求/等待实例或当前可读文字未建立 | 静音并保留现有可信文字，不人为补世界字段或借颜色猜结果 |
| AE12 非当前动作 | 自主 Agent 行为、公共事件、tick、地形/设施动画、Chat accepted、Prompt 已应用、模型检查或报价完成 | 不进入本白名单；既有文字仍按各自 authority 更新 |
| AE13 身份变化的竞争 | E02 已形成但未启动时撤销/切身份/换世界；随后初始化或调度回调完成 | 零旧声音；回调只清理旧资源，不恢复开关或把旧 cue 接到新上下文 |

分别记录原输入分类、实际接纳路径、文字与声音期望、实际触发次数、被抑制原因及候选身份。只能看到声音函数被调用却无法定位真实 producer 的测试，不足以判定 E02/E03 的真实语义已接入。

<a id="audio-asset-check"></a>
## 4. AU-ASSET：配方、声波与试听

当前设计没有已生成素材；实际制作后逐种核查：

1. 将编辑配方版本与生成器 source、作者/来源及适用许可关联。三个键均为原创程序化正弦提示时明确无录音采样；若换入录音、模型生成声或外部样本，保留实际来源、使用条件、署名与复用许可，不能由根 LICENSE 自动推定。
2. 三份参考文件分别为 48 kHz、单声道、24-bit PCM WAV。S00/S01/S02 帧数分别为 7,680 / 12,480 / 20,160；时长分别为 160 / 260 / 420 ms。文件头的采样率、声道和编码必须与实际数据一致。
3. 对波形计算峰值、均值与首尾包络：每个脉冲首尾 20 ms 淡变，绝对峰值不超过 0.10 满刻度；无截波，首尾及静音间隔样本为零，全段样本均值绝对值不超过 0.0001 满刻度。分析应注明窗函数/舍入容差；参考 24-bit 量化允许单个样本不超过 1 LSB 的舍入差，不据此放宽错误时长或音量。
4. 用时域包络和频谱核 660 Hz / 440 Hz、脉冲数量、间隔和持续时间。测试预期取自设计配方，不从被测生成器重新导出同一参数表当断言。
5. 运行合成在实际设备采样率上核同一声学参数；不要要求它与 48 kHz 参考文件逐字节一致，也不要以播放参考 WAV 代替实际生成器接入。
6. 独立试听 S00、S01、S02，打乱顺序。记录是否可区分、是否刺耳/突变、是否让人误以为“世界成功/获得奖励”、重复提示是否烦扰。没有受测听者和环境记录时，只能称作者试听，不能称玩家理解通过。

试听从较低且可自行调整的系统/应用音量开始；记录设备、浏览器/WebView、实际应用音量和环境。数字峰值不代表耳边声压，不需要采集听力或其他健康数据。玩家可自行停止；不以继续听完作为游戏或测试任务要求。

若辨识度或含义失败，声音 owner 修配方、文字或事件归属，再对同版本三种提示重验；不得只提高音量、改成循环警报或用音调承载新的独占信息。

<a id="audio-state-cases"></a>
## 5. AU-STATE：受控状态、优先级和资源

实际播放器接入时，用受控时钟与音频适配替身验证以下独立情境。替身能控制初始化成功/拒绝/不返回、音频状态中断和迟到完成；断言覆盖门控与真实反馈消费者，不只测试一个同名枚举函数。

| 用例 | 执行方法 | 判据 |
| --- | --- | --- |
| AS01 默认与零音量 | 新实例不点设置；开启并播放提示时把音量设 0，期间到达 E02；再恢复音量；另在零音量期间失活后提高音量 | 默认零上下文/零声音；零音量时停止当前及待启动节点，丢弃期间提示且界面标静音，可保留同一上下文；提高音量不新建上下文、不试听、不补播，新事件才重新评估；已暂停时仍须显式恢复 |
| AS02 音量与关闭 | 播 S02 中调整音量、关声；在淡出/停止前后到达回调 | 平滑变化不超过设计范围；关闭后旧节点不重启，原文字和操作不受影响 |
| AS03 初始化并发 | 重复点击开启/试听，初始化未返回 | 至多一个上下文和一个初始化尝试；按钮状态可读，重复操作不积压多次试听 |
| AS04 初始化超时 | 第一次尝试超过 2 s；切关声或重试后旧成功返回；另令旧关闭结果未知 | 旧代次只清理；没有旧试听、第二个并存上下文或无限自动重试；未确认旧关闭时保持不可用 |
| AS05 失活 | 可用时 blur、隐藏或最小化，期间生成结果，再回到窗口 | 旧节点停止、状态暂停；聚焦不自动补播，显式恢复只试听 S00 |
| AS06 身份和世界 | 当前播放或等待中切身份/世界；同身份连接代次失效 | 前者默认关闭/音量 25，后者暂停并清旧资格；均无旧声和旧原操作继承 |
| AS07 设备与资源错误 | 创建/恢复/合成/输出分别拒绝或异常 | 保留原文字、动作和查询；状态不可用，有显式本地重试；无系统警报/外部播放器替代 |
| AS08 终态与重复 | 一次 E03 后重复结果、组件重渲染、原 scope 未变的表面重排 | 同等待实例只有一次机会；被限频或静音抑制也不重置机会 |
| AS09 同批竞争 | 同次更新产生 E01/E02/E03；再分别制造同优先级和高优先级到达 | 最高优先级胜出，最多一种提示；低/同优先级丢弃，有额度的高优先级先停旧再启新 |
| AS10 滚动速率 | t=0 和 t=1 s 启动两次；t=4.999 s 再请求；t=5.001 s 给新的有效事件 | 任意 5 s 窗口不超过两次；t=4.999 s 丢弃不排队，后续只有新事件按额度判定 |
| AS11 过期候选 | 候选形成后冻结调度超过 200 ms，或淡出期间 scope 改变 | 丢弃过期/失效候选，不靠恢复 event loop 补响；原反馈继续可读 |
| AS12 销毁 | 挂载/开启/发声/卸载反复执行，保留旧 Promise 后再返回 | 节点和旧引用释放、旧代次无效；重新挂载默认关闭，不保留队列或旧声音设置 |

资源断言至少包含上下文数量、活动节点数量、当前候选/等待实例数量、初始化并发数和两个滚动启动时刻。退出后不能只断言“UI 不见了”；必须核音频资源及迟到回调。任何 localStorage、网络查询、世界提交或模型调用都不是声音设置的预期副作用。

<a id="audio-runtime-cases"></a>
## 6. AU-RUNTIME：实际 Web/native 播放

只有实际声音消费者与设置已进入同一候选，且具备原任务授权时执行。本手册不要求为文档 PR 启动 Runtime，也不为试听制造付费模型或真实经济动作。优先复用当前已授权、可控的反馈场景；缺真实权威结果时把 AE03/AE04 的真实集成留为未验证，不用 DOM 手改成功状态冒充。

记录 OS/架构、浏览器或 WebView 引擎/版本、构建、viewport/DPR、输出设备和实际应用音量。Web 与 native 每个声称支持的组合独立执行；native 需为同官方 build 的世界窗口。真实页面在正常自动播放策略下运行，不使用禁用策略的启动参数获得通过。

1. 新建当前测试实例，先观察初始静音和设置状态，再明确开启。核首次试听说明、实际可闻声与可读状态；适配可用但系统设备静音时，不让页面宣称“已经听到”。
2. 开关、音量、试听和恢复使用指针与键盘各操作一遍。比较应用音量 0/25/100；实际试听由受测人选择适宜的系统音量，不改其他应用或系统音量来假装应用开关有效。
3. 对合法实时结果和拒绝执行 AU-EVENT；同时核等待、未知、重连、历史回读、语言切换都不播放新的结果提示。只能确认世界结果真实来自当前原请求时，才写真实集成通过。
4. 播放中切标签页/窗口、最小化、离开 Viewer；重新进入时核无旧提示。native 核宿主失活、最小化和关闭的真实生命周期，不仅在 Web 文档上手动触发事件。
5. 在隔离测试环境改变浏览器允许播放条件或用实际可用的设备断开/中断方式；不改个人系统安全策略。若环境无法形成某失败，记录缺口，受控适配测试只承接其自身层级。
6. 普通提示和停止各至少采 30 次，记录调度起点、实际可观察输出、末尾停止及 outlier。输出/耳听延迟没有可靠采样方法时写未知，不能把 Promise resolve 或图标改变当 audible 起点。音频录制需要原测试授权，且不得夹带私聊/麦克风内容。
7. 在原 Viewer 负载下持续 30 min，反复开启/关闭/失活、断连和恢复。比较静音与开启时的输入响应及音频资源变化，确认无连续 1 s 交互无响应、无未释放本专题节点或旧提示；不把 JS heap 单独当全部宿主资源。
8. 关闭音频或回退静音候选后，原目标、拒绝、未知结果查询和合法操作仍完整。声音组件移除不能使原反馈渲染或原请求恢复依赖缺失。

失败按来源分为内容/配方、触发归属、设置状态、平台适配、设备/环境或验证缺前置，修实际所属职责；不要把所有问题归为“浏览器不支持”。

<a id="audio-equivalence-cases"></a>
## 7. AU-EQUIVALENCE：静音、双语与可访问性

使用同一实际候选和同一原事实，分别在默认关闭、可用、音量零、暂停、不可用下检查。声音只是可丢弃的提醒，原事实不能随这些模式变少。

| 检查 | 方法与通过判据 |
| --- | --- |
| 原事实完整 | 对 AE03、AE04、AE05 分别指出原行动/对象、真实状态或未知、原因/阻塞、当前可行下一步；没有声音也能找到它们 |
| 零独占语义 | 检查帮助、提示和教程没有“听到两声即已成功”等仅靠音调的指令；声音不披露文字无权读取的对象或结果 |
| 双语 | 中英文的开启、试听、静音、暂停、不可用和恢复含义一致；尤其核“当前会话”“本地试听”“不会执行游戏操作”和音量 0 文案 |
| 键盘与焦点 | 用 Tab/方向键/Enter/Space 操作语义控件；标签、当前状态、音量和值域可读，有可见焦点；停止/重试不会意外把焦点移到提交世界动作 |
| viewport 与文字 | desktop、窄屏、低高度、200% 文字分别找到关声和原决策入口；不靠隐藏标签、图标或 hover 解释状态 |
| 减少动态效果 | 开启系统减少动态效果后保持原文本；不会用自动发声补偿被减少的动画 |
| 辅助技术 | 在实际声称支持的屏幕阅读器/浏览器组合核声音设置名称与值；原反馈不因同时发声而重复新增一份 live 播报 |
| 副作用 | 开关、试听、暂停/恢复不改变世界、原请求或读取资格；设备失败不触发世界重试或模型调用 |

真人理解验证沿[首局真人试玩手册](../../testing/manual/first-session-human-playtest.manual.md)，只选实际采用音频的同候选且沿原招募/同意安排。可加入两个开放任务：“不听声音时如何判断这次操作的结果？”“听到提示后，你认为发生了什么，依据在哪里？”记录原话和实际行为，不先教受测人把 S01 当成功，不用作者解释代替首次理解。只有静态审阅或模型推演时，不声称真人理解通过。

## 8. AU-CANDIDATE：交接、变更与回退

沿原 PR/构建记录关联下列实际对象，不另造全仓声音台账：

- 采用的产品/专业条款、S00～S02 内容版本和中英文文案版本。
- 实际生成器 source、三份参考文件及来源/许可资料；无文件时明确“未制作”。
- 原反馈消费者、门控、设置和 Web/native 输出适配的真实代码位置；待实现的路径不写成已存在链接。
- 实际 source、tested tree、Viewer bundle 和 native 安装包身份，使用的 OS/浏览器/WebView/设备，以及各层执行结果。
- 当前失败、未执行场景与回退方式；证据中不复制私有 scope 或凭据。

变更频率、时长、音量/包络时重验 AU-ASSET 和实际试听；变更触发条件、身份或原请求关联时重验 AU-EVENT/STATE 及对应真实入口；变更设置和文案时核静音、双语、键盘与布局；更换浏览器/WebView 或输出适配时按实际平台重验生命周期和失败路径。没有触达的原世界规则不由音频回归重新验收。

回退至静音行为后核原文字、操作和查询仍在，所有旧声音节点与回调已失效；不能把已经听到的错误提示说成已撤回，也不能为音效回退重放或撤销世界操作。详细执行、修复和清理事实留在该 PR/Task，长期设计只保留有效合同和方法。
