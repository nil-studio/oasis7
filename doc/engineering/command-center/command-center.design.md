## 1. 问题、目标与非目标

指挥中心的主要入口是 ChatGPT Sites 浏览器工作台。Worker 在服务器端读取 GitHub 已提交文档、PR 与有界 CI 摘要，生成总览、工作、规范与决定、待我处理四个一致视图；D1 是个人决定、问题、显式关系、阅读位置和偏好的单一写入权威。用户在另一台设备登录同一 Site、选择同一项目与环境后，读取同一批已保存个人记录，不依赖某台开发机在线。

GitHub、正式文档和原工具继续拥有其来源事实。云端工作台只读来源并保存个人记录；开发执行仍在原 Codex，CI 详细日志、重跑与其他写操作仍在原 GitHub。只读 CI 摘要必须保留准确工作/检查身份、tested commit、事件时间与覆盖，不能由“已合入”或“检查成功”推导部署、验收或目标完成。

本机 Tauri/Rust 辅助端只承载设备、工作树、Git/CLI、signer、本地未提交材料和私有资料等能力。用户可从辅助端打开浏览器中的云端工作上下文，或从准确导航入口进入原工具；云端不扫描本机、不建立设备配对、远程命令队列、后台任意命令桥或隐式上传通路。已有外部调度和执行系统仍由其原 authority 管理，本工作台不另造调度器。

## 2. 上游约束与相关角色

产品负责人维护用户承诺及范围；系统实现维护领域、授权、存储和生命周期；接入实现维护 GitHub 的版本、覆盖及外部定位边界；验证工作覆盖浏览器、真实云端持久化与适用本机行为。角色描述用于定位专业责任，不新建强制串行交接。

已有仓库与外部来源保持事实所有权。工程工具沿 engineering 专业域组织，产品四域、现行规范主责、Issue 可选和实际 PR/CI 交付方式不变。Sites 的托管身份和数据库能力是部署依赖，应用必须实现本文的 scope、事务、内容与恢复合同；平台提供某项能力不证明本产品已完成相关验证。

## 4. 边界与结构

<a id="DES-CC-001"></a>

### 4.1 App、核心与外部来源

Trace refs: O7-REQ-6e70287f-a156-4544-997d-5c1752e5efde；承接[REQ-CC-001](command-center.prd.md#REQ-CC-001)。

| 组件 | 拥有的职责 | 读写边界 |
| --- | --- | --- |
| Sites 浏览器 UI | 四视图、文档树、统一工作详情、个人编辑、阅读与导航 | 调用同源受限 API；本地状态只是最后成功快照或未提交草稿，不能宣称已云端保存 |
| Worker 应用层 | 可信身份核对、project/environment/scope 授权、来源读取、共享投影、个人事务和导出恢复 | 不执行本机命令；不接受客户端 owner、任意 URL、任意 SQL 或来源文本指令 |
| D1 | 个人记录/不可变修订/幂等结果；与之隔离的可重建来源缓存 | 个人数据单一写主库；源缓存重建不修改个人数据；数据库提交后才返回保存成功 |
| GitHub/原工具 | 正式文档、PR/CI 及各自实际执行事实 | 云端通过受限 HTTPS adapter 读取；写操作与执行返回原工具 |
| 本机 Tauri/Rust 辅助端 | 设备/工作树/CLI/signer、本地未提交和私有资料、工具操作账本 | 使用本机有限 IPC；云端核心页面在系统浏览器打开，远程页面不取得 Tauri IPC 权限 |

云端 `Project` 由稳定项目 ID 与经核实的 provider/host/repository ID 标识，仓库名称和 URL 是可更新属性。用户显式选择 `environmentId` 与 `scopeId`；环境是阅读与个人记录的适用上下文，不证明该环境已部署、在线或可执行。不同项目、环境或阅读 scope 不因同名、同分支或同 remote 自动合并；改变查询窗口不改变个人记录归属。

本机 `LocalProjectRef` 独立保存设备、规范化工作树、`git_common_dir` 与本机环境身份；同仓不同 clone/worktree 不自动合并本机资料或私有库。用户可在本机核对它与云端项目的准确导航关系，导航只带允许公开的项目/工作标识，不上传路径、凭据、资料或 dirty 内容。路径失效只影响本机定位，不能改变云端项目、owner 或权限。

### 4.2 代码落点与职责

最终模块按职责分界，不要求同一语言跨运行时共享源码；共享领域语义、序列化合同和验收反例。云端文件组织由 Site 工程维护，下列是职责，不声称本仓库已有对应云端文件。

| 落点 | 最终职责 |
| --- | --- |
| Site UI / 同源 API | AppShell、四视图、工作详情、文档阅读、来源检查与有限个人操作入口；页面不自算另一套完成/关注状态 |
| Worker 来源 adapter | 固定 provider/repository 的 HTTPS 文档/PR/CI 读取，提交版本、coverage、分页、超时和失败；不决定目标完成 |
| Worker 领域与投影 | Goal/Rule/WorkRef、显式关系、问题和决定的语义；一次组合 Home/Work/Attention 投影 |
| Worker 个人存储层 | scope 授权、CAS/幂等、不可变修订、阅读偏好、原子导出/恢复与错误合同 |
| `tools/oasis7-command-center/core/src/` | 本机文档/Git/工具读取及本机操作；保留适用的原始工具存储与兼容，不再作为云端个人数据第二写主库 |
| `tools/oasis7-command-center/src-tauri/`、`ui/` | 目录选择、菜单栏、有限系统导航、可信本机界面和工具退出保护 |
| 契约/fixture 与真实环境测试 | 来源身份、版本、分页、个人事务和导航的跨层反例；云端持久化与本机副作用分别验证 |

本机应用保持独立 Cargo workspace、锁文件与当前 Rust/Cargo 缓存约定，不为云端浏览器部署引入模拟器、游戏 Agent 协议、Viewer 依赖或生产本机 HTTP 服务。

### 4.4 共享呈现投影与查询边界

Trace refs: O7-REQ-a6126ad0-2f2d-47ad-a504-5e9ceff92cff；承接[REQ-CC-005](command-center.prd.md#REQ-CC-005)。

## 5. 关键运行流程

<a id="DES-CC-004"></a>

### 5.1 打开项目、索引规范与记录决定

Trace refs: O7-REQ-eb004bfb-41c7-4e8f-aa5b-1f52cec6cf08；承接 [REQ-CC-004](command-center.prd.md#REQ-CC-004) 的适用义务。

浏览器先经平台登录和应用 scope 校验，再恢复用户最后选择的项目/环境与已保存阅读位置。没有已授权 scope 时显示选择入口，不通过 URL、旧浏览器状态或缓存猜测个人归属。Worker 返回该范围最后成功来源与个人记录，独立标明读取、旧结果和缺口；来源更新不阻塞已经授权的个人编辑。

项目注册的文档入口及[项目地图](../../../skills/oasis7-command-center/references/project-map.md)只提供显式导航，目标读取 core PRD 当前阶段章节，规范效力读取主责身份、范围和替代关系，不按 mtime 排序。一次云端文档读取绑定经核实的 GitHub 仓库与不可变 commit；浮动 main 先解析 commit，树、文件和章节共同声明实际基线。发现新提交使旧来源标为可更新，不静默改写已保存的历史依据。

受限 Markdown parser 产生可定位的标题、段落、表格、代码与链接块；解析语法不自动决定条款效力。已有条款 ID 优先，标题定位须处理重复；行号只辅助跳转。保存原版本引用与可取得内容，历史工作可回到当时条款并找到明确后继。只有真实阅读版本与范围可比较时计算“自上次查看变化”，缺少历史内容或阅读记录时说明缺口。

个人决定保存内容、理由、适用范围及正式文档关联，草稿、确认和替代沿[§7.4](#cc-decision-attention-state)。云端保存成功以原子提交及其 revision 为准；确认时间绑定实际确认的不可变版本，实质编辑生成待确认版本，不能继承旧确认。正式文档修改继续在原工具完成。

本地未提交预览独立由辅助端读取，明确工作树、基线及 dirty/untracked 范围，不与云端正式快照混成一个索引。notify 事件只提示失效，去抖后重读；初次载入、唤醒、聚焦及手动刷新校准，不索引 `target`、`node_modules` 或 Git objects，不用全目录递归监听声称完整一致性。

### 5.2 Git、GitHub 与刷新发布

云端来源 adapter 经注册项目的固定 HTTPS provider/仓库读取。允许的方法、端点、分页、路径、目标主机与重定向均受 allowlist 约束，不接受任意 URL 代理。公开 GitHub 来源可无访客凭据读取；需要额外权限的来源只有在实际授权路径可用时接入，不以平台 service bearer 冒充个人连接器 consent。

PR 保留 host/repository ID/number、HEAD、状态及原 URL；CI 摘要另外保留 workflow/check/run 身份、关联 PR/branch、head/tested commit、实际状态和事件时间。只在可核实对应工作的准确提交时展示为该版本的检查结果；SHA 不匹配、检查未完成、取消、跳过、旧结果及读取范围不全分别显示。详细日志、重跑和其他写入使用原 GitHub 入口，读到成功检查不构成目标验收或部署证明。

列表、显式后续页和已知对象补读使用同一来源身份。截断、未读取、成功空、无权限、404 与真正可核实的删除分别保留；对象缺席不能推导不存在、未合入或关系失效。来源诊断只显示连接、账号/服务来源、范围、补读入口与错误；PR 在统一工作列表/详情呈现，不产生另一套 PR 选择状态。

初始读取预算为每次 HTTP 请求最多 10 秒、单来源尝试总期限 30 秒；列表每页最多 100 项、一次最多 10 页，已知对象补读一次最多 20 个且计入同一总期限。具体 provider 限制更低时采用较低值并返回实际 coverage。到达页数、字节或时间预算返回已读范围、剩余 cursor 与原因；“继续读取”开启有界新尝试，不在后台无限追页。限额保留最近成功事实并显示 retry-after，不忙重试；失败后个人数据仍可独立使用。

一次刷新按“读取候选 → 核对身份/版本/范围 → 事务应用 → 发布 view revision”处理。按 scope/source key 记录 attempt generation，旧 generation 不能覆盖较新结果；失败只更新该来源尝试/错误元数据，不清空成功快照。分页保留各页实际版本/时间和完整度，不宣称整个远端原子快照。切换项目后的晚到结果只能提交其原范围，不能更新当前项目视图。

本机 Git 仅在辅助端以参数数组、明确 cwd、超时和输出上限调用，采用 status `--porcelain=v2 -z --branch`、worktree `list --porcelain -z` 等机器输出，处理空格/换行路径与 detached HEAD。读取不隐含 fetch、切分支、reset、提交或清理；本地远端引用只是最近所知状态，不上传为云端实时事实。

### 5.5 持续状态维护与架构阅读

按[持续更新流程](command-center.manual.md)维护两个派生仓库入口：`command-center/README.md` 承载长期/短期目标、当前进展、近期变化与人工关注；`command-center/architecture/README.md` 承载关键设计与部署索引。两者通过原有文档适配器读取并下钻源条款，不建立第二套任务表、产品权威或部署库存。

来源事实改变后，负责当前工作或回顾的执行者核对影响，在已有授权内维护主责和摘要；普通客户端刷新仅重新读取，不能自行写入仓库、创建 PR、SSH 采样或启动模型。合入后状态在下一次刷新协调，不为每次合入递归生成状态 PR。目标、已合入代码、实际测试、部署、目标验收使用各自来源。

摘要声明的文档基线、来源观测窗口与实际环境核验分别保留。文件索引的 revision/读取时间只说明读取了哪个摘要版本；没有读取其引用的 PR/环境，不能刷新其内部事实时间。原始内容中缺少时间、覆盖或来源时展示缺口，不推测。四区与摘要的呈现合同由 §5.6 和 §9.1 承接，当前实现证据集中见 §3。

架构索引从事项进入原有主责条款，分别展示设计边界、已有实现与实际部署证据。显式后继沿当前已读文档的完整路径与章节定位，缺失、歧义或不安全目标保留具体诊断；索引条目不能仅凭文档 active 或引用关系成为权限、写入权、部署就绪或完成证明。历史清单保留原采样日期，未知环境状态不补造实时拓扑。

### 5.6 首页判断投影

Trace refs: O7-REQ-ce7b612a-3316-4c40-9009-c0d295ff0ed6；承接 [REQ-CC-013](command-center.prd.md#REQ-CC-013) 的适用义务。

Worker 应用层在既有来源快照之上生成 `HomeProjection`，四个区域及默认交互由 [REQ-CC-013](command-center.prd.md#REQ-CC-013) 与[首页布局](command-center.prd.md#cc-home-layout)主责。目标定位沿 core 当前阶段及显式主责引用；状态摘要沿现有稳定章节读取，复用 Markdown 块和链接，而非把文件全文直接放到首页。摘要无法结构化提取时提供该区正文的阅读入口及覆盖说明，保留其他已解析区域；只完成该降级不能宣称首页整体验收通过。

投影中的每个结论分别保留原文定位、源 revision、事实性质、摘要内部核验时间和读取时间。已核实 PR 更新其对应字段，不覆盖主责目标；与摘要冲突时保留双方版本及冲突字段，不用一个“最新时间”覆写整条记录。摘要自己的归纳不升级为运行事实。

首页 grid 子项和内部 grid 单元允许收缩（min-width:0、minmax(0,1fr)），标题、链接及版本使用可换行样式，不以 overflow:hidden 隐藏必要内容。各卡片独立按内容高度排布，避免近期成果拉伸重点产生大块空白。摘要冲突按章节身份与 revision 分组，组内按完整声明去重并保留全部不同 WorkRef；默认折叠，展开显示原声明与每个对应 PR 入口。公共核验边界只出现一次，聚合不修改源状态或个人待办。

重点排序输入只有主责显式阶段顺序、用户已保存置顶及组内来源顺序；缺少优先级时保留并列。下一步引用现有主责或个人选择，分析建议单独带性质且不改变源关系。近期结果按明确 PR/交付身份聚合，保留事件时间和比较基线。待处理投影复用原请求身份和 §5.3 的已处理结果；人工关注、事实缺口和普通提醒分组，观察不全不生成虚构请求。

默认“近七日”为用户时区的今天及前六个自然日，显示具体日期、时区和“今天截至本次观察”。查询固定 timezone、asOf 与换算后的 UTC 半开区间，夏令时按日历边界处理，不能直接减 7×24 小时；用户改变窗口或时区仅重算投影。成果按源 eventAt 倒序，相同时以稳定事件身份排序；按原 WorkRef/事件身份归并重复观察，同一 PR 的提交/检查在其交付结果下展开，不叠加为多个已完成目标。不同真实事件保留各自时间，未知 eventAt 单列“本次观察到，事件时间未知”，不用 fetchedAt/lastReadAt 补造；“自上次查看”只有明确同范围阅读基线时才单独可用。

阅读基线保存实际展示的 WorkRef/事件集合、窗口/cursor、源/view revision 与用户阅读时间；观察到来源和用户已读分别记录。首页只展示三项时不能用一个 `new Date()` 把未展示的分页/截断窗口全标已读；进入其他页后只提交该已展示范围的阅读记录。来源覆盖改变而无法比较时说明缺口，仍可看固定日期成果，不生成完整“自上次查看变化”的保证。

| 分区 | 投影输入与输出 | 缺口/动作边界 |
| --- | --- | --- |
| 当前重点与下一步 | 目标原条款、已核实成果、剩余条件、显式下一动作、关联 WorkRef；默认最多三项，其余可展开 | 无明确排序保留并列；不从 PR 数量推算优先级，不让用户先填写关系才显示可读取目标 |
| 最近成果变化 | 按用户选择的比较窗口、事件身份与适用版本聚合真实结果，链接同一工作 | 同一 PR 的提交/检查/合入不重复算成果；没有事件时间则不伪入窗口，改列“本次新观察到”并说明时间未知 |
| 需要我处理 | §5.3 的仍需用户回答事项与数量，事实缺口和知悉信息分组 | 没有个人问题项可以为空；来源不可用显示该范围未知，不能显示“全部处理完” |
| 返回工作 | 已确认工作关系、用户近期进入位置和未发送草稿存在性 | 不包含私有正文、秘密或私有线程；没有历史时给可读工作入口，不创建空任务 |

`HomeProjection`、`WorkDetailProjection` 和 `AttentionProjection` 从同一已提交来源集合及个人记录 revision 生成，并发布共同 `viewRevision`。各区返回自己的可用/部分/旧结果和缺口，来源集合并非原子远端时刻；一处失败不清空其他区。投影缓存键包括 schema、Site/owner/project/environment/scope、实际阅读基线、来源 revision 集合、个人记录 revision 和比较窗口，缓存缺失可重算。一次保存/处理成功使相关投影失效；旧计算结果提交前须核对全部输入 revision，不能重新引入已处理问题。

项目选择和连接配置只在首次打开或用户展开时占据主要空间；身份、SHA 和诊断按需展开，当前判断受影响的具体缺口直接显示。查询先校验可信身份和 scope，再返回该身份下的最后成功投影及分区状态，并独立校准来源；身份未核实、过期或切换时不展示旧个人快照，不保存到未核实项目。后台全量扫描不作为每次 `query_view` 的前置。

### 5.7 统一工作详情、关联与原工具接续

Trace refs: O7-REQ-fdf061f8-ebdf-46e3-91a5-a2311e2bcb93；承接 [REQ-CC-014](command-center.prd.md#REQ-CC-014) 的适用义务。

Worker 应用层以 §6.2 的 WorkItem 原来源身份构造[统一工作详情](command-center.prd.md#cc-work-detail)。首屏先返回工作目的、当前可核实结果、主要剩余条件和可用下一动作；来源/目标关系、PR、外部定位、个人问题及保存结果作为同一详情的区域。原文、完整SHA、来源身份和读取诊断可展开，不抢占首屏判断。局部关系图消费同一 WorkItem.goals 与未移除个人关系，同章节的个人记录优先（含已移除记录，避免旧投影复活）。节点保留来源/个人确认标签，按 section ID 查找当前原文并比较确认摘要；缺原文不可点击，摘要变化明确提示打开的是当前版本。图仅为关联，不推出工作顺序或验收状态。不同视图只传相同工作引用和返回位置；详情不创建新任务表或将多个源状态压成统一完成值。未产生 PR 的明确会话仍可作为工作入口，后续取得显式 PR 关系再关联到原工作。

关联保存来源双方身份、原依据版本、关系种类、提出方式（源明确引用、用户确认或建议）、适用项目/环境/阅读范围及当前可定位性。读取到 URL 只证明链接存在；只有正文明确表达的服务目标、验收或会话关系才能投影为该语义。候选查询优先当前工作已有关系、来源明确引用和用户选择范围，不默认展开上百个全仓复选框。相同端点/种类/范围关系去重，重复刷新只更新观测；具体修改、冲突和移除沿 §7.5。正式文档关联保留原条款定位，打开时显示实际已读版本；不可读时保留原ID及具体缺口，不产生决定同步状态。

外部定位与系统导航复用[DES-CC-007](#DES-CC-007)，工作详情仅展示明确的打开或复制入口；同一工作可保存多个准确定位，不能靠同分支猜测会话关系。

详情进入 §9.1 的主阅读区；首页、工作列表、关注、关系和工具返回都通过原 WorkRef 定位同一详情，不把它追加在长来源列表底部。返回上下文保存入口、筛选、列表/详情位置和焦点；切换同一工作保留页签，选择其他工作先恢复该工作的状态。工具动作及个人编辑表单按动作打开，结束后回到原 WorkRef/页签并显示实际结果。

云端个人编辑覆盖决定、问题、关系、阅读位置与偏好；本机工具编辑只在辅助端。各自的未提交输入留存沿原身份和入口隔离，工作选择与阅读位置从该 scope 已保存记录恢复。旧记录的保存与隐私约束统一见[数据兼容](#DES-CC-008)。

### 6.1 来源合同与错误

Trace refs: O7-REQ-2d1f3577-785e-40ac-8d25-ba0d414511f6；承接 [REQ-CC-002](command-center.prd.md#REQ-CC-002) 的适用义务。

关键对象包含 `SourceRef`：provider/主机、经核实的仓库及访问上下文、环境、对象身份、可得 revision、事实性质与 coverage。事实性质区分源事实、Agent 汇报、模型归纳、用户选择和待核实关联；未取得的字段保持未知。[产品来源状态](command-center.prd.md#cc-source-states)由领域层统一产生，不由各页面或客户端时间猜测。

| 字段组 | 语义与更新条件 |
| --- | --- |
| `sourceRevision` / `observedAt` | 实际读取的源版本与该事实被来源/采样者核实的时间；摘要正文有独立核验时间时保留它，缺失则未知 |
| `fetchedAt` / `lastAttempt` / `lastSuccess` | 本服务拉取、尝试及成功读取的时间；重新读到同一旧正文只更新读取元数据，不改变正文事实的核验时间 |
| `eventAt` / 事件身份 | 合入、检查完成等来源明确事件的实际时间；未知时不能用文件 mtime、拉取时间或排序位置替代 |
| `coverage` | 项目/访问范围、不可变基线、查询窗口、已读对象/页、cursor、截断/遗漏/失败原因；“查询空”只在成功且声明范围完整时成立 |
| `generation` / `viewRevision` | 同一来源键的读取代次及已提交投影版本；不是上游事件顺序，也不是远端原子快照 |
| `FactCell<T>` | 值、原 SourceRef、依据版本、事实性质、适用范围、核实/旧结果/冲突/未知状态及原因；每个结论独立回溯 |
| `SourceSnapshot` | 不可变清单/分块、内容摘要、来源版本和发布指针；大小超过事务预算时分块保存，校验完整性后原子发布，见 §7.1 |

时间统一存可解析 UTC 值及来源时区/精度，UI 按用户明确保存的时区呈现；未设置时可采用浏览器报告的时区并显示实际值，不猜测用户所在地。无上游时间时保留空值，不同来源时钟不足以证明严格先后。`stale` 带具体原因：源已有新版本、超过明确有效窗口或刷新失败沿用旧结果；日期较老但没有时效合同的规范不自动退役。日期范围或时区变化只重算投影，不改写事实。

| 字段 authority | 可更新的字段 | 不得顺带推出 |
| --- | --- | --- |
| 当前主责文档/明确验收条款 | 目标、适用条件、规范效力与显式下一步 | PR/CI 现状、实际部署或验收通过 |
| 派生状态摘要 | 其原核验窗口内的说明与判断，保留摘要性质 | 新拉取即为当前事实，或据摘要修改正式要求 |
| GitHub | 对应 PR HEAD、PR/CI 对象状态、准确提交及真实事件 | 未读页没有工作，合入/检查成功等于部署、测试覆盖完整或目标完成 |
| 本机 Git / 原运行时回执 | 原工作树或 instance/thread/turn/request 的实际观察及操作结果 | 云端已拥有本机事实、所有外部任务结束或产品验收 |
| 用户明确选择/确认 | 置顶、个人计划、关系与有依据的核实结论 | 改写源状态、接管会话、授予新权限或更新正式条款 |

读取到比摘要窗口更新的 PR 事实时，只更新对应 PR 字段；保留摘要旧声明并指出冲突。目标、部署和验收各守自己的 authority，不做整条记录 last-write-wins。无法裁决的同字段冲突并列依据及版本，将受影响结论设为待核对，其他字段继续可用。

错误合同返回 `category`、scope、受影响来源/字段、最后成功范围、必要诊断引用和有限 `recoveryAction`，区分未认证、无权限、未接入、对象不在覆盖范围、限额、超时、存储故障与版本冲突。加载、成功空、部分、旧结果、错误和未接入分别可见。可重读不等于可重发副作用，不能仅凭 `retryable` 自动重发保存或工具输入。

可配置的关页后后台来源刷新、实际配置/停用回执及执行状态沿[有界采集与故障隔离](#cc-host-concurrency)；它与本次来源读取结果分开展示，不能由快照存在推断后台任务已配置或正在运行。

ID、Git OID、外部节点与 cursor 使用明确字符串；revision 是验证过的非负安全整数或明确的字符串计数格式，不能依赖 JavaScript 不安全整数。云端 API 严格解码，未知字段/超预算输入明确拒绝；本机 serde/ts-rs 只负责其真实 DTO 和 JSON 往返，不假设 TypeScript `bigint` 可自动 JSON 化。

### 6.3 原工作身份与外部定位

### 6.4 应用 IPC 与能力校验

Trace refs: O7-REQ-417e1bc6-1dac-4b80-891a-cef1f770bf55；承接[REQ-CC-007](command-center.prd.md#REQ-CC-007)。

云端同源 API 只公开有限领域操作，外部来源内容始终作为数据。下表为稳定语义合同，具体路由和 schema 随实现版本固定；旧路由兼容不能减弱身份、scope 或事务要求。

| 操作 | 输入身份/版本 | 成功与失败边界 |
| --- | --- | --- |
| 读取投影/文档/来源详情 | 已授权 project/environment/scope、不可变引用、查询范围和 cursor | 返回实际来源/个人 revision、coverage 与分区状态；不隐式全仓扫描或补取任意路径 |
| 有界刷新/补读 | 已核实来源配置、来源键、attempt generation | 原子发布该来源成功结果；失败保留旧数据，不修改个人记录 |
| 个人创建/修改/确认/移除 | 可信 owner、scope、稳定对象 ID、mutation ID、payload fingerprint、expectedRevision | 数据库原子提交后返回对象及新 revision；旧版本或同幂等键不同内容为 409 |
| 个人列表/历史/偏好 | 同一 owner 与完整 scope、明确分页/版本 | 所有查询和 join 具有相同授权边界；404 不泄露其他 owner 的存在性 |
| 导出/恢复 | 可信 owner、选定 scope、snapshot/schema 版本；恢复另有显式目标确认 | 一致导出或有界明确拒绝；恢复先校验且原子提交，不按文件内账户字段授予归属 |
| 精确导航 | 验证后的工具/来源身份与 allowlist 定位，用户明确点击 | 只报告导航接受/拒绝与复制后备，不隐含读设备、执行命令或授予连接器权限 |

个人写请求必须通过可信 Site origin/同源防伪校验，跨源请求不能仅靠带有用户头放行。共享公开来源刷新可由平台验证的 service bearer 调用且没有访客身份；无 Origin 的服务请求只适用于明确允许的公开来源操作，带 Origin 时仍须匹配 Site origin。服务身份不能访问个人列表、历史、导出、恢复或个人连接器，也不能伪造 owner。请求运行时不得接受任意 SQL、DDL、shell、全磁盘读取或任意 URL 转发。

本机辅助端仍以有限 IPC 完成目录/本机文档/Git、工具与系统导航，Rust 再校验路径/身份/能力。远程 Site 页面在默认系统浏览器打开，不加载到拥有本机 IPC 权限的远程 WebView；无需为此自建 OAuth、设备配对或桥接服务器。本机 route 只在本机解析为允许的导航目标，不能包含可执行命令、shell 参数、凭据或上传指令。

### 6.5 云端个人空间与可信身份

Trace refs: O7-REQ-57c9e8ba-3698-48b0-8f25-02c8f17ef0d6；承接[REQ-CC-017](command-center.prd.md#REQ-CC-017)。

可信主体来自 Sites 在受保护请求边界提供的用户身份，不能从请求 body/query、显示名、邮箱或自行声明的 header 取得。平台 user ID 只在同一 Site 稳定，跨 Site/Remix 可能不同；`OwnerKey=(siteNamespace, platformSubject)` 是应用的身份命名空间。邮箱只可显示，不能作为数据主键、自动归并、授权或恢复映射依据。必须验证部署入口不会让直达 Worker 或伪造身份头绕过平台校验。

`PersonalScope=(OwnerKey, projectId, environmentId, scopeId)` 是所有个人表、修订、幂等结果、阅读偏好、关系、历史、导出与恢复的共同隔离键。项目/环境从已验证配置选择，所有读取、更新、关联 join、对象定位和缓存键都核对完整 scope；仅在 UI 中过滤、仅凭 record ID 或只检查记录主表均不充分。范围切换不重写对象归属，URL 只表达选择意图，服务端仍授权。

只有具有同 Site 可信访客身份的请求可以访问个人空间。未登录或过期返回 401；已登录但无目标范围权限返回 403 或不泄露存在性的 404；service bearer 不能替代访客。再次登录同一 Site 和主体后可跨设备读取已保存数据；新 Site、新主体或显式跨项目恢复需要独立确认和 §10 的数据映射，不能通过相同邮箱推断等同。

## 7. 状态、事务与持久化

### 7.1 三类数据与事务边界

Trace refs: O7-REQ-a0a5fd88-9df3-47ba-a778-ceae9c330949；承接[REQ-CC-011](command-center.prd.md#REQ-CC-011)。

| 数据组 | 权威与内容 | 提交/恢复边界 |
| --- | --- | --- |
| 可重建来源 | GitHub/原工具为原始 authority；D1 保存已提交文档、索引、PR/CI 与投影缓存 | 小结果原子发布；大树/正文先写不可变候选分块，核对完整清单/摘要后以 CAS 原子切换 current pointer；失败保留旧快照，仅清理无引用候选 |
| 云端个人记录 | D1 为唯一写主库：决定、问题、关系、定位、已读版本/位置及偏好 | 同一 scope 的当前指针、不可变修订、幂等结果和 personalRevision 同事务提交；来源缓存重建不改个人记录 |
| 本机工具/材料 | 独立本机存储：资料、未提交预览及位置、ToolJobs、原 operation/job 与未知结果 | 本机合同独立恢复及退出核对；不与 D1 双写，不因云端不可用重建个人数据第二主库 |

个人写入使用 D1 支持的原子 batch 或经验证的等效事务。CAS 更新必须带完整 scope 与 expectedRevision；历史插入与幂等成功结果只能来自该次确实成功的更新，受影响零行不能生成伪历史。并发更新、确认或移除至多一个成功，其他返回最新可读 revision 与 409，保留编辑供用户明确核对，不静默 last-write-wins 或自动合并。

`mutationId` 在 owner/scope/操作下唯一，保存规范化请求指纹和提交结果。相同键及相同请求重试返回原提交结果，不再创建对象或修订；同键不同内容返回冲突。网络超时但服务端已提交时可用原键查询或重试核对；不能换键重做以猜测结果。幂等结果与被引用修订保留兼容查询，不在未说明的短期 TTL 后悄悄失去去重能力。

当前记录和历史读取使用同一事务快照或固定可证明的 revision 水位；大范围导出固定清单和水位后分页，不能把两次竞争读取拼成混合历史。个人修订不可变，删除/移除以显式 tombstone 或事件保留历史；schema 演进不得就地重写原确认内容、时间和依据。

### 7.2 流量控制与故障隔离

<a id="cc-host-concurrency"></a>

Worker 的来源请求、解析、分页、D1 操作和发布保持有界并发、字节及期限；取消/切换 scope 后不得让旧响应覆盖当前页面。来源读取在数据库事务外完成，事务只处理校验后的小型提交或指针切换，不能占着事务等待外部 HTTP。大文档/树按清单分块，不假定完整仓库可装入一次 Worker 请求或单个 D1 行。

同源重复读取、冷却中或满额返回具体拒绝/下一次可尝试时间，不创建隐式无限队列。浏览器可在前台恢复或用户点击时有界校准；用户也可明确配置关页后继续的来源刷新，由 Sites linked automation 或既有受控调度触发同一有界 Worker 来源入口，不在应用内另造开发执行调度器。后台任务只读取已配置范围内的公开 GitHub 来源并更新可重建缓存，不访问个人记录/连接器，不写仓库、不运行模型任务，也不扫描或上传本机资料。

后台刷新的配置由站点配置者通过平台关联 automation 或既有调度的受控管理入口维护，明确 project/source scope、频率、时区、启停状态与授权服务凭据；凭据只在平台/服务端保存。调度器拥有触发计划和实际执行状态，Worker 拥有每次来源读取的尝试、成功、错误与发布版本。Site 保存准确关联标识并展示“未配置/启用/停用/状态未知”、最近尝试、最近成功与当前异常，不能以页面偏好或缓存时间猜测调度正在运行。配置/停用入口必须连接该实际管理能力，只有取得其成功回执才显示已生效；权限撤销、关联失效或执行不可查询时显示具体限制。

后台调用使用平台验证的 service bearer，并遵守 §6.4 的公开源 allowlist、限额、冷却与 generation 校验；服务身份不取得访客身份或个人连接器 consent。停用后不再发起新的调度尝试，已在途读取仍按原身份/版本校验完成或失败，不能声称停用撤销已经发布的快照。关闭网页不会停用已配置任务，未配置或不可用时不声称持续更新。慢来源不阻塞缓存阅读和无依赖的个人保存，数据库故障、调度故障与来源故障分别显示。本文只定义配置与运行合同，不创建或启用实际调度。

本机解析、进程和工具存储仍遵循有界队列、锁外 I/O、取消和独立退出保护；本机失败不把云端全部视图变为未知。云端无法取得本机实时状态时明确未接入，不伪造本机心跳。

### 7.3 保存结果、离线与工具操作

个人保存状态区分 `未提交草稿 / 保存中 / 已保存(revision) / 冲突 / 失败 / 结果待核对`。只有数据库提交回执证明“已保存”；请求已发送、HTTP 连接断开或本地输入仍在都不证明云端持久化。回执绑定原 owner/scope/object/mutation，切换页面后迟到结果也不得显示为新范围的保存成功。

离线只允许阅读该已验证会话最后取得的快照及保留设备界面中的未提交草稿，并明确旧结果/离线时间和未保存状态。默认个人快照与草稿保存在当前会话内存，关闭页面前不承诺草稿持久化；明确提交的云端阅读位置可在重新登录后恢复。本地未提交预览及其位置由辅助端独立保存，不属于云端个人副本。

离线期间不自动排队后台重放、合并或同步个人写入，也不回退为本地可写个人主库。重新联网后先核对身份与 scope，再读取服务器 revision；用户明确保存草稿，冲突保留双方供选择。先前响应未知的写入使用原 mutationId 核对结果，不将其作为新的离线任务执行。显式退出清除页面个人快照，必要草稿在退出前由用户自行复制；切账号不得向新主体展示旧草稿。

来源读取或外部导航无确认结果时保留对应未知状态，不能修改缓存宣称源已改变。本机工具仍使用原 operation/job 核对未知副作用，工具账本独立；浏览器关页或云端重试不得重复本机操作。

### 7.4 个人决定与替代历史

Trace refs: O7-REQ-eb004bfb-41c7-4e8f-aa5b-1f52cec6cf08；承接[REQ-CC-004](command-center.prd.md#REQ-CC-004)。

决定以稳定 Decision ID 组织不可变修订，内容、理由、适用范围及正式条款引用均属于实质语义。每次保存记录作者主体、scope、依据版本、revision 与服务端时间；确认额外绑定实际确认的内容摘要和修订，不能只保存一个脱离内容的 `confirmed` 标签。

| 事件 | 当前呈现及持久结果 | 禁止推导 |
| --- | --- | --- |
| 新建/修改草稿 | 保存新的不可变待确认修订，旧修订保留 | 保存不等于用户确认或正式条款变更 |
| 用户确认 | CAS 核对所见修订与摘要，原子记录确认版本、真实 confirmedAt 与作者 | 同时发生实质修改时不能确认用户未见的新内容 |
| 编辑已确认决定的内容/理由/范围/正式条款关联 | 创建新的待确认修订，当前修订不继承旧确认；原已确认版本及时间保持历史可读 | 不能就地替换已确认正文、复制旧 confirmedAt 或把新修订标为已确认 |
| 用户确认替代 | 新版本经显式确认后记录 supersedes 关系及时间；原决定/版本、原确认和替代依据留存 | 新建相似文本不自动替代；替代不写回正式文档 |
| 仅置顶、展开、显示偏好变化 | 更新独立偏好，不修改决定语义修订或确认时间 | 阅读/排序动作不重新确认决定 |
| 来源条款变化/失效 | 保留决定原引用，显示 changed/missing/ambiguous/unavailable 与可读依据 | 来源刷新不重写决定、不续期确认、不生成“已同步”状态 |

确认与替代关系必须位于已授权范围，禁止自替代、循环和未经确认的语义覆盖；正式条款的后继关系只更新解析状态，个人决定是否继续适用由用户明确判断。当前修订与历史确认分开展示，不能让查看历史产生“当前仍已确认”的歧义。

规范章节按文档路径分组并默认折叠，各组复用原章节身份和来源详情，搜索不受折叠影响。决定编辑器默认关闭；新建、编辑已有决定或从历史建立草稿时打开并聚焦，收起保留当前输入并返回触发入口，切项目按原 scope 隔离草稿。

决定由规范与决定入口阅读/保存，不参加个人问题数量。正式文档关联只打开依据，不推导实现状态、自动写回文档或另建决定同步/证据/全范围 checkbox 工作流。已保存修订与替代历史不是可重建缓存；旧同步/证据/关注数据沿 §10 原值保留，不重新投影或执行。

<a id="cc-link-lifecycle"></a>

### 7.5 关联生命周期与并发修改

关系的提出/确认来源与当前可定位性分别保存，避免把源明确引用、个人确认和猜测混成一个 active 状态。个人关系所有端点和历史必须通过同一 scope 授权；跨范围来源只可作为明确引用，不能借关联获得另一范围个人数据的访问权。

| 事件 | 持久/派生结果 | 用户与来源边界 |
| --- | --- | --- |
| 读到明确源引用 | 保存源端点、关系种类、源版本和语义依据，由该来源投影，可与个人关系并存 | 普通链接不升级为依赖，源刷新不删除历史依据 |
| 出现建议/用户确认 | 建议保留候选/理由，确认后保存个人 relation revision、确认时间和范围 | 建议不参与完成/阻塞判断；确认不改源文件或授予会话控制 |
| 条款修订/重命名 | 优先显式稳定身份，再核对明确后继及范围，保存新定位与原依据 | 唯一且范围可核实的后继可更新解析定位并显示变化；语义替换或多候选须用户修复，不凭标题相似迁移 |
| 缺失/冲突/读取失败 | 保留原关系，解析状态为 `missing / ambiguous / unavailable / changed`，带候选/原因 | 未读取不是删除；失败不清空已确认关系，只有受影响工作显示缺口 |
| 修复/变更 | 用户从原关系查看差异并确认新端点/种类/范围，使用 CAS 和幂等键保存 | 原端点与版本留存；失败保留输入，冲突不静默覆盖另一设备修改 |
| 移除 | 个人关系记录 removal 标记；源关系可保存个人隐藏/不采用选择 | 不删除源对象、不伪称源取消关系；重复读取或源 commit 变化不复活个人移除项，真正新声明可提示但不自动恢复 |

关系键为同一 scope 下两端稳定身份、种类和适用范围，源版本另存为依据，行号变化不产生重复关系。修复/移除先提交再失效首页/详情投影；同一工作服务多个目标仍引用同一 WorkRef。个人隐藏不改变原源声明的真实性，来源详情仍可核对原声明。

## 8. 部署、安全与运行约束

云端浏览器、Worker 与 D1 由同一 Site 部署边界管理；Site 访问设置是外层边界，应用每次请求仍执行 §6.5 的身份与 scope 校验。客户端 owner、URL 项目名、邮箱或“只有站主可访问”不能代替记录级隔离。共享公开来源缓存按 provider/repository/版本/范围分区；含个人字段的投影、阅读偏好与历史不得进入公共缓存。

个人响应及导出使用 `Cache-Control: no-store`，禁止 CDN、共享 Cache API、service worker 或跨用户服务端缓存存储个人内容。当前会话内存快照绑定 owner/scope；身份过期、账号切换、明确撤权或 401/403 后立即停止该范围读取/写入并遮蔽旧个人内容。重新联网或重新登录先授权再恢复。已经交付到离线设备或导出的副本无法保证远程擦除，不声称撤权可收回过去下载的数据。

项目访问撤销、来源凭据失效或仓库权限变化时，后续请求重新核验访问上下文；受权限控制的来源缓存不可凭“曾经读过”继续对已失权主体提供。错误诊断只描述允许公开的范围，不泄露其他 owner、私有路径或存在性。公开项目缓存的保留与个人空间数据保留分别处理，清缓存不等于删除个人数据。

平台管理浏览器登录；应用不保存用户密码、OAuth token 或自制登录 cookie。公开 GitHub 读取无需访客 token，受限来源只沿实际支持的授权路径接入；service bearer 仅保存在部署/调用端，不能写入前端、URL、日志或个人记录，不能用于个人连接器代理。本机 Git/gh、signer 与操作凭据留在原工具，不上传到 Sites。

仓库文档、PR 内容和日志都是展示数据，不能触发命令、权限扩大或任意 URL 请求。Markdown 原始 HTML 禁用，代码/高亮转义，默认不自动加载远程图片；外链协议和目标按对应导航合同校验。CSP 限制实际需要的资源，不因文档含脚本而放宽。云端日志只记脱敏的 scope/operation 标识、类别、计数和耗时，不默认记录个人正文、完整提示词、transcript、token 或导出内容。

本机生产 WebView 只加载打包静态资源，Node/npm 只用于构建测试；Tauri capabilities/CSP 与 Rust 双重限制，app commands 纳入明确清单。Finder 启动不假定继承交互 shell PATH、代理或 SSH agent，允许显式选择并显示实际 Git/gh 路径及版本，不执行 shell 初始化脚本修复环境。远程云端页面只能打开系统浏览器，不能取得本机命令、SQL、全盘或协议透传能力。

本机分发的 .app/.dmg、arm64/所需 x86_64、Developer ID 签名、公证/stapling 与 updater 按真实开放范围验证；更新包签名和 Apple 代码签名分别核对，重启遵守工具退出合同。云端发布不能证明本机签名或特权集成可用，暂停能力保持配对工具设计的明确边界。

App 提供“显示 / 文字与界面大小”入口，100% 为默认，支持选择 150%、200% 及复位；在浏览器和本机界面分别采用受支持的缩放/布局能力实际生效；云端个人显示偏好按 scope 保存，本机专用界面偏好保留本机。实现与验收记录实得 CSS 视口和布局，不能用截图后放大、系统放大镜或只在测试 DOM 注入样式代签该入口；调整大小不重新加载来源或触发工作动作。

首页重点直接展示主责章节的首个普通正文段落（若含明确“当前目标：”前缀则取其后正文），不把章节名作为具体交付内容。忽略标题、HTML、代码块、列表和表格作为目标句来源；未提取到正文时保留章节入口。仅当章节内表格包含“里程碑 / 工作包、主责、依赖与产出、退出条件”四列并且各行完整时，将原值投影为带库图标的里程碑卡；可展开主责、依赖和退出条件，统一标注计划来自原文、验收未核实，不生成顺序依赖、进度或自动摘要。完整 Markdown 原文仍在默认关闭的“完整目标与依据”。近期成果按用户实际选定并显示的时区日期分组，节点显示短时间、标题和结果文字，完整 ISO 事件时间可展开；共同的合入/验收边界仅出现一次，预览数量与其余入口保留。关联数量仅计算当前已读工作与显式关系，零匹配表示尚无已读明确关联，不能推断目标没有工作；移除的个人关系覆盖旧来源投影。首页四个语义区不渲染成等权重的文字框：当前工作、目的和下一步占主要阅读区；个人问题在有内容或覆盖缺口时形成清楚的次区，突出准确已知数量及少量具体问题；最近成果使用真实事件时间与短结果的纵向时间线；返回入口用工作名称、上次位置组成轻列表。主区选中工作后直接进入同一详情；宽屏可保留旁列表，不能把详情挂在原四区和来源列表之后。关注数量存在未读范围时同时显示该范围未知，不把数量写成全局完整值。

WorkList 在同一列表中提供全部、进行中、已合入、已关闭、外部或未核实五类带库图标与文字的筛选按钮，明确显示选中状态；数量只计算当前已读且命中文本筛选的工作，状态不从目标验收或工具运行推断。文本和状态共同筛选后分页；清空筛选同时恢复两项。筛选先在当前页面生效，明确保存的导航偏好按云端 owner/project/environment/scope 恢复；切换项目不能继承另一项目筛选，未保存搜索输入保持设备草稿；失败和未读范围仍独立显示。首页返回与列表筛选解耦，先按个人置顶、明确最近打开排序，未被这两项排序的工作优先已读进行中 PR，其余保留来源顺序；不能因此隐藏明确置顶或最近打开的已合入工作。WorkList 每页默认 20 项、最多 50 项；首页默认最多三项重点、三条成果事件、三个返回入口和两项个人问题预览，其余有带范围的“查看全部/继续读取”。一项默认只呈现名称/目的、当前结果、必要剩余条件和一个主要动作；工作名不按固定行高裁断。真正待答及高影响警告始终在所属工作摘要或关注区可见；条目超预算时保留准确已知数量、第一项实质内容和直达完整处理列表，不把警告全部藏进“更多”。这些是默认条目、字段与动作预算，不限制读取真实完整内容。

显式文档树展开后沿用模块图标语言：节点以独立展开图标、带文档类型图标的标题按钮、短类型标签及紧凑来源入口呈现；类型直接使用已读清单 kind，未知使用通用文档，不从标题推断。完整阅读按钮 aria-label 保留“查看文档：名称”，树的 aria-level、aria-selected 与游走焦点保持。树线只表达源导航层级，不表达配对、依赖或完成；选中与焦点用边线及背景区分。

WorkDetailPane 的固定摘要顺序为工作名称/目的、当前可核实结果、主要剩余条件与下一动作；下方用“概览 / 依据 / 历史”二级页签。页头保留完整工作名称，下方并排展示来源结果与目标验收两个独立事实卡，均用库图标和文字；只有存在该范围与版本下的独立目标验收依据才显示对应结论，否则显示“尚未核实”；不得从 PR、检查成功或 remaining 自由文本推断验收。剩余条件、导航边界和来源覆盖合并在默认关闭的“来源与核验范围”；具体读取错误、个人待答及操作回执仍在所属位置直接显示，不随普通说明折叠。选中工作后旁列表筛选默认关闭，摘要显示当前状态、文本条件及已读匹配数，展开复用原输入和五类状态按钮；返回列表恢复完整筛选，不重置既有条件，跨设备恢复只采用该 scope 已提交的阅读/偏好版本。存在明确目标关系才展示关系图；无关系时仅显示一行提示与依据入口，不保留重复标题节点和空图容器。已知端点直接打开；依据显示可读条款及影响判断的版本差异；历史承载真实结果事件、个人变更与操作回执。关联编辑、个人决定、个人问题按动作打开，本机 ToolTask 沿明确入口进入辅助端；表单有清楚取消/返回，不与全部资料常驻堆叠。

SourceInspector 由具体事实的“查看依据”打开，在宽屏替换次级面板，在紧凑布局替换主区并带返回；不创建第三列。来源摘要先展示读到什么、覆盖/时效和具体缺口，完整路径、SHA、协议身份与 raw JSON 在其内按需展开，复制、定位原文和原工具打开保持可用。未安装/未连接仅在相关动作处显示可执行恢复步骤，不默认展开不可执行的完整配置表单。PR只在统一工作列表呈现；GitHub来源区保留连接、账号、范围补读和错误。文档原文检索保持独立入口。

规范阅读复用统一受限 Markdown 组件和已提交文档索引：当前主题正文在主阅读区呈现，标题、段落、列表、引用和代码块有独立层级，正文最大行宽约 48em，短段之间有可辨留白。目录/配对可按布局保留为次区，完整元数据和原始 Markdown 按需展开，不以一整块等宽源文本替代正文。受限渲染、代码转义、禁用 raw HTML 与远程媒体自动加载仍沿 §8；排版不引入可执行内容或新的来源权威。

保存、失败和未知结果贴近触发动作，用可读状态区域通知；输入错误留在相关字段，成功定位到原工作结果。返回恢复选择、筛选、位置与焦点，页签/面板切换保留所属工作的输入；焦点不能跳到页面底部长列表。图标按钮有可读名称，键盘可进出来源检查/工具动作，关闭后回到触发控件；加载与重读保留已可读内容，空、部分、旧、错误和未接入分别使用 §6.1 状态。

全局搜索保存提交查询与结果的同代快照，输入修改和异步过期响应不改变旧结果标签。以路径聚合结果，图标区分PRD、设计和其他文档，显示返回章节数及正文原句片段；查询标签在窄窗折叠输入时仍可见。单次搜索默认最多返回100条，等于限额时显示范围提示而不猜测总数。正文按不区分大小写的字面子串渲染安全mark，不解释为HTML或正则；匹配导航仅在当前已渲染正文中计数，标题/路径命中而正文无匹配时明确说明。打开后先完成详情聚焦再定位首处，前后导航不移动键盘焦点；关闭仍回到原data-source-ref入口，查询/展示不改写来源版本。

云端中文检索必须覆盖已声明的已提交文档范围，优先标题、路径及已有条款 ID，支持“规范”“合入”等两字查询。采用实际部署验证过的索引能力；缺少所需 tokenizer 时使用有界、参数化的子串查询或声明覆盖的应用索引，不因 D1 兼容部分 SQLite 就假定 FTS5/trigram 可用。本机预览可继续使用 [SQLite FTS5 trigram](https://sqlite.org/fts5.html#the_trigram_tokenizer)，少于三个 Unicode 字符回退到选定范围的参数化子串查询。两端都限制结果、取消和去抖，unicode61 不等于完整中文分词，trigram 不自动覆盖两字搜索。

窄窗口（沿用 47.5rem 容器断点）使用带当前页面名的导航按钮作为可见标题，隐藏重复页眉说明；全局搜索用带文字的按钮按需展开，原搜索语义和 IME 处理不变。文字与界面设置放入现有项目面板，宽窄窗口均可访问；关闭折叠区域后不能遗留不可见焦点，按钮保留 aria-expanded 和可见焦点。首页 DOM 与视觉顺序均为目标正文、主要动作、关联信息、里程碑；通过紧凑项目栏及标题间距，使约 729×628 逻辑像素的默认字号窗口首屏可见目标与主要动作。完整分支移入项目入口，不在顶部重复排列品牌、身份和说明；150%/200% 等大字号允许自然换行及纵向滚动，不裁断标题或隐藏工作。

IME composition 期间 Enter 只用于候选操作，不能误提交搜索/发送；保留已获用户确认的真实 IME 结果。视觉验收检查受影响的输入/焦点路径，历史 IME 结果保持其原版本证据；VoiceOver 不在本产品验收范围，既定语义控件、可读名称、焦点和键盘义务仍保留。长文档、列表、日志与来源跳转须在真实云端浏览器证明，本机工具另在真实 App 验证；mock 不替代对应系统体验。

章节目录由当前已读章节正文开头的 ATX / Setext 标题构成有序层级；层级跳跃连接最近较浅标题，前言与未识别标题保持平级，不改变 section ID、修订或阅读位置合同。目录采用嵌套列表与独立展开/阅读按钮，初始展开根标题，恢复或切换章节时展开其祖先；支持手动折叠，当前祖先有独立样式。标题按钮保留含行号的可读名称和辅助定位，视觉正文只显示标题；切换文件/修订重建局部展开状态；已提交文档的持久阅读偏好按原 scope 与源版本恢复，失效位置按文档树合同处理，不错用另一版本的行号。

## 10. 兼容、迁移与回滚

### 10.1 独立来源与局部可用

<a id="DES-CC-012"></a>

Trace refs: O7-REQ-240b3b67-49ff-4ac1-9ae8-112619efd09c；承接[REQ-CC-012](command-center.prd.md#REQ-CC-012)。

云端个人数据与可重建来源分开失效。GitHub 不可用时，已授权用户仍可读取最后成功来源并保存不依赖新源事实的个人记录；每项来源显示账号/服务来源、范围、最近成功及当前错误。D1 不可用时只能显示已取得快照和未保存草稿，保存明确失败或待核对，不能将页面状态伪作云端持久化。没有历史成功快照时显示实际缺口，不制造示例事实。

### 10.2 数据迁移与版本回退

<a id="DES-CC-008"></a>

Trace refs: O7-REQ-2866f4e6-092d-49e8-b8b3-782db0f16763；承接[REQ-CC-008](command-center.prd.md#REQ-CC-008)。

个人格式、来源快照与数据库 schema 分别版本化；应用只编辑能完整理解的版本，未知未来格式保留原值并拒绝编辑，不因解析失败写空或以默认值覆盖。缓存升级/重建只触及可重建来源，不能删除个人决定、关系、问题、历史或阅读记录。

导出包含明确 schema、生成时间、Site/原主体来源标识、项目/环境/scope、记录与不可变修订、确认/替代/移除关系、阅读偏好、固定快照水位、计数及完整性摘要。导出文件是用户数据，不含平台/工具密钥、本机私有资料、旧 runtime transcript 或任意数据库执行语句；来源缓存可另建清单说明其可重建性质，不与个人备份混淆。

恢复文件按不可信输入处理：先验证格式版本、大小、清单/摘要、引用完整性及循环，再向当前可信用户呈现目标 project/environment/scope 和冲突。文件中的 owner、邮箱、权限或 Site 信息只作为来源元数据，不能决定访问权；实际目标 owner 由当前 Site 的可信请求产生。跨 Site/主体/项目映射必须明确选择并核对，不能凭同邮箱、同仓名或相同路径自动合并。恢复幂等键绑定导入批次、源身份/版本及目标 scope，重复提交不复制记录或历史。

文件摘要、计数及引用校验只能证明文件内部一致性，不能证明作者身份、原确认真实发生或声明内容可信。文件自填的 author、confirmedAt、confirmed 状态及其相互匹配的摘要不得生成当前可信确认。只有在同 Site、同可信 owner/scope 下，与服务端既有不可变修订及其确认事件逐项核对一致，才可恢复该既有确认的身份、内容和原时间；不能据此把修改过的内容或新的目标范围沿用为已确认。其余导入保留原作者/确认时间等为明确的来源声明，当前内容标为待核实/待确认；用户重新确认时生成新的可信修订与实际确认时间，原声明仍留在历史，不新增签名或文件自证信任机制。

恢复不静默覆盖已有修订或把旧确认套到新内容。保留原业务身份/依据及来源元数据，冲突由用户明确选择保留、建立映射或拒绝；用户没有选择前不改变现存记录。恢复提交前完整验证，以事务或不可变候选清单加原子指针保证不出现半批个人状态；失败保留现存数据及原文件。恢复后重新核对原来源引用，缺失/失权标为不可读，不能为了让页面无错误而删掉历史关系。

本机旧 Project.id/environment 与版本化 personal family 只可经上述显式导入映射进入云端；不启动后台双写、目录同步或自动上传。本机旧 Codex 运行/请求/操作/输入、私有标记与工具凭据保持原存储，不删除、不发送、不作为当前云端工作或退出依据；无法安全判定私有性时不公开内容。旧启用偏好不启动执行。旧 CI 字段可以按版本读取其历史含义，但新的云端检查事实必须从 GitHub 重新取得准确身份/提交，不能把旧缓存字段冒充当前检查。

旧 `decision_followthrough_v1` 行及 revision 冻结保留，不重新投影、保存、转换或执行。要求所有 personal family 同 revision 的旧 App 可能拒绝读取新格式，合同不承诺无缝降级，也不能为兼容旧版改写证据或回退个人 revision。工具资料和未知 operation/job 的备份/恢复仍走独立本机合同，云端导入不触发设备副作用。

### 10.3 D1 发布兼容与恢复边界

Trace refs: O7-REQ-57c9e8ba-3698-48b0-8f25-02c8f17ef0d6；承接[REQ-CC-017](command-center.prd.md#REQ-CC-017)。

Sites 的 D1 迁移是 schema-only，并在新 Worker 上传之前执行；发布失败时数据库可能已经采用新 schema。迁移与 Worker 切换不是一个原子事务，不能把“部署失败”理解为数据库未变化。运行请求不执行 DDL，也不在普通启动时隐式改写个人数据。

schema 演进必须让旧 Worker 与新 schema 在发布窗口仍可安全共存，或在明确的兼容拒绝下只读而不损坏数据。默认采用可兼容扩展、显式版本读取和可恢复的数据变换；删除/改义字段只有在实际旧消费者、未完成请求和恢复需求都核对后才可实施。数据变换与 schema migration 分开记录，使用受授权的有界迁移操作、幂等与回退依据，不假定 schema-only 发布器会迁移个人内容。

代码回滚只回到可与现存 schema 共存的已知构建，不自动撤销已执行 DDL 或已提交用户写入。每个发布候选声明兼容的 schema/read/write 版本范围，并验证“旧代码+新schema”“新代码+旧数据”和上传失败组合；不兼容时优先保护现存数据并明确停止写入，不能让旧版覆盖它不认识的字段。

个人导出与平台数据库备份具有不同范围：前者可由 owner 验证和恢复自己的个人空间；后者是站点运维恢复，必须核对真实可用能力、保留期、恢复点、权限及全站影响，不能由“D1有备份能力”推导应用已完成恢复验证。恢复旧备份会影响备份后写入，应先保留可取得的新数据及明确损失窗口；它不能撤销原 GitHub/Codex/本机工具已经发生的副作用。实际实施次序、备份命令、恢复演练与迁移进度记录在独立 Issue、PR/运行手册，不在本合同维护执行流水。

### 11.2 实施时的验证层与关键反例

1. 领域与契约层固定文档/PR/CI/个人记录样本，核对身份、来源版本、中文搜索、时间窗口、关系和决定转移；完整 JSON 解码和错误语义不能只靠静态类型。
2. Worker/D1 集成层覆盖 CAS 零行、竞争更新、写入后响应丢失、相同/不同指纹重试、当前+历史一致读取、导出水位、恢复中断及来源候选分块发布；证明事务内不会出现孤立历史、重复操作或半批状态。
3. 真实平台层从受保护 Site 入口验证可信用户、无用户的 service bearer、同 Site 多设备、可用测试主体间隔离、撤权与伪造头；不能仅构造本地 header 就声称平台身份可信。
4. 真实浏览器按[产品整体验收](command-center.prd.md#cc-product-acceptance)完成开始一天、规范阅读、问题处理、决定确认与修改、返回工作、跨设备恢复和离线重连；保留准确来源/窗口与动作回执。
5. 本机层验证原工具导航、CLI/signature/资料、未知 operation/job 及关窗/退出；与云端浏览器证据分开，fixture 不代签系统能力。

每次验证只执行本次影响的必要范围和既定门禁，记录未覆盖情形。新的平台能力或跨主体/跨Site恢复未经真实候选验证时保留未证明边界，不能通过增加文档链接、编译通过或单请求成功宣称完整迁移验收。

## 12. 技术决定与实际风险

### 12.1 技术路线比较与决定

架构决定 `CC-CLOUD-CORE`：2026-10-22，owner 为 `runtime_engineer`，产品范围由 `producer_system_designer` 共同维护。选择依据是非本地阅读/管理与设备能力具有不同可用性、数据和权限边界；此决定由 Git 保留此前桌面整体承载方案的历史，不改写旧验收结论。

| 路线 | 选择与理由 | 代价和复核触发 |
| --- | --- | --- |
| Sites 浏览器 + Worker/D1 为云端核心；Tauri/Rust 为本机辅助 | 最终主路线。个人数据同 Site 单一权威，浏览器无需开发机在线，本机秘密和能力保持原边界 | 承担平台身份、Worker/D1配额、真实并发/恢复与发布兼容验证；不同运行时共享语义而非强求同一源码 |
| Sites UI + 外部 HTTPS 后端 | 条件备选；仅在已实测平台限制妨碍必要索引/数据库事务/恢复/受限服务身份或部署独立性时评估 | 增加授权、跨域、运维与备份边界；必须证明可信Site主体传递与scope授权，不能把邮箱或service bearer当访客；不得与D1长期双主写入 |
| 完整桌面核心 + 云端摘要镜像 | 不作为最终核心方案；不能满足不依赖开发机的完整工作视图和跨设备个人连续性 | 桌面仍用于设备能力，但不保留个人数据第二写主库或只给网页固定摘要 |
| 长期云端到设备执行桥/设备配对 | 不在最终范围内 | 只有新的明确产品需要和授权边界成立才另行设计；本合同不预设远程队列、任意命令、心跳或隐式上传 |

云端采用 Site 支持的前端栈，本机保留 Tauri/Rust 与适用 Solid 组件，不以 UI 框架差异引入第二套工作事实或个人记录语义。具体库/数据库特性以候选版本实测固定，框架替换仅在必要能力或维护成本有明确证据时考虑；不使用未经验证的性能排名作为架构依据。

## 13. 本机工具合同

<a id="DES-CC-015"></a>

Trace refs: O7-REQ-fd3b34c6-4fb4-4614-8d7b-744a86d29c3a；承接 [REQ-CC-015](command-center.prd.md#REQ-CC-015) 的适用义务。

本机资料、同包 CLI、已有 signer 的普通调用、后台工具操作及私有资料隔离由[本机工具集成](local-tools.design.md)主责。资料由原 context 文件和历史拥有，辅助端内置能力与已安装 CLI 分别观察；Apple 签名及管理员助手等暂停能力不因云端入口而开放。云端不接收密钥、私有资料全文、本机路径或未提交代码，不承担本机资料索引。

辅助端使用 §5.7 的工作引用和返回位置打开云端核心页面；只有允许公开的最小工作标识进入浏览器URL。Site入口可给出明确原工具定位与复制后备，不能把定位变成命令、参数代理、设备配对或上传许可。工具端在本机重新核验实际设备、工作树和能力，网页选择 project/environment 不自动授权设备操作。

就地反馈、独立导出/恢复输入及可信签名请求沿 [DES-CC-TOOLS-005](local-tools.design.md#DES-CC-TOOLS-005)。工具结果保留原 operation/job 和范围，返回工作只导航到同一上下文，不自动上传结果或使工作/PR/目标完成。私有资料只在受控本机工具界面展示；需要正式来源结果时由其原工具/仓库依据取得，不借普通返回链接传播秘密。
