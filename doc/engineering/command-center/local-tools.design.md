## 1. 目标、职责与能力边界

本机工具属于指挥中心的本地辅助端。普通用户 Rust 宿主拥有设备与工作树绑定、context 私有资料库、同包 CLI、兼容 signer 及工具操作记录；这些能力可在云端不可用时独立使用。云端网页承担日常四视图和云端个人空间，不承载本机工具执行、私有资料正文、口令、密钥或工具账本。

云端与本地通过准确的来源/工作引用和普通浏览器导航关联。远程 Sites 页面在系统浏览器打开，不加载进拥有 Tauri IPC 的本机 WebView；没有设备配对、云端命令队列、localhost 代理或资料自动上传。导航只提供上下文，本机重新核对设备、环境、工作树及操作权限；工具操作与结果仍由本机原接口拥有。

本机首页只保留“本机工具”和“工作树预览”。工作树入口显示真实选择的本机项目、HEAD 与 dirty 状态，文档预览只读取有界 tracked 工作树材料；这些内容不通过导航发送到云端。本机移除 GitHub 来源读取、统一工作投影及个人问题/决定/关系写入口，旧个人表和历史原样保留，不在此转换、上传或删除。预览偏好与阅读版本使用设备命名空间，与旧个人记录分离；重建缓存不能改写旧个人数据。云端工作上下文、安全往返及正式数据切换仍按各自主责合同独立实现和验证。

Apple 代码签名和管理员助手集成仍按用户的既有暂停决定保持关闭，包括 SMAppService／认证 XPC／Authorization Services、signer 初装、密钥与 policy/grant 管理、受保护加密密钥导入导出和 signer 备份计划恢复。已有兼容安装的普通 caller 不受该暂停影响。通用自动更新、其他 purpose UI、远程安装和动态插件不属于本设计开放能力；不得用 shell/sudo 或云端代理绕过限制。

## 2. 普通用户能力与边界

context 的 `application` 应用接口共享显式资料 root、完整原文校验、条件保存、历史恢复身份校验及原快照实现；CLI 不在 GUI 进程中运行。`info --json` 固定 schema 1，未知构建来源返回 null；它不打开资料库或 custody。caller 的 info 和其 context info 分别表示各自能力。

资料绑定持久保存真实 root、设备号/inode、store ID、原 store 项目 ID、面板关联项目 ID 和单调版本。日常条目读写按原绑定核对目录及 store 身份。Git 历史读取与恢复通过持有的原目录身份执行，并在完整读取操作期间核对绑定路径和 Git 元数据目录／gitfile 目标身份；资料根目录或 Git 元数据被更名、替换时拒绝，不从复用路径读取另一个资料库。

普通项目和私有资料目录双向包含均拒绝，普通索引、缓存回退、搜索、阅读历史访问和来源打开都检查私有隔离；用户历史数据保留而不经普通入口暴露。正文只按需读取，不持久复制到普通文档索引。

Git 元数据采用各子命令前后及返回前的持续身份重核验，实际 Git 仍按路径访问元数据；不将该核验描述为原子快照，也不声称消除在全部核验之间发生并恢复的瞬时 ABA 替换。

简化表单修改完整原文中的负责字段，保留其余合法元数据。新建是 create-only，修改提交读取时 revision；CLI 与 GUI 使用原跨进程写锁。冲突保留草稿，重新读取后可再次保存；已确定未写入的错误不能锁死目标。保存、回读或重新加载期间的新编辑以草稿世代检查保留；继续保存只采用本次确切保存修订做 CAS，不采用未展示的外部较新修订覆盖并发修改。新建绑定失败且已证明无副作用时只回收当前保留记录世代中所有操作声明均已证明无副作用的新建私有目录保留记录，不解除既有绑定或其他运行中／未知操作的隔离。资料落盘、Git 提交和远端同步是独立事实。

加密资料快照沿用 context 的明确选择范围、create-only 输出和新目录恢复。口令通过绑定窗口／操作／用途的随机短时句柄进入宿主内存，一次消费、两分钟过期，不持久化到任务或日志。恢复在目录和项目校验前消费正确窗口／操作／用途的句柄；后续拒绝或对话框取消时销毁已消费口令，错误窗口／操作／用途不消费原请求的句柄。快照在独立阻塞 worker 中执行，不持普通项目索引锁。

恢复不要求原资料库仍可读取：已连接库只消费保存的 store／项目身份，新机器可不提供旧绑定，由口令认证的同一份密文确定资料库身份。当前普通项目关系由宿主固定；新目标先登记私有排除，再写入明文并建立绑定。恢复准入同时固定独立暂存目录名称；暂存创建后出错按可能已写入处理，核对最终目录缺失时也核对原暂存，不将保留明文判为无副作用。恢复、证据和核对始终绑定原密文摘要与条目修订，不因源目录丢失重放未知操作。

可选 CLI 与 App 同次构建，catalog 固定提交、release、target、大小和 SHA-256；桌面目标架构必须同步传入 CLI 构建及清单，不支持的聚合目标在构建前拒绝；仅复制核对后的资源到用户受管版本目录，不覆盖不同内容的已有文件。实际绝对路径可调用，PATH 可见性单独显示；不临时下载或从项目执行安装脚本。

## 3. 已有 signer

后端只读取固定安装描述并核对普通 caller UID、受保护实际路径、release manifest 和 executable SHA-256。未知或不兼容安装保留原状；不经普通 App 读取 custody。

绑定证据从同一个持有的资料目录读取库配置和目录身份；执行核对原身份，初始化、发布与绑定持续使用原对象，拒绝采用后来出现的不同库。恢复后的绑定直接读取已发布目录句柄，不再按路径重开。快照导出也固定原输出父目录；以目录句柄祖先身份排除资料库内部输出，目录别名或源目录改名不能绕过限制。

桌面 CI 对普通 PR 和 main 推送均监听 Cargo 包装驱动、实际 Python/helper 输入及工具链配置，避免只改包装驱动时跳过 App/CLI 验收。CLI 包装只接受可核验的已提交源输入，构建前后检查 tracked、untracked、资料 CLI 源目录中被忽略的输入及 HEAD；清单查询失败禁止发布。CLI 安装和中断核对共用普通用户目录中的跨进程锁；原安装仍活跃则保留未知，无最终发布时解除原占位供明确新安装，残留暂存和其他版本不删除。

文件签名要求明确 file、job、signer、grant 和完整合法 SignContext；不自动填示例值。只读准备校验明确确认无副作用时，表单保留草稿并允许修正；进入原 caller 准备边界、旧操作或结果未知时仍冻结原 Job，先核对，不能另建操作绕过未知结果。

原 caller 第一次 prepare 前重新核对原准入的源文件摘要、大小、设备和 inode，禁止采用替换文件的新身份。第一次 prepare 建立私有 job，原 Rust 类型生成 context、file envelope 和 canonical JobInput，第二次 prepare 固定原请求。提交和 inspect 绑定原 job；界面核对结果时传入原预览指纹，已核实 committed 后才允许显式开始新请求并清空表单及临时操作 ID，原 Job 和账本保留。未知或未完成结果不能清空绕过；准备响应丢失时核对原 operation ID、安装、源文件和冻结 envelope，成功后恢复原 prepared 身份及提交入口，表单仍冻结且不重放 prepare。

提交把原 IPC 请求及安装发行身份摘要传入 caller；caller 在实际请求构成后、调用 worker 前核对，旧安装缺少 frozen_submit_v1 时在工具操作准入前拒绝提交，不创建 unknown 资源占位；实际发送边界再次核验，不能降级绕过。

准备的非秘密固定输入与原 operation 在同一事务保存；重启后从操作记录显式恢复原请求，重新核对源文件、安装、原输入和同一份已验证准备快照的指纹，随后显式 inspect 原 Job 才开放提交。没有恢复证据的旧记录明确拒绝，不从表单猜测，不重放 prepare。退出冻结拒绝只在锁内证明没有原操作、没有同资源运行中或未知记录且未写入时返回无副作用；旧记录或不确定存储错误保持未知。

准备不等于 worker 已授权。独立验签重建相同 context 的 envelope，并核对用户明确的预期公钥。选中文件必须是有界普通文件，不接受 FIFO、符号链接或读取中变动。

缺少密钥、policy、grant 或 purpose 配置时明确显示未配置；当前暂停的管理员集成不能用 shell/sudo 透传代替。

## 4. 操作与退出

工具操作先在 SQLite 事务中原子登记 operation ID、输入指纹、不可变目标资源及动作。相同 ID/输入回读既有记录，不重放；不同输入拒绝；已有 running/unknown 占位防止重复副作用。signer 的 ASCII Job 资源按大小写保守共用占位，以覆盖常见 macOS 目录别名；回读核对也使用同一 ASCII 资源别名规则，核对原操作的全部不可变指纹后才解除 unknown。原输入指纹和 Job ID 仍精确核验，其他工具资源保持精确比较。终态不倒退，崩溃中的任务转 unknown，不由进程消失推导回滚。

快照恢复从原证据核对父目录身份，并通过持有的目录句柄完成写入和发布；替换路径不接收正文。父目录在执行中改名时，结果可能位于改名后的原目录，操作保持未知并拒绝绑定替换位置。

完整退出仍冻结独立 ToolHost 的工具任务准入并核对所有项目的 ToolJobs；运行中或未知工具效果阻止安全退出声明。窗口关闭留后台，取消退出解除工具冻结。工具冻结、取消及批准在同一工具状态锁下核对，口令和正文不作为恢复参数。

<a id="DES-CC-TOOLS-004"></a>

## 5. 私有资料隔离与旧数据兼容

资料正文只在明确选择的本机资料操作中使用，普通项目索引、工作列表与个人问题不接收私有正文。旧线程私有标记和操作记录保留且继续参与隐私排除，不转换为当前工作或重放动作。备份遵循资料库的加密快照合同，不将旧执行数据库混入普通配置备份；外部工具中的资料由用户在原工具管理。

<a id="DES-CC-TOOLS-005"></a>

## 6. 按任务组织工具入口与结果反馈

本节复用 §2–5 的接口、ToolJobs、私有隔离和退出规则，定义本地辅助端的工具交互；工具可从本地入口独立打开，也可接续已校验的工作定位。实际能力与验收按 §11 的证据范围判断，不建立第二套工具授权或操作账本。

### 6.1 入口、能力与操作范围

任务入口以库图标、短名称和真实读取状态形成紧凑导航，选中态有边线、背景与文字标记。资料显示当前已读绑定范围，签名沿 signer observation，CLI 沿安装观察，操作核对沿已读 ToolJobs；检查中、未检测和读取失败不转换成可用或空记录。备份恢复与独立验签不以 signer 安装作为前提。选中任务就近显示下一步与必要能力缺口，完整项目路径、版本与原始观察归可展开诊断；输入、原 Job 核对和恢复入口保持原行为。自动或手动读取环境仅更新读取状态，不使用写操作完成通知，不声称工具效果完成。

本机工具首页按“资料”“备份与恢复”“签名与验签”“CLI”提供任务入口，先说明可完成的结果、当前可用性及一个下一动作；仅打开选中任务的表单。未连接、读取失败、不兼容和用户暂停分别显示，按每项任务的真实前提开放动作：建库/连接不要求已有绑定，新机器恢复不要求旧库可读，安装同包 CLI 不要求已有 CLI，独立验签不要求安装或连接 signer。暂停能力保留原因及原合同入口，不展示可提交的配置表单；已有兼容 signer 的普通 caller 仍可使用。

从统一工作详情进入时，传入原工作引用、明确执行环境及返回位置；这些只是导航上下文，不携带授权或推导签名输入。工具表单从宿主读取当前真实绑定与能力，不能以页面缓存启用动作。本机受控详情最多显示该范围允许的操作类型、状态及核对入口，不复制私有库名、路径、条目、口令、完整请求或派生正文。返回云端只恢复原工作与阅读位置，不自动回传工具状态或结果；用户明确录入的非秘密个人陈述保持其来源性质，不能充当工具已核实事实。私有资料与签名结果仍在其原受控入口阅读。

| 独立验签 | 显式文件、完整 context、预期公钥与签名 | 显示匹配或具体不匹配项；通过仅证明该组输入，不赋予执行授权 |
| 安装同包 CLI | 已验证包版本、目标绝对路径及当前安装差异 | 安装完成与 PATH 可见性独立显示；原版本保留规则沿 §2 |

导出与恢复口令分别绑定当前窗口、操作及用途。表单只申请自己的短时句柄，不读取另一任务的输入；取消、完成、过期或离开该口令步骤时清除对应 UI 临时值和未消费句柄，重新进入重新输入。已消费句柄与正在执行的原任务按 §2–4 处理；清除 UI 不取消、回滚或重发操作。口令不进入普通草稿、返回栈、错误样本或日志。

签名上下文导入只接收用户明确选择的完整 SignContext JSON，复用 [SignContext](../../../crates/oasis7_local_signer/src/protocol.rs) 的严格字段与校验，不另创请求格式。文件读取沿 [file CLI](../../../crates/oasis7_local_signer/src/file_cli.rs) 的普通文件、身份、摘要与 64 KiB 预算；预览固定读取到的原文及摘要，内容改变须重新导入。job、signer、grant 和源文件仍由用户分别明确选定；已准备请求通过原 operation/Job 的恢复入口打开，不从任意 JSON 导入成已准备或已授权状态。前端逐字段显示来源、缺失和校验结果；后端仍对完整输入、实际文件、安装和原请求重新校验。缺 job、grant、purpose/context 等输入时指出具体缺口，不生成示例授权、不从工作目标推导，也不将 JSON 解析成功等同 worker 授权。

### 6.2 云端与本机往返

从本机打开云端时，只使用用户已配置的站点来源和非秘密的项目/环境/WorkRef 定位；访问仍由浏览器登录与云端授权决定，不把本机 UID、邮箱或 URL 中的 owner 当作云端身份。不得把本机绝对路径、私有库名、条目、口令、签名输入、操作句柄或凭据写进 URL、referrer、云端个人记录及普通诊断。

云端只能打开已支持且严格校验的原工具定位；`codex://threads/<UUID>` 沿总体设计的限定格式处理，不能附加命令、任意路径或自动执行参数。本机工作树引用由设备上的既有绑定解析，云端传入的标签不能替代实际目录与仓库身份。目标不可用、不匹配或无本机处理程序时，保留原工作并提供安全复制/手动选择入口，不回退到 shell、任意 URL fetch 或不受控本地服务。

打开浏览器、复制定位或操作系统接受导航，只证明导航动作发生；不能标成会话恢复、工具执行、签名完成或云端记录已保存。从工具返回时只恢复所选工作与阅读位置；不上传私有操作结果。关闭云端标签页、退出登录或云端失联不会取消本机工具；本机退出仍按 ToolHost 的真实运行/unknown 状态核对。

<a id="62-每次操作的反馈与恢复"></a>

### 6.3 每次操作的反馈与恢复

每个任务表单拥有自己的提交状态、字段错误、结果区域和原 operation 引用。主要按钮只描述当前可执行步骤；不可用时就地给出实际原因与修复入口。错误留在发起位置附近，定位相关字段；异步结果通过可访问状态区域通知，不抢用户正在编辑的焦点。用户显式查看结果或返回时，才定位相关操作、结果或原触发控件。成功结果先用用户可理解的结论和下一动作表达，原始 JSON、完整摘要与协议字段在诊断详情按需展开。

提交前校验失败保留草稿且不声称已执行；宿主证明无副作用的失败允许修正后再次明确提交。已经运行或效果未知时显示原操作的核对入口，遵守原资源占位与冻结，不能把一般“重试”映射成新操作。迟到结果必须匹配窗口、原操作、输入版本及表单世代，不能覆盖用户新任务或新草稿；回读可更新原操作历史。独立工具的局部失败不清空其他资料或冻结无冲突任务；完整退出仍由既有统一协调入口决定。

界面职责拆为工具总览、单任务表单和操作结果组件；共用 bridge/ToolJobs，不在 UI 再执行 CLI、重算签名授权或推断持久化成功。读取状态可以独立刷新；写操作返回后优先回读受影响对象，不以连续重读全部工具状态作为显示本次结果的前提。
