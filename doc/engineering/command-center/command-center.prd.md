## 一、产品定位与目标

客户端服务 oasis7 项目负责人的个人开发工作，提供 macOS 优先的独立桌面入口。打开项目后，用户能够回答：当前最重要的目标是什么，已经验证到哪里，今天的工作依据哪些决定，哪些问题确实需要自己处理。

核心使用闭环为“看清当前重点与变化 → 选择一项工作 → 带着依据进入原工具 → 处理真实问题 → 回看结果与剩余条件”。首次采用时接续用户已有的开发现场；使用指挥中心不要求搬迁既有会话、重建任务或重复填写已经明确的上下文。

| 原始问题 | 产品应提供的结果 | 观察方式 |
| --- | --- | --- |
| 短期与长期目标分散，进度难判断 | 从当前阶段沿里程碑、工作和验收依据下钻，也能回到长期方向 | 用户能说明下一项交付、已知进展及未知范围，并打开依据 |
| 制定规范后忘记理由，决策难连续 | 可检索当前适用规则，查看理由、范围、历史后继及已保存决定 | 用户能找到当时决定和现在适用条款，分清规范与实现状态 |
| Codex 会话、分支和任务切换繁琐 | 在工作目的旁找到已有现场、PR事实及正确处理入口，通过原工具接续工作 | 用户能回到已有工作；外部处理结果沿其实际来源核实 |
| 为看板维护关系和状态耗费时间 | 复用明确引用和已保存上下文，只核对歧义或改变的关系 | 用户无需逐项复制 PR 地址、重填任务目的或每次确认同一关系 |

工程工具保持在 engineering 文档域，不增加游戏产品第五域。游戏内 Agent、玩家 Viewer 与开发 Codex 会话分别建模。

首版不承担完整 IDE、通用多租户管理平台、跨机器安装平台或自主 Agent 调度器的职责。它关联现有目标、规范和交付事实，保留必要的个人记忆；任务本身仍可只存在于 PR、已有 Issue 或受支持开发会话中。

文档索引、来源跳转和数据一致性是支撑能力。基础产品发布须完成下述日常工作闭环；仅有这些支撑能力的版本按实际范围说明为基础切片。

## 二、用户与使用场景

主要用户是同时承担产品决策、实现与交付的项目负责人。用户可能并行使用本地工作树、多个 Codex 会话和个人云端开发机，已有有效授权与项目操作习惯。

| 场景 | 用户问题 | 本次操作的完成标志 |
| --- | --- | --- |
| 开始一天的开发 | 今天最应推进什么，昨天有什么变化？ | 从首页说清近期重点、变化、剩余条件，选择下一项工作并打开正确现场 |
| 准备作出决定 | 之前为什么这么定，这次会影响什么？ | 找到适用条款及理由，能区分决定草稿、已确认内容和替代历史 |
| 多项开发并行 | 哪项工作要接着做，哪些问题需要我决定？ | 在一个工作详情中找到目标、依据、PR及已有会话入口；未知观察范围明确可见 |
| 中途离开与恢复 | 关窗口会发生什么，重新打开还能续上吗？ | 恢复项目、阅读位置及已保存个人记录，明确外部工作仍由原工具负责 |

次要使用者是按用户明确指令开发或刷新看板的 Codex。Skill 提供调用方法与按需参考，不构成实时后台服务，也不拥有产品规则的另一份副本。

## 三、信息架构与用户旅程

### 四个主视图

| 视图 | 首屏重点 | 详情与主要入口 |
| --- | --- | --- |
| 方向与进度（默认首页） | 当前重点与下一步、需要我处理、近期成果、返回进行中的工作 | 长期方向、里程碑依赖、统一工作详情、验收依据与来源覆盖 |
| 规范与决策 | 关键架构与部署索引、适用规则、个人决定 | 文档树总览、原文、边界与理由、设计/实现/实际部署分别核验、历史后继及受影响工作 |
| 开发执行 | 按工作目的组织的工作、个人问题与最近结果 | 统一工作详情、已有工具入口、原工具定位与交付来源 |
| 待我处理 | 个人问题、阻塞性问题、待选择事项 | 必要背景、选项影响、推荐理由、处理入口及保存结果 |

项目与环境选择、来源连接状态、搜索和最近成功读取时间属于共享入口。视图之间共享关联，打开 PR 或条款时保留当前筛选和返回位置。

已打开项目时，路径选择和连接配置收进上下文入口；首屏先展示用户结果。来源版本、完整身份和读取诊断在详情按需展开，影响当前判断或操作的缺口直接显示。“本机工具”是独立辅助入口，不改变四个业务主视图，资料、CLI 和 signer 按 [REQ-CC-015](#REQ-CC-015) 提供。

### 首页与统一工作详情

首页按 [REQ-CC-013](#REQ-CC-013) 的四区组织用户结果；同一工作的完整内容按 [REQ-CC-005](#REQ-CC-005) 下钻。首页和列表中的主动作首先进入正确工作或个人问题；在原工具中执行，不由指挥中心启动模型任务。

目标、执行和待处理视图均打开相同工作详情。返回恢复进入前的视图、筛选、展开、滚动位置和焦点，已保存记录按原工作和项目恢复；打开来源或辅助工具不会重建工作。在一个视图处理后，其他视图读取同一结果；结果晚到时仍归原工作，不能覆盖当前正在看的另一项工作。

### 典型旅程

1. 打开本地项目，读取已有摘要、目标、文档/Git；明确连接 GitHub 后补充真实 PR。
2. 从首页进入工作，核对结果、剩余条件和依据，打开原 PR 或已记录的外部 Codex 入口继续执行。
3. 回顾决定与关系，按需保存个人问题；回答只改变个人记录，源变化沿实际来源核实。
4. 关窗或重开后恢复阅读位置，刷新实际来源；不启动、停止、恢复或重放任何模型任务。

### REQ-CC-001：独立入口与项目上下文

Trace ID: O7-REQ-6e70287f-a156-4544-997d-5c1752e5efde

日常交付为可直接启动的 macOS App。用户无需先开终端、启动看板服务或部署中心服务；浏览器界面用于开发预览。

打开项目时识别实际仓库与工作树，显示当前项目、环境、分支和读取基线；允许切换已有项目上下文。未提交文档与已提交版本可辨认，工作树内容不能标为 main 已生效内容。

同仓库多个工作树属于一个项目阅读范围，工作树和环境仍是来源及执行边界。项目总览可以关联它们的工作；正式目标默认读取明确选定的主线基线，工作树中尚未合入的目标修改单独展示。每次动作绑定具体环境和工作树，不将总览范围当成跨环境授权。当前实现的工作树隔离数据不因此自动迁移或合并。

项目上下文入口默认只显示项目名、所选环境和必要的工作树标记；完整路径、基线及连接设置按需展开。首次未选项目时显示“打开本地项目”，已选项目后让位于首页结果。切换总览阅读范围不改变执行目标；原工具定位保留原工作树，不因阅读范围切换而重绑。

恢复上次项目时同时恢复视图偏好和阅读位置。路径不存在或仓库不匹配时，说明具体问题并允许重新选择；不静默改成另一个目录或仓库。

- 实现状态：部分实现
- 实现与验证依据：[当前源码与差距](command-center.design.md#cc-current-implementation)；[验证方法](#cc-product-acceptance)。
- 核对日期与基线：2026-10-19；文首源码基线，仅核对入口与边界，不代表整体验收。

### REQ-CC-002：来源可信与局部可用

Trace ID: O7-REQ-2d1f3577-785e-40ac-8d25-ba0d414511f6

每项重要结论能够打开来源，显示可取得的源版本、观测时间、性质和覆盖范围。性质至少区分源事实、Agent 汇报、模型归纳和待核实关联；未知字段不补造。

项目状态摘要和架构索引保留自身的来源基线、事实核验时间及覆盖范围；客户端刚刚读取文件，不代表其中的 PR、验收或部署事实也刚刚核验。摘要的归纳不因进入仓库就取得源条款或运行事实的权威。

各来源分别展示加载、成功空结果、部分读取、过期、错误和未接入。读取失败保留最近成功事实，说明哪个区域受影响；GitHub 不可用不妨碍阅读已加载规范，外部定位与实际可读取来源分别说明。

<a id="cc-source-states"></a>

| 可观察状态 | 页面如何解释 | 可执行的下一步 |
| --- | --- | --- |
| 首次加载 / 正在刷新 | 首次显示正在读取的来源；刷新保留旧内容与其时间，不将整个页面清空 | 可先阅读已可用区域；需要该来源的动作说明等待原因 |
| 成功但无匹配结果 | 明示成功读取的范围与筛选条件，不能写成“项目没有工作” | 清除筛选、展开范围或返回目标 |
| 未接入 / 查询失败 / 部分读取 | 区分尚未配置、实际失败和覆盖不全；失败说明受影响范围与最近成功时间 | 对该来源连接、重试或打开原入口，其余区域继续使用 |
| 事实陈旧 / 核验时间未知 | 同时保留事件时间、来源观测时间和摘要内部核验时间；旧摘要上新鲜的文件读取时间不改变结论 | 核对受影响来源；无新结果时继续保留旧依据及限制 |
| 源事实与摘要冲突 | 当前源事实在其职责字段显示；同项旧判断及版本放在冲突详情，不把整个工作改为未知 | 打开两方依据，核实需要修订的摘要或关系，不自动回写 |

GitHub来源区只管理连接、账号、页范围补读与错误，不重复渲染PR行；所有PR统一进入工作列表与详情。同一失败在来源级集中解释，工作行只标记其具体影响。没有可用依据的结论保持未知；部分 PR 窗口之外的对象不得被推定不存在或已经完成。

刷新读取既有事实或订阅已支持事件，不暗含模型运行、Git fetch、分支切换或远端写入。需要分析或执行的动作另有明确入口，沿用实际授权。

### REQ-CC-003：短期与长期目标及进度

首页先呈现当前阶段与近期交付，长期方向保持可见且层级独立。当前阶段读取 core PRD 的“当前阶段交付目标与全局 P0”及其主责引用，不采用文件开头历史里程碑作默认。沿“长期目标—里程碑—关联工作—验收依据”下钻；工程支撑工作可独立筛选，沿用项目既有产品分类。

已有关联来源沿 [REQ-CC-014](#REQ-CC-014) 复用。未知分母时仍提供已核实成果、剩余条件及可执行的下一步；缺少总体百分比不应使页面退化为只列原文或统一显示未知。

目标、阶段和依赖来自当前主责文档或用户明确确认的关系。一个工作可关联多个目标；未确认关系显示为建议，不自动成为依赖或阻塞，不把长期愿景的全部内容提升为当前前置条件。

明确列出完成条件、已核实部分、尚未覆盖或未知部分。只有适用验收集合、分母与结果均可核实时，展示“已验证项 / 适用项”；其他情况使用文字说明，不生成总体完成率。

保留[项目状态](README.md)的持续阅读入口，集中呈现长期方向、短期目标、目前进度、最近做了什么及下一步。近期变化写清所选窗口、变化对目标的影响、实际结果和来源；聚合同一结果的碎片活动，不用提交数量替代成果。没有可靠上次阅读基线时，不宣称这是“自上次查看以来”的完整变化。

状态页按[持续更新流程](command-center.manual.md#cc-maintenance-triggers)随有关工作与回顾维护，是首页摘要的已有承载来源。客户端提供直接入口及按 [REQ-CC-013](#REQ-CC-013) 组织的首页投影；读取不完整或摘要与源冲突时保留已知部分及时间。当前通用检索入口仅满足来源可读，专用汇总仍按实际实现说明；文档存在不代表后台服务已启动。

- 实现与验证依据：[当前源码与差距](command-center.design.md#cc-current-implementation)；[验证方法](#cc-product-acceptance)。

### REQ-CC-004：规范与决定的连续性

Trace ID: O7-REQ-eb004bfb-41c7-4e8f-aa5b-1f52cec6cf08

按事项范围展示当前规则摘要、主责条款、理由、源版本和后继关系，支持中文、标题、路径与条款 ID 搜索。历史工作可以打开当时依据，也能找到现行条款。

提供[顶层架构索引](architecture/README.md)，按总体分层、环境/部署、世界权威、存储恢复、接入权限及两类 Agent 等问题定位主责条款。每项保留关键边界、适用范围、理由入口和值得重新关注的变化；部署相关项分别展示设计约定、已有实现及最近实际环境核验，历史清单或设计图不能当作当前在线拓扑。索引以原文为依据，不复制为另一份架构规范。

规范效力依据主责身份和显式替代关系；修改时间、被引用次数和模型记忆不能单独决定优先级。无法消解的冲突列出来源及受影响结论，不让无关工作一并阻塞。

### REQ-CC-010：中文与可读的信息交互

Trace ID: O7-REQ-76d54ed7-4028-460a-b22b-37a9088ad245

默认密度优先保证用户能快速辨认任务、结果和动作，并有足够留白连续阅读中文；不以首屏显示最多字段或缩小文字为目标。列表用于扫描，表格只用于必要比较，图形用于解释真实关系与事件，正文、证据和表单按任务展开。支持键盘导航、可见焦点、明确标签；状态同时使用文字，不仅以红绿颜色区分。用户于 2026-10-18 明确不需要 VoiceOver 相关功能，因此 VoiceOver/读屏适配与专项验证不在本产品范围，也不作为验收或 Issue 关闭条件；现有标准标签、文字状态与键盘操作保留。

默认用用户能行动的名称显示重点、工作和问题。完整 SHA、外部会话定位及来源路径在详情保留；首页只突出影响判断的来源时效、缺口及动作条件。空状态说明下一项可做操作，配置成功后回到原工作；提示按来源聚合，避免同一缺口在每行重复占据首屏。

<a id="cc-ui-hierarchy"></a>

默认层级为“页面任务与主动作 → 工作名/结论/下一步 → 来源时效及具体缺口 → 按需诊断”。页面标题、区标题、工作目的和辅助说明有明确层次；重点区、待答区、成果时间线与返回列表使用不同的视觉权重，不套用等重文字卡。主导航、PR 状态、置顶与个人待答使用一致的库图标配短标签，未知使用独立问号状态。统一工作列表提供带图标、文字和已读匹配数量的状态筛选，不能把局部数量表述为全局完整进度；首页返回保留置顶和明确打开记录优先，无个人记录的其余项优先显示进行中 PR，已读历史仍可查看。首页用目标标题、明确关联数量或未知标签、紧邻的下一动作组成紧凑图标路线，完整目标原文默认折叠；不从长段落自动提炼新目标，也不把缺少关联写成目标没有工作。选中工作后，旁列表的文本和状态筛选默认折叠为可展开摘要，保留当前条件及已读匹配数；概览将来源与核验长说明集中在默认折叠入口，短未知标签、具体读取错误和待答问题仍直接可见。窄窗口合并页面标题与导航，显示设置进入项目入口，全局搜索按需展开，使主操作及返回工作先于长原文出现。工作概览仅在存在明确关系时提供可点击的局部关系图，无关系时显示紧凑提示与关联入口，不重复整块工作标题；只连接当前工作与已保存或明确来源的目标；原文未读、版本变化及无关系分别可见，连线不表示进度或因果。产品文档根按明确声明的四域呈现首屏可识别的紧凑图标地图与匹配文件数；搜索与维护说明让位于域入口。打开文档直接阅读有效恢复章节或首个有内容章节，宽窗口左目录右正文，窄窗口目录可折叠；显式配对在正文前可见，完整路径和字节数归详情。展开后沿原树阅读，域标题和专题保持紧凑图标/短行布局，来源路径及声明默认折叠，影响所选项的错误与边界提示保持可见；数量仅为本次筛选的去重文件数。配对图只连接显式声明的原文与可定位目标，节点以可读文档名或原目标文件名呈现，可定位目标直接打开；完整路径和声明行按需展开，读取状态及未解析诊断保持可见。窄窗口使用同一紧凑关系结构，让正文先于技术身份。高级筛选、完整版本与操作说明按需展开，错误与范围缺口直接可见。图标配短标签表达对象类型和已知状态；关系线只表达来源明确或用户确认的关系，建议线必须标“待核实”。没有可证明的分母不画进度环/百分比，没有关系或事件时不补装饰性连线、趋势和时间点。

常规与紧凑窗口沿[视觉构成设计](command-center.design.md#cc-visual-composition)采用明确的正文、辅助文字、主操作高度和分区留白基准。每一可操作对象默认只突出一个主动作，其他动作收进就近菜单；工作标题优先用简短目的表达，长中文自然换行，行高随内容增长。确需收起时保留明确全文入口，不能裁掉区分工作所必需的信息。危险警告、真实待答原因、执行目标差异和未知发送结果保持可见，不能被标题截断或藏进提示浮层。长文本、完整身份和证据按需阅读，首页不嵌套多块长正文滚动区。

| 2. 需要我处理：条件式高关注区 | 有真实请求时与当前重点同层呈现；短问题、受影响工作、等待原因和真实数量，按原请求顺序。无请求时收成说明观察范围的轻状态，不占一个等高空卡 | “处理请求”进入原工作中的准确问题；默认预览之外保留“查看其余”及已知数量，全部真实请求可达；无请求不等同全局无阻塞 |
| 3. 近期成果：事件时间线 | 默认用户时区的今天及前六个自然日，明确显示时区与起止时间，今天截至本次观察时刻；按实际事件时间从新到旧呈现短结果、对目标的影响及来源入口，同一事件不重复计数。可改窗口，有可靠基线才提供“自上次查看” | “查看结果”进入原工作及证据；预览之外显示其余结果入口和覆盖范围。成功空说明窗口；事件时间未知的观察单列，不混入时间线 |
| 4. 返回工作：轻量列表 | 用户最近打开或置顶的已有工作，每行目的、最新已知结果及返回动作；原工具和上次位置作辅助说明。私有正文和派生私有内容不进入首页 | “继续工作”回原详情或可信原入口；保留其余工作入口。无阅读记录时提供当前已知工作，不生成虚假最近活动 |

首页各列与长标题、路径、版本标识必须能收缩和换行，不产生页面级横向溢出。旧摘要核对按原章节及版本聚合，默认仅显示受影响章节数量和展开入口；展开后保留原声明、所有关联 PR 身份及双方依据，公共边界只说明一次，不按 PR 重复整段摘要。

常规窗口先呈现主要重点与真实关注；没有个人待答问题时，返回工作与重点同层呈现，成果时间线随后展示。紧凑窗口按重点、真实关注、返回工作、成果顺序阅读。四区不要求等宽、等高或在一屏装满，来源诊断与配置不参与争夺主视觉。缺少可靠摘要时保留已确认工作的直接入口；只有缺少工作关系的目标回退为有限原文摘要。未接入、加载、已读为空、错误、陈旧和冲突按 [REQ-CC-002](#REQ-CC-002) 就近简要解释，不能把同一来源提示复制成每行长段落。

“待我处理”默认直接呈现未决个人问题、相关工作及处理操作，不重复通用 PR 工作列表。没有未决问题时显示当前个人记录范围的空状态与工作入口；已处理历史按需展开。个人记录未读取或读取失败不得显示无问题；原工作暂不在来源窗口时仍保留问题与原身份，提供补读路径。

待回复数量在共享导航保持可见，不因三项重点限制、窗口高度或预览截断隐藏真实请求。已读结果超出预览时始终给出“查看其余”入口；来源尚未完整读取时说明已知范围，不把未知总量写成精确剩余数。首页不再并列重复呈现同一批 PR、原始百项章节及一套工作列表；全量查找进入相应工作/文档入口，来源读取预算保持原约定。

每项重点的目标、已核实成果、剩余条件、下一动作、关联工作及来源时效均可从该重点或详情查到；默认只突出工作目的、当前结果和下一动作。目标或剩余条件摘要仅在直接影响当前判断时出现，完整依据与来源按需查看，影响判断的时效和缺口保持可见。下一动作复用主责条款或用户明确保存的选择；新的分析建议标明性质和依据，经用户采用后才成为个人计划，不自动改写正式目标、依赖或权限。

目标/完成条件取自主责文档，阶段叙述复用项目状态，PR事实取自GitHub；项目摘要中人工核实的 CI/运行结果保留其原来源与时间，不转成 App 检查详情。源事实与摘要冲突时，仅受影响结论列出冲突和核对入口，其余可用区域继续展示；新读取旧摘要不刷新内部事实时间。没有摘要或关系时仍展示可读取目标、Git 和已确认工作，说明具体缺口与补充入口。

近期成果按实际结果聚合，同一交付的提交、PR及验证不重复计为成果；事件时间、观测时间和比较窗口分别保留。首页读取和刷新不启动模型或仓库写入；模型分析通过用户明确选择的单独动作提供。

## 五、状态与进度的解释

| 来源或状态 | 可以说明 | 仍须单独核实 |
| --- | --- | --- |
| 文档为 active | 对应文档身份及条款效力 | 能力是否已实现、是否通过验收 |

## 六、验证与验收条件

下表是客户端功能的产品验收，不为每次文档或一般开发任务增加完整运行要求。实现时按改动覆盖对应条件，系统设计映射可自动化、旧库兼容回归与真实桌面验证。

| 稳定条款 | 对应需求 | 场景与通过条件 |
| --- | --- | --- |
| <a id="AC-CC-001"></a>AC-CC-001 | [001](#REQ-CC-001) | 从 macOS 正式 App 入口打开真实项目，无需终端启动后端；显示正确工作树及基线，重开恢复位置，项目打开后配置折叠，错误路径可修复；同仓库两工作树进入一个阅读总览，原个人数据和控制身份不混并；切换阅读范围不改变待发送任务的环境 |
| <a id="AC-CC-002"></a>AC-CC-002 | [002](#REQ-CC-002) | 成功空、未接入、失败、部分读取分别可辨且有对应动作；失败保留可用事实与范围，来源跳转正确，慢来源不阻塞已可用区域；旧摘要称 PR 未合入而源已合入时显示当前事实、旧判断及各自时间，不因读取文件刷新事实时效，不波及无关工作 |
| <a id="AC-CC-003"></a>AC-CC-003 | [003](#REQ-CC-003) | 一个 PR 服务两个目标且无 Issue 时可关联下钻；验收分母未知不显示百分比，长期未实现项不自动成为当前阻塞；能从状态入口读到长期/短期目标、当前进展和有明确窗口的最近变化，并下钻来源 |
| <a id="AC-CC-004"></a>AC-CC-004 | [004](#REQ-CC-004) | 规则与历史后继可定位；决定只保存内容、理由、范围和正式文档关联，草稿/确认/替代历史与原确认时间可辨；重开和缓存重建保留记录，旧同步数据不改写且无现行投影/写入口，待我处理不出现决定同步面板。 |
| <a id="AC-CC-005"></a>AC-CC-005 | [005](#REQ-CC-005) | 同一工作从各视图进入同一概览/依据/历史详情，主区替换与返回位置正确；原 PR 及外部会话打开/复制入口可用；来源诊断区无第二套PR行；检查状态通过原 PR 在 GitHub 查看，App仅导航，不宣称外部结果。 |
| <a id="AC-CC-006"></a>AC-CC-006 | [006](#REQ-CC-006) | 个人问题可新增、回答、关闭并重开保留；空状态与个人处理结果准确，个人记录与源事实可区分。 |
| <a id="AC-CC-007"></a>AC-CC-007 | [007](#REQ-CC-007) | 正确保存、打开/复制外部定位；非法协议/UUID/附加路径/query/fragment拒绝，错误可恢复，返回原工作与焦点。 |
| <a id="AC-CC-008"></a>AC-CC-008 | [008](#REQ-CC-008) | 含旧 enabled/active/unknown/未决/私有记录的真实格式数据库打开后原数据保留；刷新、缓存重建、重开均不重放。 |
| <a id="AC-CC-009"></a>AC-CC-009 | [009](#REQ-CC-009) | 关窗后菜单栏恢复；完整退出保留独立工具任务保护，外部工作不受影响。 |
| <a id="AC-CC-010"></a>AC-CC-010 | [010](#REQ-CC-010) | 按下述视觉与窗口场景核对默认密度、主次、真实图形、一个局部主动作和来源展开；长中文及 150%/200% 放大不裁掉必要信息、不缩字塞首屏，危险/真实待答/未知结果不被隐藏；错误就地可辨且不抢编辑焦点；保留两字搜索、IME Enter 不误发、返回焦点及长列表/日志缺口，VoiceOver 不纳入 |
| <a id="AC-CC-011"></a>AC-CC-011 | [011](#REQ-CC-011) | 重启或重建索引后个人关联、阅读位置、草稿、已确认决定及未决操作保留；检查诊断与发布资源无凭据，展示内容不能触发本机操作 |
| <a id="AC-CC-012"></a>AC-CC-012 | [012](#REQ-CC-012) | GitHub不可用或本机工具缺失时，本地阅读与个人记录仍可用；来源缺口只影响相关操作。 |
| <a id="AC-CC-013"></a>AC-CC-013 | [013](#REQ-CC-013) | 四区有明确主次而非等重文字卡，已有关系直接进入对应工作，无关系才有限目标回退；未知分母、无排序、空/旧/冲突均有解释和动作，三项重点不隐藏同级及真实请求；近七个自然日有明确时区/边界、按事件倒序、未知事件单列、结果去重及其余入口；无重复 PR/章节主列表，刷新不运行模型 |
| <a id="AC-CC-014"></a>AC-CC-014 | [014](#REQ-CC-014)、[005](#REQ-CC-005)、[007](#REQ-CC-007) | 已有关系直接复用，一个工作关联两目标且多会话不串联；依据图示不虚构关系，编辑只在选择关联/修复后打开；候选有依据且默认不手填已有 PR，旧关系可逐项修复/移除而不改源任务；保存/取消返回原页签和位置，只读原入口正确，跨视图/重开不重填上下文，未核实不显示完成 |
| <a id="AC-CC-015"></a>AC-CC-015 | [015](#REQ-CC-015) | 按任务进入资料、快照、签名/独立验签及 CLI；导出和恢复各自收集口令并明确范围；签名上下文导入不生成授权，无 signer 仍可独立验签；结果就地显示并安全返回原工作，私有内容不外溢；缺失工具不阻塞无依赖工作，暂停能力不开放 |
| <a id="AC-CC-016"></a>AC-CC-016 | [016](#REQ-CC-016) | 首次按产品/专业上下文进入阅读树，当前主题的标题/段落/列表/代码块有清楚层级，原文与配对先于诊断；三分钟内定位四域产品专题及其设计、engineering 工具及其专业设计；多对多不复制，搜索保留祖先；无配对/未读/断链/歧义/历史/未提交/限额/读取失败分别可辨；返回/重开恢复位置，真实 App 键盘/窄窗可用，刷新无模型或写入 |

### 视觉与窗口场景

本表细化 AC-CC-005/007/010/013/014/016 的体验判据；具体尺寸、文字与控件基准由[系统视觉构成](command-center.design.md#cc-visual-composition)承接。实现后在真实 App 使用代表性长中文、真实来源与标明性质的回放样本验证；文档检查不代签这些场景，原功能验收只保留原范围。

| 场景 | 可观察通过条件 |
| --- | --- |
| 常规窗口：1280×830、1440×900 | 首先辨认当前重点和真实待答，有关系可直接进入工作；成果时间线与返回列表为次级阅读，不出现四块等重长文或重复百项来源列表。无需展开原文、完整身份或输入表单即可说清一行工作的目的、结果和下一步 |
| 紧凑窗口：1024×768、728×627 | 改为适用的单主内容布局，工作详情不在首页下方；输入、工具及依据阅读后能返回原位置。允许纵向滚动，不缩字号维持并排，不横向裁掉标题展开、状态或操作 |
| 长中文及 150% / 200% 放大 | 按系统基准的代表性常规/紧凑组合完成定位、查看依据、编辑和返回；标题可展开、操作可换行，个人问题和工具危险/未知警示完整。放大前后仍是原工作与原来源，草稿保留；不要求所有分区同时出现在首屏 |
| 空、错误、未知与超出预览 | 无请求时显示轻状态；加载不冒充成功空，失败保留旧结果。真实待答即使超出预览仍有数量与完整入口，未知总量不造剩余数。未知事件不伪入时间线，无法证明的关系不画成已确认；来源/诊断展开不改变事实或触发运行 |

### 日常工作闭环的整体验收

采用真实代表性项目：至少三项近期工作，含一个 PR 服务两个目标、一个 PR 尚无会话、两个不同的原工具定位。来源窗口同时包含真实结果、一个真实个人问题、一个已确认决定、一个普通知悉变化，以及一项旧摘要与当前 PR 事实冲突。验收环境可使用受控来源/存储回放构造稀有故障，但真实桌面导航、输入和返回操作仍在 App 中执行；样本不得把回放状态说成外部工具的实际运行状态。

| 用户任务 | 通过条件 |
| --- | --- |
| 开始一天 | 可用来源加载完成后，用户五分钟内说清当前重点、已核实成果和主要剩余条件；从首页找到下一项工作并进入正确工具或详情，无需搜索状态页、通读原始 PRD或手填已有 PR 地址。没有明确排序时能看见并列项与缺口 |
| 处理中断 | 从首页找到一个真实待处理事项，在同一工作上下文理解原因与选项，记录个人回答或打开原工具处理；回到原工作查看实际结果或明确待核实状态。刷新不重新请求已处理事项，也不将普通知悉提醒列为待批准 |
| 恢复工作 | 关窗后保留当前个人编辑；完整重开后回到原工作、筛选、阅读位置及已保存记录；明确时间窗口内的变化可下钻来源。来源不可用时保留最后结果，原环境与个人记录可核对，不要求重建已有工作 |

同时记录各任务的完成情况、耗时、额外搜索/切换/录入和具体卡点。五分钟衡量已可用数据下的理解与定位；首次加载另记实际耗时、数据量与可用反馈，不能从一次样本推导启动性能保证。纯设计交付只核对这些条件是否完整可执行，不冒充实际用户验收。

## 七、首版范围、风险与后续扩展

现行产品围绕“判断下一步—阅读依据—进入原工具—记录个人结果”工作。工程工具保持在 engineering 文档域；游戏Agent、部署控制、通用IDE及远端执行宿主不在范围内。CI查看与开发执行沿文首所述原工具边界。

文档树、本机工具、私有数据与界面验收分别沿对应条款和专题设计；未证明范围在系统设计 §3 记录。公开分发、证书、自动更新和其他桌面系统按实际需求另行验证，旧验收不扩大到新环境。
