## 一、产品定位与目标

指挥中心服务 oasis7 项目负责人的个人开发工作。用户从一个私有的 Sites 网页入口进入项目，不需要先启动本地应用；登录后能够回答：当前最重要的目标是什么，已经验证到哪里，今天的工作依据哪些决定，哪些问题确实需要自己处理。更换设备后仍使用同一套已保存记录和工作上下文。

核心使用闭环为“看清当前重点与变化 → 选择一项工作 → 带着依据进入原工具 → 处理真实问题 → 回看结果与剩余条件”。首次采用时接续用户已有的开发现场；使用指挥中心不要求搬迁既有会话、重建任务或重复填写已经明确的上下文。

| 原始问题 | 产品应提供的结果 | 观察方式 |
| --- | --- | --- |
| 短期与长期目标分散，进度难判断 | 从当前阶段沿里程碑、工作和验收依据下钻，也能回到长期方向 | 用户能说明下一项交付、已知进展及未知范围，并打开依据 |
| 制定规范后忘记理由，决策难连续 | 可检索当前适用规则，查看理由、范围、历史后继及已保存决定 | 用户能找到当时决定和现在适用条款，分清规范与实现状态 |
| 工程模块、依赖和开发规范分散，难以形成全局认识 | 从分层架构图下钻模块、组件、源码与适用规范，并看到版本变化及 dot 维护状态 | 用户能解释一条关键关系、找到修改依据，并识别覆盖缺口 |
| Codex 会话、分支和任务切换繁琐 | 在工作目的旁找到已有现场、PR事实及正确处理入口，通过原工具接续工作 | 用户能回到已有工作；外部处理结果沿其实际来源核实 |
| 为看板维护关系和状态耗费时间 | 复用明确引用和已保存上下文，只核对歧义或改变的关系 | 用户无需逐项复制 PR 地址、重填任务目的或每次确认同一关系 |

工程工具保持在 engineering 文档域，不增加游戏产品第五域。游戏内 Agent、玩家 Viewer 与开发 Codex 会话分别建模。

产品各面的职责如下；来源的位置不改变其语义权威。

| 产品面 | 承担的能力 | 数据与权限边界 |
| --- | --- | --- |
| 云端工作台 | 四主视图、统一工作详情、目标与依据、完整文档树、工程架构与规范视图、来源刷新和个人空间 | 已提交项目资料从明确授权的 GitHub 来源读取；决定、问题、关系、阅读位置和显示偏好的持久真值在云端 |
| 本地设备组件 | 工作树与未提交文件阅读、私有资料、CLI、signer 和原生工具 | 文件、密钥、私有正文与工具操作留在本机；不承担第二套可写个人业务库，不复制全部核心 UI |
| 原工具 | GitHub 的审阅、日志和重跑，Codex 的开发执行及其他明确工具操作 | 指挥中心提供准确入口；页面刷新、恢复或导航不启动模型、执行命令或取得原工具权限 |

产品不承担完整 IDE、团队协作管理平台、跨机器安装平台或自主 Agent 调度器的职责。它关联现有目标、规范和交付事实，保留必要的个人记忆；任务本身仍可只存在于 PR、已有 Issue 或明确记录的外部开发会话中。

文档索引、来源跳转和数据一致性是支撑能力。基础产品发布须完成下述日常工作闭环；仅有这些支撑能力的版本按实际范围说明为基础切片。

## 二、用户与使用场景

主要用户是同时承担产品决策、实现与交付的项目负责人。用户可能在多台设备上访问同一站点，并行使用本地工作树、多个 Codex 会话和个人云端开发机，已有有效授权与项目操作习惯。登录站点与取得 GitHub 或本机工具权限是不同条件。

| 场景 | 用户问题 | 本次操作的完成标志 |
| --- | --- | --- |
| 开始一天的开发 | 今天最应推进什么，昨天有什么变化？ | 从首页说清近期重点、变化、剩余条件，选择下一项工作并打开正确现场 |
| 准备作出决定 | 之前为什么这么定，这次会影响什么？ | 找到适用条款及理由，能区分决定草稿、已确认内容和替代历史 |
| 多项开发并行 | 哪项工作要接着做，哪些问题需要我决定？ | 在一个工作详情中找到目标、依据、PR及已有会话入口；未知观察范围明确可见 |
| 中途离开与恢复 | 关窗口会发生什么，重新打开还能续上吗？ | 恢复项目、阅读位置及已保存个人记录，明确外部工作仍由原工具负责 |
| 更换设备或暂时断网 | 哪些内容已经保存，哪些还只在这台设备？ | 同账号读取云端确认的记录；离线输入明确为未保存草稿，恢复网络后由用户核对再提交，不能用另一台设备的旧值覆盖新记录 |

次要使用者是按用户明确指令开发或刷新看板的 Codex。Skill 提供调用方法与按需参考，不构成实时后台服务，也不拥有产品规则的另一份副本。

## 三、信息架构与用户旅程

### 四个主视图

| 视图 | 首屏重点 | 详情与主要入口 |
| --- | --- | --- |
| 方向与进度（默认首页） | 当前重点与下一步、需要我处理、近期成果、返回进行中的工作 | 长期方向、里程碑依赖、统一工作详情、验收依据与来源覆盖 |
| 规范与决策 | 工程架构、适用规则、个人决定 | 分层图与模块下钻、文档树总览、原文、边界与理由、设计/实现/实际部署分别核验、版本变化与历史后继 |
| 开发执行 | 按工作目的组织的工作、个人问题与最近结果 | 统一工作详情、已有工具入口、原工具定位与交付来源 |
| 待我处理 | 个人问题、阻塞性问题、待选择事项 | 必要背景、选项影响、推荐理由、处理入口及保存结果 |

四个主视图及统一工作详情由云端工作台提供。项目与环境选择、来源连接状态、搜索和最近成功读取时间属于共享入口。视图之间共享关联，打开 PR 或条款时保留当前筛选和返回位置；本机辅助界面只处理依赖该设备的阅读或工具任务。

已打开项目时，仓库连接与环境选择收进上下文入口；本地路径只在相应设备界面核对。首屏先展示用户结果。来源版本、完整身份和读取诊断在详情按需展开，影响当前判断或操作的缺口直接显示。“本机工具”是独立辅助入口，不改变四个业务主视图，资料、CLI 和 signer 按 [REQ-CC-015](#REQ-CC-015) 提供。

### 首页与统一工作详情

首页按 [REQ-CC-013](#REQ-CC-013) 的四区组织用户结果；同一工作的完整内容按 [REQ-CC-005](#REQ-CC-005) 下钻。首页和列表中的主动作首先进入正确工作或个人问题；在原工具中执行，不由指挥中心启动模型任务。

目标、执行和待处理视图均打开相同工作详情。返回恢复进入前的视图、筛选、展开、滚动位置和焦点，已保存记录按原工作和项目恢复；打开来源或辅助工具不会重建工作。在一个视图处理后，其他视图读取同一结果；结果晚到时仍归原工作，不能覆盖当前正在看的另一项工作。

### 典型旅程

1. 登录私有站点，选择已授权仓库与明确提交基线，读取目标、文档树、项目摘要和真实 PR/CI 范围；恢复同一账号已保存的工作上下文。
2. 从首页进入工作，核对结果、剩余条件和依据，打开原 PR 或已记录的外部 Codex 入口继续执行。
3. 回顾决定与关系，按需保存个人问题；云端确认后才能显示已保存。回答只改变个人记录，源变化沿实际来源核实。
4. 需要查看未提交文件、私有资料或操作 signer/CLI 时，明确进入本机辅助界面；核对原工作和目标设备，材料不因导航上传。
5. 重开页面或换设备后恢复云端已保存的阅读位置；未提交输入仅在当前浏览器或设备会话内存中作为草稿，关闭会话不保证恢复。刷新与恢复不启动、停止或重放任何模型或本机任务。
6. 准备修改或评审时，从“工程架构”看全局，再搜索模块、crate/工具或路径，查看职责、已确认关系及适用规范；进入同版本原文/代码后返回原对象。来源更新后可比较变化，读不全或尚待核对的部分直接可见。

## 四、产品需求与设计条款

以下要求是目标合同；每条状态卡分别说明设计覆盖和实现范围，不把文档补全视为功能交付。证据共用[固定基线与验收边界](#cc-product-evidence-baseline)，具体剩余实现由实际 Task/PR 跟踪。

<a id="cc-product-evidence-baseline"></a>

### 核对基线与证据范围

本文描述最终产品合同。实现核对区分本地现有能力、Sites 已有基础切片和本文新增的组合义务；源码存在、页面可打开或文档已采纳均不证明组合验收通过。自动测试、浏览器操作、本机导航和整体验收必须分别提供实际结果。历史测试、IME 人工确认和旧功能记录保存在[日常验证记录](daily-work-verification.manual.md)，不扩大到新的云端入口或跨设备范围。

Sites v6 已有云端个人记录、交付摘要、原文阅读及相应接口验证，不能继续用旧版基础切片概括全部能力。下列状态卡只更新有固定来源支持的范围；真实登录、浏览器交互、双设备、正式目标绑定、旧数据迁移和本机往返仍按各自证据单独核实。文档要求已覆盖与功能已验证分别判断。

云端范围包含已提交文档、只读 GitHub Issue/PR/CI、个人空间、原工具安全导航与四主视图；本机保留未提交材料、私有资料和设备工具。CI 摘要必须绑定准确工作、候选提交、运行类型与覆盖，详情、日志、重跑和写操作仍在 GitHub；开发执行在原 Codex 工具完成。VoiceOver 不在验收范围；Apple 签名/管理员集成保持暂停。实施次序、数据搬迁和交付进展由对应 Issue/PR 承载，不构成本文的另一套产品阶段。

### REQ-CC-001：独立入口与项目上下文

Trace ID: O7-REQ-6e70287f-a156-4544-997d-5c1752e5efde

日常入口是可直接访问的私有 Sites 工作台。用户无需先开终端、启动本机服务或运行桌面 App，便可使用已授权的云端来源和个人空间。本地组件只在用户需要设备能力时使用，macOS 为本机能力的受支持入口；本地未启动不阻塞云端日常阅读和保存。

打开云端项目时识别稳定的仓库身份，显示当前项目、所选环境或阅读范围、分支和固定提交基线，并允许切换已有上下文。仓库重命名、设备更换或本地目录不同不产生新的个人项目。站点账号与来源连接分别展示，不能把站点登录解释为 GitHub 授权。

同仓库的已提交工作可以进入同一项目总览，环境和阅读范围仍是独立边界。正式目标默认读取明确选定的主线基线。工作树、未提交变更和私有材料只在本机界面查看，不因来源刷新或打开项目上传。每次本机导航保留原设备路由和环境意图，由本机解析实际路径；切换云端阅读范围不重绑设备目标，也不构成执行授权。

项目上下文入口默认只显示项目名、所选环境和必要的来源标记；完整提交身份与连接设置按需展开。首次未选项目时显示“选择项目”，已选项目后让位于首页结果。本机路径和私有配置不作为云端身份字段，也不要求上传后才能使用站点。

恢复上次项目时按 [REQ-CC-017](#REQ-CC-017) 读取同一账号已保存的视图偏好和阅读位置。仓库权限不足或基线不可读取时保留原身份并说明缺口；本机路径失效由本机修复，不静默改成另一仓库或目录。

- 实现状态：部分实现
- 实现与验证依据：[当前能力与差距](command-center.design.md#cc-current-implementation)；[验证方法](#AC-CC-001)。

### REQ-CC-002：来源可信与局部可用

Trace ID: O7-REQ-2d1f3577-785e-40ac-8d25-ba0d414511f6

每项重要结论能够打开来源，显示可取得的源版本、观测时间、性质和覆盖范围。性质至少区分源事实、Agent 汇报、模型归纳和待核实关联；未知字段不补造。

项目状态摘要和架构索引保留自身的来源基线、事实核验时间及覆盖范围；客户端刚刚读取文件，不代表其中的 PR、验收或部署事实也刚刚核验。摘要的归纳不因进入仓库就取得源条款或运行事实的权威。

各来源分别展示加载、成功空结果、部分读取、过期、错误和未接入。读取失败保留最近成功事实，说明哪个区域受影响；GitHub 不可用不妨碍阅读已加载规范，外部定位与实际可读取来源分别说明。

<a id="cc-source-states"></a>

| 可观察状态 | 页面如何解释 | 可执行的下一步 |
| --- | --- | --- |
| 首次加载 / 正在刷新 | 首次显示正在读取的来源；刷新保留旧内容与其时间，不将整个页面清空 | 可先阅读已可用区域；需要该来源的动作说明等待原因 |
| 成功但无匹配结果 | 明示成功读取的范围与筛选条件，不能写成“项目没有工作” | 清除筛选、展开范围或返回目标 |
| 未接入 / 查询失败 / 部分读取 | 区分尚未配置、实际失败和覆盖不全；失败说明受影响范围与最近成功时间 | 对该来源连接、重试或打开原入口，其余区域继续使用 |
| 事实陈旧 / 核验时间未知 | 同时保留事件时间、来源观测时间和摘要内部核验时间；旧摘要上新鲜的文件读取时间不改变结论 | 核对受影响来源；无新结果时继续保留旧依据及限制 |
| 源事实与摘要冲突 | 当前源事实在其职责字段显示；同项旧判断及版本放在冲突详情，不把整个工作改为未知 | 打开两方依据，核实需要修订的摘要或关系，不自动回写 |

GitHub来源区只管理连接、账号、页范围补读与错误，不重复渲染PR行；所有PR统一进入工作列表与详情。同一失败在来源级集中解释，工作行只标记其具体影响。没有可用依据的结论保持未知；部分 PR 窗口之外的对象不得被推定不存在或已经完成。

云端文档刷新只从已授权的 GitHub 仓库读取已提交内容，并把文件树、正文、章节和显式关系绑定到同一提交。PR 与 CI 按各自实际观察窗口标注；全仓最近 Actions 不得替代某个 PR 的准确候选检查，提交不匹配、运行类型不适用或覆盖缺失时保持未核实。

交付摘要必须分别说明“与已读输入是否一致”和“相关交付证据读取到哪里”。摘要刚生成、缓存版本一致或逐字引文存在，只能证明对应性质，不能把有限输入包装成完整证据。对已收录工作，应在已声明预算内补读显式修复/关闭关联、关联 PR 的交付反馈及与其准确候选匹配的验证；已关闭工作与旧摘要冲突、有关交付位于近期窗口外时优先补读。普通交叉引用、标题相似及关闭事实本身不构成修复或验收证据。

| 当前可取得的依据 | 允许的结论 | 必须保留的边界 |
| --- | --- | --- |
| 只有旧 Issue 的问题描述，修复关系或后续反馈尚未读取 | 这是原工作要解决的问题，当前结果待核对 | 不得写成“当前缺陷仍存在”或“没有修复” |
| 已取得对应范围的交付，但验证未取得或尚未完成 | 已交付该部分，验证待补或待完成 | 区分未读取与实际未执行；不能推导整体目标失败或通过 |
| 有适用于当前候选和范围的失败或明确未解决反馈 | 该范围仍有失败或未解决问题 | 保留候选、环境、反馈时间及后续变化，历史失败不自动沿用到新候选 |
| 有准确版本与范围的通过结果 | 该范围已有验证支持 | 未覆盖的部署、整体体验、后续收益和目标条件继续单列 |

一个工作允许同时具有已交付、已验证、仍失败和证据待补的不同部分；后续任务尚未完成不能抹掉原交付，原交付通过也不自动满足后续目标。归纳规则纠错后，即使来源文字未变，也须能定向重算受影响摘要并保留旧结论与原依据；等待重算或失败时显示旧结果及原因，不把旧的“与输入一致”标记沿用为纠错完成。

用户可手动刷新，也可为公开来源配置后台刷新。后台读取须有独立可用的来源访问、受限服务身份和明确范围，不依赖用户保持网页打开或借用页面登录态；服务身份不读取非公开来源，也不代写个人记录。页面展示是否已配置、最近尝试、最近成功和当前异常，并允许停用；未配置不能声称持续更新。后台刷新只读既有事实，不写仓库、不运行模型，不扫描或上传本机资料。

用户也可明确请求一次或按约定频率执行独立的交付摘要任务，将已授权公开来源中的目标、Issue/PR 与验证反馈归纳成有依据的结果说明。独立任务可通过已连接 GitHub 的既有授权读取固定公开仓库，再经受限入口更新公开来源派生缓存；读取通路、实际读取时间和覆盖须可追溯。该来源写入不取得站点用户的个人身份，不向 Site 转交连接器权限，也不绕过私有仓库的访问限制。该任务与普通来源刷新分别配置和显示状态；页面打开、刷新、缓存缺失或来源变化均不自动启动或补跑模型。摘要保留模型归纳性质、生成时间、输入来源与覆盖，仅作为可重建的云端阅读缓存，不写仓库、个人记录或正式目标，不启动 Coding Agent 或本机操作。部分读取、任务失败及原依据被编辑时，保留最近成功结果并标明受影响结论的旧版本和缺口，不能把新读取时间当作重新核实。

### REQ-CC-010：中文与可读的信息交互

Trace ID: O7-REQ-76d54ed7-4028-460a-b22b-37a9088ad245

<a id="cc-ui-hierarchy"></a>

文档章节目录按原文 Markdown 标题层级缩进并支持折叠，默认突出主章节；当前章节与祖先路径可辨认，恢复深层阅读位置时展开其祖先。无法识别标题层级的章节保持平级，不从标题编号猜层级。行号保留为辅助定位，不重复占用目录正文。工具任务入口使用库图标、短名称和已读取状态；未检测、失败、未配置与可用分别说明，进入任务仍沿用原动作前提。自动读取不显示用户操作完成提示。

### REQ-CC-011：个人数据与隐私可预期

Trace ID: O7-REQ-a0a5fd88-9df3-47ba-a778-ceae9c330949

### REQ-CC-013：首页形成可行动的项目判断

Trace ID: O7-REQ-ce7b612a-3316-4c40-9009-c0d295ff0ed6

首页保留当前重点及下一步、真实待我处理、所选窗口内的成果变化、返回进行中的工作四个分区，按用户当前需要区分主次；项目状态和架构索引有直接入口。重点沿当前主责文档的显式阶段顺序及用户保存的置顶选择，不按文件顺序、提交数量或模型猜测排序。未明示优先级的同组项目平列并保留来源顺序，不伪造唯一推荐。

| --- | --- | --- |
| 1. 当前重点与下一步：主要阅读区 | 当前阶段采用强标题；每项以工作目的、当前结果、下一动作为主，目标与主要剩余条件作简短关联说明。默认突出最多三项，同级超出时明示“同级更多” | 有明确关系直接“查看工作”进入详情；一目标对应多项工作时在该重点内选择关联工作，不再跳去全局列表搜索。无关系才显示有限目标摘要与“查看目标”，不要求先建任务 |

首页各列与长标题、路径、版本标识必须能收缩和换行，不产生页面级横向溢出。旧摘要核对按原章节及版本聚合，默认仅显示受影响章节数量和展开入口；展开后保留原声明、所有关联 PR 身份及双方依据，公共边界只说明一次，不按 PR 重复整段摘要。

常规窗口先呈现主要重点与真实关注；没有个人待答问题时，返回工作与重点同层呈现，成果时间线随后展示。紧凑窗口按重点、真实关注、返回工作、成果顺序阅读。四区不要求等宽、等高或在一屏装满，来源诊断与配置不参与争夺主视觉。缺少可靠摘要时保留已确认工作的直接入口；只有缺少工作关系的目标回退为有限原文摘要。未接入、加载、已读为空、错误、陈旧和冲突按 [REQ-CC-002](#REQ-CC-002) 就近简要解释，不能把同一来源提示复制成每行长段落。

每项重点的目标、已核实成果、剩余条件、下一动作、关联工作及来源时效均可从该重点或详情查到；默认只突出工作目的、当前结果和下一动作。目标或剩余条件摘要仅在直接影响当前判断时出现，完整依据与来源按需查看，影响判断的时效和缺口保持可见。下一动作复用主责条款或用户明确保存的选择；新的分析建议标明性质和依据，经用户采用后才成为个人计划，不自动改写正式目标、依赖或权限。

目标/完成条件取自主责文档，阶段叙述复用项目状态，PR/CI 事实取自 GitHub 各自实际读取的对象和范围。项目摘要中人工核实的运行结果保留原来源与时间，不转换成新读取的 CI 事实；准确提交之外的运行不证明所选工作通过。源事实与摘要冲突时，仅受影响结论列出冲突和核对入口，其余可用区域继续展示；新读取旧摘要不刷新内部事实时间。没有摘要或关系时仍展示可读取的已提交目标与已确认工作，说明具体缺口与补充入口。

首页直接展示主责章节中明确的当前目标正文，紧接主要下一动作，再呈现关联信息与里程碑；常用窄窗口默认字号下目标与主动作无需滚动即可识别。该章节有结构完整的里程碑表时，以库图标卡片显示各工作包名称及可展开的主责、依赖与退出条件，不把卡片顺序当依赖或从 PR 推导验收状态。无法可靠提取时保留原文入口，不生成另一套计划。

### REQ-CC-016：产品与系统设计文档树总览

Trace ID: O7-REQ-729d655d-d8a8-4c44-9ea7-32578dc10f3f

云端“规范与决策”提供固定的“文档全局”入口，从项目首页也可直接进入。用户能先看清有哪些产品模块与专业系统、每个主题有哪些需求和配对设计，再展开原文；不必逐个搜索文件。文档树覆盖所选仓库提交中声明的产品、专业系统及其导航范围，固定的少量推荐文档不能冒充完整文档树。它是四主视图内的阅读能力，不新增产品模块或独立任务系统。

提供三种切换方式：产品树从 `doc/product/README.md` 展开现行四模块、模块主 PRD 与明确声明的专题；系统设计树按专业域入口、模块设计和明确的专题导航展开；目录视图按实际路径显示本次纳入的 PRD/design 文件，供查漏。工程工具产品合同归 engineering 专业域，不混入游戏四模块。导航层级与需求—设计配对是两类关系，目录包含不代表语义主责，普通引用不自动成为父子或配对。

<a id="cc-document-reading"></a>

首次从“文档全局”进入默认显示产品树；从工程工具或专业条款上下文进入时显示对应专业树及主题。已有阅读位置时优先恢复它，不强制回树根。默认先读主题、需求及配对设计，文件清单和目录查漏作为辅助切换；解析预算、内容摘要值、完整身份与关系诊断按需展开，不能置于每次阅读前。

已定位主题或从工作进入某条规范后，主阅读区直接显示该主题正文；目录、来源、历史和原始文本保留按需入口。标题与章节、段落、列表和代码块形成清楚的阅读层级，正文沿可读字号与行距呈现，只有代码内容使用代码样式；不能以原始 Markdown 字符或整块等宽纯文本代替默认阅读体验。返回继续原工作或原树的位置，不建立第二套文档树或专业权威。

节点以标题、文档类型、生命周期和必要配对缺口为主；详情可查看路径及所选来源版本，缺声明显示未知。默认展示当前文档并保留草稿标记，历史/退役文档可显式展开；被当前文档引用的历史对象保留入口。文件存在、配对齐全或 active 均不表示功能已实现、验收通过或已发布。概览只显示各类文档数、已解析配对数和具体缺口数，不生成设计完成率。

选择产品或需求节点时，在详情列出显式配对系统设计及其主责条款；选择设计节点可回到上游需求。同一设计服务多个产品节点时复用原对象，显示引用入口；多个候选或声明冲突并列呈现。没有发现配对显示“本次范围未发现显式配对”，未读取显示“尚未读取”，只有在所选提交中核实明确目标不存在才显示缺失。断链、孤立文档、缺少归属和解析歧义可筛选并查看依据，不由模型推断补齐。

支持折叠/展开、按标题/路径/文档或条款 ID 搜索，以及类型、生命周期和缺口筛选；搜索保留命中节点的祖先路径，显示命中数与过滤范围。选中节点先展示简介或可阅读正文与配对设计入口，再按需查看章节定位、关系依据与源版本；切换产品/设计入口、打开原文再返回时恢复筛选、展开和选中位置。键盘可完成同一旅程，宽度不足时在树与详情间切换并可返回。

云端正式阅读只使用明确选定的 GitHub 已提交基线，文件清单、树关系、章节与正文来自同一提交；主线前进不把旧树节点跳转到另一版本正文。本机未提交和未跟踪文档只在本机明确选择的预览范围中阅读，标明分支及未提交状态，不上传到云端树，也不声称已合入。

已配置的文档更新应能从检测到的新提交生成完整候选并切换到成功版本，不能长期只提示“需重新生成”而没有受控更新入口。页面区分当前阅读版本、检测到的新版本、更新中/失败及其影响；目录、正文、章节、关系和目标只能成套更新。候选不完整、校验失败或并发旧更新不得替换当前成功版本。没有内容变化时可复用已核实内容，但来源版本的变化不得使稳定目标的个人上下文失联。

### REQ-CC-017：云端个人空间与跨设备连续性

Trace ID: O7-REQ-57c9e8ba-3698-48b0-8f25-02c8f17ef0d6

用户登录私有站点后，在同一个人空间保存决定、个人问题、明确关系、原工具导航引用、工作置顶、阅读位置与显示偏好。个人记录的持久权威在云端；页面会话快照、本机旧库和未提交草稿不形成第二个可写权威，也不改变 GitHub 源事实。已保存的决定草稿属于云端记录，尚未提交的编辑仅属于当前设备会话内存，两者在界面中可区分。

保存成功必须表示云端已持久提交该记录并返回对应修订；有冲突时显示云端版本并保留当前输入，由用户核对后继续，不静默覆盖或把新版本号附到旧内容上重试。同一已确认保存请求重复到达不能生成重复记录、重复修订或重新确认决定；超时和断线若不能确定结果，应显示未知并先核对原请求，不自动重复副作用。已确认决定的内容变化与替代仍遵守 [REQ-CC-004](#REQ-CC-004)。

用户可导出自己授权范围内的个人资料、关系、原确认和修订历史、偏好及格式版本。导出清楚说明包含的个人内容和缺口，不包含来源凭据、平台会话凭据、signer 密钥、本机私有资料或工具未决操作。来源缓存可重建，不作为个人资料恢复的前提；可读资料格式不能冒称完整的业务恢复支持。

### REQ-CC-018：整体工程架构、适用规范与持续维护

Trace ID: O7-REQ-fd086a0a-3c00-41ea-b2ac-fe7cf6cbe52a

云端“规范与决策”提供固定“工程架构”入口，项目首页可直接进入。用户能先看清工程有哪些主要系统、各自负责什么及如何关联，再下钻到模块、组件/工具、源码与主责文档，并知道修改这里适用哪些开发规范。它是既有四视图内的独立阅读模块，不把工程模块增列为游戏产品域。

模块提供“看懂工程、准备修改、查看变化”三个直接入口，帮助首次理解、实际开发和日常回顾；它们复用同一地图、对象与来源。常规窗口以全局地图为主体，节点只显示短名称、一句职责和必要状态，选中后再展开详情。默认呈现系统组成及少量关键协作关系，编译依赖、规范和部署分别切换；不以统计卡、长段说明或同时叠加所有连线占满首屏。筛选和返回保留稳定位置，Runtime 与 Simulator 的并列职责清楚可辨。

架构视图按以下层次展开；每层保留所读版本、范围与具体缺口，默认聚合而不铺开全仓连线。

| 层次 | 默认回答的问题 | 可继续进入 |
| --- | --- | --- |
| 全局 | 玩家入口、Agent、世界执行、网络/存储、协议扩展及工程/测试/发行工具如何组成项目 | 主要系统、跨模块关键关系、四产品域与专业域的明确关联 |
| 模块 | 模块职责、上下游、接口/数据流与关键边界是什么 | 子组件、允许与禁止边界、产品及系统设计条款 |
| 组件与依据 | 对应哪个 crate、前端包、进程、脚本或工具，准备修改时应读什么 | 同版本代码路径、协议产物、适用规范、测试方法及已有交付证据 |

“整个工程”覆盖所选提交中明确声明的产品/专业模块与已授权工程清单，Rust、前端、脚本、测试、发行和指挥中心均可找到；文档/记录域保持其实际性质，不强画成运行服务。缺归属、未读取或无法解析的对象仍在查漏入口可见。只覆盖 Cargo 依赖或若干示例模块时必须标明范围，不能声称全工程完整；关系发现的覆盖与文件读取的覆盖分别说明。

每个节点有清楚职责与类型，每条关系有方向、类型、适用条件与依据。组成、编译依赖、运行调用/数据流、规范约束、生成关系和实际部署分别呈现；读者可切换设计与实现依据，部署层只有真实环境证据时出现。设计草稿、明确规范、指定版本实现、已测试和实际部署分别表达；有设计、路径或清单依赖不表示能力已实现。模型推断单列“待核对建议”，不能填成已确认关系。

“看懂工程”至少提供 Agent 行动到世界处理、协议到生成产物两条有依据的导览。用户在同一图中逐步看输入、责任交接、输出及关键边界，并可打开每步原文；阅读顺序不冒充实际执行顺序或运行成功。缺来源、未接通和设计目标保持可辨，路线可以停在明确断点。导览帮助理解工程，不启动游戏、开发会话或模型任务。

选中模块或组件后，“适用规范”列出通用开发流程及该对象明确适用的专业要求，每条保留适用原因、主责原文、范围、版本与后继。用户能从图中理解规则与当前对象的关系，打开准确条款及验证方法，而不需重新全仓搜索。Skill、角色和 dot 工作方法标为执行指引；正式规范仍由原主责拥有，不从图生成新的审批、CI 范围或必做清单。草稿、失效规则、未确认适用性和冲突直接可辨。

“准备修改这里”把已有信息组织为实现/设计入口、直接适用的关键约束及理由、对应验证入口三个短区，通用流程保留固定链接、完整规范按需展开。支持分别查看“依赖谁”和“谁使用它”，保留关系类型、方向、条件和范围；共享目录、规范或数据不能自动推出组件互相影响。未找到验证来源时显示缺口；没有 Issue 也能阅读，不要求先建任务，也不自动确定 CI 或派发开发。

支持中文名称、模块/包名、路径和条款 ID 搜索，按关系类型、证据性质和缺口筛选；选中后突出相关路径，其余按需展开。详情先显示职责、关键边界、上下游及适用规范，再展开完整来源与诊断；提供图例及可用键盘操作的列表。窄屏采用分组列表和详情切换，150%/200% 放大时不缩小文字硬塞全图，沿 [REQ-CC-010](#REQ-CC-010) 的交互与排除范围验收。

从图进入文档树、原文或源码后可返回原阅读目的、选中对象/关系、过滤、方向、展开及焦点；对比阅读还保留旧/新双方与所选侧，导览保留当前步骤。已保存偏好按 [REQ-CC-017](#REQ-CC-017) 跨设备恢复。图、规则和所开原文绑定明确快照，更新不悄悄替换正读版本；切换条件后迟到的查询结果不能覆盖新视图。

“查看变化”比较固定版本，并区分组件/关系/规范实际改变、解析规则或读取覆盖改变、纠错与原因未定。仅新增识别或补读成功不能称工程新增；只更新时间不产生新变化，旧引用保留，未读或缺分页不当作删除。有个人已读基线时突出自上次查看、与当前模块直接相关的少量实质变化，并能展开完整差异与前后依据；用户明确设为已读后才推进基线，首次进入或旧基线不可用时如实说明。dot 不读取个人已读历史，不因此增加订阅或通知任务。

dot 负责在既有授权的 Sites 内容维护流程内持续核对来源变化并更新派生图与规范摘要。每轮核对主责文档、已明确纳入范围的工程元数据及规则版本；只有输入/覆盖/规则改变或确需纠错时更新相关内容，发布后回读确认。页面区分当前阅读版本、检测到的新版本、覆盖缺口、最近成功核对及维护任务真实状态；任务未配置、停用、更新失败或不可观测时明确说明。普通浏览、搜索和刷新不运行模型，无变化不重复归纳。

失败保留仍可访问的最近可用版本及原时间，旧任务迟到不能覆盖新图，写入结果未知先查原结果；不能只刷新时间戳把旧架构说成最新。规范冲突或缺口回到主责来源，在现有任务汇报中说明；例行维护不自动修改正式文档、发 PR、启动开发会话或发布站点。正式文档修改另按已有授权和 PR 流程处理后再刷新图；本条不新增调度器，也不表示本次文档合入就已启用持续任务。

## 五、状态与进度的解释

| 来源或状态 | 可以说明 | 仍须单独核实 |
| --- | --- | --- |
| 文档为 active | 对应文档身份及条款效力 | 能力是否已实现、是否通过验收 |
| 用户已作出决定 | 本次明确意图及授权范围 | 正式条款是否更新、实现是否同步 |
| PR 已合入 | 对应代码已进入目标分支 | 部署、整体体验及目标验收 |
| 某次 CI 通过 | 适用测试对相应版本的结果 | 其他版本、未覆盖环境与验收条件 |
| 外部工具汇报结果 | 该汇报原本说明的范围 | 未读取来源、其他工作或目标整体验收 |
| 模型生成交付摘要 | 指定来源与窗口下的归纳，保留依据、生成时间与缺口 | 正式目标、源事实、未读验证及新权限；摘要不构成验收批准 |
| 摘要与缓存输入一致 | 摘要使用的是对应输入与归纳规则 | 关联交付是否读全、引文是否足以支持当前结论、目标是否通过验收 |
| 证据尚未读取 / 验证待完成 / 当前失败 | 分别说明读取覆盖缺口、验证过程状态或有依据的失败范围 | 三者不能互相代称；旧问题正文和来源失败均不能证明当前缺陷仍存在 |
| 更新任务已启用 / 一次执行无变化 | 实际管理来源的配置状态，或对应执行已完成检查且无待更新内容 | 未来仍会执行、所有来源已读全、所有摘要已验收；最近保存时间不能证明任务健康 |
| 查询失败或连接中断 | 本次读取或观察不可用 | 没有任务、没有阻塞、运行已停止 |
| 云端确认保存 | 当前账号与范围内的该记录及其修订已提交 | GitHub 已更新、另一条记录已保存或本机工具已执行 |
| 离线草稿 / 保存结果未知 | 当前会话仍持有输入，或尚未取得确定结果 | 云端已保存、另一设备可见或允许自动重复提交 |
| 有完整适用验收集合 | 可以呈现已验证项与适用项 | 未核实项是否通过、其他目标进度 |

来源标识、观测时间和适用范围跟随结论展示。最新源 HEAD、实际测试版本和 main 前进分别解释，沿用现行开发流程，不从一次 main 变化推导全部既有 CI 失效。

## 六、验证与验收条件

下表是产品功能验收，不为每次文档或一般开发任务增加完整运行要求。实现时按改动覆盖对应条件；系统设计分别映射服务端与身份检查、真实浏览器、旧资料兼容和本机导航/工具验证。源窗口、账户、站点、项目范围及适用构建必须明确，旧桌面验收不能代签云端入口。

### 视觉与窗口场景

本表细化 AC-CC-005/007/010/013/014/016/017 的体验判据；具体尺寸、文字与控件基准由[系统视觉构成](command-center.design.md#cc-visual-composition)承接。云端在真实浏览器使用代表性长中文、真实来源与标明性质的回放样本验证；涉及本机导航和工具时另在实际宿主核对。文档检查不代签这些场景，原功能验收只保留原范围。

| 场景 | 可观察通过条件 |
| --- | --- |
| 常规窗口：1280×830、1440×900 | 首先辨认当前重点和真实待答，有关系可直接进入工作；成果时间线与返回列表为次级阅读，不出现四块等重长文或重复百项来源列表。无需展开原文、完整身份或输入表单即可说清一行工作的目的、结果和下一步 |
| 紧凑窗口：1024×768、728×627 | 改为适用的单主内容布局，工作详情不在首页下方；输入、工具及依据阅读后能返回原位置。允许纵向滚动，不缩字号维持并排，不横向裁掉标题展开、状态或操作 |
| 长中文及 150% / 200% 放大 | 按系统基准的代表性常规/紧凑组合完成定位、查看依据、编辑和返回；标题可展开、操作可换行，个人问题和工具危险/未知警示完整。放大前后仍是原工作与原来源，草稿保留；不要求所有分区同时出现在首屏 |
| 空、错误、未知与超出预览 | 无请求时显示轻状态；加载不冒充成功空，失败保留旧结果。真实待答即使超出预览仍有数量与完整入口，未知总量不造剩余数。未知事件不伪入时间线，无法证明的关系不画成已确认；来源/诊断展开不改变事实或触发运行 |

### 日常工作闭环的整体验收

采用真实代表性项目：至少三项近期工作，含一个 PR 服务两个目标、一个 PR 尚无会话、两个不同的原工具定位。来源窗口同时包含真实结果、一个真实个人问题、一个已确认决定、一个普通知悉变化，以及一项旧摘要与当前 PR 事实冲突。至少使用两台设备或独立浏览器环境，另设无本机组件的访问环境。验收可用受控来源/存储回放构造稀有故障，但网页登录、阅读、输入与返回，以及适用的本机导航须在实际入口执行；回放不能冒充外部工具实际运行状态。

完整旅程从实际受保护 Site 入口开始：登录 → 识别当前重点与证据缺口 → 进入工作及原依据 → 保存个人问题或决定 → 打开原工具并返回同一工作 → 在另一设备继续。单独的服务接口读取、合成身份测试或部署成功不能代替真实登录。记录实际 Site 源码/部署、文档快照及数据格式版本；遇到访问拦截、授权失效或设备能力不可用时，保留具体受阻步骤，不将剩余旅程标为通过。

| 用户任务 | 通过条件 |
| --- | --- |
| 开始一天 | 可用来源加载完成后，用户五分钟内说清当前重点、已核实成果和主要剩余条件；从首页找到下一项工作并进入正确工具或详情，无需搜索状态页、通读原始 PRD或手填已有 PR 地址。没有明确排序时能看见并列项与缺口 |
| 处理中断 | 从首页找到一个真实待处理事项，在同一工作上下文理解原因与选项，记录个人回答或打开原工具处理；回到原工作查看实际结果或明确待核实状态。刷新不重新请求已处理事项，也不将普通知悉提醒列为待批准 |
| 恢复工作 | 重开或换设备后回到云端已保存的原工作、筛选、阅读位置及记录；当前会话未提交草稿与未知结果明确可辨，关页不保证草稿恢复。来源失败保留原版本，账号与项目不串联；关闭网页、恢复页面和打开本机入口均不重放模型或工具操作 |
| 保存与恢复个人空间 | 一台设备保存、另一台读取，旧版本并发提交有可恢复冲突；离线输入不冒称已保存，回网不自动上传。导出并恢复自有资料时预览冲突和范围，伪造账号字段无效，确认及替代历史保持原性质，原工具不因恢复执行 |
| 持续使用与正式切换 | main 与文档版本更新、未决记录增长及任务无变化/失败后，仍能找到同一目标、工作和个人上下文；读取旧依据不会被静默替换。旧数据迁移完成实际预览、回读与恢复核验后，按既有迁移范围确认唯一写入口；需要本机工具的步骤独立验证安全往返，未验证项明确保留 |

同时记录各任务的完成情况、耗时、额外搜索/切换/录入和具体卡点。五分钟衡量已可用数据下的理解与定位；首次加载另记实际耗时、数据量与可用反馈，不能从一次样本推导启动性能保证。纯设计交付只核对这些条件是否完整可执行，不冒充实际用户验收。

## 七、产品范围、取舍与边界

产品围绕“判断下一步—阅读依据—进入原工具—记录个人结果”工作。云端工作台与个人空间是日常主入口，本地设备组件承接未提交材料、私有资料和受限设备工具。工程工具保持在 engineering 文档域；游戏 Agent、部署控制、通用 IDE、团队协作、通知系统及远端执行宿主不在范围内。

选择云端个人数据单一权威使跨设备连续性明确，也意味着离线输入不能承诺云端保存或自动合并。保持本机私有资料和设备操作在本机，避免为同一工作台增加隐含上传、通用远控或第二套核心 UI；代价是云端只能按来源确认公开交付与个人记录，不能推断本机实时状态。来源更新、个人保存和原工具执行分别反馈，互不代签。

文档树、个人空间、本机工具、私有数据与界面验收分别沿对应条款和专题设计；现有实现及未证明范围在系统设计 §3 记录。公开分发、证书、自动更新和其他本机系统须有适用证据，旧验收不扩大到新环境。实施排期、搬迁清单和交付流水只在对应 Issue/PR 维护，本文保留可独立理解的最终行为、兼容与恢复合同。
