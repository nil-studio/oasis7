## 一、产品定位与目标

客户端服务 oasis7 项目负责人的个人开发工作，提供 macOS 优先的独立桌面入口。打开项目后，用户能够回答：当前最重要的目标是什么，已经验证到哪里，今天的工作依据哪些决定，哪些问题确实需要自己处理。

核心使用闭环为“看清当前重点与变化 → 选择一项工作 → 带着依据进入正确工具或自管会话 → 处理真实问题 → 回看结果与剩余条件”。首次采用时接续用户已有的开发现场；使用指挥中心不要求搬迁既有会话、重建任务或重复填写已经明确的上下文。

| 原始问题 | 产品应提供的结果 | 观察方式 |
| --- | --- | --- |
| 短期与长期目标分散，进度难判断 | 从当前阶段沿里程碑、工作和验收依据下钻，也能回到长期方向 | 用户能说明下一项交付、已知进展及未知范围，并打开依据 |
| 制定规范后忘记理由，决策难连续 | 可检索当前适用规则，查看理由、范围、历史后继和尚未同步的决定 | 用户能找到当时决定和现在适用条款，分清规范与实现状态 |
| Codex 会话、分支和任务切换繁琐 | 在工作目的旁找到已有现场、实际可观察状态及正确处理入口，也可按需新建自管工作 | 用户能回到已有工作；可控动作有回执，外部处理结果沿其来源核实 |
| 为看板维护关系和状态耗费时间 | 复用明确引用和已保存上下文，只核对歧义或改变的关系 | 用户无需逐项复制 PR 地址、重填任务目的或每次确认同一关系 |

工程工具保持在 engineering 文档域，不增加游戏产品第五域。游戏内 Agent、玩家 Viewer 与开发 Codex 会话分别建模。

首版不承担完整 IDE、通用多租户管理平台、跨机器安装平台或自主 Agent 调度器的职责。它关联现有目标、规范和交付事实，保留必要的个人记忆；任务本身仍可只存在于 PR、已有 Issue 或受支持开发会话中。

文档索引、来源跳转和协议正确性是支撑能力。基础产品发布须完成下述日常工作闭环；仅有这些支撑能力的版本按实际范围说明为基础切片。

## 二、用户与使用场景

主要用户是同时承担产品决策、实现与交付的项目负责人。用户可能并行使用本地工作树、多个 Codex 会话和个人云端开发机，已有有效授权与项目操作习惯。

| 场景 | 用户问题 | 本次操作的完成标志 |
| --- | --- | --- |
| 开始一天的开发 | 今天最应推进什么，昨天有什么变化？ | 从首页说清近期重点、变化、剩余条件，选择下一项工作并打开正确现场 |
| 准备作出决定 | 之前为什么这么定，这次会影响什么？ | 找到适用条款及理由，能区分历史决定、草稿和待同步内容 |
| 多项开发并行 | 哪个会话在做什么，哪些在等我？ | 在一个工作详情中找到目标、依据、PR/CI及已有会话入口；未知观察范围明确可见 |
| 中途离开与恢复 | 关窗口会发生什么，重新打开还能续上吗？ | 能预期运行行为，恢复已有信息，不重复执行已发出的动作 |

次要使用者是按用户明确指令开发或刷新看板的 Codex。Skill 提供调用方法与按需参考，不构成实时后台服务，也不拥有产品规则的另一份副本。

## 三、信息架构与用户旅程

### 四个主视图

| 视图 | 首屏重点 | 详情与主要入口 |
| --- | --- | --- |
| 方向与进度（默认首页） | 当前重点与下一步、近期成果、需要我处理、返回进行中的工作 | 长期方向、里程碑依赖、统一工作详情、验收依据与来源覆盖 |
| 规范与决策 | 关键架构与部署索引、适用规则、待同步决定 | 文档树总览、原文、边界与理由、设计/实现/实际部署分别核验、历史后继及受影响工作 |
| 开发执行 | 按工作目的组织的进行中工作、等待输入、失败与最近结果 | 统一工作详情、已有工具入口、会话详情、受支持动作与交付来源 |
| 待我处理 | 真实输入请求、阻塞性问题、待选择事项 | 必要背景、选项影响、推荐理由、处理入口及回执 |

项目与环境选择、来源连接状态、搜索和最近成功读取时间属于共享入口。视图之间共享关联，打开 PR 或条款时保留当前筛选和返回位置。

已打开项目时，路径选择和连接配置收进上下文入口；首屏先展示用户结果。来源版本、完整身份和协议诊断在详情按需展开，影响当前判断或操作的缺口直接显示。“本机工具”是独立辅助入口，不改变四个业务主视图，资料、CLI 和 signer 按 [REQ-CC-015](#REQ-CC-015) 提供。

### 首页与统一工作详情

首页按 [REQ-CC-013](#REQ-CC-013) 的四区组织用户结果；同一工作的完整内容按 [REQ-CC-005](#REQ-CC-005) 下钻。首页和列表中的主动作首先进入正确工作或真实请求；只有工作详情或执行输入区明确标示的发送动作才启动工作。

目标、执行和待处理视图均打开相同工作详情。返回恢复进入前的视图、筛选、展开、滚动位置和焦点，未发送普通草稿按用户留存选择恢复；打开来源或辅助工具不会重建工作。在一个视图处理后，其他视图读取同一结果；结果晚到时仍归原工作，不能覆盖当前正在看的另一项工作。

### 典型旅程

1. **首次打开**：选择本地 oasis7 仓库后进入首页，先读到已有项目摘要、当前目标和可用工作。连接 GitHub 后补充 PR/CI；已有会话通过受支持连接或明确来源入口关联。无法观察的工具说明范围，并允许打开原入口。实验 Codex 的安装与连接设置在用户选择自管执行时展开。
2. **确定下一步**：从首页重点打开工作详情，核对剩余条件与推荐依据，选择下一动作。已有工作优先回原工具；新工作继承目的、范围、条款引用及环境供用户修改，预览实际输入后一次明确发送。回到详情可看到发送状态及后续来源结果。
3. **回顾并修改决定**：从工作详情打开适用条款及理由，记录新的决定或草稿，保留原工作和受影响关系；回写有实际来源后更新同步结果。已确认关系无需重复录入，失效关系按 [REQ-CC-014](#REQ-CC-014) 处理。
4. **处理运行请求**：从首页或待我处理进入原工作和具体请求，看到背景、选项影响及处理入口。可控请求在原身份下回答；外部请求打开原工具处理，客户端回读结果，未取得结果时保持待核实。处理后回到原详情，刷新和重连不重复发送答案。
5. **离开并恢复**：关窗后从菜单栏恢复上次工作、阅读位置和会话内草稿；完整重开只恢复用户选择留存的普通草稿；首页显示实际可核实的变化。完整退出按自管工作的状态处理；异常重开先呈现原工作与未决操作，核对后继续，不重建会话或重发任务。

### REQ-CC-001：独立入口与项目上下文

Trace ID: O7-REQ-6e70287f-a156-4544-997d-5c1752e5efde

日常交付为可直接启动的 macOS App。用户无需先开终端、启动看板服务或部署中心服务；浏览器界面用于开发预览。

打开项目时识别实际仓库与工作树，显示当前项目、环境、分支和读取基线；允许切换已有项目上下文。未提交文档与已提交版本可辨认，工作树内容不能标为 main 已生效内容。

同仓库多个工作树属于一个项目阅读范围，工作树和环境仍是来源及执行边界。项目总览可以关联它们的工作；正式目标默认读取明确选定的主线基线，工作树中尚未合入的目标修改单独展示。每次动作绑定具体环境和工作树，不将总览范围当成跨环境授权。当前实现的工作树隔离数据不因此自动迁移或合并。

项目上下文入口默认只显示项目名、所选环境和必要的工作树标记；完整路径、基线及连接设置按需展开。首次未选项目时显示“打开本地项目”，已选项目后让位于首页结果。切换总览阅读范围不改变执行目标；待发送草稿保留原环境，必须显示目标差异，由用户明确改选后才可发往其他环境。

恢复上次项目时同时恢复视图偏好和阅读位置。路径不存在或仓库不匹配时，说明具体问题并允许重新选择；不静默改成另一个目录或仓库。

- 系统设计依据：[DES-CC-001](command-center.design.md#DES-CC-001)。
- 实现状态：已实现待验证
- 实现与验证依据：显式同仓工作树阅读引用保留原执行身份，项目设置折叠，工作/筛选/普通草稿恢复。 见[源码、原生与回放证据](daily-work-verification.manual.md)。

### REQ-CC-002：来源可信与局部可用

Trace ID: O7-REQ-2d1f3577-785e-40ac-8d25-ba0d414511f6

每项重要结论能够打开来源，显示可取得的源版本、观测时间、性质和覆盖范围。性质至少区分源事实、Agent 汇报、模型归纳和待核实关联；未知字段不补造。

项目状态摘要和架构索引保留自身的来源基线、事实核验时间及覆盖范围；客户端刚刚读取文件，不代表其中的 PR、验收或部署事实也刚刚核验。摘要的归纳不因进入仓库就取得源条款或运行事实的权威。

各来源分别展示加载、成功空结果、部分读取、过期、错误和未接入。读取失败保留最近成功事实，说明哪个区域受影响；GitHub 不可用不妨碍阅读已加载规范，Codex 未连接不阻塞其他视图。

<a id="cc-source-states"></a>

| 可观察状态 | 页面如何解释 | 可执行的下一步 |
| --- | --- | --- |
| 首次加载 / 正在刷新 | 首次显示正在读取的来源；刷新保留旧内容与其时间，不将整个页面清空 | 可先阅读已可用区域；需要该来源的动作说明等待原因 |
| 成功但无匹配结果 | 明示成功读取的范围与筛选条件，不能写成“项目没有工作” | 清除筛选、展开范围或返回目标 |
| 未接入 / 查询失败 / 部分读取 | 区分尚未配置、实际失败和覆盖不全；失败说明受影响范围与最近成功时间 | 对该来源连接、重试或打开原入口，其余区域继续使用 |
| 事实陈旧 / 核验时间未知 | 同时保留事件时间、来源观测时间和摘要内部核验时间；旧摘要上新鲜的文件读取时间不改变结论 | 核对受影响来源；无新结果时继续保留旧依据及限制 |
| 源事实与摘要冲突 | 当前源事实在其职责字段显示；同项旧判断及版本放在冲突详情，不把整个工作改为未知 | 打开两方依据，核实需要修订的摘要或关系，不自动回写 |

同一失败在来源级集中解释，工作行只标记其具体影响。没有可用依据的结论保持未知；部分 PR 窗口之外的对象不得被推定不存在或已经完成。

刷新读取既有事实或订阅已支持事件，不暗含模型运行、Git fetch、分支切换或远端写入。需要分析或执行的动作另有明确入口，沿用实际授权。

- 系统设计状态：已覆盖
- 系统设计依据：[DES-CC-002](command-center.design.md#DES-CC-002)。
- 实现状态：已实现待验证
- 实现与验证依据：逐字段 SourceFact、REST 分页/已知 PR 补读、旧摘要与实际合入冲突、来源隔离及慢源/取消回归。 见[源码、原生与回放证据](daily-work-verification.manual.md)。
- 核对日期与基线：2026-10-18；[本轮固定源码与验收边界](daily-work-verification.manual.md)。
- 剩余范围：本次 REST 窗口有限，实际测试对象缺 receipt 仍未知；不推断部署或全仓完成。

### REQ-CC-003：短期与长期目标及进度

首页先呈现当前阶段与近期交付，长期方向保持可见且层级独立。当前阶段读取 core PRD 的“当前阶段交付目标与全局 P0”及其主责引用，不采用文件开头历史里程碑作默认。沿“长期目标—里程碑—关联工作—验收依据”下钻；工程支撑工作可独立筛选，沿用项目既有产品分类。

已有关联来源沿 [REQ-CC-014](#REQ-CC-014) 复用。未知分母时仍提供已核实成果、剩余条件及可执行的下一步；缺少总体百分比不应使页面退化为只列原文或统一显示未知。

目标、阶段和依赖来自当前主责文档或用户明确确认的关系。一个工作可关联多个目标；未确认关系显示为建议，不自动成为依赖或阻塞，不把长期愿景的全部内容提升为当前前置条件。

明确列出完成条件、已核实部分、尚未覆盖或未知部分。只有适用验收集合、分母与结果均可核实时，展示“已验证项 / 适用项”；其他情况使用文字说明，不生成总体完成率。

保留[项目状态](README.md)的持续阅读入口，集中呈现长期方向、短期目标、目前进度、最近做了什么及下一步。近期变化写清所选窗口、变化对目标的影响、实际结果和来源；聚合同一结果的碎片活动，不用提交数量替代成果。没有可靠上次阅读基线时，不宣称这是“自上次查看以来”的完整变化。

### 日常工作闭环的整体验收

采用真实代表性项目：至少三项近期工作，含一个 PR 服务两个目标、一个 PR 尚无会话、两个同分支不同会话、一个仅可打开原工具的外部会话。来源窗口同时包含真实结果、一个真实输入请求、一个已确认未同步决定、一个普通知悉变化，以及一项旧摘要与当前 PR 事实冲突。验收环境可使用受控请求/来源回放构造稀有故障，但真实桌面导航、输入和返回操作仍在 App 中执行；样本不得把回放状态说成外部工具的实际运行状态。

| 用户任务 | 通过条件 |
| --- | --- |
| 开始一天 | 可用来源加载完成后，用户五分钟内说清当前重点、已核实成果和主要剩余条件；从首页找到下一项工作并进入正确工具或详情，无需搜索状态页、通读原始 PRD或手填已有 PR 地址。没有明确排序时能看见并列项与缺口 |
| 处理中断 | 从首页找到一个真实待处理事项，在同一工作上下文理解原因与选项，完成受支持回复或打开原工具处理；回到原工作查看实际结果或明确待核实状态。刷新不重新请求已处理事项，也不将普通知悉提醒列为待批准 |
| 恢复工作 | 关窗后恢复会话内草稿；完整重开后回到原工作、筛选、阅读位置和用户选择留存的未发送普通草稿；明确时间窗口内的变化可下钻来源。来源不可用时保留最后结果，原环境及未决操作可核对，不要求重建工作或重复发任务 |

同时记录各任务的完成情况、耗时、额外搜索/切换/录入和具体卡点。五分钟衡量已可用数据下的理解与定位；首次加载另记实际耗时、数据量与可用反馈，不能从一次样本推导启动性能保证。纯设计交付只核对这些条件是否完整可执行，不冒充实际用户验收。

个人云端接入、自动更新和其他桌面系统由实际使用需求决定。若明确要求完整退出后任务继续、多个客户端共享执行现场或重启后无人值守恢复，再扩展独立执行宿主；其新承诺须同步到产品与系统设计。

首版不以包体、内存或帧率的未测量数字作为成效声明。评估产品价值时，以前述用户问题能否依靠真实来源完成为主，并记录代表性场景下实际观察到的检索与操作体验。
