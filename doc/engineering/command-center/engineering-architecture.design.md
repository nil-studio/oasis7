## 1. 问题、目标与非目标

现有文档树回答“资料在哪里”，架构索引回答“哪些边界值得关注”；两者尚不足以从同一入口看清整个工程的组成、组件间关系和修改时适用的开发规范。本设计在云端“规范与决策”内承接全局架构、模块下钻、规范关联与版本变化，帮助负责人在准备开发、评审和回顾时找到准确依据。

阅读围绕“看懂工程、准备修改、查看变化”三个目的组织。第一次进入能辨认主要职责，沿有依据的导览理解一次交接；准备修改时直接找到入口、边界与验证方法；再次进入能定位真实变化。三个目的共享同一架构与来源，不新增主视图、任务系统或临时模型问答。

架构与规范视图是已授权来源的派生投影。专业文档拥有设计，源码与清单拥有其版本的实现事实，真实环境证据拥有部署事实；图、dot 解释及更新状态不成为新的架构或开发规范权威。工作区、未提交文件、私有资料、开发会话正文和机器操作仍在原边界内，不进入本模块。

本模块不实现任意代码调用图、实时服务发现、全仓静态分析、完整 SBOM、IDE 或新的开发调度器；不为了绘图新增要求登记、架构审批、CI 门禁或一份必须人工维护的全仓关系台账。只能证明清单依赖时就显示清单依赖，不能用它代替运行时调用或权限。

## 4. 边界与结构

以下为本模块的目标数据流；箭头表示读取或派生，不表示仓库写入、开发派工或部署授权。

```mermaid
flowchart TD
  Docs["同提交主责文档"] --> Collect["受限来源读取"]
  Meta["已授权工程清单"] --> Collect
  Dot["既有 dot 内容维护"] --> Collect
  Collect --> Snapshot["不可变来源候选"]
  Snapshot --> Project["架构与规范投影"]
  Project --> Cache["校验与条件发布"]
  Cache --> View["图与规范阅读"]
  View --> Reader["同版本正文与代码依据"]
  Dot --> Verify["发布回读与状态核对"]
  Cache --> Verify
```

Worker 来源 adapter 读取受控路径及固定提交，解析层建立带证据的对象，投影层生成聚合视图和变化，D1 只保存可重建缓存及成功指针。UI 使用已发布对象，不在浏览器扫描仓库、运行仓库脚本或请求模型。dot 调用已有受限维护入口并核对结果，不直接操作 D1 或将模型输出当作任意图写入指令。

### DES-CC-ARCH-001：来源、范围与关系语义

<a id="DES-CC-ARCH-001"></a>

从[文档总入口](../../README.md)和 core 模块地图枚举声明的产品与工程模块，再读取明确链接的模块/专题主责。首个实现至少覆盖玩家入口与 Viewer、Agent 接入/Harness/Provider、Simulator 与权威 Runtime、World Service、网络/共识/存储、协议与 WASM 扩展、测试/构建/发行/运维，以及指挥中心自身；不是只展示 Rust crate。`playability_test_result`、历史记录或纯文档域以其实际性质显示，不能强画成运行服务。

“全工程”表示已核对所选提交中声明的模块清单和允许元数据清单，所有条目均可定位或有明确缺口，不表示所有隐式语义关系都已发现。四产品域是关联维度，专业模块与 crate 是另一种分组，多对多关系必须有来源；engineering 不成为第五游戏产品域。默认图聚合主要系统，折叠项和未归属组件仍可查找。

Sites 指挥中心及其他独立仓库组件可以先由本仓库的主责设计作为设计节点覆盖；未获准接入其源码时明确“外部实现来源未接入”，不为达到全工程覆盖扩大仓库范围。以后确有授权接入时，每个仓库固定自己的 commit 并作为显式依赖版本记录；单仓同提交约束分别成立，不能把业务仓库 SHA 当作 Sites 或其他仓库 SHA。

| 来源 | 可提取内容 | 提取与证明边界 |
| --- | --- | --- |
| core、模块设计、明确专题及现行规范 | 显式职责、组成、接口/数据流、主责与适用范围、明确后继 | 仅支持已声明解析语法或带原文位置的已核对关系；普通超链接不是依赖，目录不是语义归属 |
| 同 SHA 的 Cargo workspace/成员清单 | 成员、path 依赖、normal/build/dev、optional、features、target 条件 | 工作区继承和别名正确解析；未解析条件保留原值/未知，不冒充某 profile 的实际依赖闭包，不执行 Cargo/build.rs |
| 同 SHA 的 package 清单、受控边界及协议产物清单 | 前端/工具包、显式脚本入口与依赖、允许/禁止边界、生成输入输出 | 首版按明确 allowlist 支持格式；依赖锁定、动态加载与跨语言调用只显示已确认范围，不执行脚本或递归读取任意 URI |
| Git/PR/检查与环境原证据 | 实现交付关联、准确版本与明确环境结果 | 按已有 `WorkRef`/证据合同读取；部署覆盖是可选独立层，没有证据即“未核实”，不自动 SSH 或探测服务 |
| 架构索引和 dot 归纳 | 阅读导航、说明与关注变化 | 保留原事实时间及来源；与主责/当前源码冲突时展示双方，不能覆盖原事实 |

首版按下表实现有版本的确定性提取 profile。新增格式在 adapter 中列明字段、选择器及失败分类；不要求业务模块另填一份全仓台账，不执行所读脚本。表头、schema 或必要字段不匹配时记录不支持/待核对；不能静默改成模型解析。

| 既有来源与支持结构 | 首版输出 | 解析及证明边界 |
| --- | --- | --- |
| [core 模块地图](../../core/prd.md)中 `模块 / 主职责 / 关键实现载体` 表 | 声明模块、职责、载体声明与主责引用 | 表格用 Markdown AST 解析；路径/glob 只在同提交允许清单内匹配，零匹配、重复身份或未归属保留缺口；目录存在不证明它是 Rust 包或运行服务 |
| Cargo workspace/成员 TOML；明确允许的 [Viewer package](../../../crates/oasis7_viewer/package.json) 与[指挥中心 package](../../../tools/oasis7-command-center/ui/package.json) | 按包类型生成对象、声明依赖及显式脚本入口 | Cargo 保留 workspace 继承、别名、kind/cfg/features；package 的 dependencies/devDependencies/scripts 分开，脚本文本不是已执行调用链 |
| [Rust 边界规则](../../../scripts/cargo-dev-architecture.json)的 `revision`、`rules[].key/upstream/roots/forbidden/kinds/declaration_kinds/profiles/test_kinds` 及显式例外字段 | 规则对象、适用对象/条件及准确上游 | `forbidden` 是约束；`allows` 自由文本作说明；不把禁止项画成已发生依赖，也不把生产闭包条件扩大到所有 dev 输入 |
| [协议 profile](../../../crates/oasis7_agent_api/protocol_codegen/profile.json)的 `profile/source/output/export_roots` 与[产物 manifest](../../../crates/oasis7_agent_api/protocol_codegen/generated/manifest.json)的 `inputs/outputs` | 生成范围、产物及其输入关系 | profile 表示配置；manifest 路径与内容 hash 须同版本核对，输出相对 `output` 解析并检查逃逸；缺文件/不匹配标缺口，文件齐全不代替生成测试或部署 |
| 明确主责专题的指定锚点、职责表及方向声明 | 受支持局部语法中的职责/关系；导览引用的原文说明 | adapter 固定文档与局部语法，不通配所有“依赖”标题；不能解析的正文仍可读，普通链接与讲解步骤不自动生成调用边 |

模块的载体声明、实际包/文件解析结果与设计中的运行组件分别记录；一个包可以服务多个模块，同一对象只保留一个身份及多条有依据的归属。既有模块表中的概括路径、旧包名或 glob 不能覆盖实际清单。例如 Viewer 路径可由 package 清单说明前端工具，不能因目录位于 `crates/` 就宣称为 Cargo 成员；World Service 的合法组合由[模块边界](../../world-simulator/llm/agent-game-client-boundary.design.md#des-agc-001)及实际声明核对，不从画面上下位置推导禁入关系。

“已核对关系”必须有可重建依据：受控提取规则定位准确源路径、锚点/原文区间与内容 hash，记录规则版本和明确关系含义。源原文或规则发生变化时，相应关系失效并待复核；一次人工或模型解释不能作为永久确认边，缺可重建来源时只保留带引用的说明/建议，不建立确认关系。

节点的身份包含可信 repository ID、对象命名空间及已有稳定定位，版本独立保存。需求用唯一 Trace ID，规范用其声明定位；代码对象用 workspace/package 或规范化仓库路径，路径重命名只有显式迁移或可核实的一对一来源时才建立别名。名称相同、目录邻近或内容相似不合并；无稳定定位的条目保留临时身份和限制，不声称跨版本同一对象。

每条边带 `from/to`、关系类型、必要子类型、条件、事实性质和准确来源；必须有唯一可解析的两端。箭头只表达下表中的关系语义，不能随阅读方向翻转或统一解释为数据流。

| 关系类型 | 方向与必要子类型 | 默认用途与遍历边界 |
| --- | --- | --- |
| `contains` | 整体 → 部分 | 分组/下钻；不经共同父节点推出兄弟组件互相影响 |
| `declared_dependency` | 使用方 → 依赖方；保留 normal/build/dev、target、optional/features 条件 | 查看声明依赖或反向使用者；条件未知单列，不能当作已激活闭包 |
| `calls_or_transports` | `call` 为调用方 → 被调用方；`transport` 为发送方 → 接收方 | 明确调用或传输；回应须有独立依据，连通不证明执行顺序 |
| `reads_or_writes` | `read`、`write` 均为操作方 → 数据对象，并明确操作类型 | 资源访问阅读；此箭头不是数据流方向，共享数据不自动推出写者/读者互相依赖 |
| `governed_by` | 对象 → 规则 | 适用规范导航；不跨共同规则传播代码影响 |
| `generated_from` | 产物 → 输入 | 生成来源与反向产物查询；须保留 profile/manifest 证明范围 |
| `deployed_as` | 组件 → 有证据的环境实例 | 部署事实定位；不传播实现依赖或跨环境推断 |

允许与禁止边界作为规则约束显示，不伪装成实际依赖。关系子类型是结构化字段，不能只写在标签中；未提供必要子类型的旧数据按不支持语义处理。

`design`、`implementation`、`deployment` 与 `unverified` 分别说明关系依据；文档的草稿/有效/退役状态另存。缺实现证据的设计节点仍可阅读，但不标“已实现”。模型推断留在“待核对建议”，不进入已确认关系和影响路径；源冲突不能通过较新抓取时间裁决。Runtime 与 Simulator 的并列、Service 的组合依赖等按模块合同表达，不硬套一条统一分层禁入规则。

### DES-CC-ARCH-002：开发规范的关联

<a id="DES-CC-ARCH-002"></a>

选择模块/组件时，先说明当前对象直接适用的关键边界，提供通用开发流程的固定入口，完整规范按需展开；每条包含标题、适用范围、适用原因、主责原文、所读版本、条款效力和后继。通用流程只来自 [workflow/source-of-truth](../workflow/source-of-truth.md)，测试操作来自 [testing-manual](../../../testing-manual.md)，Rust 边界/协议产物来自相应主责合同。角色说明、Skill 和 dot 工作方法标为执行指引，不能与正式规范竞争效力。

规则适用由原条款明确范围、受控提取规则及已核实对象映射得出；规则项说明采用哪项条件。未能判断的关联显示“待确认适用”，不宣称无规则或自动添加必做项；不因为文本出现“必须”就跨范围扩大义务。设计草稿、已废止条款和旧版本只在相应状态下呈现；有效性冲突及缺失后继保留双方并链接原文。

“依赖谁”和“谁使用它”分别沿声明依赖的正向、反向查询，默认只看一跳；扩展深度时仍使用同一关系族、证据层与条件。调用、传输、读写和生成关系分别显式选择，不自动组成混合的传递影响链；组成、规范、部署边只用于相应导航。条件未解析或是否激活未知时显示声明与限制，不混入确认生效的路径。结果保留方向、跳数、依据与截断，表示已核实范围内的关联，不声称穷尽代码影响，不决定 CI 范围或形成审批清单。规则正文变化使相应关联待核对；个人决定与确认仍引用原版本，不由规则刷新自动续期。

### DES-CC-ARCH-003：浏览器交互与阅读恢复

<a id="DES-CC-ARCH-003"></a>

“规范与决策”内固定提供“工程架构”“文档全局”和既有规范/决定入口。架构页保留全局→模块→组件三层，并提供“看懂工程 / 准备修改 / 查看变化”三个阅读目的；切换的是同一对象集合的呈现与查询，不另建主导航。

<a id="cc-architecture-first-screen"></a>

#### 首屏与稳定布局

常规窗口以一张全局地图为主阅读区，顶部紧凑显示项目、阅读版本、搜索与来源状态；选中后再打开详情。节点默认只显示短名称、一句职责及必要类型/状态，路径、hash、完整规范和诊断按需展开。来源公共缺口集中说明，具体对象仍保留自己的限制，不把同一句状态复制成整屏标签。

默认按明确职责分组展示系统组成，少量已有依据的主要协作关系按需突出；编译依赖、规范和部署关系分别切换，不能默认叠加所有边族。Runtime 与 Simulator 保持可辨的并列职责，共享协议/WASM 和工程支撑按来源分组，画面位置不表示调用先后或禁止依赖。同一快照中搜索、筛选和返回尽量保留节点位置；布局确定性排序，新增/缺失对象局部调整，缩小字号不能用来填满画布。§9 容量值是保护上限，不是首屏填充目标。

<a id="cc-architecture-guided-reading"></a>

#### 有依据的工程导览

首版至少提供“Agent 行动如何到达世界处理”和“协议如何形成生成产物”两条可用阅读路线，入口直接放在地图旁。前者从[客户端与世界边界](../../world-simulator/llm/agent-game-client-boundary.design.md#des-agc-001)解释执行方、Game Client、服务端准入与 Runtime 的分工；后者沿协议 profile、manifest、真实输出及明确消费者。路线覆盖到哪里就说明到哪里，不能将 bootstrap profile 扩成全部 Game API，或把 Simulator 接入权威 Runtime 的必经链。

路线是有版本的轻量阅读配方，引用当前快照中已有节点/边和准确来源，由受控 adapter 维护少量模板，不复制另一份图。每步解释输入、责任、输出或边界，突出当前对象，支持上一步、下一步、打开依据和回全局；必要分支明确列出，不默认播放动画。步骤次序先表示阅读顺序，只有原文明确支持时才另外说明运行/事务先后，不能从图连通自动推导一次实际成功请求。

源片段、关系或配方改变后重新校验；未核对部分标断点，设计步骤保留设计状态。用户可以读已确认部分，但不得跨缺口拼成完整调用链。解释优先用确定性模板与准确摘述；不为点击导览临时调用模型。首版验收至少一条涉及执行责任交接及明确失败/恢复边界的路线。

#### 准备修改与来源往返

选中对象后，“准备修改这里”显示三个短区：实现/设计入口、直接适用的关键约束及理由、对应验证入口与覆盖边界。通用流程保留固定链接；找不到验证来源时明确待核对，不能推出无需测试。没有 Issue/WorkRef 也能使用，有工作上下文则返回原工作；该动作只组织阅读，不生成强制检查单、创建任务、派工或替用户确定 CI。

搜索支持中文名称、模块、包名、仓库路径及完整 Trace ID，结果保留分组和定位路径。关系类型、设计/实现/部署证据、条件与缺口可过滤，图例同步解释，颜色之外有文字/线型。点击规则进入同版本条款，打开正文或源码后返回选中对象、筛选与焦点；组件的目录包含和文档配对由原阅读入口承接，不在图中猜配对。

<a id="cc-architecture-change-cause"></a>

#### 回访与变化原因

对比固定的两个快照时，节点、关系、规则内容/适用性与来源覆盖的差异分别保留旧、新引用。每项同时给出原因：来源实际变化、提取规则变化、读取范围/覆盖变化、纠错或混合/未确定。只有来源差异支持时才称“组件新增/依赖改变”；同提交升级 parser、扩大 allowlist 或补读成功显示“新增识别/纳入”，不能包装成工程更新。只改版本绑定而已提取字段相同不刷出整图变化；不支持的正文有变化仍标待核对，不宣称语义未变。

只在完整清单或精确对象查询证明不存在时判删除，迁移保留别名与原证据。格式或关系语义不兼容时只比较可核对部分，另一侧不当作空图。变化不证明实际代码影响、验证通过或部署完成。

有个人已读基线时显示“自上次查看的变化”，否则提供明确版本选择。默认先列与当前模块直接相关的少量实质变化，以“什么变了—涉及哪里—查看依据”表达，保留完整列表和排序理由；不凭数量造风险等级。只更新时间无新变化。用户明确“设为已读基线”才更新基线，打开页面或后台刷新不自动清零；旧基线不可读时说明无法比较。用户侧沿已有权限生成该视图，dot 只维护公共派生差异，不读取个人已读记录、不新增订阅或通知任务。

<a id="cc-architecture-reading-context"></a>

#### 查询上下文与恢复

阅读上下文保存目的/模式、单快照或对比双方身份、所选节点/边及旧/新侧、关系族/条件/遍历方向、已提交查询、导览身份/步骤、展开路径和返回焦点。查询游标及异步结果绑定这份上下文摘要；条件或版本切换后，旧响应丢弃，旧游标明确失效并从原查询重读，不能混入新过滤结果。

上下文和个人已读基线沿已有个人记录保存为本模块独立键，不保存整图、短期分页游标或模型正文；跨设备恢复重新签发绑定相同查询的游标。自动更新不抢走正读版本，显式切换才恢复能唯一匹配的对象，失效项保留原引用并回退可读上级。窄屏使用分组列表和详情切换，键盘无需拖动画布即可完成定位、导览、来源阅读与返回；沿既有 150%/200% 缩放及 VoiceOver 排除范围验收。

## 5. 关键运行流程

### DES-CC-ARCH-004：dot 持续维护与接入

<a id="DES-CC-ARCH-004"></a>

工程图接入既有 [Sites 内容 review](../../../.agents/dot/tasks/sites-content-review.md)，作为同一公开来源维护任务的受影响投影。其时间、并发和补跑沿 [SCHEDULE](../../../.agents/dot/SCHEDULE.md) 与真实运行器；主 Agent 协调，subagent 完成具体核对，不能另起“架构定时器”或在缺执行能力时声称后台维护正常。此处是目标接入合同，当前任务对架构元数据及缓存的覆盖需在实施时明确更新和验收；文档采纳不启用任务。

1. **固定范围。** 读取可信 Site/project/公开来源 scope、已发布版本、已采用规则、任务真实启用状态及预算；未配置/停用/未知分别反馈。只解析所选 ref 一次得到 commit，候选所需仓库文件全部来自该 commit，禁止中途重新读浮动 main 拼接。
2. **核对输入。** 通过原受限入口读取主责文档及显式允许的工程清单，记录清单完整性、内容 hash、引用覆盖、解析器/投影规则版本；新来源类别必须在实现配置和任务范围明确纳入。来源正文不能扩充 allowlist、权限或预算。
3. **构造候选。** 以内容和规则变化确定受影响节点、关系、规范与导览，复用已核实且输入未变的内容；变更项按来源变化、提取/覆盖变化与纠错说明原因。删除、重命名、规则失效和不再支持的解析分别记录；不能只监听 Markdown 变化而漏掉清单变化。确实无变化且无待核对项时只更新真实读取/任务健康，不写新内容 revision。
4. **校验与解释。** 检查唯一身份、关系两端、准确引用、规则效力、coverage 和预算；未读/歧义不补边。需要归纳描述时仅使用同一已有授权摘要作业允许的输入、scope、规则和预算，先确认其合同支持本类输出；否则保留确定性图和原文，标“解释待更新”。页面读取、搜索、缩放及普通来源刷新不调用模型。
5. **条件发布。** 按 §7 对完整候选使用原 scope、预期 revision、输入指纹和幂等标识发布；与其他触发共用原作业去重，旧任务不能覆盖新输入或已纠错结果。权限不足、超预算或缺共同去重时保留 last-good 并报告，不切换其他服务代跑。
6. **回读确认。** 回读成功指针、输入 fingerprint、coverage、变更对象及其源引用；只有范围匹配、写入确定且回读成功才称该投影已更新。受理、执行中、源读取成功、模型完成、发布成功与回读确认分别报告。无变化但已核对也可记录本次检查完成，不改事实观测时间。

维护只写允许的公开派生缓存。若发现正式规范遗漏或冲突，保留“待核对/待修正文档”和准确来源并在既有汇报中指出；例行任务不创建 Issue/PR、不改仓库或个人决定、不启动 Coding Agent、不发布站点。另有明确文档修改授权时，先按普通 PR 流程更新主责条款，再刷新本投影；不能为了让图一致而重写正确规范。用户暂停时停止新读取/归纳/发布请求，对在途写入查询原结果，保留真实状态，不暗中补跑。

## 6. 接口与数据合同

接口由现有 Worker/来源适配器承接；下表为逻辑合同，不要求新增独立服务。实现按现有路由风格设置受限路径，路径、版本和错误码在该实现中固定。

| 对象或接口 | 生产者 → 消费者 | 身份与版本 | 成功与失败边界 |
| --- | --- | --- | --- |
| `ArchitectureSnapshot` | 来源/投影 → D1/UI | 可信 scope、repository ID、source commit、document snapshot、formatVersion、parserVersion、policyVersion、inputFingerprint、snapshotId/revision、coverage、构建时间 | 节点/关系/规范/引用完整闭包；生成时间不代替源事实时间；不接受客户端声称的主责或覆盖成功 |
| `ArchitectureNode` / `ArchitectureEdge` | 受控解析 → 投影 | 稳定对象 key、版本、节点类型/边类型/子类型/方向、条件、事实性质、`SourceRef`/原文定位与内容 hash | 缺唯一身份、两端、必要子类型或证据的关系不进入确认图；未知组件可作为缺口对象保留 |
| `RuleBinding` | 规范解析 → 详情 | 对象 key、规范定位/Trace ID、条款版本、适用条件与理由、效力/后继、依据 | 生命周期与实现状态分开；模型建议不能提升为现行要求 |
| `ArchitectureGuide` | 受控配方/投影 → UI | guide key、配方版本、snapshot、适用范围、步骤/分支、节点/边引用、步骤依据及缺口 | 顺序默认只表示阅读；没有执行次序依据不得升级为运行路径；断点不自动补边 |
| `ArchitectureChange` | 确定性差异投影 → UI | 两个 snapshot、对象、前后字段/引用、变化类别、原因及可比较范围 | 源码变化与识别/覆盖变化分开；无法归因明确未知；不把模型严重度当事实 |
| 读取概览/子图/详情/搜索/导览/差异 | Worker → 当前授权用户 | 单 snapshot 或固定对比双方、所选侧、关系族/条件/方向、queryContext 与有界 cursor | 分页/异步响应绑定完整查询；过期或不匹配 cursor 明确拒绝，重读原查询不混入新指针；无权访问不泄露对象、数量或缓存 |
| 构建/发布/查询原提交 | 既有获准维护任务 → Worker | scope、预期 current revision、输入 fingerprint、规则版本、幂等键 | 完整验证后 CAS；同键同内容返回原结果，同键不同内容拒绝；超时先查原提交；不提供任意图/SQL/URL 写入 |
| 阅读偏好 | 当前可信用户 → 个人服务 | 已有个人 envelope、本模块独立 object key、expected revision、阅读上下文与显式已读基线 | 沿原 CAS/身份；不持久化游标；维护服务无个人读写权，不随来源清理删除 |

`coverage` 分开记录应枚举/已枚举的模块和元数据清单、已读/未读/失败文件、受支持/不支持的关系类型、条件解析及缺口原因。源清单完整、解析完整、语义关联完整不是同一字段；分母无法确定时不显示全仓完成率。源事实引用保留实际 commit/path/anchor 或准确检查/环境记录，不把 UI 节点 key 当证据。

`inputFingerprint` 包含允许来源集合及配置 revision、其内容 hash、document snapshot、清单、coverage、parser/policy/format/导览配方版本和纠错 revision；单纯查询时间与运行次数不在内容指纹中。无关源码提交可在重新核实全部依赖输入和清单未变后复用投影内容，但新 commit 的引用需要形成新的版本绑定，不给旧对象就地换 SHA；相同 commit/输入的重复核对不新建内容版本。变化分类依据这些输入差异与对象前后值，不能只看 snapshot ID；个人基线与视图选择不进入公共内容指纹。

## 7. 状态、事务与持久化

### DES-CC-ARCH-005：版本发布与失败恢复

<a id="DES-CC-ARCH-005"></a>

快照数据是 D1 的可重建来源缓存，复用文档快照的不可变候选和[持续发布合同](document-tree.design.md#cc-document-snapshot-update)。候选分块落库后验证关系闭包、manifest/count/hash、规则、导览引用和 coverage，再以事务同时完成候选可读标记及成功指针 CAS；图、节点、边、规范、导览及引用不允许分别成为“当前”。差异缓存固定引用两个可读快照，不替换其内容。UI 的一次阅读绑定 snapshot，不把某批旧节点与新边拼起来。

发布边界再次校验当时有效的服务权限、scope、来源 allowlist 与配置 revision；不能只信构造候选时固定的权限。构建期间来源范围收缩或撤权使旧候选拒绝发布，已存内容继续受当前读权限约束；旧任务不得通过成功指针重新暴露被撤来源。

初次来源只能部分取得时，可发布原子、明确 `partial` 的候选用于阅读已核实部分，并把未读范围建为缺口；它不成为“完整全工程”的成功基线。已有完整 last-good 后，失败/不完整候选只能并列查看，不能替换其成功指针或清空旧对象。分块中断、格式/引用校验失败以及存储错误均不切换指针。元数据采集失败与语义关系未声明分别说明；即使文件读取完整，也不声称语义完备。

| 观测情况 | 页面与持久化处理 | 后续动作 |
| --- | --- | --- |
| 所读输入/规则均匹配 | 显示该快照“与已读来源一致”及覆盖、最后核对时间 | 不推导工程实现/部署/验收完成；无变化只记读取健康 |
| 检测到新 commit/规则，尚未发布 | 旧快照保留原身份，显示新版本待更新 | 既有任务构造候选；正在阅读不自动切换 |
| 限流、权限或预算导致部分读取 | 保留可访问的 last-good，显示失败/未读范围及原事实时间 | 仅在原授权/预算内恢复；撤权后先执行访问控制，不继续供给被撤来源 |
| 明确删除/迁移 | 旧快照与原引用保留；新版本按准确来源标删除/后继 | 无明确后继不按名称重绑；缺分页不能当删除 |
| 并发旧结果或规则纠错后迟到 | 当前输入、policy 或纠错 revision 不匹配则 CAS 拒绝 | 原任务重读后判断是否仍需处理；不提升旧结论 |
| 发布响应或回读丢失 | 标为结果未知，保留原幂等标识和最后确定版本 | 查询原提交；不能换标识重复写，也不能声称已更新 |
| 维护停用/未配置/不可观测 | 内容仍标自身版本，运行状态独立显示 | 不代启或推断正在维护；恢复沿原任务 |

内容状态、coverage、任务配置/执行、源读取、解释生成和发布回读分别记录，沿[更新健康](command-center.design.md#cc-update-health)展示。`current` 仅表示对已读输入的匹配；内容过旧、未读取远端变化与任务不可观测不能互相代称。

成功快照和仍被读取/引用的历史版本按现有缓存保留政策处理。若原版本已不可取得，保留身份和“原版本不可用”，不默读 main；个人关系和阅读偏好独立保存。缓存重建与清理不删除个人历史；原始验收证据由原来源保存，架构缓存不承诺永久证据归档。

## 8. 部署、安全与运行约束

功能在已存在的私有 Sites/Worker/D1 项目内实施，沿原 Site 身份、scope 与来源凭据；不改为公开站点，也不把公开 GitHub 内容的维护权扩成个人资料权限。业务仓库和 Sites 源码仓库是不同版本域：业务 commit、Site source/build 与部署 revision 在验证时分别记录，公共 `site/` 不是此功能的默认落点。

源文件、图标签、Markdown、关系说明和模型输出一律是数据。解析不得执行仓库代码、build.rs、package scripts、模板指令或嵌入 Mermaid 的 click/HTML/脚本；关系图用受限结构化节点/边渲染。超长文本、恶意 URI、路径穿越、symlink 逃逸、重复身份与过大关系集合拒绝或隔离并报告。源链接仅按既有安全导航打开，图不能请求任意地址或创建本机命令通路。

来源读取与缓存更新凭据在服务端持有最小范围，不能接受浏览器传入的 owner、Site、repository 或 allowlist 作为授权。搜索/子图/历史/差异同样执行授权，撤权使相应旧缓存不可读取；last-good 只在仍有权范围内保留可见性。维护日志只记录身份、版本、覆盖与错误，不写令牌、本机路径、私有正文或个人决定。

## 9. 质量与容量

## 10. 兼容、迁移与回滚

新模块以可重建缓存与独立阅读偏好接入，旧文档树、个人决定、工作关系和来源缓存不迁成架构真值。旧快照没有架构投影时显示“尚未生成/未接入”，保留原文阅读，不能把空数据解释为工程为空。

实现先按原 D1/Worker 兼容合同部署可选 schema/受限接口，再生成验证候选并向 UI 开放；规则版本与数据格式分开。旧客户端忽略不认识的模块，新客户端遇到不支持格式保留来源入口，不猜字段。失败时停用本模块读取/发布并回到兼容的最后成功快照或原文阅读；不能靠数据库破坏性降级回滚，已保存个人记录不删除。

dot 的架构来源范围、输出能力及回读在原任务内验收后才可称持续维护已接入；若只上线图阅读，明确标注维护待接入。功能部署、来源生成、任务采用/启用和用户旅程验收各自记录，不因本设计 PR 合入而自动成立。

## 12. 技术决定、风险与复核条件

采用结构化派生关系与渐进展开，复用文档阅读、来源缓存和既有维护任务，避免增加第二套规范、文档编辑器或调度状态。源文档不具备可解析结构时保留原文/未知，按真实需求扩展受控解析；宁可明确覆盖限制，也不让模型补齐看似完整的工程图。

主要风险是模块映射不全、规范范围误判、讲解被误读为执行事实、提取变化冒充工程变化、路径迁移误合并、不同查询混读和维护健康被误报。模块边界/协议/元数据格式、规范主责或 Site 身份/存储发生变化时，重核受影响解析、关系、导览和兼容范围；不为无关 PR 全量重画或重新审定工程架构。
