## 阅读与维护入口

| 入口 | 回答的问题 | 维护内容 |
| --- | --- | --- |
| [项目状态](README.md) | 长期去哪里、近期做什么、做到哪、最近改变了什么、现在要决定什么？ | 带核验时间与来源的滚动摘要；先看当前重点，再下钻验收和工作 |
| [顶层架构索引](architecture/README.md) | 系统如何分层、如何部署、哪些边界影响本次决定？ | 按问题组织的设计入口、边界摘要、实现/部署核验位置和重新关注条件 |
| 当前产品/专业文档、Git、PR、实际 CI、运行记录 | 某项承诺或交付究竟依据什么？ | 保持原有事实与条款主责；摘要只引用，不接管 |
| [本手册](#cc-maintenance-triggers)与 [Skill](../../../skills/oasis7-command-center/SKILL.md) | Codex 下一次如何接着维护？ | 更新方法与执行入口；不保存另一份项目状态 |

云端个人空间按登录用户、项目与环境保存个人问题、决定、显式关联和阅读偏好；保存以服务端持久提交为准。个人决定保留内容、理由、范围、正式文档关联和草稿/确认/替代历史；正式条款的授权修改仍在原工具执行。个人决定不生成双轨同步、证据确认或待处理同步事项。GitHub 来源区管理连接、读取范围补读与错误，PR 与有界 CI 事实在统一工作列表/详情呈现；检查日志及执行仍回原 GitHub。

状态页及架构索引属于派生阅读材料，不是新的任务台账或产品主文档。目标和验收变更回写现有主责 PRD；架构决定回写对应 design/运行合同；部署事实回到现有环境清单、runbook 和真实操作记录。索引中的简述与来源冲突时，保留冲突并核对来源，不靠摘要改变规则。

<a id="cc-maintenance-triggers"></a>

## 什么时候更新

以实际变化触发增量维护，在日常开发和回顾中顺手完成；阅读本手册、安装 Skill 或打开客户端都不等于已经配置后台定时任务。

| 时机 | 执行者的动作 | 更新范围 |
| --- | --- | --- |
| 开始本轮相关工作、恢复中断工作 | 读状态页与架构索引，核对本轮涉及的源文档、PR 和有效用户决定 | 修正会影响当前判断的过期项；只看状态时直接给简报 |
| 短期目标、阶段优先级或长期方向明确改变 | 在已有授权内先维护主责目标，再刷新目标与依赖摘要 | 只更新受影响方向；不要由模型建议自行更改优先级 |
| 有意义的实现、修复、设计决定或验证结果形成 | 在本次工作收尾时核对结果，补充当前进展、近期变化和剩余条件 | 同一 PR 可带上当时已核实的文档更新；尚未发生的合入/部署不能预写 |
| PR 合入、撤回或关联验收结果改变 | 下一次刷新读取实际状态，更新相关进展与近期变化 | 合入后不为改一行“已合入”递归创建新 PR；可并入下一次相关维护 |
| 部署方式、服务边界、持久化/恢复、权限或外部接口改变 | 同步主责设计或 runbook，再核对架构索引及受影响目标 | 分别写设计、实现、实际环境事实；保留环境与核验时间 |
| 用户作出顶层决定，或发现确需人选择的问题 | 回写已授权主责条款，或引用已有决定/问题入口 | 更新待关注事项和受影响边界；已有授权普通工作继续执行 |
| 日常收尾、每周首次项目回顾或阶段评审 | 批量检查当前重点、近期窗口和已解决问题，清理过期摘要 | 只保留仍有决策价值的内容；无实质变化不制造提交 |

工作负责人维护自己影响的条目；跨工作汇总由正在执行项目回顾的负责人或主 Agent 完成。没有正在运行的维护执行者时，页面保持最近一次快照，下次使用先核对时间与覆盖范围，不宣称全天候自动更新。

<a id="cc-maintenance-steps"></a>

## 每轮更新步骤

1. **确定比较范围。** 读取上一份状态页中的文档基线、各来源最后成功核验时间及覆盖范围，解析本轮仓库/工作树/分支。仓库文档固定到实际读取的提交；GitHub 和环境查询各记自己的观测时间，不假装是同一瞬间。
2. **取回权威来源。** 从 [core 当前阶段](../../core/prd.md#当前阶段交付目标与全局-p0)和[产品四域](../../product/README.md)读取目标；从关联 PR、实际 CI、评审及必要的 Issue/运行记录读取进展；从架构索引下钻本轮受影响合同。先取有关变化，不全仓重写。
3. **核对差异及影响。** 判断新增事实改变了哪个目标、完成条件、架构边界或待决定事项。区分已核实事实、执行者汇报、归纳和待核实关联。一个 PR 可支持多个目标，用同一来源链接关联，不复制任务身份。
4. **先维护主责，再更新派生页。** 目标、规范或部署合同有已授权变化时先改其主责正文；已有事实只需刷新摘要。主责暂未同步的明确用户决定，引用已有记录并标明“已决定，条款待同步”，不伪造条款已生效。
5. **更新三个阅读结果。** 项目状态页同步短期/长期关联、已证实进展、最近变化和下一步；架构索引同步受影响边界与来源；待关注项只列真实决定、待补事实或需要知悉的重要变化。
6. **核对时间和链接。** 检查源版本、条款锚点、PR 状态、环境、验收范围与未知项。只成功读取某份摘要不能刷新其中所有事实的核验时间；失败区域保留最近成功结果。
7. **保存并简报。** 在本次已有文档/实施授权及分支范围内保存实际变化，按普通仓库方式提交；只读请求仅返回摘要。向用户说明本轮变化、当前仍未知的部分和入口，不把更新摘要当作合入、部署或验收。

<a id="cc-maintenance-state"></a>

## 项目状态怎么写

保持一个可扫读的滚动页面。历史依靠 Git diff、PR 和源记录追溯，不按天创建日报文件或长期复制全部提交日志。信息归属遵循[流程规范](../workflow/source-of-truth.md#information-record-placement)：同一主题有新结论时替换旧摘要，保留当前能力/限制、来源与核验窗口；不要把候选 SHA、测试数、重试/清理和 CI 等待逐轮拼接进一个长段落。没有改变当前决策的过程只留在原 Task/PR；原 run 的身份与失败链继续留其必要证据，不在摘要复制。

“下一步”是有当前来源支持的方向、真实缺口或待决定事项，不在这里重新派工或维护完整剩余项列表。closed/not_planned Task 只标历史来源；有效用户暂停仍在当前入口可见。

| 区域 | 最少信息 | 取舍 |
| --- | --- | --- |
| 核验说明 | 文档基线、来源观测时间、近期变化窗口、查询范围和缺失来源 | 各来源时间可不同；环境未读取就明确未核验 |
| 长期方向 | 预期用户结果、主责产品入口、当前阶段与它的关系 | 保持可见，默认不把长期目标升级为本轮前置条件 |
| 当前阶段与短期重点 | 阶段目标、接下来交付什么、完成条件、关联长期方向 | 从主责条款取优先级，建议另行标明 |
| 当前进展 | 已核实部分、未完成/未知部分、验收或交付来源、下一步 | PR、CI、运行状态、部署、目标验收分别说明 |
| 最近做了什么 | 日期、变化及其影响、关联目标/边界、当前结果、PR/条款链接 | 聚合同一结果的碎片提交；保留有意义修复和决定，不列活动量排名 |
| 需要人关注 | 具体问题、为什么现在需要、选项与建议、影响范围、处理入口 | 区分“需要决定”“待补事实”“知悉变化”；已解决后移出当前列表 |

为客户端首页和统一工作详情提供可复用内容时，沿 [REQ-CC-013](command-center.prd.md#REQ-CC-013) 与 [REQ-CC-014](command-center.prd.md#REQ-CC-014) 保留稳定章节和明确来源。每项重点写清目标、已核实成果、剩余条件、下一动作与关联工作；下一动作引用主责条款或真实用户选择。摘要只叙述当前工作，不额外登记任务，缺少关系或优先级时标明具体缺口。

复用 PR、条款与会话的明确引用；同一结果的碎片活动聚合到原工作。源位置变化时保留原版本，按显式后继核对；无法消解就呈现待修复及影响，不按关键词猜测。私有资料和派生会话不写入普通状态页、架构索引或公开关联。

滚动文档可保留 3–7 个当前重点、最近 7 天内最多 10–15 条有意义变化；客户端首页默认突出最多三项，其他项可展开。它们是阅读预算，不裁掉真实请求，也不作为仓库准入或验收指标；阶段回顾可明确选择更长窗口。第一次没有可靠历史基线时，用明确时间窗口，并说明不是“自上次查看以来”的完整变化。

进度优先采用“已核实内容 + 剩余条件”。只有完整适用验收集合及结果可核实时才计算验证比例；PR 数量、提交数量、文件数量、会话完成或文档 `active` 都不能作为项目总体完成率。

“最近”条目按源事件发生时间排序，同时保留核验时间；模型生成摘要的时间不是事件时间。PR 已合入可说明代码交付，设计 PR 合入可说明设计已进入仓库；均不能代替实际部署和整体验收。不要把仍在评审的分支内容混入 main 的已实现能力。

<a id="cc-maintenance-architecture"></a>

## 架构索引怎么维护

按人做决定时会问的问题组织入口：总体分层、单权威/多节点、状态与存储、环境与部署、接入与权限、运维恢复、游戏 Agent 接入，以及开发指挥客户端。仅列长期有用的边界，不复制专业文档全文或另画一张脱离实际来源的部署拓扑。

每个索引项保留：设计主题和适用范围、关键边界一句话、主责文档/锚点、设计或实现的核验来源、真实部署状态或其核验入口，以及什么变化值得人重新关注。来源迁移时沿显式后继修正链接；无法确认后继时保留缺口，不能按标题相似度自行替换。

对部署相关项分别回答以下三个问题：

| 层面 | 核对内容 | 可用来源 |
| --- | --- | --- |
| 设计约定 | 哪些服务、状态所有者、写入权与恢复边界被约定？ | 现行 design、基础设施/网络合同、runbook |
| 已有实现 | 哪些组件、配置与验证已进入指定代码版本？ | 对应实现 PR、固定提交和适用测试 |
| 当前部署 | 哪个环境实际运行什么候选，何时检查，开放范围和限制是什么？ | 最近实际部署/健康/恢复记录及现有环境清单 |

设计图中的节点数量、历史清单中的服务 active、曾经通过的验证窗口都不能推成当前生产状态。没有当前环境证据时写“未核验”，引用最近记录及日期即可。页面只保留决策需要的信息，凭据和敏感运行参数继续由既有受控入口管理。

新决定优先写回主责条款中的问题、决定、理由、影响和替代关系。索引负责让人找得到决定；个人草稿和未公开的决定仍按客户端个人数据边界保存，不因刷新自动发布到仓库。

<a id="cc-maintenance-freshness"></a>

## 时间、缺失与并行更新

仅更新部分条目时，在受影响段落记录新的来源基线和核验时间，其他条目保留原时点。页面级基线只概括其明确覆盖的范围，不能因更新一个 PR 就把整页基线前移为“全部已复核”；本次汇总时间也不代替逐项事实时间。

| 情形 | 处理 |
| --- | --- |
| 来源自上次核验后改变 | 核对受影响结论，保留新旧来源关系；本轮尚未核实的标待刷新 |
| GitHub 只读到部分页 | 写清时间/数量/对象范围，不声称完整覆盖全部项目工作 |
| 网络、权限、限额或接口失败 | 保留最后成功事实和时间，说明失败区域与下一次核对入口 |
| 来源无实质变化 | 简报可说明已核对；不只为推进日期制造提交，原事实时间保留 |
| 源文档与摘要冲突 | 展示具体冲突，回主责条款核实；不让局部冲突阻止无关开发 |
| 多个分支同时改同一摘要 | 重新读取目标分支，只合并本轮核实的条目；按来源版本/时间协调，不以整页覆盖抹掉他人更新 |
| 用户改了方向而规范未同步 | 展示真实决定来源和待同步范围；不将待回写等同于待批准 |

刷新仓库本身不等于刷新线上环境，main 前进也不自动使过去适用的 CI 失效。每项结论沿用实际 source HEAD、tested revision、候选和环境范围；客户端读取时间与摘要内部事实核验时间分别解释。

## 交付与使用方式

仓库阅读从[项目状态](README.md)进入；云端日常工作与个人空间遵循[产品合同](command-center.prd.md#REQ-CC-017)，本机操作见[本地客户端使用说明](../../../tools/oasis7-command-center/README.md)。云端索引绑定明确仓库与提交版本，本地未提交预览绑定本机工作树，两者分别显示来源及覆盖范围。已部署、可登录、来源读取成功和个人记录跨设备回读分别核验；具体实现边界见[系统设计](command-center.design.md#cc-current-implementation)。后台来源刷新必须有独立有效的来源访问与受限写入授权；仅有维护流程、网页定时器或部署成功不表示关闭页面后仍会持续刷新。

可向 Codex 直接提出以下请求：

- “按指挥面板持续更新流程，更新项目状态和架构索引，汇总最近一周变化与需要我决定的问题。”
- “只读查看项目状态，重点解释当前部署架构、最近核验时间和未知项。”
- “这项工作完成后，同步它影响的目标进度、近期变化和架构入口。”

持久文档更新沿普通分支/PR 工作完成；相关工作可原子带上摘要更新，专门回顾可批量成一个文档 PR。只读查看和客户端来源刷新不提交文件、不发评论、不启动模型任务或部署。已授权的普通工作不会因为摘要暂未刷新而新增准入、评审角色、完成证明或合入门禁。

检查实际变动的链接、稳定条款、事实语义和派生文档索引；适用命令沿现有文档治理方法。交付时说明更新范围、核验基线、缺失信息与入口；没有本次变化的页面不反复重写。

<a id="cc-architecture-verification"></a>

## 工程架构与规范模块验证

本节承接 [AC-CC-018](command-center.prd.md#AC-CC-018) 与[专题系统设计](engineering-architecture.design.md#11-验证设计与可追溯性)，用于实现后的验证；本手册不启用任务、不改变 dot 的现行写入范围。实际结果记在同一实现 PR，文档 PR 只核对合同和引用，不声称完成下列运行验证。

1. **固定来源及候选。** 分别记录业务仓库 commit、Site source/build/schema、来源 allowlist/清单/coverage、解析及规则版本、已发布 snapshot、可信账号范围与实际任务配置。先从同提交的 core/模块导航和清单列出应覆盖对象，包含前端/脚本/工具与文档域；核对图的缺口与真实未读取、未归属、条件未解析相符，不把文件数等同关系完整度。
2. **核对关系与规范。** 选择 Runtime/Simulator 并列、一个条件 Cargo 依赖、一个非 Rust 工具及一个规范适用关系，对照原文和清单；增加同名组件、普通链接、草稿/退役/冲突规范、缺后继及无实现证据反例。确认图例和方向准确、每条已确认关系有唯一两端和来源，模型建议不能补成权威关系，清单依赖不显示为实际调用/部署。
3. **完成真实浏览旅程。** 在 1440×900 与 390×844 登录浏览器中，三分钟内定位一个核心模块和一个非 Rust 工具，阅读职责、适用条款与同版本代码，返回原筛选/选择/焦点；记录实际耗时与截图。覆盖长中文、键盘、150%/200% 缩放、查漏及两固定版本差异；在第二设备核对已保存偏好，原版本缺失时保留引用而不换读 main。VoiceOver 沿既有排除范围。
4. **验证维护和恢复。** 用获准隔离来源依次制造文档、元数据和规则独立变化，连续无变化，分页/分块失败，初次 partial，有 last-good 时失败，删除/迁移，旧任务迟到，规则纠错及发布回读丢失；核对内容指纹、原子指针、CAS、幂等和旧引用。检查相同输入周期碰撞复用原任务，来源/摘要停用与状态不可读不代启，普通页面交互不调用模型，来源成功与图发布/回读状态分别呈现。
5. **验证安全与兼容。** 使用合成恶意链接/图标签、超大图、路径逃逸及不支持格式，核对不执行代码、不请求任意 URI、不扩大 allowlist；在采集完成、发布之前撤回一个来源或发布权限，确认旧候选被拒绝；撤权后搜索/子图/历史/差异均不泄露缓存。检查旧客户端/旧快照、候选失败回退及个人记录保留。运行器仍未接入时明确“模块可读，维护待接入”，不由配置文件、PR 合入或一次手动刷新证明后台持续运行。

语义样本/组件测试、Worker/D1 事务、真实 Site 身份和浏览器、实际任务执行分别报告范围；测试入口与命令由实现工程提供，不能用此方法文字代替已经执行的证据。例行维护发现需改正式条款时按现有权限汇报，另有文档修改授权才走普通 PR；不为验证本模块自动创建开发任务或修改生产权限。

## 云端个人空间与本机边界验证

本节提供可重复的验证方法，不代表任何候选已经通过。使用专用合成记录及获准测试身份，按实际 Site、应用 source/build、schema 版本、项目/环境、浏览器与设备记录结果；真实结果及未执行范围写入实现 PR。用户信息、凭据、本机私有正文与原始敏感日志不写入公开证据。

| 场景 | 操作与核对 | 不得替代的证据 |
| --- | --- | --- |
| 云端持久保存与跨设备恢复 | 在已登录浏览器保存个人记录、阅读位置与时区，记录服务端返回修订；关闭页面，在另一独立设备/会话登录同一 Site 和主体回读；分别验证项目、环境、视图与本机预览 namespace | 仅原页面内存、健康响应或服务令牌请求不证明用户保存与跨设备恢复 |
| 身份、来源及退出 | 核对未登录、其他 owner、错误项目/环境、篡改记录 ID、跨来源写请求、退出及撤权；检查历史、导出、关联与缓存同样隔离；服务身份只允许已配置公开来源刷新，不获得个人或非公开来源访问 | Site 外层可访问不证明行级授权；存在 GitHub 凭据不证明访客有来源权限 |
| 并发、幂等与故障 | 两会话同时修改同一 revision，重发同一请求及同键不同正文，模拟响应丢失和事务失败；核对冲突保留草稿、记录/历史一致且不产生重复修订；离线输入保持未提交，重连不自动重放 | 客户端显示成功不代替持久提交；刷新失败不能清空个人数据 |
| 决定与恢复文件 | 确认一个具体修订，再修改内容、理由、范围或条款关联，核对新修订待确认及旧确认历史；导出后预览恢复，测试冲突、重复导入、未知格式和篡改 confirmed 字段；仅能核对既有不可变修订的历史恢复其证据，其余保留来源声明及待核实状态 | 文件摘要仅证明内部一致；导入文件不授予 owner，也不自动生成可信确认或触发原工具操作 |
| 来源完整性与阅读 | 核对固定提交的完整/partial 文档树、四域/专业导航、目标与工作关系、准确章节和键盘/IME 返回；模拟 GitHub 权限/限额、截断树、分页遗漏及过期响应，检查最后成功快照；CI 明确 PR HEAD、tested commit、运行类型和覆盖 | 少量预置文档不证明完整树；最新 Actions 运行不证明当前 PR 全部门禁 |
| 浏览器与本机能力 | 同包 App 与真实浏览器核对正确/恶意定位、错误设备或工作树、缺处理程序、云端失联和本机 unknown 操作；在本机资料使用合成 canary，检查 URL、网络及普通日志无私有内容、工具状态无自动上传；确认远程页面不能调用 Tauri IPC，退出浏览器不取消本机操作 | 复制/打开定位不证明恢复会话或执行成功；模拟 UI 不证明原生文件选择、真实 signer 或系统授权 |

部署兼容还需分别验证旧 Worker 与新 schema、新 Worker 与旧数据、schema 已应用但 Worker 上传失败，以及保留个人记录的恢复方案；代码回退不能代替数据库恢复。涉及本机管理员或 signer 首次配置的场景继续遵守现有用户暂停，只记录未执行范围，不以文档修订解除暂停。
