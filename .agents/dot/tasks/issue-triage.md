# 增量 Issue 整理

Trace refs: O7-REQ-1a003dc5-18f2-4cd3-adbb-d1b95316086e。

由时间表指定的 subagent 执行，主 Agent 只协调。统一承接五类 Issue 的分类、类型转换、完成核验、查重和归并；不自动启动开发。唯一类型合同见[开发流程规范](../../../doc/engineering/workflow/source-of-truth.md#issue-lifecycle)，周期与迁移见 [SCHEDULE](../SCHEDULE.md)。

## 输入与范围

目标仓库为 `nil-studio/oasis7`。输入包括采用的规则提交、真实激活时间、计划槽及合并范围、已授权范围、上次完整读取水位、分页进度、持续待办、依赖映射、证据指纹、在途执行与未知写入。每轮处理新增或有实质变化的非 PR Issue，覆盖五类及缺类/多类项，不把所有无标签项自动归为缺陷。

首次从获准的开放项盘点和迁移待办开始，范围未明确时只处理激活后的增量；不默认扫描全部历史。后续使用实际查询时间作为读取上界，以前次已完成水位重叠读取并去重，不以计划槽代替真实覆盖时间。查询 open/closed 的更新：人工关闭、重开、正文和评论变化均可改变原待办；保留人工状态，不擅自重开已关闭项。分页或历史不可完整取得时保留进度和缺口，不前移完整覆盖水位，不称已覆盖全库。

候选除 Issue 自身更新外，还包括持续待办的关联 PR、验收、依赖和明确复查点的变化；PR 合入未必更新 Issue，因此维护已跟踪依赖到 Issue 的映射，按依赖增量或有界复查发现变化。旧待办和未知结果不得因落出增量窗口丢失。没有共同状态时只做独立只读核对，不能从空记录重新派工或写入。

`updated_at` 只用于发现候选，不证明出现新事实。以正文有效内容、证据、决定、关联交付与依赖变化去重；自己的格式评论或标签修改不触发重复分析。无变化、等待用户决定且条件未变的项不重复评论。每轮按既有预算分批处理，不循环全库扫描；达到上限返回 partial、待办和水位。

## 分类与转换

缺陷根因不明或证据不足时，保留缺陷类型并列出补证条件；明确文档缺口转文档，设计充分或已有明确 bug 合同转代码，需 owner 取舍转决策，确有独立测试目标且范围/环境/退出条件明确才转测试。文档完成后可转代码，决策完成后可转文档，普通开发自测不单独转为测试项。

转换沿用原 ID，保留原问题、讨论、完成成果和全部未完义务；补齐目标类型的来源、范围、验收、依赖、交付终点和真实下一责任人，无人承接时注明待承接。在同仓库写入互斥内重新读取执行者与最新状态，更新正文当前目标、唯一类型，并以一条有实质变化的评论记录依据、完成项和剩余项；写后分别回读。五类标签定义须先存在，不在巡检中创建定义。缺权限、标签或安全协调时保留待修正，不假称转换成功。

活跃实现先协调原执行者；转换不解除暂停、不删除执行记录、不自动添加 ready 或启动 Coding Agent。非代码项不得保留可消费的 ready；不能以转测试掩盖未完实现或设计。部分写入和未知结果先查原结果，只补未确认步骤。

## 先核实，再选择动作

读取每项正文、必要评论、状态变化、关联实现与验收记录，区分已提出方案、已提交 PR、已合入和目标已满足。整理依据使用真实来源，不以年龄、标题相似、机器人标签或单个绿色检查代替完成判断。

| 情形 | 操作 |
| --- | --- |
| 全部要求和明确验收义务已满足 | 写明完成证据及范围后关闭；已按同一依据关闭且无新信息则不操作 |
| 与现有 Issue 完全重复 | 选定可继续跟踪的主 Issue，补齐遗漏信息和双向引用后关闭重复项，理由为重复而不是宣称需求已实现 |
| 多项属于同一问题且可共同交付 | 复用活跃主 Issue，迁移每项独有要求、验收和依赖，再引用并关闭已完整承接的项；主 Issue 保持开放直至全部义务完成 |
| 只部分重叠、仍有独立交付价值 | 仅关联并说明分工，不强行合并或关闭 |
| 仍有代码、测试、环境验收、部署、用户决定或证据缺口 | 保持开放，在报告说明具体剩余项；已有同样说明且无新证据时不重复评论 |

关闭完成项须确认整个 Issue 的目标，而非其中某个 PR。协调多项交付的 Issue 不能因一个 PR 合入就关闭；没有授权不取消验收义务或缩小目标。相关原始要求不同的 Issue 不因标题相似合并。

合并在本任务中指内容和跟踪归并，不删除原 Issue。优先保留已有实施关联、清楚验收范围的主 Issue，不机械选编号最小项；先把独有要求、证据、依赖和未完成事项补入主 Issue 并回读确认，再在来源项说明去向并关闭。保留原正文与讨论，不覆盖他人内容、不编造负责人/优先级；没有合适承接位置时保留原项。

## 写入、去重与恢复

仅执行 [AUTONOMY.md](../AUTONOMY.md) 授权的 Issue 补充、引用、去重、合并和关闭，不修改代码、CI、分支保护、PR 或部署，不删除 Issue。按 [HEARTBEAT.md](../HEARTBEAT.md) 使用同仓库 Issue 写入互斥，避免与 CI 卡点建单或其他周期补跑互相覆盖。

每次操作前重新核对目标仓库、Issue 编号、当前状态与最新讨论。发现人工新增要求或其他执行者已经整理时，重新判断相关动作，保留有效新内容；不对所有候选盲目批量关闭。具体问题无法核实时跳过该项写入，继续独立可做的事项，不要求每个有充分证据的关闭都重复请示。

增量读取窗口重叠，按 Issue、操作目的和证据去重，不按执行日期生成重复评论。将主 Issue 关系、已迁移内容、关闭依据和服务器回读结果保存在私有运行记录；重试先协调已有结果。若要求迁移已成功、关闭未成功，只核实并补余下动作；写入结果未知时先查服务器，不复制整轮操作。

实际权限不足、接口不支持或覆盖超出 60 分钟执行预算时保留未完成项及读取进度，返回部分完成；不把缺证据项视为可关闭。后续已授权整理任务可从记录续办，不为了耗尽积压扩大模型预算或自动启动新任务。发现误关闭时，只有本轮可证实的误操作可在原授权范围内恢复原状态并说明；已有人工新决定冲突时保留现场并报告，不覆盖他人处理。

## 返回给主 Agent

```text
结论：已整理 / 无需变更 / 部分完成；说明最值得关注的剩余事项。
范围：计划槽及合并范围、增量窗口与时区、实际查询时间、候选数量、分页及历史覆盖。
分类转换：Issue 链接、旧类型 → 新类型、依据、剩余义务及真实负责人。
已完成关闭：Issue 链接、满足的要求和完成证据。
去重/合并：来源 Issue -> 主 Issue，独有要求承接位置及真实关闭状态。
保留：仍需实现、验证、部署或决策的 Issue，以及不能合并的原因。
待协调：未完成/未知的写入、权限缺口和续办进度；不要计入已完成数。
结果：可读取的报告、操作回读及来源；不包含私有机器信息或敏感日志。
```

无变更也返回简报；只有回读确认的动作计入已整理结果。报告给主 Agent，由其统一通知，不再递归派工或重复向用户发送。

## 接入后的试用情形

这些情形用于核实真实运行器，不代表当前已执行或新增仓库门禁。

| 情形 | 期望 |
| --- | --- |
| 新建、旧项编辑、关联 PR 合入但 Issue 自身未更新 | 按 Issue 与依赖变化纳入，不只看 Issue 更新时间；PR 仅作为依赖证据 |
| 已合入 PR，但 Issue 还要求部署/验收 | 保持开放，写明未完成义务 |
| 两个标题相似但验收目标不同 | 不自动合并 |
| 来源项存在主 Issue 尚未记录的要求 | 先迁移并回读确认，再关闭来源项 |
| 连续两轮、漏槽恢复或写入响应丢失 | 协调已有结果，不重复评论、迁移或关闭 |
| 实际写入前出现人工新要求 | 重新判断相关操作，不按旧快照批量关闭 |
