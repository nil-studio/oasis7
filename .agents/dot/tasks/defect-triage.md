# 缺陷 Triage 与类型转换

Trace refs: O7-REQ-1a003dc5-18f2-4cd3-adbb-d1b95316086e；承接五类分类与有界分流，产品层不适用，不实现运行器。

由时间表指定的 subagent 在已采用版本与授权范围内执行；主 Agent 只协调。类型、准入、转换和关闭的唯一合同见[开发流程规范](../../../doc/engineering/workflow/source-of-truth.md#issue-lifecycle)，本任务不新增第六类型或实现授权。

## 目标与输入

每 20 分钟检查 `nil-studio/oasis7` 已授权范围的 open 缺陷，查重、确认事实与设计边界，将条件已明确的项在原 Issue 转为文档、代码、测试或决策。不是要求每项每轮都转换：根因/证据不足保留缺陷，记录可操作的补证条件；重复、误报或决定不做按授权与证据处理，不制造虚假下游工作。

输入包含计划槽及合并范围、采用的规则版本、真实 activated_at、候选分页/处理水位、未完成与未知写入、已处理证据指纹、写入互斥、发布者/仓库/预算授权。首次接入在明确采用范围内盘点现存 open 缺陷，分批保留进度，不追补激活前的时间槽。旧缺类、多类项只按获准迁移范围纳入待修正清单；不是把所有无标签项自动归缺陷。

后续按上轮水位读取新增/更新及到期补证项，始终处理持久待办；增量候选同时包含已授权范围内新建或更新且缺类/多类的非 PR Issue，先列待修正并核实正确类型，不自动归缺陷，也不扩大历史迁移范围；分页未完成不前移覆盖水位。`updated_at` 只用于找候选，不是出现新事实的证明。以正文有效变化、新证据/决定、相关 PR/测试结果和依赖变化核对是否需重新 Triage；自己的标签变更、格式评论或相同已读证据不触发重复分析。没有变化不写评论，也不每轮全库扫描；依赖未变或等待 owner 的项保留等待条件，只在新证据或明确复查点再处理。不得因查询只返回一页就宣称覆盖全部。

## 每项怎么处理

1. 回读正文、必要评论、分类、执行会话和相关 PR；固定受测版本/环境，区分症状、源码结论与假设。检索 open/closed 相关项，复用同源承接，不以标题相似强合并。
2. 对照主责产品/系统设计：明确实现偏差可转代码；明确文档缺口转文档；需要 owner 产品取舍转决策；需要独立、有边界的测试来确定覆盖/事实转测试。不是所有诊断都另建测试项，普通补证可继续在缺陷中完成。
3. 依五类合同补齐目标类型的必要内容、验收、依赖、下一责任人和交付终点；保存原事实、历史讨论与未完义务。文档完成后的代码接续、决策后的文档接续、合理的测试接续由相应任务负责人同样在原 ID 处理，不等待本缺陷周期扫描所有其他类型。
4. 在同仓库写入互斥内重新读取最新状态，确认无人并发接手或改变要求，再更新唯一类型/当前任务摘要并记录转换依据；不覆盖其他标签或他人正文。转换不新增 ready、不自动解除 paused/blocked，不启动 Coding Agent。活动任务需先与原执行者交接，不能用换类绕过在途任务。
5. 回读分类、正文及转换 comment；未完全成功保留分步结果，下一轮只补未确认部分。API 写入不是原子事务；正文/标签冲突或写入未知期间不得派工。未变更不重复评论；没有权限的动作报告准确阻塞。

原问题已被完整承接且确实重复，或充分证实误报时，按已有关闭权限记录依据和去向后关闭；没有关闭权限则只提出建议。不因无法复现、年龄或缺格式自动关闭。明确取消目标须由有权者决定。每日[前三日整理](issue-triage.md)仍负责独立的完成核验与归并；两项共享操作记录，已做的动作不重做。

## 调度与执行边界

按 [SCHEDULE](../SCHEDULE.md) 的周期合并规则处理漏槽；每类周期项各有一个待派承接项，运行中不重派，最多保留一个后续项。共用 [HEARTBEAT](../HEARTBEAT.md) 的并发、执行预算、同仓库写入互斥及结果未知协调。达到本轮上限交付 partial 与水位，不自建循环、额外定时器或递归派工追赶积压。

仅做已授权的 GitHub 读取、分类、增量正文/评论和上述去重关闭；不改代码、workflow、权限、PR、标签定义或部署，不创建开发会话、不消费未批准模型额度。模板/标签定义由规范采用者预先配置，本任务不在每轮自行重建。缺真实触发器、持久状态或派工接口时报告未接入，文件合入不等于任务启用。

## 返回与接入验收

返回实际查询时间、规则版本、周期覆盖和候选分页范围；列出已转换项的旧/新类型及依据、保留项及补证条件、待 owner 决定、待承接和未确认写入。只有服务器回读确认的操作计入完成。无变化可给主 Agent 简报，不给每个 Issue 写空巡检 comment。

接入后须验证以下场景并记录真实结果，不把下面清单当已通过：
- 同一缺陷连续两轮/并发两轮，只执行一次有依据的转换。
- 缺设计、明确实现 bug、独立测试需求、产品取舍分别进入正确类型；无法判定不强转。
- 文档 → 代码、决策 → 文档保留同一 ID 和历史；仍未解决实现问题时不借测试类型洗掉义务。
- 活跃开发、暂停、人工并发修改、标签/正文部分写成功与响应丢失均不造成重复派工或丢失内容。
- 漏多个槽只合并一次，保留未处理分页和待办；自己的评论不形成下一轮写入循环。
- 模板、API 和旧项缺类/多类时可被识别为待修正，不进入代码消费，不批量关闭。
