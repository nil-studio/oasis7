# dot 时间表

本表是例行任务的唯一时间定义；执行方法见 [HEARTBEAT.md](HEARTBEAT.md)。表内“纳入巡检”表示配置意图，不表示外部触发器或 subagent 已启用。本次 PR 尚未启用实际巡检。

## 时间与触发

- 时区：`Asia/Shanghai`（北京时间，UTC+08:00），每日 13:00 及周期槽均按此解释；接入时明确展示，不使用设备或账户的隐含时区。
- 期望巡检：每 20 分钟一次，对齐每小时 `:00 / :20 / :40`。时间表定义到期时间，不承诺精确在该秒启动；延迟触发仍检查所有应补的项。
- 日历：每天执行，包含周末。每日事项使用稳定 ID 和日内时间；周期事项另列周期与实例规则，不套用每日去重键。
- 实际调度、持久状态和 subagent 入口均须在运行器接入时核实；文件不是这些能力的实现。

### 迁移与实际启用

本 PR 只修改流程，不注册、停用或修改线上任务。新规则被明确采用且具备执行授权后，运行器按以下顺序切换：

1. 核对两个旧任务的真实 ID、采用版本、在途执行、未完成分页、依赖待办、证据指纹和未知写入；保存切换点及可恢复交接记录。已存在但未运行的历史实例不能标为成功。
2. 阻止两个旧任务的新派工，协调已认领执行与未知结果；保留其原身份、版本、重试次数及回执，不能通过改名重新派一份。
3. 将未完成工作映射到统一待办：旧每日实例保留原计划日期与三日窗口直至有界处理完成，旧缺陷项保留实际水位；重叠证据只处理一次。历史完成记录不删除、不重跑，等待用户或执行者的项继续等待。
4. 确认旧入口不再产生新派工、状态交接完整和同仓库互斥有效，再启用唯一 `issue-triage` 周期入口，记录真实激活时间；从下一个未认领槽开始，不追补新入口激活前的空槽。
5. 回读真实任务状态并验证连续两轮不重复写入、关联 PR 变化可唤起原待办、漏槽及部分失败不会丢项。缺状态后端、原子认领或权限时仅保留配置和只读核对，不宣称迁移完成，不自动恢复另一份旧调度。

Issue 与 Sites 周期项各自保留一个 pending/waiting_executor 承接项；新增槽只扩展覆盖范围，在途身份不变。共享既有并发和执行预算，不因合并职责扩大权限、模型预算或代码开发范围。

## Sites 内容 review 与更新

| 稳定 ID | 纳入巡检 | 周期 / 到期时间 | 执行者 | 事项与输出 |
| --- | --- | --- | --- | --- |
| `sites-content-review` | 是，待核实接入 | 每 20 分钟，每小时 `:00 / :20 / :40` | subagent | 按 [Sites 内容 review](tasks/sites-content-review.md) 核对公开来源、项目状态、交付摘要与任务运行情况；有新增或过期内容时，在已有授权和可用入口内更新，无变化不重复写 |

本项使用 `Asia/Shanghai`，按自己的真实 `activated_at` 起算，首个计划槽不得早于激活时间，不追补启用前时段。周期实例键为 `eng-cc/oasis7/sites-content-review/YYYY-MM-DDTHH:mm+08:00`，时间是计划槽而非实际开始时刻；保留运行器既有仓库命名空间，实际来源仍核对 `nil-studio/oasis7`，不因改名重建历史实例。

漏过多个槽时合并为一次针对最新可读来源的恢复 review，记录最早/最晚被覆盖计划槽、承接实例键和处理水位。首次恢复且没有待派承接项时取最新槽键；已有 pending/waiting_executor 承接项保持原键、尝试次数和 next_retry_at，新增槽只扩展其覆盖范围，不借新槽重置退避或预算；中间槽记为合并覆盖，不伪记逐槽执行成功，不重建历史摘要。在途任务或结果未知的写入必须先协调，不能被合并丢弃；运行中再到期最多保留一项后续 review。每日事项仍按原日期逐项补跑；可派的每日积压优先，周期合并项共享既有并发、单轮派工和执行预算，不占满队列追赶旧槽。

已有每小时整点的独立交付摘要任务仍以其真实任务配置为准，本表不重新创建、启停或改频。20 分钟 review 与小时触发复用同一摘要作业及输入版本去重，不能各自启动一份归纳；接管、改频或移除旧触发器必须在获准后核实真实配置和在途结果。共用作业/互斥无法确认时只检查和报告，暂停新的自动写入，不假定已有实现满足协调合同。

## 生效与补跑

每日事项首次启用记录真实 `activated_at`，从启用当天开始检查，不追溯启用前的日期；当天已经到期的项应在首次有效巡检补跑。之后保留所有到期未处理实例，按到期顺序、在并发上限内补跑，不因跨天或漏过一个时间槽丢弃任务。

每项已生成实例固定计划到期时间、时区和当时采用的配置版本。已有每日事项的时间/任务说明变更默认次日本地 00:00 生效，不改变当天已派出或已完成的实例；暂停、删除或用户停止立即阻止新派工，并协调已派任务。各周期项的规则变更在明确采用后，从下一个尚未认领的计划槽生效，保留旧实例及在途任务的版本。规则版本变化不能自行引入新授权。

CI 回顾的“前一天”相对于计划到期日计算，不相对于实际补跑日计算。例如计划 `2026-10-13 13:00 +08:00` 的项检查 `[2026-10-12 00:00, 2026-10-13 00:00)`；即使 10 月 14 日才补跑也不改统计日期。

旧每日 Issue 实例的三日窗口仅在上述迁移中保留；新增量实例按任务说明读取实际变化，不以补跑日重算旧范围。

示例仅说明时间语义，不是已创建的执行记录。执行状态不写回本表，也不为每次巡检向仓库提交文件。
