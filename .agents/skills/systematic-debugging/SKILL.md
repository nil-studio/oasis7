# systematic-debugging

通用规则见 [开发流程规范](../../../doc/engineering/workflow/source-of-truth.md)。

取得可重复失败和准确错误，区分产品、测试、环境及入口问题。缩小输入与失败边界，读相关实现和近期 diff，提出可证伪假设。

用最小实验验证关键假设，定位根因后先按[设计检查与修复](../../../doc/engineering/workflow/source-of-truth.md#root-cause-design-check)核对受影响的产品设计文档和系统设计文档，再决定修复路径。检查产品要求、体验和验收是否遗漏或冲突，以及系统职责、接口、状态和失败/恢复合同是否足以支持正确行为。

有设计缺陷时，先修订受影响的产品/系统文档，再按正确约定补回归、修复实现并验证；设计与实现同时有问题也按此顺序。设计正确而实现偏离时，直接修复验证，不为流程改文档。缺文档或约定含糊不能直接认定纯代码 bug；查明设计依据，必要取舍超出授权时只暂停依赖动作。只修有问题的层级，同一 PR 连续完成，不要求文档先单独合入。

不用重启、跳过测试或吞错误掩盖根因，也不改写正确设计或放宽测试迁就错误实现。对可自动复现行为先写或修正回归测试，观察失败再修复；测试保护真实行为，避免镜像实现。验证受影响消费者、兼容和失败路径，说明环境限制。在当前 PR 或已有 Task 简述根因、设计判断及依据、修复与验证结果，不新建排障表单或流程任务。

复杂问题按需请求领域协作，给出复现、上下文、写入范围和期望结果；不依赖流程身份。重复失败时修正假设，不堆叠猜测补丁。

## 选择能检出原症状的反馈环

保留失败版本、输入、错误与原请求身份；先选成本最低且能稳定判红的方法，不把全部工具依次跑完。重启、新世界或新请求上的正常结果不能替代原失败。

| 症状 | 优先实验 | 判断边界 |
| --- | --- | --- |
| 特定输入、编码或恢复状态失败 | 缩减为固定 fixture | 保留触发条件，确认失败来自行为断言而非环境未就绪 |
| 多阶段请求或时序相关 | 回放原事件，并对照边界前后的输入/输出 | 找首个分歧；回放不代替真实网络或 Runtime 验收 |
| 多种合法输入组合破坏不变量 | 性质测试或有界 fuzz，并缩减反例 | 不变量取自合同；随机跑完不等于穷尽 |
| 同输入在宿主或实现之间不同 | 对齐版本和 canonical 输入后差分 | 再用独立样例核对，避免两个实现共同出错 |
| 历史好/坏版本之间的稳定回归 | 用同一判红用例 bisect | 首个坏提交只是候选；排除环境漂移和 flaky 后核实因果 |

一次实验区分一个关键假设，先说明预期观察，再改变最小因素并对照结果。反证出现时修改假设，不叠加无关补丁；修复后重跑原失败及受影响消费者。回归用例按[公共行为与独立预期值](../../../testing-manual.md#regression-oracle)选择接缝，不能用被测转换再生成 expected。

## 跨边界定位

从请求发出的真实入口沿已有 request/correlation、world 及适用 fence 追到权威结果，比较每个受影响边界的输入、输出与错误。入口关联应来自实际记录，不用时间接近猜关联；缺字段或材料时明确未知，再补最小必要观测。trace success、日志中的 committed 或本地 UI 状态均不能代签世界效果。

优先读取已有证据；故障注入只在获准的隔离范围执行。诊断输出只保留定位所需字段并脱敏，不记录密钥、私有目标或完整敏感 payload；请求/用户等高基数标识不作为指标标签。定位恢复问题时按[原请求恢复定向回归](../../../testing-manual.md#request-recovery-regression)核对原身份、当前权限与业务结果，不用更换意图绕过未决状态。

## Known Failure Modes

局部失败只阻塞依赖动作，其他已授权工作继续。目标或外部影响扩大时确认新增部分；远程结果不明先查询，不重复创建或伪造完成。不以 Task、Project、模型观测或 receipt 代替真实结果。
